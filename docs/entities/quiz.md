# Викторина (GameQuestion)

Описание сущностей для вопросов и ответов в викторинах на LED-платформе.

Используется в сценариях: **Индивидуальная викторина**, **Командная игра** (раунды).

Индивидуальная викторина и командная игра используют одну и ту же сущность вопроса. В обоих режимах оператор может выбрать опубликованный шаблон или настроить раунды вручную. В командном режиме ответы объединяются по командам, в индивидуальном — учитываются отдельно.

---

## GameQuestion (Вопрос викторины) {#gamequestion}

Вопрос для викторины на LED-платформе. Используется как в индивидуальной викторине, так и в раундах командной игры.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор вопроса |
| `type` | integer | Числовой тип вопроса из [справочника](../references/quiz-question-types.md) |
| `text` | text | Текст вопроса |
| `profession_id` | bigint, nullable | FK → professions.id; необязательная привязка для рекомендаций |
| `media_id` | integer (int64), nullable | ID файла (изображение или видео) |
| `difficulty` | integer, nullable | Числовой уровень сложности из [справочника](../references/quiz-difficulty.md) |
| `age_group` | integer, nullable | Числовой ID возрастной группы из [справочника](../references/profstart-age-groups.md) |
| `time_limit` | integer | Время на ответ в секундах, обязательное положительное значение |
| `points` | integer | Баллы за правильный ответ |
| `explanation` | text, nullable | Методическое пояснение к правильному ответу |
| `round_type_id` | integer, nullable | Числовой ID типа раунда из [справочника](../references/scenario-round-types.md) (для классификации вопросов) |
| `tags` | json, nullable | Теги (профессия, отрасль, компетенция) — см. заметку ниже |
| `answer_key` | json, nullable | Эталонный ответ для структурированных типов (`matching`, `role_distribution` и др.); формат зависит от типа вопроса |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата обновления |

Форматы JSON-поля `GameSessionAnswer.answer` определяются типом вопроса. Для вопросов с выбором `option_id` и `option_ids` ссылаются на `GameAnswerOption.id`; идентификаторы в массивах передаются в порядке, выбранном участником.

| Типы вопроса (ID) | Формат ответа | Настройка эталона |
|------------------|---------------|------------------|
| single: 1, 3, 4, 8, 9, 11, 14, 15, 16, 17, 18 | {"option_id": 12} | Один вариант с is_correct=true. Для yes_no создаются два варианта. Для 8, 9, 17 медиа прикладывается к вопросу. |
| multiple: 2, 13 | {"option_ids": [12, 14]} | Правильные варианты с is_correct=true; порядок незначим. |
| matching: 5, 7, 12 | {"pairs": [{"left_option_id": 12, "right_option_id": 14}]} | Две стороны через side=1/2, эталонные пары в answer_key.pairs. Распределение ролей — сопоставление, без participant_id. |
| sorting: 6, 10 | {"option_ids": [14, 12, 13]} | Правильная последовательность по GameAnswerOption.order. |

Структурированный ответ передаётся JSON-объектом в поле answer. Все 18 ID сохранены;
типов со свободным ответом нет. Поля text вопроса и вариантов остаются. Дополнительное
answer.text сохраняется вместе с ответом, но не участвует в проверке и не заменяет
option_id/option_ids/pairs. Ответ только с text не считается правильным.

Для типов 5, 7 и 12 сначала создаются варианты с side=1/2, затем в PUT вопроса
задаётся answer_key.pairs с фактическими ID вариантов. Частичный балл учитывает
правильно сопоставленные пары; одинаковые левые элементы с неверными правыми не дают баллов.
Одинаковые повторные пары не заменяют отсутствующие эталонные пары.


Проверка зачётного ответа выполняется автоматически по вариантам ответа, их порядку и `answer_key` в зависимости от типа вопроса. Ручная оценка оператором в API викторины не предусмотрена. До показа правильного ответа данные `is_correct` и `answer_key` не возвращаются в состоянии сессии для LED и мобильного клиента.

`tags` — необязательный массив строк для классификации вопросов. Использование тегов, сложности и возрастной группы при автоматическом выборе, а также альтернативу с явными `question_ids` описывает [сущность игровой сессии](game-session.md#gamesession).

### Связи

- **GameQuestion → File**: вопрос может иметь медиа-файл (`media_id`)
- **GameQuestion → GameAnswerOption**: один вопрос имеет множество вариантов ответа
- **GameQuestion → GameSessionQuestion**: вопрос может использоваться в шаблонах и игровых сессиях
- **GameQuestion → ScenarioRoundType**: вопрос может быть классифицирован по типу раунда (`round_type_id`)

### Где используется

- **CMS** — создание и управление вопросами
- **LED-медиаплатформа** — показ вопросов в индивидуальной викторине и командной игре
- **Аналитика** — анализ ответов по вопросам

## GameAnswerOption (Вариант ответа викторины) {#gameansweroption}

Вариант ответа для вопроса викторины.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор варианта |
| `question_id` | integer (int64) | ID вопроса |
| `text` | text | Текст варианта ответа |
| `media_id` | integer (int64), nullable | ID файла (изображение) |
| `is_correct` | boolean | Является ли вариант правильным |
| `order` | integer | Порядок отображения |
| `side` | integer, nullable | Сторона сопоставления для типов 5, 7, 12 (matching): `1` — left, `2` — right; для остальных типов не заполняется |

### Связи

- **GameAnswerOption → GameQuestion**: вариант принадлежит одному вопросу (`question_id`)
- **GameAnswerOption → File**: вариант может иметь медиа-файл (`media_id`)

В ответах CMS и в `current_question.question.answer_options[]` игрового состояния каждый вариант содержит `side`: `1` — left, `2` — right, `null` — сторона не задана. Поле возвращается оператору, LED и участнику через `GET /quiz/sessions/{id}` и `GET /quiz/sessions/active?device_id=...`.

Для типов 5, 7, 12 (matching) варианты делятся на две стороны через `side` (`1` — left, `2` — right); `answer_key.pairs` содержит соответствие между ID элементов этих сторон. Баллы вопроса (`points`) задаются целым числом; рассчитанный счёт хранится как десятичное число из-за множителя раунда.

### Где используется

- **CMS** — создание вариантов ответов
- **LED-медиаплатформа** — показ вариантов участникам


## Файлы в API

Файлы загружаются в multipart-запросе, а ответы возвращают универсальный объект
с URL, MIME-типом, названием и описанием. Формат и поля загрузки описаны в
[контракте файлов](files.md#загрузка-и-ответ-api).


В CMS `profession_id` можно опустить или передать ID активной профессии.
PUT с пустым полем или строкой `null` снимает привязку; отсутствие поля сохраняет
её. Неизвестная или удалённая профессия даёт 404. Привязка копируется в вопрос
сессии и используется для [рекомендаций](user-recommendations.md#источник-ответов-викторины).
