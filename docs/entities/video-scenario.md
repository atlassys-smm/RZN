# Профессии в действии

Описание сущностей для интерактивных видеосценариев с точками выбора.

Используется в сценарии: **Профессии в действии**.

---

## InteractiveVideoScenario (Видеосценарий)

Интерактивный видеосценарий с точками выбора. Видео воспроизводится на LED-платформе, в конце каждого фрагмента пользователь делает выбор, который влияет на дальнейший ход видео.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор сценария |
| `title` | string | Название сценария |
| `description` | text, nullable | Описание сценария |
| `profession_id` | integer (int64), nullable | ID профессии из справочника (связь с направлением) |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата обновления |

### Связи

- **InteractiveVideoScenario → InteractiveVideoScenarioBranch**: сценарий имеет множество веток. Стартовая ветка определяется как ветка с `parent_id = null` — её `media_id` является стартовым видео сценария.
- **InteractiveVideoScenario → Profession**: сценарий может быть привязан к профессии (`profession_id`)

### Где используется

- **CMS** — создание и управление видеосценариями
- **LED-медиаплатформа** — воспроизведение видеосценариев с интерактивными выборами

### Данные профессии в CMS

`GET /api/cms/video-scenarios` возвращает `items` и `total`. Каждый элемент списка
сохраняет `id`, `title`, `description`, `profession_id`. Только при запросе
`GET /api/cms/video-scenarios?select=profession` добавляется поле `profession`.

Этот же параметр доступен при получении одного сценария:
`GET /api/cms/video-scenarios/{id}?select=profession` возвращает полные данные
профессии вместе с деревом веток. Без параметра поле `profession` отсутствует
и данные профессии не загружаются. При отсутствии привязки по запросу возвращается
`profession: null`; мягко удалённая профессия существующего сценария также доступна.

## InteractiveVideoScenarioBranch (Ветка видеосценария)

Ветка видеосценария — фрагмент видео с вариантами выбора. После воспроизведения видеофрагмента пользователю показываются варианты выбора (дочерние ветки). Если дочерних веток нет — сценарий завершается.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор ветки |
| `scenario_id` | integer (int64) | ID видеосценария |
| `parent_id` | integer (int64), nullable | ID родительской ветки (null для стартовой записи) |
| `reference_branch_id` | integer (int64), nullable | Ссылка на существующую ветку того же сценария. При выборе backend сразу переходит к цели ссылки |
| `media_id` | integer (int64), nullable | ID собственного видеофайла. Обязателен для обычной ветки; у ссылочной может отсутствовать |
| `prompt` | text, nullable | Текст вопроса в точке выбора. Заполняется для веток с дочерними вариантами (стартовая и промежуточные). Пустой/null для конечных веток. |
| `text` | text, nullable | Текст-подпись варианта выбора (то, что видит пользователь при выборе из родительской ветки). Заполняется для дочерних веток. Пустой/null для стартовой. |

### Связи

- **InteractiveVideoScenarioBranch → InteractiveVideoScenario**: ветка принадлежит одному сценарию (`scenario_id`)
- **InteractiveVideoScenarioBranch → InteractiveVideoScenarioBranch**: ветка может иметь родительскую ветку (`parent_id`) и дочерние ветки
- **InteractiveVideoScenarioBranch → File**: ветка может иметь видеофайл (`media_id`)

### Ссылочные ветки

Ссылочная ветка имеет собственные `parent_id` и `text`: в списке вариантов и голосах используется её ID, а текст ответа не подменяется текстом цели. `reference_branch_id` указывает на существующую ветку того же сценария. Видео для такой ветки не требуется. Собственные видео и `prompt`, если они сохранены, при показе игнорируются.

После выбора победителя backend разрешает цепочку ссылок и сразу сохраняет конечную целевую ветку в PostgreSQL и Redis. LED получает её ID, видео, вопрос и дочерние варианты. Это действует при закрытии голосования по таймеру, при отсутствии голосов и при досрочном завершении. После потери Redis воспроизводится сохранённая целевая ветка.

Стартовая ветка и ветка с дочерними вариантами не могут стать ссылочными. К ссылочной ветке нельзя добавить детей: дальнейшие переходы задаются у цели. При создании и обновлении в CMS ссылки на себя, другой сценарий, отсутствующие ветки и циклы, включая циклы через дочерние варианты, отклоняются с 400. Несколько вариантов с разными текстами могут ссылаться на одно продолжение.

Во время реальной сессии циклическая цепочка ссылок не вызывает ошибку 400 и не зацикливает API-запрос: обход прекращается при повторном попадании в ветку. Воспроизводится последнее встреченное собственное видео; если в цепочке его нет, повторяется текущая ветка. Циклы обычного воспроизведения через вопросы во время показа не блокируются. Проверки циклов при сохранении в CMS остаются обязательными.

CMS принимает `reference_branch_id` в multipart POST/PUT и возвращает его в ответах ветки и дереве. В PUT отсутствие поля сохраняет ссылку, пустое значение снимает её. При снятии ссылки нужно собственное сохранённое видео или новый `file` в том же запросе, иначе возвращается 422. Ранее загруженное собственное видео при установке ссылки сохраняется. Дерево CMS строится по `parent_id`; поддерево цели в ссылочную ветку не копируется. Ветки с `reference_branch_id = null` работают по прежней логике.

### Где используется

- **CMS** — создание дерева веток видеосценария
- **LED-медиаплатформа** — воспроизведение видео и показ вариантов выбора

### Примечания

- **Стартовая ветка** — ветка с `parent_id = null`. Её `media_id` — это первое видео сценария. Может содержать `prompt` — вопрос, который показывается после первого видео перед первым выбором.
- **Видео обязательно у обычных веток** — при создании сценария стартовой ветке автоматически подставляется системное видео-заглушка (`DEFAULT_SCENARIO_VIDEO_ID` из конфигурации), пока редактор CMS не заменит его реальным роликом. У остальных обычных веток файл передаётся в поле `file` multipart-запроса при создании (`POST /cms/video-scenarios/{id}/branches`), а `media_id` сохраняется только как внутренняя связь в БД.
- **Ветвление** — глубина дерева и количество вариантов на каждом уровне не ограничены: у любой ветки (включая дочерние) может быть свой набор дочерних веток со своей точкой голосования.
- **Варианты выбора** — дочерние ветки (у которых `parent_id` = id текущей ветки). Текст варианта берётся из поля `text` дочерней ветки.
- **Конец сценария** — обычная ветка без дочерних веток. Система определяет это автоматически. У конечной ветки `prompt` не заполняется.
- **Логика воспроизведения**: воспроизводится видео текущей ветки → если есть `prompt`, показывается текст вопроса → в конце показываются варианты выбора (дочерние ветки с их `text` и превью) → пользователь выбирает → воспроизводится видео выбранной ветки → и так далее.
- **Определение победителя голосования**: побеждает вариант с наибольшим числом голосов. При равенстве голосов у нескольких вариантов побеждает тот, что раньше набрал свой последний голос (сравнивается время последнего голоса каждого варианта — `votes.last_vote_at`). Голоса, поступившие после истечения таймера, не учитываются.

## InteractiveVideoSession (Сессия показа)

Сессия показа видеосценариев на LED-платформе. Создаётся оператором при запуске показа «Профессии в действии». Хранит выбранные сценарии, настройки голосования и текущее состояние показа.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор сессии |
| `device_id` | integer (int64) | ID LED-устройства, на котором запущен показ |
| `status` | integer | Статус сессии: `1` — active, `2` — finished |
| `settings` | json | Настройки показа (см. ниже) |
| `participant_count` | integer | Счётчик успешных join, изначально 0; каждый повторный join тоже учитывается. Возвращается в `voting_point.participant_count` запросов state и voting |
| `created_at` | timestamp | Дата создания |
| `finished_at` | timestamp, nullable | Дата завершения показа |

### settings

| Поле | Тип | Описание |
|------|-----|----------|
| `scenario_ids` | integer[] (int64) | ID видеосценариев для показа (порядок определяет очередь воспроизведения) |
| `voting_duration` | integer | Длительность голосования в секундах (по умолчанию 30) |
| `result_display_duration` | integer | Длительность показа результата в секундах (по умолчанию 5) |

### Связи

- **InteractiveVideoSession → Device**: сессия привязана к конкретному LED-устройству (`device_id`)
- **InteractiveVideoSession → InteractiveVideoScenario**: сессия содержит список сценариев (`scenario_ids`)

### Где используется

- **Оператор** — создание и остановка показа
- **LED-медиаплатформа** — получение текущего состояния показа
- **Мобильный клиент** — подключение к показу по QR-коду, голосование

### Примечания

- При создании сессии фронтенд может передать либо `scenario_ids` (ручной выбор), либо `profession_count` (количество случайных сценариев). Бэкенд конвертит `profession_count` в `scenario_ids` (случайный выбор из доступных) перед сохранением.
- На время показа устройство занято — повторный запуск на том же устройстве невозможен (ошибка `device_busy`).

### Превью сценариев на LED

`GET /interactive-video/sessions/{id}/scenarios` (с префиксом `/api`) возвращает
массив сценариев сессии в порядке `settings.scenario_ids`. Каждый элемент содержит
`id`, `title`, `description`, `profession_id` и `first_branch` со стартовой веткой
(`parent_id = null`). Ветка содержит `id`, `scenario_id`, `parent_id`, `text`,
`prompt`, `reference_branch_id` (для стартовой ветки — `null`) и объект `file`: `url`, `preview_url`, `mime_type`, `title`, `description`.
LED использует `first_branch.file.preview_url` для изображения карточки.

Если стартовой ветки нет, `first_branch` равен `null`; если у файла нет превью,
`preview_url` равен `null`. Удалённые сценарии пропускаются. Пустой список сценариев
даёт `[]`, неизвестная сессия — 404. Запрос доступен и для завершённых сессий,
не меняет позицию воспроизведения и не обращается к состоянию Redis.

### Досрочное завершение голосования

После каждого принятого голоса проверяется текущий participant_count. Если он больше нуля и число голосов в текущей точке достигло этого значения, голосование завершается досрочно: применяется обычный выбор победителя, показ переходит к его ветке в фазе playing, voting_ends_at очищается. После votes_updated отправляется phase_changed (только type). Ожидать остаток таймера не требуется; дальнейшее воспроизведение и переходы выполняются как обычно. При отсутствии участников досрочного завершения нет. Повторные голоса не учитываются; поздний голос получает voting_closed. Счётчик participant_count сохраняет прежнюю семантику: каждый успешный /join увеличивает его, включая повторное подключение того же пользователя.
