# Организации

Описание сущности для справочника организаций (учебные заведения и работодатели).

---

## Organization (Организация)

Единый справочник организаций. Используется в ПАК «Интерактивная карта региона» и аналитике.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор |
| `name` | string | Название организации |
| `type` | integer (OrganizationType) | `1` — работодатель, `2` — учебное заведение |
| `full_name` | text, nullable | Полное название |
| `location` | text, nullable | Населённый пункт или территория |
| `industry_branch_id` | integer (int64), nullable | FK → `industry_branches.id`; индустрия определяется через отрасль |
| `employee_count` | integer, nullable | Численность работников |
| `scale_or_product` | text, nullable | Масштаб деятельности или продукция |
| `practice_info` | text, nullable | Практика и наставничество |
| `education_level` | string, nullable | Уровень учебного заведения |
| `deleted_at` | timestamp with time zone, nullable | Отметка удаления |
| `address` | text, nullable | Адрес |
| `coordinates` | json, nullable | Координаты на карте (широта, долгота) |
| `description` | text, nullable | Описание |
| `website` | string, nullable | URL сайта |
| `phone` | string, nullable | Контактный телефон |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата обновления |

### Где используется

- **ПАК «Интерактивная карта региона»** — отображение на карте
- **Аналитика** — рейтинг организаций по интересам/просмотрам
- **Цифровой профиль** — выбранные организации в профиле

---

## Связанные разделы

- **API:** `/organizations` — API с JWT, `/organizations` (POST/PUT/DELETE) — CMS

## EducationProgram (Направление подготовки)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Идентификатор |
| `name` | string | Название направления подготовки |
| `education_level` | string | Уровень образования |
| `duration` | string | Срок обучения, включая текстовые пояснения |
| `base_class` | string, nullable | База приёма |
| `created_at` | timestamp with time zone | Дата создания |
| `updated_at` | timestamp with time zone | Дата изменения |
| `deleted_at` | timestamp with time zone, nullable | Отметка удаления |

Направление уникально по точному сочетанию `(name, education_level, duration, base_class)`.
`base_class=NULL` учитывается в уникальности и отличается от пустой строки. Близкие названия
не объединяются; разные уровни, сроки или базы приёма означают разные направления.
POST активного дубликата и PUT на занятое сочетание возвращают 409. POST удалённого сочетания
восстанавливает его ID, не восстанавливая автоматически удалённые связи.

### OrganizationEducationProgram (Направление в учебном заведении)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Идентификатор связи |
| `education_program_id` | integer (int64) | FK → `education_programs.id` |
| `organization_id` | integer (int64) | FK → `organizations.id`, учебное заведение типа 2 |
| `created_at` | timestamp with time zone | Дата создания |
| `updated_at` | timestamp with time zone | Дата изменения |
| `deleted_at` | timestamp with time zone, nullable | Мягкое удаление связи |

Пара `(education_program_id, organization_id)` уникальна, включая удалённые строки.
POST удалённой пары восстанавливает её ID; связи профессий относятся к общему направлению и не изменяются.
Уровень, срок и база приёма хранятся только в `education_programs`.
Фильтр `organization_id` списка направлений использует активные связи, но не дублирует направления.
DELETE связи мягко удаляет только связь с организацией, сохраняя направление и его связи с профессиями.
DELETE направления мягко удаляет все его активные связи с организациями и профессиями.
Изменение названия, уровня, срока или базы общего направления отражается во всех связанных организациях.
Для изменения программы только у одного заведения нужно создать другое направление и изменить связь.
Направления подготовки доступны через CRUD `/organizations/education-programs`. Списки справочников исключают удалённые записи, а GET элемента по ID возвращает их независимо от deleted_at связанных сущностей. Исключение — `/professions/{profession_id}/employers` и `/professions/{profession_id}/educations`: для сохранённых рекомендаций они возвращают связанные организации независимо от `deleted_at` профессии, связей, программ и организаций.

## API справочников и мягкое удаление

| Ресурс | Запросы |
|--------|---------|
| `/organizations` | GET списка, POST; `/organizations/{id}`: GET, PUT, DELETE |
| `/organizations/education-programs` | GET списка, POST; `/organizations/education-programs/{id}`: GET, PUT, DELETE |
| `/organizations/education-programs/links` | GET списка, POST; `/organizations/education-programs/links/{id}`: GET, PUT, DELETE |

GET доступны с действующим Bearer JWT пользователя (включая гостя), сотрудника любой роли или активного устройства; POST/PUT/DELETE — только со staff access-токеном редактора контента или администратора. Отсутствующий или недействительный токен возвращает 401, недостаточная роль сотрудника при записи — 403. Все новые сведения из JSON доступны в ответах и запросах изменения. Пропущенные поля PUT сохраняются, явный null очищает nullable-поля.

Удалённые строки не попадают в списки и total. GET по удалённому ID возвращает запись; PUT и повторный DELETE возвращают 404. GET по неизвестному ID возвращает 404. Новые ссылки проверяются на доступность и тип организации. Удаление профессии, работодателя или программы помечает их связи удалёнными. Индустрию, направление, отрасль или учебное заведение с активными зависимостями удалить нельзя (409). Повторный POST удалённой пары восстанавливает её с тем же ID; изменение на уже существующую пару возвращает 409.

## Организации и направления по выбранным профессиям

GET `/api/organizations/recommendations?profession_ids=1&profession_ids=2&profession_ids=3`
принимает от 1 до 3 различных ID профессий. Достаточен действующий JWT пользователя,
гостя, сотрудника любой роли или активного устройства; сохранённый профиль не требуется.

Ответ содержит `employers`, `educations` и `education_programs` в том же формате и с теми же правилами ранжирования, что и `/users/me/recommendations`: до пяти организаций каждого типа и отдельно до пяти направлений. Выше больше различных совпавших профессий, затем ID организации или направления по возрастанию. Направления выбираются по прямым связям с профессиями, независимо от организаций; поле `education_program` содержит полные данные направления, рядом возвращаются `profession_ids`, `profession_count` и `position`. Учитываются профессии, связи, программы и организации с `deleted_at`. Результат не сохраняется.

Отсутствие связей даёт пустые массивы. Неизвестный ID — 404; отсутствующий параметр,
повторяющиеся ID, больше трёх ID или неверный формат — 422; недействительный JWT — 401.

### Покрытие выбранных профессий

Правило покрытия применяется отдельно к каждому из трёх списков: employers, educations, education_programs. Сначала формируется топ-5 по числу различных совпавших профессий DESC и ID организации или направления ASC. Затем проверяется покрытие каждой выбранной профессии. Если для неё есть связанные записи, но ни одна не попала в топ-5, лучшая из них заменяет последнюю запись, удаление которой не лишает покрытия другие профессии. Одна запись может покрывать несколько профессий. После замен сохраняется сортировка по рейтингу; лимит — 5 уникальных записей в каждом списке. Если соответствующих связей нет, покрытие этой профессии в данном списке не требуется.

Правило действует для `/users/me/recommendations` и `/organizations/recommendations`, в том числе для профессий, связей, программ и организаций с `deleted_at`.
