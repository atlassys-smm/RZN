# Таймер

Единое описание работы таймера для всех сценариев: викторина (GameSession) и видеосценарии (InteractiveVideoSession).

---

## Принцип работы

Таймер основан на **абсолютном timestamp** `ends_at` (UNIX, миллисекунды). Клиент вычисляет оставшееся время:

```
remaining = ends_at - Date.now()
```

Это решает проблему рассинхронизации при задержках сети — каждый клиент считает самостоятельно от общего ориентира, а не зависит от количества полученных обновлений.

---

## Таймер викторины (GameSession)

### Хранение в Redis

| Ключ | Тип | Описание |
|------|-----|----------|
| `session:{id}:timer` | hash | Состояние таймера |
| → поле `ends_at` | integer (UNIX мс) | Абсолютный timestamp — момент, когда время на текущий вопрос истекает |
| → поле `remaining_at_pause` | integer (мс) | Сколько миллисекунд оставалось на момент паузы. Присутствует только когда таймер на паузе |

> `remaining` (оставшееся время) — вычисляемое значение, не хранится. Клиент считает: `remaining = ends_at - Date.now()`.

### Состояния таймера

| Состояние | Условие | Что видит клиент |
|-----------|---------|------------------|
| **Идёт** | Поле `ends_at` есть, `remaining_at_pause` отсутствует | `remaining = ends_at - now` |
| **Пауза** | Поля `ends_at` и `remaining_at_pause` есть | `remaining = remaining_at_pause` |
| **Не запущен** | Ключ `timer` отсутствует | Таймер не отображается |

### Операции

#### Старт вопроса

```
HSET session:{id}:timer ends_at (Date.now() + question.time_limit * 1000)
HDEL session:{id}:timer remaining_at_pause
```

#### Пауза

```
remaining = ends_at - Date.now()
HSET session:{id}:timer remaining_at_pause remaining
```

Таймер останавливается. На LED и планшете отображается замороженное значение.

#### Возобновление

```
HSET session:{id}:timer ends_at (Date.now() + remaining_at_pause)
HDEL session:{id}:timer remaining_at_pause
```

Таймер продолжает отсчёт с сохранённого значения.

#### Добавить время

```
HINCRBY session:{id}:timer ends_at (additional_seconds * 1000)
```

Если таймер на паузе — обновляется `remaining_at_pause`.

#### Завершить досрочно

```
DEL session:{id}:timer
Перейти к показу ответа / следующему вопросу
```

### Восстановление после сбоя

При перезапуске сессия восстанавливается из БД (`current_round_index`, `current_question_index`). Таймер **сбрасывается** — оставшееся время не сохраняется в БД, оператор начинает вопрос заново.

## Таймер видеосценария (InteractiveVideoSession)

### Хранение в Redis

Таймер голосования хранится в отдельном ключе:

| Ключ | Тип | Описание |
|------|-----|----------|
| `interactive-video:session:{id}:timer` | hash | Состояние таймера |
| → поле `ends_at` | datetime (ISO) | Абсолютный timestamp окончания голосования |
| → поле `remaining_at_pause` | integer (мс) | Оставшееся время на момент паузы (если поддерживается) |

Ключ `timer` создаётся при начале голосования. В фазе `playing` — отсутствует.

### Состояния

| Фаза | Таймер |
|------|--------|
| `playing` | Не активен |
| `voting` | `ends_at = now + voting_duration` (из settings) |

### Операции

#### Начало голосования (advance)

При достижении точки ветвления видео:

```
phase = voting
ends_at = now + settings.voting_duration
```

Длительность берётся из `settings.voting_duration` (по умолчанию 30 секунд).

#### Завершение голосования (sync_phase)

При каждом обращении к состоянию сервер проверяет: если `now >= ends_at` — голосование закрывается автоматически.

#### Ручное завершение

Оператор может завершить голосование досрочно через `POST /interactive-video/sessions/{id}/advance`.

## Синхронизация с клиентами

Все клиенты (LED-экран, планшет оператора, мобильный клиент) получают `ends_at` через WebSocket и вычисляют оставшееся время локально.

При необходимости сервер может отправить событие завершения таймера через WebSocket — но это опционально: клиент и так определяет истечение по `remaining <= 0`.

### Формат передачи

| Контекст | Канал | Поле | Формат |
|----------|-------|------|--------|
| Викторина | WebSocket | `timer.ends_at` | integer (UNIX мс) |
| Видеосценарий | WebSocket | `timer.ends_at` | integer (UNIX мс) |

### Клиентская логика

```javascript
// Обновление при получении события
const remaining = timer.ends_at - Date.now();

// Локальный отсчёт между обновлениями WebSocket
function tick() {
  const remaining = timer.ends_at - Date.now();
  if (remaining <= 0) {
    // Время вышло
  } else {
    // Показать remaining
  }
}
```

### Пауза (только викторина)

При паузе сервер отправляет событие с `timer.remaining_at_pause` — клиент показывает замороженное значение и останавливает локальный отсчёт. При возобновлении — новое событие с обновлённым `ends_at`.
