# Таймер

Таймеры викторины и «Профессий в действии» возвращают `remaining_ms` — оставшееся
время в миллисекундах, вычисленное сервером при формировании ответа.
`ends_at` сохраняется как абсолютный UNIX timestamp в миллисекундах.

## Викторина

Таймер находится в `timer` состояния сессии и в ответах операций паузы,
возобновления и добавления времени. Остановка возвращает состояние сессии с `timer`.
В статусах waiting, results и finished объект `timer` в состоянии сессии отсутствует.

| Поле | Тип | Значение |
|------|-----|----------|
| `ends_at` | integer, null | UNIX timestamp окончания в мс; null на паузе или после остановки |
| `remaining_at_pause` | integer, null | Остаток на момент паузы в **секундах**; null при работающем или остановленном таймере |
| `running` | boolean | Идёт ли таймер |
| `remaining_ms` | integer >= 0 | Остаток в миллисекундах по времени сервера на момент ответа |

Расчёт `remaining_ms`:

- Работающий таймер: `max(0, ends_at - server_now_ms)`.
- Пауза: `max(0, remaining_at_pause * 1000)`.
- Остановленный или отсутствующий таймер в активной сессии: `0`.

В Redis сохраняются исходные поля таймера в `quiz:session:{id}:timer`.
`remaining_ms` в Redis и БД не сохраняется, а вычисляется заново при каждом ответе.
На паузе ответы продолжают приниматься в обоих режимах викторины:
`running=false` и `remaining_at_pause` не null. Нулевой сохранённый остаток тоже
отличает паузу от остановки. После остановки оба `ends_at` и `remaining_at_pause`
равны null, приём закрыт. Уже отправленные ответы и запрет повторной отправки сохраняются.
Последний ответ может закрыть вопрос по правилу «все ответили» и во время паузы.
Для бонуса за скорость время ответа на паузе считается до `paused_at`, поэтому
ожидание на паузе не уменьшает бонус. После возобновления длительность паузы
исключается существующей корректировкой `started_at`.

Пауза сохраняет целые секунды по существующим правилам; возобновление устанавливает
новый `ends_at`, добавление времени изменяет срок окончания или остаток на паузе.

## Профессии в действии

В фазе голосования таймер находится в `voting_point.timer`:

| Поле | Тип | Значение |
|------|-----|----------|
| `ends_at` | integer | UNIX timestamp окончания голосования в мс |
| `remaining_ms` | integer >= 0 | `max(0, ends_at - server_now_ms)` на момент формирования ответа |

Таймер возвращается в состоянии сессии (`/state`, `/active`, ответ `/advance`)
и в пользовательском ответе `/voting`. Вне голосования `voting_point = null`.
При отсутствии срока окончания `voting_point.timer = null`.

Исходный `voting_ends_at` сохраняется в Redis в
`interactive-video:session:{id}:state` в формате ISO. `remaining_ms` не сохраняется.
При обращении к состоянию сервер проверяет истечение срока голосования и закрывает его.

## Синхронизация клиента

WebSocket передаёт тип события. После события клиент запрашивает состояние через REST
и получает свежий `remaining_ms`. Ежесекундной рассылки остатка по WebSocket нет.
При подключении, возобновлении вкладки и переподключении клиент заново запрашивает состояние.

Для работающего таймера клиент использует монотонный счётчик прошедшего времени:

```javascript
const receivedAt = performance.now();
const initialRemainingMs = timer.remaining_ms;

function remainingMs() {
  if (timer.running === false) return initialRemainingMs;
  return Math.max(0, initialRemainingMs - (performance.now() - receivedAt));
}
```

`Date.now()` и системная дата устройства в этом отсчёте не участвуют.
Остаток соответствует моменту формирования ответа сервером; доставка ответа добавляет сетевую задержку.
После паузы, возобновления или добавления времени клиент начинает отсчёт с нового ответа.
