# Профессии, отрасли и направления

Описание сущностей для справочника профессий, отраслей и профессиональных направлений.

---

## Profession (Профессия)

Справочник профессий. Используется в различных модулях системы: викторины, тесты, командные игры, рекомендации, аналитика.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор профессии |
| `name` | string | Название профессии |
| `description` | text, nullable | Описание профессии |
| `media_id` | bigint, nullable, FK → files.id | Собственный файл профессии; при null для выдачи используется мужское фото шаблона аватара |
| `industry_id` | integer (int64) | ID индустрии, к которой относится профессия |
| `direction_id` | integer (int64), nullable | ID профессионального направления; может быть не назначено |
| `skills` | text, nullable | Ключевые навыки |
| `prospects` | text, nullable | Перспективы карьеры |
| `min_salary` | integer, nullable | Минимальная зарплата, тыс. руб. |
| `max_salary` | integer, nullable | Максимальная зарплата, тыс. руб. |
| `deleted_at` | timestamp with time zone, nullable | Отметка удаления |

### Связи

- **Profession → Industry**: профессия принадлежит одной индустрии (`industry_id`)
- **Profession → Direction**: профессия может принадлежать одному направлению (`direction_id`)
- **Profession → File**: собственный файл хранится через media_id.
- **Profession → ProfessionAvatarTemplate**: один шаблон на профессию; male_photo_file_id используется при отсутствии собственного файла.

### Файл профессии в API

Во всех ответах с профессией возвращается `file` стандартного формата FileResponse. Приоритет — собственный `professions.media_id`, затем `profession_avatar_templates.male_photo_file_id`, при отсутствии обоих — `null`. Женское фото для подстановки не используется. Подстановка выполняется при чтении, не заполняет media_id и учитывает замену мужского аватара.

Правило общее для списка и карточки профессии, вложенной профессии CMS видеосценариев, общих рекомендаций, результатов и истории ПрофСтарта и предпросмотра конструктора. В сохранённых рекомендациях доступны также мягко удалённые профессии. В снимки файл не записывается. В JSON выдаётся объект file; media_id остаётся внутренней связью.

`POST /api/professions` и `PUT /api/professions/{id}` принимают multipart/form-data по образцу `POST /api/organizations`: поля профессии и необязательные `file`, `file_preview`, `file_title`, `file_description` передаются в одной форме. Отдельных маршрутов для файла нет. Без нового файла при редактировании сохраняется прежний. Для видео превью создаётся автоматически, если не передано своё. Метаданные файла относятся к новому файлу. Для очистки direction_id, min_salary и max_salary в PUT допустимы пустое значение или строка null.

### Где используется

- **CMS** — управление справочником профессий
- **LED-медиаплатформа** — отображение профессий в сценариях, голосование за профессии (генерируется динамически)
- **ПрофСтарт** — рекомендации профессий по результатам теста
- **Командная игра** — вопросы о профессиях
- **Цифровой профиль** — выбранные профессии в профиле
- **Аналитика** — анализ интереса к профессиям
- **Обратная связь** — выбор интересующих профессий в анкете

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор индустрии |
| `name` | string | Название индустрии |
| `deleted_at` | timestamp with time zone, nullable | Отметка удаления |

### Связи

- **Industry → Profession**: одна индустрия имеет множество профессий

### Где используется

- **Аналитика** — анализ интереса к индустриям
- **Цифровой профиль** — выбранные индустрии в профиле

## Direction (Профессиональное направление)

Общий справочник профессиональных направлений платформы.

!!! note "Новая модель ПрофСтарт"
    В трёх предзаданных тестах показатели рассчитываются по отдельным `TestGroup`, а профессии подбираются через `TestGroupProfession`. `Direction` остаётся общим справочником платформы; его восемь направлений не являются шкалами этих тестов. См. [группы результатов](test.md).

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор направления |
| `name` | string | Название направления |
| `description` | text, nullable | Описание направления |
| `deleted_at` | timestamp with time zone, nullable | Отметка удаления |

### Связи

- **Direction → Profession**: одно направление имеет множество профессий

### Где используется

- **CMS** — управление справочником направлений
- **ПрофСтарт** — связь с профессиями через отдельные группы тестов; `Direction` остаётся метаданными профессии
- **Аналитика** — анализ интереса к направлениям
- **Цифровой профиль** — рекомендуемые направления в профиле

### Примечания

В системе предусмотрено не менее 8 профессиональных направлений:

1. Естественно-научное
2. Инженерно-техническое
3. Информационно-математическое
4. Социально-коммуникативное
5. Гуманитарно-языковое
6. Художественно-творческое
7. Организационно-предпринимательское
8. Практико-производственное

## Иерархия

```
Industry (Индустрия)
  └── Profession (Профессия)
        └── Direction (Направление)
```

Профессия принадлежит одной индустрии и может быть отнесена к одному профессиональному направлению. Индустрия и профессиональное направление — разные способы группировки профессий. Детальная отрасль классифицирует работодателей.

## IndustryBranch (Детальная отрасль)

Индустрии хранятся в существующей `industries`, детальные отрасли — в `industry_branches`.
Профессиональные направления `directions` и направления подготовки `education_programs` — разные справочники.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Идентификатор |
| `name` | string | Название |
| `industry_id` | integer (int64) | FK → `industries.id` |
| `created_at` | timestamp with time zone | Дата создания |
| `deleted_at` | timestamp with time zone, nullable | Отметка удаления |

## Связи профессий

`profession_employers` связывает профессии с организациями типа `1` (работодатель).
`profession_education_programs` связывает профессии с общими направлениями подготовки независимо от организаций.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Идентификатор связи в обеих таблицах |
| `profession_id` | integer (int64) | FK → `professions.id` в обеих таблицах |
| `employer_id` | integer (int64) | FK → `organizations.id`, только `profession_employers` |
| `education_program_id` | integer (int64) | FK → `education_programs.id`, только `profession_education_programs` |
| `created_at` | timestamp with time zone | Дата создания в обеих таблицах |
| `deleted_at` | timestamp with time zone, nullable | Отметка удаления в обеих таблицах |

Каждая пара связанных сущностей уникальна, в том числе после отметки удаления: повторное
добавление такой связи должно восстанавливать существующую строку.

Списки справочников исключают строки с `deleted_at`. GET элемента по ID возвращает и мягко удалённую запись, независимо от удаления связанных сущностей. DELETE помечает строку удалённой; PUT и повторный DELETE возвращают для неё 404. Получение организаций по профессии для сохранённых рекомендаций также учитывает удалённые записи (см. ниже).

## API справочников и мягкое удаление

| Ресурс | Запросы |
|--------|---------|
| `/industries` | GET списка, POST; `/industries/{id}`: GET, PUT, DELETE |
| `/directions` | GET списка, POST; `/directions/{id}`: GET, PUT, DELETE |
| `/industries/branches` | GET списка, POST; `/industries/branches/{id}`: GET, PUT, DELETE |
| `/professions` | GET списка, POST; `/professions/{id}`: GET, PUT, DELETE |
| `/professions/employers` | GET списка, POST; `/professions/employers/{id}`: GET, PUT, DELETE |
| `/professions/education-programs` | GET списка, POST; `/professions/education-programs/{id}`: GET, PUT, DELETE |

GET доступны с действующим Bearer JWT пользователя (включая гостя), сотрудника любой роли или активного устройства; POST/PUT/DELETE — только со staff access-токеном редактора контента или администратора. Отсутствующий или недействительный токен возвращает 401, недостаточная роль сотрудника при записи — 403. Все новые сведения из JSON доступны в ответах и запросах изменения. Пропущенные поля PUT сохраняются, явный null очищает nullable-поля.

Удалённые строки не попадают в списки и total. GET по удалённому ID возвращает запись; PUT и повторный DELETE возвращают 404. GET по неизвестному ID возвращает 404. Новые ссылки проверяются на доступность и тип организации. Удаление профессии, работодателя или программы помечает их связи удалёнными. Индустрию, направление, отрасль или учебное заведение с активными зависимостями удалить нельзя (409). Повторный POST удалённой пары восстанавливает её с тем же ID; изменение на уже существующую пару возвращает 409.

## Где работать и учиться по профессии

GET с JWT `/api/professions/{profession_id}/employers` и
`/api/professions/{profession_id}/educations` возвращают организации целиком в формате
`{items: Organization[], total: integer}` с обычными параметрами `limit` (по умолчанию 20)
и `offset` (по умолчанию 0), в порядке ID организации по возрастанию.

Работодатели (`type=1`) выбираются по `profession_employers`.
Учебные заведения (`type=2`) выбираются через `profession_education_programs`
и `organization_education_programs.organization_id`. Несколько программ одного заведения дают одну
организацию; total и пагинация также считают уникальные организации.

Эти два запроса предназначены для сохранённых рекомендаций: `deleted_at` профессии,
связей, программ и организаций не ограничивает выдачу, даже если удалена вся цепочка.
Возвращаются текущие данные сохранённых строк, а не снимок на дату рекомендации.
Неизвестная профессия даёт 404; существующая (включая удалённую) без связей — 200
с пустыми items и total=0. Списки справочников и новый подбор профессий по-прежнему
исключают удалённые записи; GET элемента по ID возвращает и удалённую запись.

Пара `(profession_id, education_program_id)` уникальна, включая удалённые строки. Одной привязки профессии к направлению достаточно для рекомендации всех учебных заведений этого направления. Создание связи не требует наличия организаций; удаление отдельной связи организации с направлением не изменяет привязку профессии.
