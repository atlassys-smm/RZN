# Игровая сессия

Описание сущностей для проведения игровых сессий на LED-платформе.

Игровая сессия — это факт проведения игры или викторины. В зависимости от режима сессия может быть:
- **Индивидуальная викторина** (`mode = 1`) — вопросы с вариантами ответов, все участники отвечают индивидуально, рейтинг по `individual_score`
- **Командная игра** (`mode = 2`) — профориентационная игра с формированием команд, раундами заданий, обсуждениями и рейтингом команд

Используется в сценариях: **Индивидуальная викторина**, **Командная работа**.

→ [GameQuestion и GameAnswerOption](quiz.md#gamequestion) | [Шаблоны сценариев](scenario-template.md#scenariotemplate) | [CMS: Викторина](../subsystems/cms/quiz.md)

## GameSession (Игровая сессия) {#gamesession}

Факт проведения игры или викторины. API создания сессии принимает готовый массив `rounds`: клиент оператора может составить его вручную или взять раунды и вопросы опубликованного шаблона. ID шаблона в запросе и сессии не хранится. Для раунда можно передать конкретные `question_ids` или выполнить автоматический выбор по `question_count` и `question_filters` (`difficulty`, `age_group`, `tags`). Сессия привязана к LED-устройству, у которого может быть не более одной незавершённой сессии (`status` 1 или 2).

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор сессии |
| `device_id` | integer (int64) | ID LED-устройства, на котором проводится сессия |
| `mode` | integer | Режим: `1` — individual (индивидуальная викторина), `2` — team (командная игра) |
| `status` | integer | Статус: `1` — waiting (формирование команд), `2` — active (идёт игра), `3` — finished (завершена) |
| `current_round_index` | integer | Индекс текущего раунда |
| `current_question_index` | integer | Индекс текущего вопроса в раунде |
| `settings` | json | Настройки сессии — см. ниже. Включая `team_count` для `mode = 2` (team) |
| `created_at` | timestamp | Дата создания |
| `finished_at` | timestamp, nullable | Дата завершения |

После ответа последнего участника индивидуальной игры или ответа капитана последней непустой команды приём ответов автоматически закрывается. Голос капитана всегда решающий, независимо от `is_final`; предварительные голоса остальных участников не завершают командное голосование. Пустые команды не учитываются. После `answers_update` отправляется `all_answered` (только поле `type`), затем применяется та же обработка, что при окончании таймера через `/led/next`: при числовом `auto_reveal_delay` ответ раскрывается и начисляются баллы, при `null` ожидается ручной `reveal` или `skip`. Досрочное закрытие не отправляет `timer_expired` или `timer_stopped`. Дальнейший переход выполняется по существующему сценарию LED, задержки отсчитывает клиент.

### Дополнительный финальный раунд

После раскрытия последнего вопроса последнего раунда сессия остаётся в `active`.
Оператор выбирает обычный `POST /api/quiz/sessions/{id}/finish` или
`POST /api/quiz/sessions/{id}/final-round` с `question_ids` либо `question_count`
и необязательными `question_filters` (`difficulty`, `age_group`, `tags`).
При передаче обоих способов приоритет у `question_ids`. Выбор по количеству использует
общую базу вопросов, ранее использованные вопросы не исключаются.

Запуск финала добавляет последний раунд `FINAL = 9` в `game_session_rounds` и его вопросы
в `game_session_questions`, затем сразу начинает первый вопрос. После 8 основных раундов
допускается девятый, финальный. Сохраняются ID сессии, состав, настройки и накопленные баллы;
действует существующий финальный множитель. При некорректном выборе вопросов изменения не сохраняются.

REST-состояние содержит вычисляемый `can_start_final_round`: `true` только в `active`,
на последнем вопросе последнего раунда, после его раскрытия и при отсутствии любого раунда
с типом `9`. Поле доступно независимо от `select`, восстанавливается при повторном чтении
и равно `false` в `waiting`/`finished` и после добавления финала. Ответ оператора с
`correct_answer` до reveal не означает раскрытие для игроков.

Добавить финал можно один раз; повторный или параллельный запрос получает `409`.
Раунд типа `9`, заданный при создании сессии, также запрещает добавление ещё одного финала.
После последнего вопроса финала клиент вызывает обычный `/finish`, повторного выбора нет.
Для запуска используются существующие `question_started` и `session_state`;
события устройства о начале/завершении всей сессии при добавлении финала не отправляются.
Новые статусы, задержки и временные метки не вводятся.

### settings (JSON)

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `team_count` | integer | — | Количество команд для `mode = 2`: от 2 до 8 |
| `auto_reveal_delay` | integer, nullable | `0` | Задержка в секундах от закрытия приёма ответов до показа правильного ответа |
| `auto_next_delay` | integer, nullable | `null` | Задержка в секундах от показа ответа до следующего вопроса внутри раунда |
| `between_rounds_delay` | integer, nullable | `10` | Задержка в секундах от показа ответа на последний вопрос раунда до запуска следующего раунда |
| `show_intermediate_results` | boolean | `true` | Показывать промежуточный рейтинг после каждого раунда |
| `scoring` | json | — | Настройки системы начисления баллов — см. ниже |

Для всех трёх задержек `null` отключает автоматическое действие, `0` выполняет его без ожидания, положительное целое число задаёт задержку в секундах. Отрицательные значения запрещены. Если поле отсутствует при создании сессии, используется значение из стандартных настроек CMS; явно переданный `null` сохраняется. При обновлении настроек CMS отсутствующее поле не меняется, `null` отключает действие. Поля `auto_reveal` и `auto_next` удалены и не принимаются API.

Внутри раунда действует `auto_next_delay`, между раундами — только `between_rounds_delay`; задержки не суммируются. Автопоказ отсчитывается от окончания таймера или ручного закрытия приёма ответов, автопереход — от показа ответа. Задержки отсчитывает клиент. Сервер хранит настройки и не проверяет время этих задержек: LED вызывает `POST /quiz/sessions/{id}/led/next` после нужного ожидания, а при `null` не запускает соответствующее автоматическое действие. После ручной остановки таймера `0` раскрывает ответ сразу; при положительной задержке клиент вызывает `reveal` по её окончании, при `null` ожидает оператора. Ручные `reveal` и `next` доступны независимо от задержек. Сессию после последнего вопроса завершает оператор через `finish`.


Время на ответ берётся из `GameQuestion.time_limit` (у каждого вопроса своё).

### scoring (JSON)

Параметры системы баллов, сохраняемые в снапшоте при создании сессии. Во время активной сессии изменение невозможно.

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `partial_correct.enabled` | boolean | `true` | Частичный балл за задания с несколькими правильными элементами |
| `speed_bonus.enabled` | boolean | `true` | Бонус за быстрый ответ |
| `speed_bonus.coefficient` | decimal | `1.5` | Множитель за быстрый ответ |
| `speed_bonus.threshold_percent` | integer | `50` | Порог быстрого ответа (% от времени на вопрос, 0–100) |
| `streak_bonus.enabled` | boolean | `true` | Бонус за серию последовательных правильных ответов |
| `streak_bonus.step` | decimal | `0.05` | Шаг коэффициента за каждый последовательный правильный ответ |
| `streak_bonus.max` | decimal | `2.0` | Предельный коэффициент серии |
| `consensus_bonus.enabled` | boolean | `true` | Бонус за единогласный ответ команды |
| `consensus_bonus.coefficient` | decimal | `1.2` | Множитель при единогласном правильном ответе |
| `final_multiplier.enabled` | boolean | `true` | Повышающий множитель финального раунда |
| `final_multiplier.coefficient` | decimal | `1.5` | Множитель баллов в финальном раунде |
| `penalty.enabled` | boolean | `false` | Штраф за неправильный ответ |
| `penalty.coefficient` | decimal | `0.0` | Доля баллов вопроса, вычитаемая при неправильном ответе (0.0 — нет штрафа, 1.0 — все баллы) |

→ Механика расчёта — в подсистеме [Правила начисления баллов](../subsystems/led-platform/quiz.md#правила-начисления-баллов)

### Связи

- **GameSession → Device**: сессия проводится на одном LED-устройстве
- **GameSession → GameSessionRound**: сессия имеет множество раундов
- **GameSession → GameSessionTeam**: сессия имеет множество команд (для `mode = 2`, team)
- **GameSession → GameSessionParticipant**: сессия имеет множество участников

### Где используется

- **LED-медиаплатформа** — проведение сессий
- **Аналитика** — анализ результатов сессий

## GameSessionRound (Раунд сессии)

Снапшот раунда, заполненный при создании сессии из шаблона или вручную оператором; дополнительный финальный раунд может быть добавлен в активную сессию через `/final-round`.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор |
| `session_id` | integer (int64) | ID сессии |
| `round_type` | integer | Числовой ID типа раунда из [справочника](../references/scenario-round-types.md) |
| `order` | integer | Порядок раунда в сессии |

### Связи

- **GameSessionRound → GameSession**: раунд принадлежит одной сессии
- **GameSessionRound → GameSessionQuestion**: раунд имеет множество вопросов

## GameSessionQuestion (Вопрос в раунде сессии)

Снапшот вопроса, закреплённого за раундом сессии.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор |
| `round_id` | integer (int64) | ID раунда сессии |
| `question_id` | integer (int64) | ID исходного вопроса ([GameQuestion](quiz.md)) |
| `order` | integer | Порядок вопроса в раунде |

### Связи

- **GameSessionQuestion → GameSessionRound**: вопрос принадлежит одному раунду
- **GameSessionQuestion → GameQuestion**: ссылка на исходный вопрос (текст, варианты, время, баллы)
- **GameSessionQuestion → GameSessionAnswer**: вопрос имеет множество ответов

## GameSessionTeam (Команда в сессии) {#gamesessionteam}

Команда, участвующая в командной игре. Создаётся автоматически при создании сессии (по `team_count`).

Используется только для сессий с `mode = 2` (team).

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор команды |
| `session_id` | integer (int64) | ID сессии |
| `name` | string | Название команды |
| `color` | string | Цвет команды (для визуального различия) |
| `captain_id` | integer (int64), nullable | ID капитана команды (ссылка на GameSessionParticipant) |
| `score` | decimal | Итоговый счёт команды |
| `created_at` | timestamp | Дата создания |

### Связи

- **GameSessionTeam → GameSession**: команда принадлежит одной сессии
- **GameSessionTeam → GameSessionParticipant**: капитан команды и множество участников

### Примечания

- Состав команды — от 2 до 10 человек
- Капитан — первый подключившийся к команде; может передать роль; при отключении — случайный; оператор может сменить
- При переносе капитана в другую команду новый капитан старой команды выбирается случайно из оставшихся участников. Если участников не осталось, `captain_id` старой команды становится `null`. Если в целевой команде нет капитана, им становится перенесённый участник (даже если до переноса он не был капитаном); существующий капитан целевой команды сохраняется.
- При начале игры команды с 0 участников автоматически исключаются из сессии; после исключения должны остаться не менее 2 команд, в каждой — не менее 2 участников

## GameSessionParticipant (Участник сессии)

Участник игровой сессии. Может быть авторизованным пользователем или гостем.

Поля `name` и `participant_name` участника викторины формируются из `users.first_name` и `users.last_name` через пробел, в порядке «Имя Фамилия». Пустые части и лишние пробелы пропускаются; если имя и фамилия отсутствуют или пользователь не привязан, возвращается пустая строка. Это правило применяется к составу сессии, ответам участников, ответам для капитана и индивидуальным результатам. При регистрации нового гостя сохраняются `first_name="Гость"` и `last_name=str(users.id)`, поэтому его имя отображается как «Гость 123», где 123 — ID пользователя, а не участника сессии.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор |
| `session_id` | integer (int64) | ID сессии |
| `team_id` | integer (int64), nullable | ID команды (null для индивидуальной викторины) |
| `user_id` | integer (int64), nullable | ID пользователя (null для гостя) |
| `individual_score` | decimal | Индивидуальный счёт участника |
| `joined_at` | timestamp | Дата подключения к сессии |

### Связи

- **GameSessionParticipant → GameSession**: участник принадлежит одной сессии
- **GameSessionParticipant → GameSessionTeam**: участник может принадлежать команде
- **GameSessionParticipant → User**: участник привязан к пользователю (nullable)

### Примечания

- Для индивидуальной викторины `team_id` = null
- Капитан определяется через `GameSessionTeam.captain_id`, не через роль участника

## GameSessionAnswer (Ответ в сессии)

Факт ответа на вопрос в рамках сессии. Хранится в Redis для производительности; структура описана ниже для понимания логики.

### Структура данных в Redis

Ответы хранятся в нескольких ключах Redis:

| Ключ | Тип | Описание |
|------|-----|----------|
| `quiz:session:{id}:answers` | hash | `{participant_id → json(answer)}` — предварительные ответы участников на текущий вопрос |
| `quiz:session:{id}:scores` | hash | `{"{session_question_id}:{participant_id}" → json({is_correct, score, team_id})}` — результаты проверки ответов с начисленными баллами |
| `quiz:session:{id}:final_answers` | hash | `{"{session_question_id}:{team_id}" → "1"}` — отметка о том, что капитан команды уже отправил решающий ответ |

### Логические атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `session_id` | integer (int64) | ID сессии |
| `session_question_id` | integer (int64) | ID вопроса в сессии (GameSessionQuestion) |
| `participant_id` | integer (int64) | ID автора зачётного ответа (капитан команды или индивидуальный участник) |
| `team_id` | integer (int64), nullable | ID команды (для team mode) |
| `answer` | json | Ответ — структура зависит от типа вопроса |
| `is_correct` | boolean | Правильность ответа |
| `score` | decimal | Начисленные баллы |

В командном режиме предварительные ответы участников хранятся в `answers` и доступны капитану. В `scores` сохраняется результат проверки решающего ответа капитана, который участвует в расчёте счёта команды.

Зачётные ответы в обоих режимах проверяются автоматически по эталону вопроса. Ручное выставление баллов оператором не входит в API викторины.

### Где используется

- **Аналитика** — анализ результатов, статистика правильных ответов
- **Результаты** — формирование рейтингов по раундам и итогового

## Состояние активной сессии (Redis)

Текущее состояние игры доступно через Redis. Таймер использует абсолютный UNIX timestamp в миллисекундах `ends_at`; на паузе `ends_at = null`, а оставшееся время возвращается в `remaining_at_pause`. При сбое таймер сбрасывается.

| Ключ | Тип | Описание |
|------|-----|----------|
| `quiz:session:{id}:timer` | hash | Таймер текущего вопроса. Поля: `ends_at` (UNIX timestamp мс, null на паузе), `remaining_at_pause` (секунд осталось на момент паузы), `running` (boolean) |
| `quiz:session:{id}:answers` | hash | `{participant_id → json(answer)}` — предварительные ответы участников на текущий вопрос |
| `quiz:session:{id}:scores` | hash | `{"{session_question_id}:{participant_id}" → json({is_correct, score, team_id})}` — результаты проверки ответов |
| `quiz:session:{id}:final_answers` | hash | `{"{session_question_id}:{team_id}" → "1"}` — отметка о решающем ответе капитана |
| `quiz:session:{id}:revealed` | string | `"0"` или `"1"` — правильный ответ уже показан |

### Логика таймера

- **Старт вопроса**: `ends_at = now + question.time_limit`, `running = true`
- **Пауза**: `remaining_at_pause = max(0, ends_at - now)`, `ends_at = null`, `running = false`
- **Возобновление**: `ends_at = now + remaining_at_pause`, `running = true`
- **Клиент вычисляет**: если `running` → `max(0, ends_at - now)`, иначе → `remaining_at_pause`

После создания сессии набор раундов и вопросов этой сессии не редактируется; после запуска игры (`status = 2`, active) нельзя менять ход и состав игры, кроме предусмотренных операторских действий над командами. Вопрос, используемый хотя бы одной незавершённой сессией, нельзя редактировать или удалять. Изменение шаблона влияет только на будущие сессии.

## Особенности режимов

### Индивидуальная викторина

- `mode = 1` (individual)
- Оператор выбирает опубликованный шаблон; вопросы берутся по заданным в нём `question_id`
- Каждый участник отвечает персонально через `answer`
- `GameSessionTeam` не создаётся
- Рейтинг формируется по `individual_score`

### Командная игра

- `mode = 2` (team)
- Команды создаются автоматически при создании сессии (`team_count`)
- Участники выбирают команду через `team/{teamId}/join`
- Каждый участник отправляет предварительный ответ через `answer`; ответы видны капитану
- Любой ответ капитана через `answer` считается решающим, независимо от `is_final`; повторная отправка запрещена
- Рейтинг формируется по `GameSessionTeam.score`
