# Игровая сессия

Описание сущностей для проведения игровых сессий на LED-платформе.

Игровая сессия — это факт проведения игры или викторины. В зависимости от режима сессия может быть:
- **Индивидуальная викторина** (`mode = individual`) — вопросы с вариантами ответов, все участники отвечают совместно, вопросы формируются случайным образом
- **Командная игра** (`mode = team`) — профориентационная игра с формированием команд, раундами заданий, обсуждениями и рейтингом

Используется в сценариях: **Индивидуальная викторина**, **Командная работа**.

## GameSession (Игровая сессия)

Факт проведения игры или викторины. Содержит настройки, которые задал оператор при запуске.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Уникальный идентификатор сессии |
| `mode` | enum | Режим: `individual` (индивидуальная викторина), `team` (командная игра) |
| `scenario_template_id` | UUID, nullable | ID шаблона сценария (для командной игры, если оператор выбрал шаблон) |
| `started_at` | timestamp | Дата и время начала сессии |
| `ended_at` | timestamp, nullable | Дата и время завершения сессии |
| `settings` | json | Настройки оператора: выбранные типы раундов (от 3 до 8), фильтры по сложности/возрасту/тегам, количество вопросов и другие параметры |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата обновления |

### Связи

- **GameSession → [ScenarioTemplate](scenario-template.md)**: сессия может ссылаться на шаблон сценария
- **GameSession → GameSessionTeam**: сессия имеет множество команд (для режима `team`)
- **GameSession → GameSessionParticipant**: сессия имеет множество участников

### Где используется

- **LED-медиаплатформа** — проведение сессий
- **Аналитика** — анализ результатов сессий
- **CMS** — просмотр истории сессий

## GameSessionTeam (Команда в сессии)

Команда, участвующая в командной игре. Создаётся при формировании команд оператором или участниками.

Используется только для сессий с `mode = team`.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Уникальный идентификатор команды |
| `session_id` | UUID | ID сессии |
| `name` | string | Название команды |
| `color` | string, nullable | Цвет команды (для визуального различия) |
| `captain_participant_id` | UUID, nullable | ID командира команды (ссылка на GameSessionParticipant) |
| `score` | integer | Итоговый счёт команды |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата обновления |

### Связи

- **GameSessionTeam → GameSession**: команда принадлежит одной сессии (`session_id`)
- **GameSessionTeam → GameSessionParticipant**: капитан команды (`captain_participant_id`)
- **GameSessionTeam → GameSessionParticipant**: команда имеет множество участников

### Где используется

- **LED-медиаплатформа** — отображение команд, рейтинга
- **Аналитика** — анализ результатов по командам

### Примечания

- Состав команды — от 2 до 10 человек (согласно ТЗ)
- В сессии может быть от 2 до 8 команд
- Командир — первый подключившийся к команде; может передать роль другому участнику; при отключении командира система назначает случайного; оператор может сменить командира

## GameSessionParticipant (Участник сессии)

Участник игровой сессии. Может быть авторизованным пользователем или гостем.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Уникальный идентификатор участника |
| `session_id` | UUID | ID сессии |
| `team_id` | UUID, nullable | ID команды (null для индивидуальной викторины) |
| `user_id` | UUID, nullable | ID авторизованного пользователя |
| `guest_id` | UUID, nullable | ID гостя (если не авторизован) |
| `role` | string, nullable | Роль в команде (для командной игры) |
| `individual_score` | integer | Индивидуальный счёт участника |
| `joined_at` | timestamp | Дата подключения к сессии |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата обновления |

### Связи

- **GameSessionParticipant → GameSession**: участник принадлежит одной сессии (`session_id`)
- **GameSessionParticipant → GameSessionTeam**: участник может принадлежать команде (`team_id`)
- **GameSessionParticipant → User**: участник может быть авторизованным пользователем (`user_id`)

### Где используется

- **LED-медиаплатформа** — отображение участников, приём ответов
- **Аналитика** — анализ результатов по участникам
- **Цифровой профиль** — привязка результатов к профилю пользователя

### Примечания

- Один из идентификаторов обязателен: `user_id` или `guest_id`
- Для индивидуальной викторины `team_id` = null
- Для командной игры `role` = "командир" у первого подключившегося или назначенного командира

## Особенности режимов

### Индивидуальная викторина

- `mode = individual`
- Использует раунды с разными типами вопросов (как командная игра)
- Оператор выбирает шаблон сценария или настраивает раунды вручную
- Каждый участник отвечает персонально
- `GameSessionTeam` не создаётся
- `GameSessionParticipant.team_id` = null
- Рейтинг формируется по `individual_score` каждого участника

### Командная игра

- `mode = team`
- Оператор выбирает [шаблон сценария](../subsystems/cms/quiz.md#шаблоны-сценариев) или собирает раунды вручную
- Если выбран шаблон — используются заранее подобранные вопросы из шаблона
- Если шаблон не выбран — оператор выбирает от 3 до 8 типов раундов из [справочника](../references/scenario-round-types.md), система подбирает вопросы по фильтрам (сложность, возраст, теги)
- Вопросы классифицированы по типам раундов через `GameQuestion.round_type_id`
- Создаются `GameSessionTeam` для каждой команды
- Команды имеют свои цвета, названия, командиров и счёт
- Итоговый рейтинг формируется по баллам команд (`GameSessionTeam.score`)
