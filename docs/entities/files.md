# Файлы

Описание сущности для хранения файлов (видео, изображения, документы).

---

## File (Файл)

Универсальная сущность для хранения файлов, которые используются в различных модулях системы (видео для LED, изображения для профессий, документы и т.д.).

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор файла |
| `type` | integer | Тип файла: `1` — video, `2` — image, `3` — document, `4` — audio |
| `module` | string | Код модуля файла, например `quiz`, `video_scenarios`, `professions`, `surveys`, `led`, `profstart`, `avatars`; по умолчанию `general` |
| `file_path` | string | Путь к файлу в хранилище |
| `file_preview_path` | string, nullable | Путь к переданному превью или первому кадру видео |
| `mime_type` | string | MIME-тип файла (например, `video/mp4`, `image/jpeg`) |
| `size` | integer | Размер файла в байтах |
| `title` | string | Название файла |
| `description` | text, nullable | Описание файла |
| `uploaded_at` | timestamp | Дата загрузки |
| `uploaded_by` | integer (int64), nullable | ID пользователя, загрузившего файл |

### Связи

- **File → QuizQuestion**: файл может использоваться как медиа в вопросе викторины (`media_id`)
- **File → TestQuestion**: файл может использоваться как медиа в вопросе теста (`media_id`)
- **File → TeamGameQuestion**: файл может использоваться как медиа в вопросе командной игры (`media_id`)
- **File → InteractiveVideoScenario**: файл может использоваться как видео в видеосценарии (`video_id`)
- **File → Profession**: файл может быть связан с профессией (изображение или видео)
- **File → SurveyQuestion**: файл может использоваться как медиа в вопросе анкеты (`media_id`)

- **File → Organization**: необязательное вложение организации (`media_id`, модуль хранения `organizations`); в API — объект `file`.
- **File → LedScreensaver**: обязательный медиафайл заставки LED (`media_id`).

### Где используется

- **CMS** — загрузка и управление файлами
- **LED-медиаплатформа** — воспроизведение видео и показ изображений
- **ПрофСтарт** — показ изображений в вопросах теста
- **Командная игра** — показ медиа в вопросах
- **Профессии** — изображения и видео для профессий
- **Обратная связь** — медиа в вопросах анкеты

### Примечания

- Файлы хранятся в локальном хранилище (NAS)
- Один файл может использоваться в нескольких местах (переиспользование)
- Поддерживаемые форматы видео: MP4/H.264, MOV
- Поддерживаемые форматы изображений: JPEG, PNG, GIF


## Загрузка и ответ API

Файлы передаются непосредственно в `multipart/form-data` и сохраняются через
`app/services/files/service.py:save_file`. ID файлов остаются внутренними внешними
ключами БД и не принимаются в запросах создания/редактирования медиа.

Ответ содержит `file` (или `null`, если медиа отсутствует):

```json
{
  "file": {
    "preview_url": "/api/files/<uuid>_preview?expires=<timestamp>&sig=<signature>&ttl=<ttl>&v=<version>",
    "url": "/api/files/<uuid>?expires=<timestamp>&sig=<signature>&ttl=<ttl>",
    "mime_type": "video/mp4",
    "title": "Название файла",
    "description": null
  }
}
```

URL подписан и получает полный срок от создания: 1 или 90 дней по полю
`files.module`. У каждого файла и версии превью собственная дата истечения.
Суточная ссылка обновляется при остатке часа или меньше, 90-дневная — дня
или меньше. До обновления одинаковые параметры дают одинаковые `sig` и
`expires`, а предыдущая ссылка действует до своего `expires`. Новая версия
превью, политика срока или ключ подписи сразу меняют ссылку. Сроки хранятся
в памяти процесса API; после его перезапуска первая выдача создаёт новую ссылку.
Просроченные записи очищаются ежедневно в 02:00 по Москве фоновой задачей
каждого процесса API. В обработке запросов массовая очистка не выполняется.
При выдаче через CDN браузерный кэш разрешён для успешных ответов:
`Cache-Control: private, max-age=N, must-revalidate`. Значение N ограничено
оставшимся сроком подписанной ссылки и политикой `ttl`. После его истечения
браузер обязан перепроверить файл. Ошибки имеют `no-store`, а превью без версии
`v` — `max-age=0` с перепроверкой при каждом использовании.
Поля `image_url`, `media_url`, `media_id` в этих
ответах заменены объектом `file`. Для шаблона аватара профессии возвращаются
`male_file` и `female_file` с той же структурой. Название по умолчанию берётся из
имени загруженного файла; описание необязательно.

- Ветки видеосценариев: поля формы `parent_id`, `text`, `prompt`, `file`,
  `file_title`, `file_description`. При создании обязательны `parent_id`, `text`,
  `file`; при обновлении все поля необязательны. Без нового файла сохраняется
  текущий. Стартовое видео заменяется тем же PUT ветки.
- Вопросы викторины: каждое поле (`text`, `question_type`, `difficulty`,
  `time_limit`, `points`, `age_group`, `explanation`, `round_type`, `tags`,
  `answer_key`, `answer_options`, `file_title`, `file_description`) передаётся
  отдельно в form-data. `file` — необязательное медиа вопроса. `tags` передаётся
  повторяющимися полями с одним именем. `answer_options` (массив объектов) и
  `answer_key` (объект) передаются JSON в одноимённых текстовых полях.
  В Scalar JSON вставляется как текст целиком, без дополнительных кавычек.
  Пустые необязательные `answer_key` и `condition` пропускаются.
  Также принимается одиночный JSON-объект в `answer_options` и повторяющиеся
  поля `answer_options` с отдельными JSON-объектами (как их отправляет Scalar).
  Все варианты собираются в массив в порядке частей запроса.
  Файлы вариантов передаются отдельными полями `answer_option_files[0]`,
  `answer_option_files[1]` и т. д. Индекс начинается с нуля и соответствует
  позиции в `answer_options`. Метаданные при создании задаются в соответствующем
  объекте варианта (`file_title`, `file_description`). При PUT индексы соответствуют
  текущему списку `answer_options` из GET; замена файлов вариантов не меняет
  остальные данные вариантов. Неверные и повторные индексы возвращают 422.
- Вопросы анкет: поля `type`, `text`, `order`, `required`, `parent_id`, `condition`,
  `scale_min`, `scale_max`, `file_title`, `file_description` передаются отдельно
  в form-data, `file` — необязательный файл. `condition` — JSON-объект в
  одноимённом поле. При создании обязательны `type`, `text`, `order`;
  при обновлении поля необязательны.

Общего поля `body` с JSON-строкой нет. Простые поля передаются обычными значениями
формы, а JSON используется только для отдельных вложенных структур. Например:

```text
text=Тестовый вопрос
question_type=1
difficulty=1
time_limit=30
points=10
answer_options=[{"text":"Ответ","is_correct":true}]
file=<файл вопроса>
answer_option_files[0]=<файл варианта>
```

- Аватары пользователя: файл `photo` и необязательные поля формы `file_title`,
  `file_description`; `profession_id` сохраняется в query.
- Аватары профессии: `male_photo`, `female_photo`; метаданные в полях формы
  `male_file_title`, `male_file_description`, `female_file_title`,
  `female_file_description`.

В БД сохраняются прежние связи с файлами. Миграция `0036` добавляет nullable-поле
`files.file_preview_path`; старые записи получают `null`. Старые файлы
при замене сохраняются: они могут использоваться копиями анкет и другими
сущностями. Новые файлы и сущность сохраняются в общей транзакции; при ошибке
новые загрузки очищаются. При обновлении без файла метаданные текущего файла
не изменяются.


## Хранение файлов

### Подписанные ссылки и CDN

`file.url` и `file.preview_url` действуют 1 день для `files.module` из списка
`avatars`, `avatar_generation_inputs` и 90 дней для остальных
значений. Срок одинаков для оригинала, превью и уменьшенных вариантов.
Ссылки содержат только относительные
пути `/api/files/...` с параметрами подписи и срока. Домен CDN подставляет
фронтенд; API не добавляет домен в ответ. Новые ссылки подписываются
отдельным `FILE_SIGNING_SECRET`, одинаковым у API и CDN. Размеры `width` и
`height` по-прежнему не входят в подпись. На основном API ранее выданные прямые
ссылки с подписью JWT-ключом действуют до истечения срока; CDN принимает только
ключ файлов. Без отдельного ключа сохраняется прежняя подпись JWT-ключом.

Новые ссылки содержат `ttl` (`86400` или `7776000`), включённый в HMAC после
UUID, срока действия и версии превью, если она есть. Основной API передаёт
проверенный подписанный срок CDN через `X-Accel-Expires`; без `ttl` используется
1 день. Модуль определяет срок при создании ссылки; его изменение не приводит
к отказу в скачивании по уже выданной действующей ссылке. CDN проверяет подпись
до выдачи из кэша, использует отдельные зоны с TTL 1 и 90 дней без ограничения
общего размера. Неиспользуемые записи удаляются по `inactive` соответствующей зоны.
Ранее выданные ссылки без `ttl` действуют до прежнего срока в суточной зоне.
Запрос `GET /api/cms/files/cdn-manifest` включает только связанные с активным
контентом файлы с 90-дневной политикой, даже если суточный файл используется
в викторине или другом модуле.
`preview_url` содержит `v` — SHA-256 уникального пути превью. Версия входит в
подпись и ключ кэша CDN. При замене превью меняется ссылка; фронтенд получает
новый `preview_url` после сохранения или повторного чтения объекта. Превью с
версией кэшируются на 1 или 90 дней по модулю файла. Основной API возвращает 404 для уже заменённой
версии, не выдавая новое изображение под старой версией. Закэшированная старая
ссылка может выдавать прежнюю копию до истечения TTL. Ссылки без версии работают
с текущим превью через BYPASS. Версия обновляется и в кэшированных ответах модулей.

Каждая новая загрузка получает каталог `/data/uploads/<module>/<uuid>/`,
где `uuid` совпадает с идентификатором файла в БД. В каталоге находятся
исходник, превью при наличии и `cache/` после первого уменьшения. Имя исходника
на диске формируется как `<12 символов SHA-256>.<ext>`. Расширение
берётся из имени загрузки. Отображаемое имя хранится отдельно в `title`.
Пути к исходнику и превью хранятся в `files.file_path` и
`files.file_preview_path` относительно `/data/uploads`. Старые файлы
читаются по сохранённым путям.

При неудачной загрузке или откате транзакции каталог новой загрузки удаляется.
При удалении новой записи удаляется её каталог вместе с превью и кэшем.

## Превью файлов

Маршруты загрузки, кроме аватаров профессий и пользователей, принимают необязательное поле
`file_preview` (JPEG, PNG,
WebP или GIF). Файл сохраняется рядом с основным, относительный путь записывается
в `files.file_preview_path`. Для файлов вариантов викторины поля называются
`answer_option_file_previews[0]`, `answer_option_file_previews[1]` и т. д.

Если загружено видео и превью не передано, после commit запускается фоновая
asyncio-задача в API. Она получает только ID файла, открывает свою сессию БД,
извлекает первый кадр через FFmpeg и сохраняет PNG. Загрузка не ждёт генерацию;
до готовности preview_url равен null. Одновременно выполняется до двух генераций.
Для остальных типов автоматическое превью не создаётся. Переданное
превью используется без извлечения кадра. При создании превью передаётся вместе
с новым файлом. В PUT/PATCH можно передать только превью для уже прикреплённого
файла. При отсутствии вложения сервер возвращает 422. Основной файл, его UUID
и метаданные сохраняются. Для шаблонов аватаров используются поля
male_file_preview и female_file_preview без соответствующих исходников.
Новое превью записывается под уникальным именем и становится доступно после commit,
поэтому уменьшенные копии прежнего превью не используются. Прежние файлы превью
сохраняются на диске. При ошибке транзакции удаляется только новая загрузка.

Объект `file` содержит `preview_url`: подписанный URL со сроком 1 или 90 дней по модулю файла либо
`null`, если превью нет. Основной файл и превью скачиваются одним запросом
`GET /files/{file_uuid}` по готовой ссылке; идентификатор превью имеет суффикс
`_preview`. Подпись привязана к полному идентификатору, отдельно для каждого файла.
Ответ содержит MIME-тип файла и `Content-Disposition: inline`. Для скачивания
добавьте `&type=download` к подписанной ссылке, чтобы получить
`Content-Disposition: attachment`. Подпись остаётся действительной. CDN
использует одну копию для обоих режимов и меняет заголовок при выдаче.
Имя основного файла берётся из `title`. При необходимости к нему дописывается
расширение из `file_path` или, если в пути его нет, расширение по MIME-типу.
Уменьшенная копия получает расширение своего формата. При удалении файла
удаляется и превью.
При ошибке загрузки или транзакции новые файлы очищаются; фоновая задача не
запускается. Ошибки FFmpeg логируются, основной файл сохраняется, превью остаётся
null. На извлечение кадра отводится не более 60 секунд. Лимит загружаемого превью — 1 ГиБ.

После commit генерации или замены превью публикуется его текущая версия по UUID
в общем Redis-клиенте. Кэши викторины, видеосценариев, ПрофСтарта, рекомендаций и
анкет пакетно обновляют версии всех вложений, включая уже имевшие превью;
содержимое и суточная подборка не пересчитываются.
Таблицы заданий, очереди и повторы не используются. При остановке API фоновые
задачи отменяются, FFmpeg завершается; после перезапуска задачи не восстанавливаются.

Для запуска этой версии нужны миграция `0036` и API-образ с зависимостью `imageio-ffmpeg`, поставляющей FFmpeg.
Превью для уже существующих видео автоматически не заполняются.

### Размер изображения при скачивании

К подписанному `file.url` для растрового изображения или `file.preview_url` можно
добавить `width` и `height`. Достаточно одного параметра. Каждый принимает целое
число от 1 до 2048 пикселей. Например, `&width=320&height=180` вписывает картинку
в рамку 320 × 180 с сохранением пропорций. Если картинка уже помещается в рамку,
сервер отдаёт исходный файл. Параметры не входят в подпись ссылки.

JPEG, PNG, WebP, GIF, BMP, TIFF, AVIF и ICO уменьшаются с сохранением формата.
Прозрачность и кадры анимации сохраняются. Размер файла для обработки ограничен
64 МиБ, размер изображения — 40 млн пикселей. Для анимаций лимит составляет
300 кадров и 64 млн пикселей по всем кадрам.

Готовые варианты сохраняются по фактическим размерам и расширению формата результата. Для новых
файлов путь имеет вид `<module>/<uuid>/cache/<имя исходника>/<ширина>x<высота>.<ext>`.
Оригинал и превью используют отдельные подкаталоги кэша. Для старых файлов
сохраняется прежнее расположение кэша рядом с исходником или превью.
