# Файлы

Описание сущности для хранения файлов (видео, изображения, документы).

---

## File (Файл)

Универсальная сущность для хранения файлов, которые используются в различных модулях системы (видео для LED, изображения для профессий, документы и т.д.).

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор файла |
| `type` | integer | Тип файла: `1` — video, `2` — image, `3` — document, `4` — audio |
| `module_code` | string | Символьный код модуля, к которому относится файл (например, `quiz`, `video_scenario`, `profession`, `survey`, `team_game`, `profstart`) |
| `file_path` | string | Путь к файлу в хранилище |
| `file_preview_path` | string, nullable | Путь к переданному превью или первому кадру видео |
| `mime_type` | string | MIME-тип файла (например, `video/mp4`, `image/jpeg`) |
| `size` | integer | Размер файла в байтах |
| `title` | string | Название файла |
| `description` | text, nullable | Описание файла |
| `uploaded_at` | timestamp | Дата загрузки |
| `uploaded_by` | integer (int64), nullable | ID пользователя, загрузившего файл |

### Связи

- **File → QuizQuestion**: файл может использоваться как медиа в вопросе викторины (`media_id`)
- **File → TestQuestion**: файл может использоваться как медиа в вопросе теста (`media_id`)
- **File → TeamGameQuestion**: файл может использоваться как медиа в вопросе командной игры (`media_id`)
- **File → InteractiveVideoScenario**: файл может использоваться как видео в видеосценарии (`video_id`)
- **File → Profession**: файл может быть связан с профессией (изображение или видео)
- **File → SurveyQuestion**: файл может использоваться как медиа в вопросе анкеты (`media_id`)

### Где используется

- **CMS** — загрузка и управление файлами
- **LED-медиаплатформа** — воспроизведение видео и показ изображений
- **ПрофСтарт** — показ изображений в вопросах теста
- **Командная игра** — показ медиа в вопросах
- **Профессии** — изображения и видео для профессий
- **Обратная связь** — медиа в вопросах анкеты

### Примечания

- Файлы хранятся в локальном хранилище (NAS)
- Один файл может использоваться в нескольких местах (переиспользование)
- Поддерживаемые форматы видео: MP4/H.264, MOV
- Поддерживаемые форматы изображений: JPEG, PNG, GIF


## Загрузка и ответ API

Файлы передаются непосредственно в `multipart/form-data` и сохраняются через
`app/services/files/service.py:save_file`. ID файлов остаются внутренними внешними
ключами БД и не принимаются в запросах создания/редактирования медиа.

Ответ содержит `file` (или `null`, если медиа отсутствует):

```json
{
  "file": {
    "preview_url": "/api/files/<uuid>_preview?expires=<timestamp>&sig=<signature>",
    "url": "/api/files/<uuid>?expires=<timestamp>&sig=<signature>",
    "mime_type": "video/mp4",
    "title": "Название файла",
    "description": null
  }
}
```

URL подписан и действует 24 часа. Поля `image_url`, `media_url`, `media_id` в этих
ответах заменены объектом `file`. Для шаблона аватара профессии возвращаются
`male_file` и `female_file` с той же структурой. Название по умолчанию берётся из
имени загруженного файла; описание необязательно.

- Ветки видеосценариев: поля формы `parent_id`, `text`, `prompt`, `file`,
  `file_title`, `file_description`. При создании обязательны `parent_id`, `text`,
  `file`; при обновлении все поля необязательны. Без нового файла сохраняется
  текущий. Стартовое видео заменяется тем же PUT ветки.
- Вопросы викторины: каждое поле (`text`, `question_type`, `difficulty`,
  `time_limit`, `points`, `age_group`, `explanation`, `round_type`, `tags`,
  `answer_key`, `answer_options`, `file_title`, `file_description`) передаётся
  отдельно в form-data. `file` — необязательное медиа вопроса. `tags` передаётся
  повторяющимися полями с одним именем. `answer_options` (массив объектов) и
  `answer_key` (объект) передаются JSON в одноимённых текстовых полях.
  В Scalar JSON вставляется как текст целиком, без дополнительных кавычек.
  Пустые необязательные `answer_key` и `condition` пропускаются.
  Также принимается одиночный JSON-объект в `answer_options` и повторяющиеся
  поля `answer_options` с отдельными JSON-объектами (как их отправляет Scalar).
  Все варианты собираются в массив в порядке частей запроса.
  Файлы вариантов передаются отдельными полями `answer_option_files[0]`,
  `answer_option_files[1]` и т. д. Индекс начинается с нуля и соответствует
  позиции в `answer_options`. Метаданные при создании задаются в соответствующем
  объекте варианта (`file_title`, `file_description`). При PUT индексы соответствуют
  текущему списку `answer_options` из GET; замена файлов вариантов не меняет
  остальные данные вариантов. Неверные и повторные индексы возвращают 422.
- Вопросы анкет: поля `type`, `text`, `order`, `required`, `parent_id`, `condition`,
  `scale_min`, `scale_max`, `file_title`, `file_description` передаются отдельно
  в form-data, `file` — необязательный файл. `condition` — JSON-объект в
  одноимённом поле. При создании обязательны `type`, `text`, `order`;
  при обновлении поля необязательны.

Общего поля `body` с JSON-строкой нет. Простые поля передаются обычными значениями
формы, а JSON используется только для отдельных вложенных структур. Например:

```text
text=Тестовый вопрос
question_type=1
difficulty=1
time_limit=30
points=10
answer_options=[{"text":"Ответ","is_correct":true}]
file=<файл вопроса>
answer_option_files[0]=<файл варианта>
```

- Аватары пользователя: файл `photo` и необязательные поля формы `file_title`,
  `file_description`; `profession_id` сохраняется в query.
- Аватары профессии: `male_photo`, `female_photo`; метаданные в полях формы
  `male_file_title`, `male_file_description`, `female_file_title`,
  `female_file_description`.

В БД сохраняются прежние связи с файлами. Миграция `0036` добавляет nullable-поле
`files.file_preview_path`; старые записи получают `null`. Старые файлы
при замене сохраняются: они могут использоваться копиями анкет и другими
сущностями. Новые файлы и сущность сохраняются в общей транзакции; при ошибке
новые загрузки очищаются. При обновлении без файла метаданные текущего файла
не изменяются.


## Превью файлов

Маршруты загрузки, кроме аватаров профессий и пользователей, принимают необязательное поле
`file_preview` (JPEG, PNG,
WebP или GIF). Файл сохраняется рядом с основным, относительный путь записывается
в `files.file_preview_path`. Для файлов вариантов викторины поля называются
`answer_option_file_previews[0]`, `answer_option_file_previews[1]` и т. д.

Если загружено видео и превью не передано, FFmpeg декодирует его первый кадр и
сохраняет PNG. Для остальных типов автоматическое превью не создаётся. Переданное
превью используется без извлечения кадра. Превью передаётся вместе с новым файлом;
без основного файла запрос отклоняется с 422.

Объект `file` содержит `preview_url`: подписанный URL со сроком 24 часа либо
`null`, если превью нет. Основной файл и превью скачиваются одним запросом
`GET /files/{file_uuid}` по готовой ссылке; идентификатор превью имеет суффикс
`_preview`. Подпись привязана к полному идентификатору, отдельно для каждого файла.
Ответ содержит MIME-тип скачиваемого файла. При удалении файла удаляется и превью.
При ошибке загрузки, извлечения кадра или транзакции новые файлы очищаются.
Повреждённое видео возвращает 422, отсутствие FFmpeg — 503. На извлечение кадра
отводится не более 60 секунд. Лимит размера загружаемого превью — 1 ГиБ.

Для запуска этой версии нужны миграция `0036` и API-образ с зависимостью `imageio-ffmpeg`, поставляющей FFmpeg.
Превью для уже существующих видео автоматически не заполняются.
