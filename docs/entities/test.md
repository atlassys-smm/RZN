# ПрофСтарт — сущности

Целевая модель трёх предзаданных тестов. Таблицы модуля требуют реализации; User, Profession и File уже существуют. ID — integer (int64), веса и баллы — decimal, даты — UTC timestamp. [Методики](../subsystems/profstart/methods.md) · [API](../api/profstart.md).

## TestType — тип теста

Таблица `test_types`, три предзаданные записи.

| Поле | Описание |
|---|---|
| `id` | PK |
| `code` | Уникальный неизменяемый код: solomin, holland, dellinger |
| `name`, `description` | Название, описание |
| `created_at`, `updated_at` | Даты |

CMS читает каталог; создание дополнительных типов в текущий контракт не входит.

## ProfStartTest — версия теста

Таблица `profstart_tests`. В API test_id обозначает версию, test_type_id — методику.

| Поле | Описание |
|---|---|
| `id`, `test_type_id` | PK, FK → TestType |
| `version` | Положительный номер внутри типа, назначается сервером |
| `name`, `description`, `instructions` | Тексты теста |
| `age_group_ids` | Список допустимых возрастных групп; пустой — без возрастного фильтра |
| `published_at` | Nullable дата публикации: null — черновик теста |
| `created_at`, `updated_at` | Даты |

Уникальность (test_type_id, version). Черновик существует только у теста и определяется published_at=null. Публикация проверяет весь состав и устанавливает дату. Отдельного поля состояния нет.

Для новых прохождений доступна опубликованная версия с наибольшим version внутри типа. Прежние опубликованные версии остаются неизменяемыми для начатых сессий и истории; отдельное архивирование не используется. Копирование создаёт новый тест с published_at=null и собственными ID вложенных записей.

## TestGroup — группа результата

Таблица `test_groups`.

| Поле | Описание |
|---|---|
| `id`, `test_id` | PK, FK → ProfStartTest |
| `code`, `name`, `description` | Код и тексты группы |
| `category` | subject, labor, riasec, geometry |
| `order` | Порядок отображения |

У группы нет собственного черновика, статуса или публикации. Она входит в состав теста. Уникальность (test_id, code); точный набор 7/6/5 проверяется при публикации теста. Группы не заменяют Direction. Одна группа Соломина используется на обеих осях.

## TestQuestion — вопрос

Таблица `test_questions`.

| Поле | Описание |
|---|---|
| `id`, `test_id` | PK, FK → ProfStartTest |
| `type` | Только single_choice |
| `axis` | want, can, general |
| `text`, `media_id` | Текст, nullable FK → File |
| `order` | Положительный порядок, уникальный внутри теста |
| `created_at`, `updated_at` | Даты |

У вопроса нет собственного черновика, статуса или публикации. Во всех тестах пользователь выбирает один вариант; различаются подписи, количество и изображения. Все вопросы обязательны, набор и порядок фиксированы. Возрастная доступность задаётся тесту.

## TestAnswerOption — вариант с весом

Таблица `test_answer_options`. Группа и вес хранятся непосредственно в варианте.

| Поле | Описание |
|---|---|
| `id`, `question_id` | PK, FK → TestQuestion |
| `text`, `media_id` | Подпись, nullable FK → File; картинка обязательна для фигур |
| `value` | Nullable integer; у Соломина 0, 1, 2, 3 |
| `order` | Порядок, уникальный внутри вопроса |
| `group_id` | FK → TestGroup той же версии теста |
| `weight` | Конечное число; Соломин 0–3 и равно value, Голланд/Деллингер — 1 |

Каждый вариант связан с одной группой. Ось расчёта берётся из TestQuestion.axis, отдельно в варианте не дублируется. У вопроса 4/6/5 вариантов. Ноль — полноценный выбранный ответ; несвязанным группам начисляется нулевой вклад. Отдельной сущности для веса нет, правильных ответов нет.

## TestGroupProfession — связь с профессией

Таблица `test_group_professions`, многие-ко-многим с существующей Profession.

| Поле | Описание |
|---|---|
| `id`, `group_id`, `profession_id` | PK; FK → TestGroup, Profession |
| `coefficient` | Decimal, 0 < значение ≤ 1, по умолчанию 1 |

Уникальность (group_id, profession_id). Для профессии Соломина необходимы subject- и labor-группы той же версии. У геометрического теста связь может быть задана для любой фигуры. [Формула рекомендаций](../subsystems/profstart/results.md).

Группы, вопросы, варианты и связи редактируются как содержимое неопубликованного теста, без отдельного жизненного цикла. После публикации для изменения состава копируется весь тест.

## TestSession — прохождение

Таблица `test_sessions`.

| Поле | Описание |
|---|---|
| `id`, `test_id`, `user_id` | PK; FK → версия, User; пользователь всегда заполнен |
| `age_group_id` | Nullable выбранная возрастная группа |
| `status` | in_progress, completed, abandoned |
| `started_at`, `completed_at` | Начало и nullable успешное завершение |
| `created_at`, `updated_at` | Даты |

Тип интерфейса и источник не сохраняются. Для прерывания достаточно status=abandoned; completed_at остаётся null. Повторное прохождение создаёт новую сессию. Завершение и запись результата — атомарная операция.

## TestAnswer — ответ пользователя

Таблица `test_answers`.

| Поле | Описание |
|---|---|
| `id`, `session_id`, `question_id`, `answer_option_id` | PK и FK на сессию, вопрос, один вариант |
| `answered_at` | Время записи |
| `time_spent_ms` | Целое ≥ 0, присланное клиентом |

Уникальность (session_id, question_id). Повтор того же варианта не начисляет баллы повторно; другой вариант уже отвеченного вопроса — 409. Принадлежность вопроса и варианта версии проверяется сервером.

## TestResult — результат пользователя

Таблица `test_results`, одна запись на полностью завершённую сессию.

| Поле | Описание |
|---|---|
| `id`, `session_id`, `test_id`, `user_id` | PK; уникальный FK → сессия; FK → версия, User |
| `test_code_type` | Сохранённый код solomin, holland или dellinger |
| `test_version` | Номер версии теста |
| `answered_count`, `question_count` | Полнота; для результата равны |
| `created_at` | Время окончательного расчёта |

Название теста при необходимости читается из ProfStartTest по test_id; в результате не дублируется. Результат окончательный, собственного черновика нет. Дополнительные признаки качества не хранятся.

## TestResultScore — показатель группы

Таблица `test_result_scores`.

| Поле | Описание |
|---|---|
| `id`, `result_id`, `group_id`, `axis` | PK, FK, ось |
| `group_code`, `group_name`, `category` | Снимки подписей |
| `raw_score`, `max_score` | Сумма весов и достижимый максимум |
| `normalized_score` | Decimal 0–100, два знака |
| `rank`, `is_leading` | Место и признак положительного максимума |

Уникальность (result_id, group_id, axis). Все показатели, включая нулевые, сохраняются: 14/6/5.

## TestResultProfession — сохранённая рекомендация

Таблица `test_result_professions`.

| Поле | Описание |
|---|---|
| `id`, `result_id`, `profession_id` | PK, FK → результат, Profession |
| `profession_name` | Снимок названия профессии |
| `score`, `position` | Балл 0–100, позиция |
| `reasons` | JSON-массив: группа, ось, показатель, coefficient, вклад |

Уникальность (result_id, profession_id). Сохраняются группы и числовые вклады без отдельного текста пояснения связи. Изменения каталога не пересчитывают историю; удаление связанных профессий блокируется ссылочной целостностью.
