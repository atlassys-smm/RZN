# ПрофСтарт — сущности

Модель расширяемого каталога типов; расчёт результатов поддерживает solomin, holland и dellinger. User, Profession и File используются из существующих справочников. ID — integer (int64), статусы — integer enum, веса и баллы — decimal, даты — UTC timestamp. [Методики](../subsystems/profstart/methods.md) · [API](../api/profstart.md).

## AgeGroup — возрастная группа

Таблица `age_groups`. По умолчанию: 12–14 лет и 15–17 лет; границы включительно.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `name` | string | Уникальное название |
| `min_age` | integer (smallint), nullable | Нижняя граница возраста в полных годах; null — без нижней границы |
| `max_age` | integer (smallint), nullable | Верхняя граница возраста в полных годах; null — без верхней границы |

Справочник возвращают GET `/profstart/age-groups` и GET `/cms/profstart/age-groups`. ID передаётся клиентом; сервер не вычисляет группу автоматически из даты рождения.

## TestType — тип теста

Таблица `profstart_test_types`, три предзаданные записи и типы, добавляемые CMS. Вес относится к типу целиком и одинаков для всех его версий.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `code` | string | Уникальный код типа; solomin, holland, dellinger фиксированы; новый код можно изменить, пока нет связанных тестов |
| `name` | string | Название |
| `description` | text | Описание |
| `recommendation_weight_percent` | integer (smallint) | Влияние на общий подбор, 0–100%; solomin 40, holland 40, dellinger 20; новые типы 0 |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата изменения |

CMS создаёт типы, читает каталог и карточки, изменяет name/description и удаляет неиспользуемые типы. Название и описание можно менять и у используемых типов. Код дополнительного типа можно изменить только без связанных тестов; предзаданные solomin, holland, dellinger фиксированы. Недопустимая смена кода — 409; дубликат кода — 409. Удаление типа с active-тестом — 409; ссылки остальных тестов также защищены FK, связанные тесты и историю каскадно не удаляют. Итоговый расчёт поддерживает только solomin, holland, dellinger; новые типы до появления алгоритма недоступны для пользовательского старта.

Влияние на общий подбор задаётся в profstart_test_types.recommendation_weight_percent: целый процент 0–100, стандарт solomin=40, holland=40, dellinger=20. Сумма весов поддерживаемых типов — ровно 100; 0 отключает влияние типа, сохраняя возможность отдельного прохождения. У новых типов без алгоритма вес по умолчанию 0 и положительное значение запрещено: 422.

Проценты доступны в карточке и каталоге типов. Перераспределение сохраняется атомарным PUT /cms/profstart/test-types/recommendation-weights с полным набором solomin/holland/dellinger. PATCH одного типа также проверяет итоговую сумму; нарушение — 422. Для переноса процента между типами используется PUT всей тройки. Настройка изменяется и при активных тестах; сохранённые результаты отдельных тестов остаются прежними, общий подбор использует текущие веса. Тип с ненулевым весом удалить нельзя: 409; сначала требуется перераспределить проценты.

## ProfStartTest — версия теста

Таблица `profstart_tests`. В API test_id обозначает версию, test_type_id — методику.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_type_id` | integer (int64) | FK → TestType |
| `version` | integer | Положительный номер внутри типа, назначается сервером |
| `name` | string | Название |
| `description` | text | Описание |
| `instructions` | text | Инструкция перед прохождением |
| `age_group_ids` | json (массив integer int64) | ID из age_groups; пустой массив — без возрастного фильтра |
| `status` | integer (int32) | TestStatus: 1 — draft, 2 — active, 3 — archived; жизненный цикл только у теста |
| `published_at` | timestamp, nullable | Дата первой активации; null у draft, заполнена у active и archived |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата изменения |

`age_group_ids` хранится в JSON-колонке теста. CMS принимает только существующие уникальные ID справочника; неизвестные или повторяющиеся — 422. Ссылки массива проверяет сервис; внешний ключ на элементы JSON не создаётся.

Уникальность (test_type_id, version). Черновик определяется status=1 (draft); published_at=null до активации. Публикация проверяет весь состав и атомарно переводит draft в active, заполняя published_at. Частичный уникальный индекс (test_type_id) WHERE status=2 допускает не более одного активного теста одного типа.

Публикация нового draft переводит прежний active этого типа в archived в той же транзакции. /archive переводит active в archived без замены; активного теста может не быть. Начатые сессии продолжают свою версию. Вопросы и варианты active и archived неизменяемы, published_at сохраняется. Группы типа и связи профессий редактируются независимо от статуса версии. Копирование любой версии создаёт новый draft с published_at=null и собственными ID вопросов и вариантов; группы типа и связи профессий общие. Повтор /publish для active и /archive для archived идемпотентен; archived не публикуется повторно, draft не архивируется.

## TestGroup — группа результата

Таблица `profstart_test_groups`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_code_type` | string | FK → TestType.code; тип теста |
| `code` | string | Код группы; уникален внутри типа теста |
| `name` | string | Название |
| `description` | text | Описание |
| `category` | string | subject, labor, riasec, geometry |

У группы нет собственного черновика, статуса или публикации. Она общая для всех версий одного типа. Уникальность (test_code_type, code); точный набор 7/6/5 проверяется при публикации трёх поддерживаемых типов. У новых типов состав задаётся CMS. Группы не заменяют Direction. Одна группа Соломина используется на обеих осях.

Группы и связи профессий можно менять без копирования версии, включая наличие active/archived. Основные группы solomin/holland/dellinger нельзя удалять или менять их code/category (409); добавление кода вне набора методики или неверной категории отклоняется с 422. У групп дополнительных типов код и категория защищены от изменения, если есть варианты или результаты (409). Подписи и связи профессий доступны для редактирования. Группы выводятся по id. Дубликат code внутри типа — 409. Изменения учитываются при сохранении новых результатов; исторические баллы, названия и рекомендации остаются прежними. Удаление связанной с вариантами, результатами или профессиями группы — 409.

## TestQuestion — вопрос

Таблица `profstart_test_questions`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_id` | integer (int64) | FK → ProfStartTest (версия теста) |
| `type` | string | Только single_choice |
| `axis` | string | Блок вопроса: want, can, general; в результате Соломина блоки объединяются |
| `text` | text | Текст |
| `media_id` | integer (int64), nullable | Внутренний ID файла, FK → File; в API объект file; null при отсутствии медиа |
| `order` | integer | Положительный порядок, уникальный внутри теста |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата изменения |

Файл загружается при создании/изменении вопроса через multipart/form-data: file, необязательные file_preview, file_title и file_description. API не принимает media_id и возвращает объект file с url/preview_url и метаданными; без вложения file=null. Аналогичный формат применяется к вариантам. [Файлы](files.md).

У вопроса нет собственного черновика, статуса или публикации. Во всех тестах пользователь выбирает один вариант; различаются подписи, количество и изображения. Все вопросы обязательны, набор и порядок фиксированы. Возрастная доступность задаётся тесту.

## TestAnswerOption — вариант с весом

Таблица `profstart_test_answer_options`. Группа и вес хранятся непосредственно в варианте.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `question_id` | integer (int64) | FK → TestQuestion |
| `text` | text | Подпись варианта, в том числе подпись изображения |
| `media_id` | integer (int64), nullable | Внутренний ID файла, FK → File; в API объект file; null при отсутствии медиа; изображение обязательно для фигур |
| `value` | integer, nullable | Значение шкалы Соломина: 0, 1, 2, 3; у Голланда/Деллингер null |
| `order` | integer | Порядок, уникальный внутри вопроса |
| `group_id` | integer (int64) | FK → TestGroup того же типа теста |
| `weight` | decimal | Конечное число; Соломин 0–3 и равно value, Голланд/Деллингер — 1 |

Каждый вариант связан с одной группой. Блок вопроса определяется TestQuestion.axis, отдельно в варианте не дублируется. Ответы want и can суммируются в одном показателе группы. У предзаданных типов в вопросе 4/6/5 вариантов. Соломин: 42 вопроса (7 групп × 3 вопроса × 2 оси), общий максимум 18 на группу. Голланд: ровно 15 вопросов, максимум 15 на тип. Деллингер: один вопрос. Ноль — полноценный выбранный ответ; несвязанным группам начисляется нулевой вклад. Правильных ответов нет.

## TestGroupProfession — связь с профессией

Таблица `profstart_test_group_professions`, многие-ко-многим с существующей Profession.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_code_type` | string | Код типа; часть составного FK → TestGroup.test_code_type |
| `group_code` | string | Код группы; часть составного FK → TestGroup.code |
| `profession_id` | integer (int64) | FK → Profession |
| `coefficient` | decimal | 0 < значение ≤ 1, по умолчанию 1 |

Составной FK (test_code_type, group_code) с ON UPDATE CASCADE и ON DELETE CASCADE. При допустимой смене кода группы дополнительного типа связь сохраняется. Уникальность (test_code_type, group_code, profession_id). Для включения профессии в результат Соломина необходимы subject- и labor-группы того же типа. Неполная пара исключает профессию из новых рекомендаций и не мешает завершить начатую сессию; баллы групп и исторические результаты сохраняются. CMS /validate и /publish проверяют полноту пар. У геометрического теста связь может быть задана для любой фигуры. [Формула рекомендаций](../subsystems/profstart/results.md).

При копировании создаются новые ID вопросов и вариантов; question_id переназначается на копию, group_id остаётся прежним. Группы и связи профессий общие для всех версий типа. Ссылки на существующие Profession и File сохраняются.

Вопросы и варианты редактируются только у draft; для изменения их active/archived копируется тест. Группы типа и связи профессий редактируются независимо от статуса версии, без отдельного жизненного цикла.

## TestSession — прохождение

Таблица `profstart_test_sessions`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_id` | integer (int64) | FK → ProfStartTest (версия теста) |
| `user_id` | integer (int64) | FK → User, включая гостя |
| `age_group_id` | integer (int64), nullable | FK → AgeGroup; null при отсутствии выбора |
| `status` | integer (int32) | TestSessionStatus: 1 — in_progress, 2 — completed, 3 — abandoned |
| `started_at` | timestamp | Время начала прохождения |
| `completed_at` | timestamp, nullable | Время успешного завершения; null до завершения и у abandoned |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата изменения |

Сервер проверяет, что answered_count в API равен числу уникальных ответов и не превышает question_count. У completed обязателен полный набор, completed_at и связанный TestResult; у in_progress/abandoned нет результата, completed_at=null. Для закрытой сессии next_question_id=null.

Тип интерфейса и источник не сохраняются. Для прерывания достаточно status=3 (abandoned); completed_at остаётся null. Повторное прохождение создаёт новую сессию. Завершение и запись результата — атомарная операция.

У пользователя допускается только одна сессия со status=1 (in_progress) среди всех типов и версий, включая архивные. Новый старт при наличии незавершённого прохождения возвращает 409. После completed или abandoned ограничение освобождается; история сохраняется. Сервис запуска блокирует строку пользователя до конца транзакции, поэтому конкурентные запросы не создают две незавершённые сессии.

Список своих сессий доступен через GET /profstart/me/sessions с фильтром status и пагинацией; текущая in_progress — через GET /profstart/me/sessions/active (null, если отсутствует). GET /profstart/question выдаёт только следующий неотвеченный вопрос по порядку версии, POST /profstart/answer сохраняет ответ. Оба маршрута выбирают текущую сессию по пользователю без её ID; при отсутствии собственной in_progress — 409, в том числе для повтора ответа после completed/abandoned. Чтение не меняет прогресс; переход выполняется после сохранения ответа.

## TestAnswer — ответ пользователя

Таблица `profstart_test_answers`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `session_id` | integer (int64) | FK → TestSession |
| `question_id` | integer (int64) | FK → TestQuestion |
| `answer_option_id` | integer (int64) | FK → TestAnswerOption |
| `answered_at` | timestamp | Время записи |

Уникальность (session_id, question_id). Пока сессия in_progress, повтор того же варианта не начисляет баллы повторно; другой вариант уже отвеченного вопроса — 409. Принадлежность вопроса и варианта текущей версии проверяется сервером. После completed/abandoned и при отсутствии in_progress повтор ответа возвращает 409.

При записи ответа question_id необязателен в API: отсутствие или null выбирает первый неотвеченный вопрос. В БД question_id остаётся обязательным FK и сохраняется вместе с вариантом. Повтор уже принятого варианта без question_id возвращает сохранённый ответ без повторного продвижения.

## TestResult — результат пользователя

Таблица `profstart_test_results`, одна запись на полностью завершённую сессию.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `session_id` | integer (int64) | FK → TestSession; уникальный, один результат на сессию |
| `test_id` | integer (int64) | FK → ProfStartTest (версия теста) |
| `user_id` | integer (int64) | FK → User, включая гостя |
| `test_code_type` | string | Сохранённый код solomin, holland или dellinger |
| `test_version` | integer | Номер версии теста |
| `answered_count` | integer | Число принятых ответов; у результата равно question_count |
| `question_count` | integer | Число вопросов версии теста |
| `created_at` | timestamp | Время окончательного расчёта |

Название теста при необходимости читается из ProfStartTest по test_id; в результате не дублируется. Результат окончательный, собственного черновика нет. Дополнительные признаки качества не хранятся. Для чтения названия архивного теста пользователь обращается к его карточке; доступ разрешён владельцу существующей сессии этой версии.

## Общий подбор профессий

Вычисляемое представление, отдельной таблицы нет. Используются текущие веса TestType и последнее завершённое TestResult каждого типа у владельца. Сохранённые TestResultScore и TestResultProfession не изменяются. В выдаче перечислены ID исходных результатов, настроенные и эффективные веса, итоговые профессии и вклады каждого теста. [Правила расчёта](../subsystems/profstart/results.md#общий-подбор-по-трём-тестам).
