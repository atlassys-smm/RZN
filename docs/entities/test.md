# ПрофСтарт — сущности

Модель расширяемого каталога типов; прохождение и показатели групп доступны для всех типов, рекомендации — для solomin, holland и dellinger. User, Profession и File используются из существующих справочников. ID — integer (int64), статусы — integer enum, баллы — decimal, даты — UTC timestamp. [Методики](../subsystems/profstart/methods.md) · [API](../api/profstart.md).

## AgeGroup — возрастная группа

Таблица `age_groups`. По умолчанию: 12–14 лет и 15–17 лет; границы включительно.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `name` | string | Уникальное название |
| `min_age` | integer (smallint), nullable | Нижняя граница возраста в полных годах; null — без нижней границы |
| `max_age` | integer (smallint), nullable | Верхняя граница возраста в полных годах; null — без верхней границы |

Справочник возвращают GET `/profstart/age-groups` и GET `/cms/profstart/age-groups`. ID передаётся клиентом; сервер не вычисляет группу автоматически из даты рождения.

## TestType — тип теста

Таблица `profstart_test_types`, три предзаданные записи и типы, добавляемые CMS.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `code` | string | Уникальный код типа; solomin, holland, dellinger фиксированы; новый код можно изменить, пока нет связанных тестов |
| `name` | string | Название |
| `description` | text | Описание |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата изменения |

CMS создаёт типы, читает каталог и карточки, изменяет name/description и удаляет неиспользуемые типы. Название и описание можно менять и у используемых типов. Код дополнительного типа можно изменить только без связанных тестов; предзаданные solomin, holland, dellinger фиксированы. Недопустимая смена кода — 409; дубликат кода — 409. Удаление типа с active-тестом — 409; ссылки остальных тестов также защищены FK, связанные тесты и историю каскадно не удаляют. Все типы доступны для прохождения после публикации. Показатели групп и профессий сохраняются для каждого типа; итоговый рейтинг использует только источники, заданные в SOURCE_WEIGHTS.

Влияние источников задаётся в `app/models/user_recommendations/weights.py`: Соломин 40%, Голланд 40%, Деллингер 20%. В таблицах весов влияния нет; через CMS они не меняются. Общий рейтинг рассчитывается при GET из снимков источников. При неполном наборе веса доступных источников нормируются; вес 0 отключает влияние источника.

Системные типы solomin, holland и dellinger нельзя удалить. Весов влияния в карточке и каталоге типов нет.

## ProfStartTest — версия теста

Таблица `profstart_tests`. В API test_id обозначает версию, test_type_id — методику.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_type_id` | integer (int64) | FK → TestType |
| `version` | integer | Положительный номер внутри типа, назначается сервером |
| `name` | string | Название |
| `description` | text | Описание |
| `instructions` | text | Инструкция перед прохождением |
| `age_group_ids` | json (массив integer int64) | ID из age_groups; пустой массив — без возрастного фильтра |
| `status` | integer (int32) | TestStatus: 1 — draft, 2 — active, 3 — archived; жизненный цикл только у теста |
| `published_at` | timestamp, nullable | Дата первой активации; null у draft, заполнена у active и archived |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата изменения |

`age_group_ids` хранится в JSON-колонке теста. CMS принимает только существующие уникальные ID справочника; неизвестные или повторяющиеся — 422. Ссылки массива проверяет сервис; внешний ключ на элементы JSON не создаётся.

Уникальность (test_type_id, version). Черновик определяется status=1 (draft); published_at=null до активации. Публикация проверяет весь состав и атомарно переводит draft в active, заполняя published_at. Частичный уникальный индекс (test_type_id) WHERE status=2 допускает не более одного активного теста одного типа.

Публикация нового draft переводит прежний active этого типа в archived в той же транзакции. /archive переводит active в archived без замены; активного теста может не быть. Начатые сессии продолжают свою версию. Вопросы и варианты active и archived неизменяемы, published_at сохраняется. Группы типа и связи профессий редактируются независимо от статуса версии. Копирование любой версии создаёт новый draft с published_at=null и собственными ID вопросов и вариантов; группы типа и связи профессий общие. Повтор /publish для active и /archive для archived идемпотентен; archived не публикуется повторно, draft не архивируется.

## TestGroup — группа результата

Таблица `profstart_test_groups`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_code_type` | string | FK → TestType.code; тип теста |
| `code` | string | Код группы; уникален внутри типа теста |
| `name` | string | Название |
| `description` | text | Описание |
| `category` | string | subject, labor, riasec, geometry, general |

У группы нет собственного черновика, статуса или публикации. Она общая для всех версий одного типа. Уникальность (test_code_type, code); точный набор 7/6/5 проверяется при публикации трёх поддерживаемых типов. У новых типов состав задаётся CMS. Группы не заменяют Direction. Одна группа Соломина используется на обеих осях.

Группы и связи профессий можно менять без копирования версии, включая наличие active/archived. Основные группы solomin/holland/dellinger нельзя удалять или менять их code/category (409); добавление кода вне набора методики или неверной категории отклоняется с 422. У дополнительных типов для новых групп категория по умолчанию general. Код используемой группы защищён от изменения (409), а category можно менять независимо от статуса теста; изменения учитываются только в новых результатах. Подписи и связи профессий доступны для редактирования. Группы выводятся по id. Дубликат code внутри типа — 409. Изменения учитываются при сохранении новых результатов; исторические баллы, названия и рекомендации остаются прежними. Удаление связанной с вариантами, результатами или профессиями группы — 409.

## TestQuestion — вопрос

Таблица `profstart_test_questions`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_id` | integer (int64) | FK → ProfStartTest (версия теста) |
| `type` | string | Только single_choice |
| `axis` | string | Блок вопроса: want, can, general; в результате Соломина блоки объединяются |
| `text` | text | Текст |
| `media_id` | integer (int64), nullable | Внутренний ID файла, FK → File; в API объект file; null при отсутствии медиа |
| `order` | integer | Положительный порядок, уникальный внутри теста |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата изменения |

Файл загружается при создании/изменении вопроса через multipart/form-data: file, необязательные file_preview, file_title и file_description. API не принимает media_id и возвращает объект file с url/preview_url и метаданными; без вложения file=null. Аналогичный формат применяется к вариантам. [Файлы](files.md).

У вопроса нет собственного черновика, статуса или публикации. Во всех тестах пользователь выбирает один вариант; различаются подписи, количество и изображения. Все вопросы обязательны, набор и порядок фиксированы. Возрастная доступность задаётся тесту.

## TestAnswerOption — вариант ответа

Таблица `profstart_test_answer_options`. Группа и value хранятся непосредственно в варианте. Балл ответа равен value, если оно задано, иначе 1; нулевое значение даёт 0 баллов.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `question_id` | integer (int64) | FK → TestQuestion |
| `text` | text | Подпись варианта, в том числе подпись изображения |
| `media_id` | integer (int64), nullable | Внутренний ID файла, FK → File; в API объект file; null при отсутствии медиа; изображение обязательно для фигур |
| `value` | integer, nullable | Значение шкалы Соломина: 0, 1, 2, 3; у Голланда/Деллингер null |
| `order` | integer | Порядок, уникальный внутри вопроса |
| `group_id` | integer (int64) | FK → TestGroup того же типа теста |

Каждый вариант связан с одной группой. Блок вопроса определяется TestQuestion.axis, отдельно в варианте не дублируется. Ответы want и can суммируются в одном показателе группы. У предзаданных типов в вопросе 4/6/5 вариантов. Соломин: 42 вопроса (7 групп × 3 вопроса × 2 оси), общий максимум 18 на группу. Голланд: ровно 15 вопросов, максимум 15 на тип. Деллингер: один вопрос. Ноль — полноценный выбранный ответ; несвязанным группам начисляется нулевой вклад. Правильных ответов нет.

## TestGroupProfession — связь с профессией

Таблица `profstart_test_group_professions`, многие-ко-многим с существующей Profession.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `test_code_type` | string | Код типа; часть составного FK → TestGroup.test_code_type |
| `group_code` | string | Код группы; часть составного FK → TestGroup.code |
| `profession_id` | integer (int64) | FK → Profession |

Составной FK (test_code_type, group_code) с ON UPDATE CASCADE и ON DELETE CASCADE. При допустимой смене кода группы дополнительного типа связь сохраняется. Уникальность (test_code_type, group_code, profession_id). Для включения профессии в источник рекомендаций Соломина необходимы subject- и labor-группы того же типа. Неполная пара исключает профессию из новых рекомендаций и не мешает завершить начатую сессию; баллы групп и исторические результаты сохраняются. CMS /validate и /publish проверяют полноту пар. У геометрического теста связь может быть задана для любой фигуры. [Формула рекомендаций](../subsystems/profstart/results.md).

При копировании создаются новые ID вопросов и вариантов; question_id переназначается на копию, group_id остаётся прежним. Группы и связи профессий общие для всех версий типа. Ссылки на существующие Profession и File сохраняются.

Вопросы и варианты редактируются только у draft; для изменения их active/archived копируется тест. Группы типа и связи профессий редактируются независимо от статуса версии, без отдельного жизненного цикла.

## TestSession — прохождение и результат

Таблица `profstart_test_sessions`. Возрастная группа в сессии не хранится; age_group_ids версии используется только для фильтрации каталога. Завершённая сессия хранит метаданные результата и ссылку на неизменяемый источник показателей групп и профессий любого типа.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор сессии, PK |
| `test_id` | integer (int64) | FK → ProfStartTest, закреплённая версия теста |
| `user_id` | integer (int64) | FK → User, включая гостя |
| `test_code_type` | string | Снимок кода типа теста |
| `test_version` | integer | Снимок номера версии теста |
| `question_count` | integer | Число вопросов закреплённой версии |
| `answered_count` | integer | Число принятых уникальных ответов; обновляется вместе с ответом |
| `recommendation_source_id` | integer (int64), nullable | Уникальный FK → UserRecommendationSource; заполняется при завершении любого типа |
| `status` | integer (int32) | TestSessionStatus: 1 — in_progress, 2 — completed, 3 — abandoned |
| `started_at` | timestamp | Время начала прохождения |
| `completed_at` | timestamp, nullable | Время успешного завершения; null у in_progress и abandoned |
| `created_at` | timestamp | Дата создания сессии |
| `updated_at` | timestamp | Дата изменения сессии |

У completed обязателен полный набор ответов и completed_at. У каждого завершённого типа есть источник показателей групп и профессий. У in_progress/abandoned источник отсутствует. Для закрытой сессии next_question_id=null. Последний ответ, источник с показателями и перевод в completed сохраняются одной транзакцией; ошибка откатывает всё.

Частичный уникальный индекс user_id WHERE status=1 допускает только одну in_progress среди всех типов и версий, включая архивные. Старт и ответ также блокируют строку пользователя, чтобы сериализовать конкурентные запросы. Новый старт при наличии in_progress — 409.

Частичный уникальный индекс (user_id, test_code_type) WHERE status=2 допускает только одно завершение типа, независимо от версии. На abandoned индекс не распространяется: прерванную попытку можно повторить. Повторный старт завершённого типа — 409. Индекс (user_id, completed_at, id) поддерживает историю результатов.

Список своих сессий доступен через GET /profstart/me/sessions с фильтром status и пагинацией; текущая in_progress — через GET /profstart/me/sessions/active (null, если отсутствует). GET /profstart/question выдаёт только следующий неотвеченный вопрос, POST /profstart/answer сохраняет ответ. Оба маршрута выбирают собственную in_progress без ID сессии; при её отсутствии — 409. Чтение не меняет прогресс.

Операторский контур CMS получает сессии через GET /cms/profstart/sessions с фильтрами user_id/status и пагинацией. POST /cms/profstart/sessions/{session_id}/abandon сохраняет ответы и переводит in_progress в abandoned; повтор для abandoned допустим, completed — 409.

GET /profstart/sessions/{id}/result возвращает показатели завершённой сессии. История /profstart/me/results содержит только completed и сортируется по completed_at. В API результата created_at соответствует completed_at сессии; отдельного ID результата нет, используется session_id. Название теста читается по test_id; архивная карточка доступна владельцу существующей сессии.

## TestAnswer — ответ пользователя

Таблица `profstart_test_answers`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор, PK |
| `session_id` | integer (int64) | FK → TestSession |
| `question_id` | integer (int64) | FK → TestQuestion |
| `answer_option_id` | integer (int64) | FK → TestAnswerOption |
| `answered_at` | timestamp | Время записи |

Уникальность (session_id, question_id). Пока сессия in_progress, повтор того же варианта не начисляет баллы повторно; другой вариант уже отвеченного вопроса — 409. Принадлежность вопроса и варианта текущей версии проверяется сервером. После completed/abandoned и при отсутствии in_progress повтор ответа возвращает 409.

При записи ответа question_id необязателен в API: отсутствие или null выбирает первый неотвеченный вопрос. В БД question_id остаётся обязательным FK и сохраняется вместе с вариантом. Повтор уже принятого варианта без question_id возвращает сохранённый ответ без повторного продвижения.

## Показатели групп результата

Показатели всех типов хранятся в `user_recommendation_sources.group_scores`; сессия ссылается на источник через `recommendation_source_id`. Источник также содержит полный снимок соответствия профессиям в profession_scores. Итоговый рейтинг использует только источники с положительным весом в SOURCE_WEIGHTS; остальные сохраняются для истории.

| Поле | Тип | Описание |
|---|---|---|
| `group_id` | integer (int64) | Снимок ID TestGroup того же типа теста |
| `group_code` | string | Снимок кода группы |
| `group_name` | string | Снимок названия группы |
| `category` | string | Снимок категории группы: subject, labor, riasec, geometry, general |
| `raw_score` | decimal | Сумма баллов выбранных вариантов |
| `max_score` | decimal | Достижимый максимум по группе: Соломин 18, Голланд 15, Деллингер 1 |
| `normalized_score` | decimal | Показатель 0–100, округлённый до двух знаков |
| `rank` | integer | Место внутри категории |
| `is_leading` | boolean | Признак положительного максимума в категории |

Сервис сохраняет одну запись на group_id в массиве. У дополнительных типов raw_score — сумма value выбранных вариантов (null означает 1); max_score — сумма максимальных вкладов вопросов. При max_score=0 normalized_score=0. rank и is_leading определяются внутри категории, как у встроенных типов. Все показатели, включая нулевые, сохраняются: 7/6/5. У Соломина raw_score группы — сумма значений ответов из обоих блоков want и can; отдельные показатели блоков не хранятся. Поле axis в показателях отсутствует.

## Общий подбор профессий

Общий профиль хранится в `user_recommendations` и связан с User. Завершение любого типа добавляет неизменяемый источник с показателями групп и профессий. Итоговый подбор использует только источники с положительным весом в SOURCE_WEIGHTS. До трёх общих рекомендаций рассчитываются при запросе без сохранения; веса заданы в коде. Показатели групп находятся в JSON источника. Показатели отдельных тестов остаются историческими; рекомендации возвращаются только общим подбором. [Сущности общего профиля](user-recommendations.md). [Правила расчёта](../subsystems/profstart/results.md#общий-подбор-по-трём-тестам).
