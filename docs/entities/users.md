# Пользователи и гостевые сессии

Описание сущностей для работы с сотрудниками системы, пользователями платформы и гостевыми сессиями.

---

## StaffUser (Сотрудник системы)

Учётная запись сотрудника системы администрирования (CMS). Используется для управления доступом к функционалу платформы.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Уникальный идентификатор сотрудника |
| `first_name` | string | Имя |
| `last_name` | string | Фамилия |
| `email` | string | Email для входа и уведомлений |
| `password_hash` | string | Хеш пароля |
| `role` | enum | Роль: `admin`, `operator`, `analyst`, `content_editor` |
| `status` | enum | Статус: `active`, `blocked` |
| `last_login_at` | timestamp, nullable | Дата последнего входа |
| `created_at` | timestamp | Дата создания учётной записи |
| `updated_at` | timestamp | Дата последнего обновления |

### Роли

| Роль | Код | Права |
|------|-----|-------|
| Администратор | `admin` | Полный доступ ко всем разделам, управление сотрудниками |
| Оператор | `operator` | Управление сценариями на планшете LED |
| Аналитик | `analyst` | Просмотр аналитики и отчётов |
| Контент-редактор | `content_editor` | Управление контентом в CMS (справочники, вопросы, шаблоны, аватары, видеосценарии) |

### Связи

- **StaffUser** — независимая сущность, не связана с данными пользователей платформы

### Где используется

- **CMS** — управление учётными записями сотрудников, назначение ролей
- **Авторизация** — вход в CMS по email и паролю

## User (Пользователь платформы)

Учётная запись пользователя платформы, созданная через OAuth-провайдера (Яндекс ID или VK ID). Это посетители, которые взаимодействуют с ПАК и оставляют данные.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Уникальный идентификатор пользователя |
| `oauth_provider` | enum | Провайдер авторизации: `yandex`, `vk` |
| `oauth_provider_id` | string | ID пользователя у провайдера |
| `email` | string, nullable | Email из OAuth-провайдера |
| `name` | string | Имя из OAuth-провайдера |
| `avatar_url` | string, nullable | URL аватара из OAuth-провайдера |
| `gender` | enum, nullable | Пол: `male`, `female`, `unknown` |
| `birth_date` | date, nullable | Дата рождения из OAuth-провайдера |
| `status` | enum | Статус: `active`, `deactivated`, `deleted` |
| `created_at` | timestamp | Дата создания учётной записи |
| `updated_at` | timestamp | Дата последнего обновления |

### Связи

- **User → GuestSession**: один пользователь может иметь несколько привязанных гостевых сессий (`bound_to_user_id`)
- **User → AnalyticsEvent**: один пользователь может иметь множество событий аналитики (`user_id`)
- **User → SurveyResponse**: один пользователь может иметь множество ответов на анкеты (`user_id`)
- **User → ConsentAcceptance**: один пользователь может иметь несколько записей о принятии согласий (разные версии)

### Где используется

- **Идентификация и регистрация** — основная сущность для аутентификации через OAuth
- **Цифровой профиль** — агрегация данных пользователя
- **LED-медиаплатформа** — привязка результатов сессий к пользователю
- **ПрофСтарт** — привязка результатов теста к пользователю
- **Обратная связь** — привязка ответов на анкеты к пользователю
- **Аналитика** — привязка событий к пользователю, управление учётной записью (деактивация/удаление)

## GuestSession (Гостевая сессия)

Временная сессия для неавторизованного пользователя. Создаётся при сканировании QR-кода на терминале. Может быть позже привязана к учётной записи пользователя.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Уникальный идентификатор сессии |
| `guest_id` | string | Уникальный идентификатор гостя (генерируется терминалом) |
| `created_at` | timestamp | Дата создания сессии |
| `expires_at` | timestamp | Дата истечения сессии (по умолчанию 24 часа) |
| `bound_to_user_id` | UUID, nullable | ID пользователя, если сессия привязана |

### Связи

- **GuestSession → User**: гостевая сессия может быть привязана к пользователю (`bound_to_user_id`)
- **GuestSession → AnalyticsEvent**: гостевая сессия может иметь множество событий аналитики (`guest_id`)
- **GuestSession → SurveyResponse**: гостевая сессия может иметь множество ответов на анкеты (`guest_id`)

### Где используется

- **Идентификация и регистрация** — временная идентификация без авторизации
- **LED-медиаплатформа** — участие в сценариях без авторизации
- **Обратная связь** — прохождение анкет без авторизации
- **Аналитика** — привязка событий к гостевой сессии

### Примечания

- Гостевая сессия живёт 24 часа
- Может быть привязана к пользователю после авторизации (все результаты переходят в профиль)
- Если сессия не привязана, результаты остаются привязанными к `guest_id`
