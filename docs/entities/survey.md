# Анкеты

Описание сущностей для конструктора анкет обратной связи.

---

## Survey (Анкета)

Анкета для сбора обратной связи. Настраивается в CMS. Устройство загружает активную версию нужного типа `type`.

Версионирование реализуется через копирование: администратор создаёт новую анкету на базе существующей (кнопка «Создать новую версию»), старую деактивирует. Таким образом, каждая версия — это отдельная анкета со своим ID, но с тем же `type`.

### Жизненный цикл

1. **Создание** — анкета в статусе черновика (`is_active = false`), можно редактировать вопросы, текст, порядок
2. **Публикация** — анкета становится активной (`is_active = true`), доступна для прохождения на устройствах
3. **Изменение** — если нужно изменить опубликованную анкету:
   - Создать новую версию (копирование текущей активной)
   - Новая версия создаётся как черновик (`is_active = false`)
   - Редактировать новую версию
   - Опубликовать новую версию (`is_active = true`) → старая автоматически деактивируется

### Что происходит при смене версии

Если пользователь начал проходить анкету v1, но в этот момент администратор опубликовал v2:
- Пользователь завершает прохождение по v1
- Ответ (`SurveyResponse`) привязывается к `survey_id` версии v1
- Новая версия v2 не затрагивает текущие прохождения

**Техническая реализация:** устройство при загрузке анкеты получает конкретный `survey_id` (не только `type`), все ответы привязываются к этому `survey_id`.

**Ограничение:** не может быть двух активных анкет с одинаковым `type`.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор анкеты |
| `type` | integer (IntEnum) | общий для версий анкеты |
| `name` | string | Название (например, «Оценка видеорезюме», «Оценка мероприятия») |
| `description` | text, nullable | Описание анкеты |
| `is_active` | boolean | Активна ли анкета (деактивированная не показывается в точках сбора) |
| `copied_from_id` | integer (int64), nullable | ID анкеты, от которой эта была скопирована (для отслеживания версий) |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата обновления |

### Связи

- **Survey → SurveyQuestion**: анкета имеет множество вопросов
- **Survey → SurveyResponse**: анкета имеет множество ответов пользователей

### Где используется

- **CMS** — создание, копирование, деактивация анкет
- **Обратная связь** — устройство подхватывает анкету по типу `type`
- **Личный кабинет** — прохождение анкет пользователями

## SurveyQuestion (Вопрос анкеты)

Вопрос в анкете обратной связи.

### Атрибуты

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64, автоинкремент) | Уникальный идентификатор вопроса |
| `survey_id` | integer (int64) | ID анкеты |
| `parent_id` | integer (int64), nullable | ID родительского вопроса, к которому привязан условный вопрос |
| `type` | integer (IntEnum) | `1 — RATING_SCALE`, `2 — SINGLE_CHOICE`, `3 — MULTIPLE_CHOICE`, `4 — TEXT`, `5 — PROFESSION_CHOICE` |
| `text` | text | Текст вопроса |
| `media_id` | integer (int64), nullable | ID файла (изображение) |
| `required` | boolean | Обязательный ли вопрос |
| `order` | integer | Порядок отображения |
| `condition` | json, nullable | Условие показа (например, `{"operator": "lte", "value": 2}`) |
| `scale_min` | integer, nullable | Минимальное значение шкалы (по умолчанию 1) |
| `scale_max` | integer, nullable | Максимальное значение шкалы (по умолчанию 5) |

### Связи

- **SurveyQuestion → Survey**: вопрос принадлежит одной анкете (`survey_id`)
- **SurveyQuestion → File**: вопрос может иметь медиа-файл (`media_id`)
- **SurveyQuestion → SurveyAnswer**: вопрос имеет множество ответов пользователей

### Где используется

- **CMS** — создание вопросов для анкет
- **Обратная связь** — показ вопросов в точках сбора


## Файлы в API

Файлы загружаются в multipart-запросе, а ответы возвращают универсальный объект
с URL, MIME-типом, названием и описанием. Формат и поля загрузки описаны в
[контракте файлов](files.md#загрузка-и-ответ-api).


## SurveyAnswerOption (Вариант ответа)

Таблица `survey_answer_options` хранит варианты для SINGLE_CHOICE, MULTIPLE_CHOICE
и PROFESSION_CHOICE. TEXT не имеет вариантов. Для RATING_SCALE используются
только scale_min и scale_max (по умолчанию 1–5).

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer (int64) | ID варианта, передаваемый в ответах |
| `question_id` | integer (int64) | Вопрос; при его удалении удаляются варианты |
| `text` | text | Подпись варианта |
| `order` | integer | Положительный порядок, уникальный внутри вопроса |
| `profession_id` | integer (int64), nullable | FK на professions.id; обязателен для PROFESSION_CHOICE и недопустим для других типов |

Одна профессия не повторяется внутри вопроса. API возвращает варианты в `questions[].options`,
отсортированными по order и id. Копирование анкеты создаёт новые ID вопросов и вариантов,
сохраняет profession_id и связывает parent_id с новыми вопросами. Если родительский
вопрос содержит варианты, числовые ID в condition.value (один ID или массив)
заменяются на ID новых вариантов. Числовые пороги шкалы сохраняются.

Управление: `GET/POST /api/cms/surveys/{survey_id}/questions/{question_id}/options`,
`PUT/DELETE .../options/{option_id}`. POST и PUT принимают JSON с text, order и
profession_id (для обычного выбора null). Чтение доступно редактору или аналитику,
изменения — редактору. У активных анкет и версий с начатыми или завершёнными
прохождениями вопросы и варианты не изменяются; создайте новую версию.
Вопрос с выбором без вариантов нельзя опубликовать.

Миграция 0060 заменяет surveys.external_id на числовой type=1, сохраняет ID анкет
и прохождений и создаёт уникальность активного типа. Если активных анкет больше
одной, миграция останавливается для явного распределения по типам. Миграция 0061
создаёт таблицу вариантов. Старые символьные идентификаторы сохраняются только
в резервной копии, они больше не используются в API.


## Вопрос и варианты одним запросом

`POST /api/cms/surveys/{survey_id}/questions` и
`PUT /api/cms/surveys/{survey_id}/questions/{question_id}` принимают
`answer_options` — JSON-массив в отдельном текстовом поле multipart/form-data,
как при создании вопроса викторины. Остальные поля вопроса и файл передаются
отдельными частями той же формы. Медиа у вариантов анкеты нет.

Пример значения поля при создании:

```json
[{"text":"Да","order":1},{"text":"Нет","order":2}]
```

Для PROFESSION_CHOICE каждый элемент дополнительно содержит profession_id
из справочника профессий. Для TEXT и RATING_SCALE список не передаётся или пуст;
попытка добавить варианты этим типам даёт 422.

При PUT переданный список задаёт полный состав вариантов:

- Элемент с id обновляет существующий вариант своего вопроса, сохраняя ID.
- Элемент без id создаёт новый вариант. Старые варианты, которых нет в списке, удаляются.
- Без поля answer_options варианты сохраняются. `[]` очищает список.
- text и order обязательны в каждом элементе. order уникален внутри вопроса.

```json
[{"id":101,"text":"Да","order":2},{"text":"Новый вариант","order":1}]
```

Изменения вопроса и вариантов сохраняются одной транзакцией; ошибка отменяет
запрос целиком. Перестановка order и замена профессий поддерживаются в одном
запросе. Ограничения активной анкеты и версии с прохождениями сохраняются.
В ответах API список по-прежнему называется options; его id используются в
ответах посетителей и условиях показа. Отдельный CRUD вариантов также доступен.
