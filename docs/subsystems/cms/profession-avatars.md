# Аватары профессий

Управление эталонными образами профессий для ПАК «Аватар профессий». Для каждой профессии загружаются два эталонных изображения — мужской и женский образ. Эти шаблоны используются для генерации аватаров посетителей в образах профессий.

Чтение списка и карточки требует действующий токен пользователя, сотрудника или активного устройства. Создание, замена и удаление доступны admin/content_editor через staff access-токен. Проверки авторизации не меняют загрузку и обработку файлов.

---

## Режимы

- **Список** — таблица: профессия, мужское фото, женское фото
- **Карточка** — загрузка и замена эталонных изображений для профессии

---

## Карточка профессии (раздел аватаров)

Карточка выводит атрибуты сущности [Profession](../../entities/professions.md) и связанные аватары.

Для сохранения записи необходимо загрузить оба пола (мужское и женское фото).

| Поле | Тип | Обязательное | Описание |
|------|-----|:---:|----------|
| Профессия | → [Profession] | да | Профессия из справочника (выбирается из списка) |
| Мужское фото | → File | да | Эталонное изображение мужчины в образе профессии |
| Женское фото | → File | да | Эталонное изображение женщины в образе профессии |

## Файлы в API

Файлы загружаются в multipart-запросе, а ответы возвращают универсальный объект
с URL, MIME-типом, названием и описанием. Формат и поля загрузки описаны в
[контракте файлов](../../entities/files.md#загрузка-и-ответ-api).

### Превью эталонных образов

Для мужского и женского образа должна быть предусмотрена загрузка отдельной
картинки-превью вместе с соответствующим эталонным изображением. Превью используется
для предварительного просмотра образа в интерфейсах; исходное изображение сохраняется
для генерации аватара пользователя.

API создания и обновления эталонных образов принимает необязательные
`male_file_preview` и `female_file_preview` отдельно для каждого изображения.
При обновлении превью передаётся вместе с соответствующим новым исходником;
превью без него возвращает `422`. У исходников проверяются MIME-тип, сигнатура JPEG/PNG и размер файла, без декодирования. В ответах ссылки на них возвращаются в
`male_file.preview_url` и `female_file.preview_url` по общему контракту файлов.

**Статус:** реализовано. Автоматическое создание превью изображений не выполняется;
без отдельной загрузки `preview_url` равен `null`.
