# Викторина

Управление контентом викторин на LED-платформе: банк вопросов и шаблоны сценариев для командной игры.

---

## Вопросы

Управление банком вопросов для индивидуальной викторины и командной игры. Одна и та же сущность вопроса используется в обоих сценариях; конкретный набор вопросов каждой сессии определяется шаблоном или переданными оператором `question_id`, либо выбором по фильтрам.

### Режимы

- **Список** — таблица: текст вопроса, тип, сложность, возрастная группа, тип раунда, баллы; фильтрация по типу, сложности, возрастной группе, типу раунда
- **Карточка** — создание / редактирование вопроса с вариантами ответов

### Действия

| Действие | Описание |
|----------|----------|
| Создать | Новый вопрос с вариантами ответов |
| Редактировать | Изменить текст, тип, параметры, варианты ответов |
| Удалить | Удаление вопроса |

### Карточка вопроса

Карточка выводит атрибуты сущности [GameQuestion](../../entities/quiz.md#gamequestion): текст вопроса, тип, сложность, возрастная группа, время на ответ, баллы, методическое пояснение, тип раунда, медиа-файл.

- **Тип вопроса** — из [справочника типов вопросов](../../references/quiz-question-types.md)
- **Возрастная группа** — из [справочника возрастных групп](../../references/profstart-age-groups.md)

### Варианты ответов

Каждый вопрос содержит варианты ответов — сущность [GameAnswerOption](../../entities/quiz.md#gameansweroption).

## Шаблоны сценариев {#scenario-templates}

Управление шаблонами для индивидуальной викторины и командной игры. Шаблон сценария — это заранее подготовленный набор раундов с конкретными вопросами, привязанными к определённой тематике или направлению.

Шаблон хранит подготовленные типы раундов и конкретные вопросы; модель шаблона описана в [сущностях](../../entities/scenario-template.md#scenariotemplate). Порядок выбора шаблона и ручной настройки показан в [интерфейсе оператора](../../interfaces/operator-tablet/team-game-setup.md), формат создаваемой сессии — в [GameSession](../../entities/game-session.md#gamesession).

### Режимы

- **Список** — таблица: название шаблона, количество раундов, количество вопросов, статус; фильтрация по статусу
- **Карточка** — создание / редактирование шаблона с раундами и вопросами

### Действия

| Действие | Описание |
|----------|----------|
| Создать | Новый шаблон сценария |
| Редактировать | Изменить название, описание, раунды и вопросы |
| Опубликовать | Перевести из черновика в опубликованный (доступен оператору) |
| В черновик | Вернуть из опубликованного в черновик |
| Удалить | Удаление шаблона не меняет состав уже созданных сессий |

### Карточка шаблона

Карточка выводит атрибуты сущности [ScenarioTemplate](../../entities/scenario-template.md#scenariotemplate): название, описание, статус.

### Структура шаблона

Структура раундов и связей с вопросами описана для [ScenarioTemplateRound](../../entities/scenario-template.md#scenariotemplateround) и [ScenarioTemplateRoundQuestion](../../entities/scenario-template.md#scenariotemplateroundquestion); типы раундов берутся из [справочника](../../references/scenario-round-types.md).

### Работа с вопросами в раунде

Для каждого раунда администратор выбирает конкретные вопросы из банка вопросов. Доступны фильтры:

- Тип вопроса (из [справочника](../../references/quiz-question-types.md))
- Сложность (из [справочника](../../references/quiz-difficulty.md))
- Возрастная группа (из [справочника](../../references/profstart-age-groups.md))
- Тип раунда (из [справочника](../../references/scenario-round-types.md))

Вопросы можно перетаскивать для изменения порядка. Можно добавить любое количество вопросов — сессия использует только указанные `question_id`. Вопрос нельзя редактировать или удалить, пока он используется в незавершённой сессии (status `1` — waiting или `2` — active); изменения шаблона применяются только к будущим сессиям.

### Пример шаблона

**Шаблон: «IT-направление»**

| Порядок | Тип раунда | Вопросы |
|---------|-----------|---------|
| 1 | 1 (`quick_start`) | 5 вопросов на узнавание IT-профессий |
| 2 | 2 (`tools`) | 4 вопроса об инструментах разработчика, сисадмина, тестировщика |
| 3 | 3 (`skills`) | 4 вопроса о навыках и компетенциях в IT |
| 4 | 4 (`situation`) | 2 ситуационных кейса из IT-отрасли |
| 5 | 6 (`process`) | 3 вопроса на восстановление процессов (CI/CD, разработка) |
| 6 | 7 (`future`) | 3 вопроса о технологиях будущего |
| 7 | `final` | 1 комплексный финальный кейс |

## Загрузка профориентационного набора

Файл `app/data/quiz/professions_bank.json` содержит 30 текстовых вопросов с четырьмя
вариантами ответа и пояснениями: 20 одиночного выбора (`question_type=1`) и 10
мультивыбора (`question_type=2`). В каждом вопросе мультивыбора есть два или три
правильных варианта. Возрастная группа — 12–14 лет (`age_group=1`).

Два шаблона включают все вопросы без пересечений:

- «Мир профессий: техника и цифровые технологии» — 10 одиночных и 5 мультивыбора.
- «Мир профессий: люди, природа и город» — 10 одиночных и 5 мультивыбора.

В каждом шаблоне три раунда по пять вопросов: «Быстрый старт» (`round_type=1`),
«Инструменты» (`2`), «Навыки» (`3`). Шаблоны загружаются опубликованными (`status=2`)
и доступны оператору. Для одиночного выбора заданы 30 секунд и 100 баллов,
для мультивыбора — 45 секунд и 150 баллов. Файлы и дополнительные медиа не требуются.

Из корня проекта с работающими контейнерами сначала проверьте JSON без подключения к БД:

```sh
docker compose exec -T api python -m app.cli.load_quiz_bank --check
```

Загрузка в базу, указанную в конфигурации контейнера `api`:

```sh
docker compose exec -T api python -m app.cli.load_quiz_bank
```

Для другого JSON используйте `--path /путь/внутри/контейнера.json`.

JSON и Python-загрузчик
находятся в `app/`, поэтому доступны через существующий bind mount API и входят
в образ при сборке. Автоматически при запуске приложения набор не загружается;
миграция не добавляется.

Импорт выполняется одной транзакцией: 30 вопросов, 120 вариантов, 2 шаблона,
6 раундов и 30 связей вопрос/раунд. Повторный запуск с тем же JSON возвращает
`created_questions=0`, `reused_questions=30`, `created_templates=0`,
`reused_templates=2`. Вопросы распознаются по служебному тегу
`quiz-bank:<bank_code>:<key>`, шаблоны — по имени с проверкой содержимого и порядка.
Параллельные запуски импортера сериализуются advisory-блокировкой PostgreSQL.

Если ранее загруженный вопрос или шаблон изменён в CMS, имя занято другим шаблоном
либо найдены неоднозначные дубли, импорт завершается с ошибкой и полностью откатывает
свои новые записи. Существующий контент не удаляется и не перезаписывается.
Коды вопросов и `bank_code` в JSON нужно сохранять при повторной загрузке этого набора.


Вопрос может быть необязательно привязан к одной профессии через `profession_id`
в CMS API. Правильные личные ответы на привязанные вопросы накапливаются в Redis
и переносятся в рекомендации при полном завершении сессии. Ответ капитана не
засчитывается остальным участникам. [Правила учёта](../../entities/user-recommendations.md#источник-ответов-викторины).
