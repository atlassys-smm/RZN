# ПрофСтарт в CMS

CMS управляет каталогом типов, общими группами и связями профессий, версиями тестов, вопросами и вариантами со значениями. [Сущности](../../entities/test.md) · [Методики](../profstart/methods.md) · [API](../../api/profstart.md).

## Типы тестов

Предзаданы solomin, holland и dellinger. Доступны создание, чтение, изменение и удаление типа. PATCH меняет name/description даже при наличии активного теста. Код дополнительного типа можно изменить только без связанных тестов; коды solomin, holland, dellinger фиксированы. Недопустимая смена кода — 409, дубликат — 409. Название не выбирает алгоритм расчёта.

Тип с активным тестом удалить нельзя: 409. Ссылки черновиков и архивных тестов тоже защищены FK: сначала должны отсутствовать связанные тесты; история не удаляется каскадно. Архивирование теста само по себе не удаляет его связь с типом.

Новые типы можно наполнить и активировать в CMS; они доступны в пользовательском каталоге и для прохождения. Результат содержит ответы и показатели заданных групп. Источники с показателями групп и профессий создаются для всех типов. В итоговом рейтинге участвуют только источники с положительным весом в SOURCE_WEIGHTS; по умолчанию это solomin, holland и dellinger.

## Влияние типов на общий подбор

Влияние источников задаётся в `app/models/user_recommendations/weights.py`: Соломин 40%, Голланд 40%, Деллингер 20%. В таблицах весов влияния нет; через CMS они не меняются. Общий рейтинг рассчитывается при GET из снимков источников. При неполном наборе веса доступных источников нормируются; вес 0 отключает влияние источника.

Системные типы solomin, holland и dellinger нельзя удалить.

## Возрастная доступность

Возрастная доступность задаётся `age_group_ids` из GET `/cms/profstart/age-groups`. Справочник содержит name, min_age, max_age; стандартные диапазоны — 12–14 и 15–17 лет включительно. Границы nullable: null означает отсутствие соответствующей границы. ID хранятся в JSON-поле теста, неизвестные или повторяющиеся ID отклоняются с 422. Пустой массив снимает возрастное ограничение; менять его можно только у черновика.

## Статусы теста

Статус теста — integer enum TestStatus: 1 — draft, 2 — active, 3 — archived. Только тест имеет статус публикации. У групп, вопросов, вариантов и связей нет отдельных черновиков, статусов или публикаций.

| Действие с тестом | Поведение |
|---|---|
| Создать | Новый номер версии, status=1 (draft), published_at=null |
| Изменить / удалить | Только draft без сессий |
| Копировать | Любая версия → новый draft со своими ID вопросов и вариантов; группы и связи профессий общие |
| Публиковать | Проверить draft, перевести в active, заполнить published_at; прежний active того же типа перевести в archived |
| Архивировать | active → archived; новых стартов нет |

Не более одного active на test_type_id, включая одновременные публикации. Это обеспечивается транзакцией с блокировкой типа и частичным уникальным индексом (test_type_id) WHERE status=2. На один тип допустимы несколько черновиков и архивных версий; активного теста может не быть. published_at хранит дату первой активации и сохраняется у archived; статус определяется status.

Повтор /publish для active и /archive для archived возвращает прежнюю запись. Публикация archived и архивирование draft — 409; для изменения или повторного выпуска архивной версии используется /copy. Вопросы и варианты active и archived неизменяемы; группы типа и связи профессий редактируются независимо от статуса версии. Начатые сессии и их завершение сохраняются после смены активного теста.

## Группы и профессии

Карточка группы содержит test_code_type (FK на код типа), собственный code, подписи и category. Код уникален внутри типа; список отсортирован по id. Группы общие для всех версий типа и не копируются вместе с тестом. Маршруты: `/cms/profstart/test-types/{test_code_type}/groups` и вложенные ресурсы. Основные группы solomin/holland/dellinger нельзя удалять или менять их code/category: 409. Дополнительный код или неверная категория поддерживаемого типа — 422; дубликат кода внутри типа — 409. У дополнительных типов состав задаётся CMS; категория по умолчанию general. Код используемой группы защищён от изменения (409), категория редактируется для новых результатов. Подписи и связи профессий можно редактировать и при active/archived; они учитываются в новых результатах, история не меняется. Связь с профессией содержит test_code_type, group_code и profession_id; составной FK обновляется каскадно при допустимой смене кода группы дополнительного типа. Повтор связи — 409.

Для каждой профессии Соломина обязательны обе категории, subject и labor. Для фигур связи задаются одинаковым способом.

CMS допускает промежуточное состояние с одной связью subject или labor. /validate возвращает valid=false для неполной пары, а /publish такого черновика — 422. Завершение уже начатой сессии, включая архивную версию, проверяет вопросы, варианты, значения и основные группы, но не полноту связей профессий. Профессии без обеих категорий не включаются в новые рекомендации; полный результат групп сохраняется, сессия завершается штатно. Если подходящих полных пар нет, источник сохраняет profession_scores=[]. Изменение связей не пересчитывает исторические результаты и сохранённые источники общего профиля. Веса влияния типов заданы в коде. Общий рейтинг рассчитывается при каждом GET из сохранённых источников; итог не записывается в БД.

## Вопросы и варианты

Все вопросы имеют type=single_choice, ось, текст, order и при необходимости файл. Создание и PATCH вопросов/вариантов используют multipart/form-data: каждое поле отдельной частью, вложение в file, превью в file_preview; file_title/file_description описывают новый файл. file_preview без нового file — 422. Без нового file при PATCH прежнее вложение и метаданные сохраняются. В ответах возвращается file с подписанными url/preview_url и метаданными или null; media_id остаётся внутренней связью с File и не принимается API. [Загрузка файлов](../../entities/files.md). У Соломина ровно 42 вопроса: по 3 на каждую из 7 групп на каждой оси want/can. У Голланда ровно 15 вопросов с шестью действиями; у Деллингер один вопрос с пятью фигурами.

У варианта непосредственно находятся group_id и value. Создание и PATCH включают группу и значение; блок наследуется от вопроса. Итоги Соломина суммируют want и can по каждой группе. У Соломина четыре варианта с value=0/1/2/3; у Голланда и Деллингера value=null. Балл ответа равен value, если значение задано, иначе 1; value=0 даёт 0 баллов.

Удаление вопроса удаляет варианты. Удаление группы с вариантами, результатами или связями профессий блокируется 409 до удаления ссылок. Вопросы и варианты редактируются только в draft; группы и связи профессий — независимо от статуса версии.

## Проверка публикации

/validate возвращает ошибки состава с кодом, сущностью/ID и полем. /publish повторяет проверки атомарно: группы, оси, количество, single_choice, значения, порядок, изображения, профессии и парные связи Соломина. Общий максимум Соломина — 18 на группу; scale_maxima содержит семь записей без axis; Голланда — 15 на тип.

Полный [банк вопросов](../profstart/questions/index.md) содержит 42 утверждения Соломина, 15 ситуаций Голланда и один вопрос Деллингер с пятью PNG. Он задаёт начальный состав для наполнения CMS. Для новых типов действуют общие проверки целостности, без ключа одной из предзаданных методик; scale_maxima=[] до реализации алгоритма. Проверка готовности относится к тесту целиком.

Для нового типа общая проверка требует хотя бы одну группу, хотя бы один вопрос и не менее двух вариантов на вопрос; положительный уникальный порядок вопросов/вариантов, заполненные обязательные тексты, допустимые оси/категории и ссылки вариантов на группы того же типа. Для трёх поддерживаемых методик действуют точные количества и ключи из описания методик.

## Прохождения пользователей

Оператор получает список через GET `/cms/profstart/sessions` с фильтрами user_id/status и пагинацией limit/offset. Без user_id возвращаются сессии всех пользователей, отсортированные по started_at DESC, id DESC.

POST `/cms/profstart/sessions/{session_id}/abandon` переводит незавершённую сессию в abandoned и сохраняет ответы. Повтор для abandoned допустим; completed — 409, неизвестная сессия — 404. Прерывание освобождает возможность начать новую попытку. Последний ответ и прерывание блокируют пользователя и сессию в одном порядке; успешно завершённое прохождение сохраняется. Отдельная проверка роли оператора в backend CMS отсутствует.
