# ПрофСтарт в CMS

CMS управляет каталогом типов, версиями тестов и их составом: группами, вопросами, вариантами с весами и связями профессий. [Сущности](../../entities/test.md) · [Методики](../profstart/methods.md) · [API](../../api/profstart.md).

## Типы тестов

Предзаданы solomin, holland и dellinger. Доступны создание, чтение, изменение названия/описания и удаление типа. Уникальный code задаётся при создании и неизменяем. Название не выбирает алгоритм расчёта.

Тип с активным тестом удалить нельзя: 409 type_in_use. Ссылки черновиков и архивных тестов тоже защищены FK: сначала должны отсутствовать связанные тесты; история не удаляется каскадно. Архивирование теста само по себе не удаляет его связь с типом. Проверка удаления согласована с конкурентным созданием и активацией тестов.

Итоговый расчёт поддерживает только solomin, holland, dellinger. Новый тип можно наполнить и активировать в CMS, но до появления алгоритма он не входит в пользовательский каталог; прямой старт возвращает 422 unsupported_test_type. Итоги и рекомендации для него не создаются.

## Статусы теста

Только тест имеет status: draft, active, archived. У групп, вопросов, вариантов и связей нет отдельных черновиков, статусов или публикаций.

| Действие с тестом | Поведение |
|---|---|
| Создать | Новый номер версии, status=draft, published_at=null |
| Изменить / удалить | Только draft без сессий |
| Копировать | Любая версия → новый draft со своими ID всего состава |
| Публиковать | Проверить draft, перевести в active, заполнить published_at; прежний active того же типа перевести в archived |
| Архивировать | active → archived; новых стартов нет |

Не более одного active на test_type_id, включая одновременные публикации. Это обеспечивается транзакцией с блокировкой типа и частичным уникальным индексом (test_type_id) WHERE status='active'. На один тип допустимы несколько черновиков и архивных версий; активного теста может не быть. published_at хранит дату первой активации и сохраняется у archived; статус определяется status.

Повтор /publish для active и /archive для archived возвращает прежнюю запись. Публикация archived и архивирование draft — 409; для изменения или повторного выпуска архивной версии используется /copy. Состав active и archived неизменяем. Редактирование и публикация используют общую блокировку теста, чтобы изменение не записалось после активации. Начатые сессии и их завершение сохраняются после смены активного теста.

## Группы и профессии

Карточка группы содержит код, подписи, category и order. Набор 7/6/5 проверяется для трёх предзаданных методик; для новых типов состав задаётся CMS. Связь с профессией содержит profession_id и coefficient. Повтор связи — 409.

Для каждой профессии Соломина обязательны обе категории, subject и labor. Для фигур связи задаются одинаковым способом.

## Вопросы и варианты

Все вопросы имеют type=single_choice, ось, текст, order и при необходимости media_id. У Соломина ровно 42 вопроса: по 3 на каждую из 7 групп на каждой оси want/can. У Голланда ровно 15 вопросов с шестью действиями; у Деллингер один вопрос с пятью фигурами.

У варианта непосредственно находятся group_id и weight. Создание и PATCH включают группу и вес; ось наследуется от вопроса. У Соломина четыре варианта с value=weight=0/1/2/3, у Голланда и Деллингер weight=1. Отдельного ресурса для весов нет.

Удаление вопроса удаляет варианты. Удаление группы с вариантами или связями профессий блокируется 409 до удаления ссылок. Все операции редактирования состава разрешены только для draft.

## Проверка публикации

/validate возвращает ошибки состава с кодом, сущностью/ID и полем. /publish повторяет проверки атомарно: группы, оси, количество, single_choice, веса, порядок, изображения, профессии и парные связи Соломина. Максимум Соломина — 9 на группу/ось; Голланда — 15 на тип.

Пять примеров Голланда в предоставленном документе требуют дополнения до 15 вопросов. Для новых типов действуют общие проверки целостности, без ключа одной из предзаданных методик; scale_maxima=[] до реализации алгоритма. Проверка готовности относится к тесту целиком.

Для нового типа общая проверка требует хотя бы одну группу, хотя бы один вопрос и не менее двух вариантов на вопрос; положительный уникальный порядок вопросов/вариантов, заполненные обязательные тексты, допустимые оси/категории и ссылки внутри той же версии. Для трёх поддерживаемых методик действуют точные количества и ключи из описания методик.
