# ПрофСтарт в CMS

CMS управляет каталогом типов, версиями тестов и их составом: группами, вопросами, вариантами с весами и связями профессий. [Сущности](../../entities/test.md) · [Методики](../profstart/methods.md) · [API](../../api/profstart.md).

## Типы тестов

Предзаданы solomin, holland и dellinger. Доступны создание, чтение, изменение и удаление типа. PATCH меняет name/description даже при наличии активного теста. Код дополнительного типа можно изменить только без связанных тестов; коды solomin, holland, dellinger фиксированы. Недопустимая смена кода — 409, дубликат — 409. Проверка ссылок и смена кода атомарны и согласованы с созданием тестов. Название не выбирает алгоритм расчёта.

Тип с активным тестом удалить нельзя: 409. Ссылки черновиков и архивных тестов тоже защищены FK: сначала должны отсутствовать связанные тесты; история не удаляется каскадно. Архивирование теста само по себе не удаляет его связь с типом. Проверка удаления согласована с конкурентным созданием и активацией тестов.

Итоговый расчёт поддерживает только solomin, holland, dellinger. Новый тип можно наполнить и активировать в CMS, но до появления алгоритма он не входит в пользовательский каталог; прямой старт возвращает 422. Итоги и рекомендации для него не создаются.

## Влияние типов на общий подбор

Влияние на общий подбор задаётся в test_types.recommendation_weight_percent: целый процент 0–100, стандарт solomin=40, holland=40, dellinger=20. Сумма весов поддерживаемых типов — ровно 100; 0 отключает влияние типа, сохраняя возможность отдельного прохождения. У новых типов без алгоритма вес по умолчанию 0 и положительное значение запрещено: 422.

Проценты доступны в карточке и каталоге типов. Перераспределение сохраняется атомарным PUT /cms/profstart/test-types/recommendation-weights с полным набором solomin/holland/dellinger. PATCH одного типа также проверяет итоговую сумму; нарушение — 422. Для переноса процента между типами используется PUT всей тройки. Настройка изменяется и при активных тестах; сохранённые результаты отдельных тестов остаются прежними, общий подбор использует текущие веса. Тип с ненулевым весом удалить нельзя: 409; сначала требуется перераспределить проценты. Изменения и проверка суммы согласованы общей блокировкой конфигурации, включая создание/удаление типов. Конкурентные PUT сохраняют целый набор; смешение значений разных запросов запрещено.

## Статусы теста

Статус теста — integer enum TestStatus: 1 — draft, 2 — active, 3 — archived. Только тест имеет статус публикации. У групп, вопросов, вариантов и связей нет отдельных черновиков, статусов или публикаций.

| Действие с тестом | Поведение |
|---|---|
| Создать | Новый номер версии, status=1 (draft), published_at=null |
| Изменить / удалить | Только draft без сессий |
| Копировать | Любая версия → новый draft со своими ID всего состава |
| Публиковать | Проверить draft, перевести в active, заполнить published_at; прежний active того же типа перевести в archived |
| Архивировать | active → archived; новых стартов нет |

Не более одного active на test_type_id, включая одновременные публикации. Это обеспечивается транзакцией с блокировкой типа и частичным уникальным индексом (test_type_id) WHERE status=2. На один тип допустимы несколько черновиков и архивных версий; активного теста может не быть. published_at хранит дату первой активации и сохраняется у archived; статус определяется status.

Повтор /publish для active и /archive для archived возвращает прежнюю запись. Публикация archived и архивирование draft — 409; для изменения или повторного выпуска архивной версии используется /copy. Состав active и archived неизменяем. Редактирование и публикация используют общую блокировку теста, чтобы изменение не записалось после активации. Начатые сессии и их завершение сохраняются после смены активного теста.

## Группы и профессии

Карточка группы содержит код, подписи, category и order. Набор 7/6/5 проверяется для трёх предзаданных методик; для новых типов состав задаётся CMS. Связь с профессией содержит profession_id и coefficient. Повтор связи — 409.

Для каждой профессии Соломина обязательны обе категории, subject и labor. Для фигур связи задаются одинаковым способом.

## Вопросы и варианты

Все вопросы имеют type=single_choice, ось, текст, order и при необходимости файл. Создание и PATCH вопросов/вариантов используют multipart/form-data: каждое поле отдельной частью, вложение в file, превью в file_preview; file_title/file_description описывают новый файл. file_preview без нового file — 422. Без нового file при PATCH прежнее вложение и метаданные сохраняются. В ответах возвращается file с подписанными url/preview_url и метаданными или null; media_id остаётся внутренней связью с File и не принимается API. [Загрузка файлов](../../entities/files.md). У Соломина ровно 42 вопроса: по 3 на каждую из 7 групп на каждой оси want/can. У Голланда ровно 15 вопросов с шестью действиями; у Деллингер один вопрос с пятью фигурами.

У варианта непосредственно находятся group_id и weight. Создание и PATCH включают группу и вес; блок наследуется от вопроса. Итоги Соломина суммируют want и can по каждой группе. У Соломина четыре варианта с value=weight=0/1/2/3, у Голланда и Деллингер weight=1. Отдельного ресурса для весов нет.

Удаление вопроса удаляет варианты. Удаление группы с вариантами или связями профессий блокируется 409 до удаления ссылок. Все операции редактирования состава разрешены только для draft.

## Проверка публикации

/validate возвращает ошибки состава с кодом, сущностью/ID и полем. /publish повторяет проверки атомарно: группы, оси, количество, single_choice, веса, порядок, изображения, профессии и парные связи Соломина. Общий максимум Соломина — 18 на группу; scale_maxima содержит семь записей без axis; Голланда — 15 на тип.

Полный [банк вопросов](../profstart/questions/index.md) содержит 42 утверждения Соломина, 15 ситуаций Голланда и один вопрос Деллингер с пятью PNG. Он задаёт начальный состав для наполнения CMS. Для новых типов действуют общие проверки целостности, без ключа одной из предзаданных методик; scale_maxima=[] до реализации алгоритма. Проверка готовности относится к тесту целиком.

Для нового типа общая проверка требует хотя бы одну группу, хотя бы один вопрос и не менее двух вариантов на вопрос; положительный уникальный порядок вопросов/вариантов, заполненные обязательные тексты, допустимые оси/категории и ссылки внутри той же версии. Для трёх поддерживаемых методик действуют точные количества и ключи из описания методик.
