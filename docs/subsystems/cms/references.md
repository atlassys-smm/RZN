# Справочники

Базовая справочная информация, от которой зависит весь остальной контент платформы. Справочники используются в викторине, ПрофСтарт, аналитике, цифровом профиле.

---

## Отрасли

Справочник отраслей экономики. Группирует профессии и работодателей.

### Режимы

- **Список** — таблица: название, количество профессий, количество работодателей
- **Карточка** — создание / редактирование

### Действия

| Действие | Описание |
|----------|----------|
| Создать | Новая отрасль |
| Редактировать | Изменить название |
| Удалить | Только если нет привязанных профессий и работодателей |

### Поля карточки

| Поле | Тип | Обязательное | Описание |
|------|-----|:---:|----------|
| Название | string | да | Название отрасли (например, «IT», «Машиностроение») |

---

## Направления

Справочник профессиональных направлений платформы и метаданные профессий. ПрофСтарт рассчитывает показатели по отдельным группам тестов и использует связи TestGroupProfession для рекомендаций; Direction не является шкалой этих тестов. [Модель ПрофСтарт](../../entities/test.md).

В системе предусмотрено 8 направлений:

1. Естественно-научное
2. Инженерно-техническое
3. Информационно-математическое
4. Социально-коммуникативное
5. Гуманитарно-языковое
6. Художественно-творческое
7. Организационно-предпринимательское
8. Практико-производственное

### Режимы

- **Список** — таблица: название, описание, количество профессий
- **Карточка** — создание / редактирование

### Действия

| Действие | Описание |
|----------|----------|
| Создать | Новое направление |
| Редактировать | Изменить название и описание |
| Удалить | Только если нет привязанных профессий |

### Поля карточки

| Поле | Тип | Обязательное | Описание |
|------|-----|:---:|----------|
| Название | string | да | Название направления |
| Описание | text | нет | Описание направления |

---

## Профессии

Справочник профессий. Центральная сущность, связывающая отрасль и направление. Используется в викторине, ПрофСтарт, аватарах профессий, аналитике, цифровом профиле.

### Режимы

- **Список** — таблица: название, отрасль, направление; фильтрация по отрасли и направлению; поиск по названию
- **Карточка** — создание / редактирование

### Действия

| Действие | Описание |
|----------|----------|
| Создать | Новая профессия |
| Редактировать | Изменить поля карточки |
| Копировать | Дубликат профессии (для быстрого создания похожих) |
| Архивировать | Скрыть из активного справочника (профессия остаётся в привязанных записях) |
| Разархивировать | Вернуть из архива |
| Удалить | Только если нет привязанных записей (вопросы, аватары и т.д.) |

### Поля карточки

| Поле | Тип | Обязательное | Описание |
|------|-----|:---:|----------|
| Название | string | да | Название профессии |
| Описание | text | нет | Описание профессии |
| Отрасль | → Industry | да | Отрасль, к которой относится профессия |
| Направление | → Direction | да | Профессиональное направление |

### Режимы

- **Карточка** — создание / редактирование

### Действия

| Действие | Описание |
|----------|----------|
| Создать | Новое учебное заведение |
| Редактировать | Изменить поля карточки |
| Удалить | Если нет привязанных записей |

### Поля карточки

| Поле | Тип | Обязательное | Описание |
|------|-----|:---:|----------|
| Название | string | да | Название учебного заведения |
| Тип | enum | да | `school`, `college`, `university`, `courses`, `other` |
| Адрес | text | нет | Адрес |
| Координаты | json | нет | Широта и долгота для отображения на карте |
| Описание | text | нет | Описание |
| Сайт | string | нет | URL сайта |
| Телефон | string | нет | Контактный телефон |
| Направления подготовки | → Direction[] | нет | Список направлений, по которым ведётся обучение |

## Демо-просмотры для аналитики

Команда выбирает случайные **10 профессий, 10 организаций и 10 направлений
образования** и добавляет каждой записи случайное число просмотров от 1 до 10
через HTTP API. Направления образования — это `EducationProgram`
(`/organizations/education-programs`), для них публикуется
`EDUCATION_PROGRAM_VIEWED`; справочник профессиональных направлений `/directions`
в этом сценарии не используется.

```bash
docker compose exec -T api python -m app.cli.simulate_views
docker compose exec -T api python -m app.cli.simulate_views --seed 42 --report /app/storage/infra/views-run.json
docker compose exec -T api python -m app.cli.simulate_views --count 5
```

Настройки общие с остальными `simulate_*`: `DEMO_ADMIN_LOGIN`,
`DEMO_ADMIN_PASS`, `DEMO_API_URL` (по умолчанию `http://localhost:8000/api`),
`AUTH_ALLOWED_ORIGINS`, `AUTH_CONSENT_CODE`. Администратор читает списки с
пагинацией; после проверки наличия нужного числа записей во всех трёх
справочниках команда создаёт одного гостя с действующим согласием и открывает
карточки с его JWT. Просмотры сотрудников и устройств аналитика не учитывает.
Если записей недостаточно, команда завершается до создания гостя и просмотров;
можно уменьшить `--count` (по умолчанию 10).

`--seed` повторяет выбор записей и числа просмотров при неизменных справочниках.
`--base-url` и `--origin` переопределяют адрес API и Origin.
`--report` сохраняет новый JSON-файл: ID гостя, выбранные записи, плановое и
подтверждённое число просмотров каждой карточки, общий итог и незавершённый
запрос при ошибке. Каталог отчёта должен существовать; файл не перезаписывается
при старте. Сессии авторизации закрываются при выходе.

Каждый повторный успешный GET карточки добавляет отдельное событие с текущим
временем. Повторный запуск **добавляет** просмотры, а не устанавливает общий
счётчик. Запросы автоматически не повторяются: даже при сетевой ошибке событие
могло быть создано. При сбое команда останавливается, сохраняя прогресс.
Код не подключается к БД, Redis или ClickHouse напрямую.

Для появления данных в Metabase должна быть включена и настроена аналитика;
доставка событий асинхронная. Успешный отчёт подтверждает ответы API, а не
завершение доставки в ClickHouse. Выберите период, включающий дату запуска.
