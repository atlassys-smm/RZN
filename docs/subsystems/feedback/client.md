# Клиентская часть

Описание клиентских интерфейсов для прохождения анкет обратной связи.

---

## ПАК

Полноэкранное приложение на сенсорной стойке или ПАК.

### Конфигурация

Анкета зашивается через переменную окружения при деплое терминала:

```bash
SURVEY_TYPE=1
```

При запуске приложение:
1. Читает `SURVEY_TYPE` из env
2. Запрашивает у сервера активную анкету с таким `type`
3. Показывает форму прохождения

### UI/UX

- Один основной вопрос на экран
- Крупные сенсорные элементы
- Прогресс прохождения
- Возврат на предыдущий шаг
- Тайм-аут по умолчанию — **90 секунд**
- После завершения — подтверждение сохранения, очистка данных, возврат в режим ожидания

### Типы вопросов

- `rating_scale` — оценочная шкала (по умолчанию 1–5)
- `single_choice` — выбор одного варианта
- `multiple_choice` — выбор нескольких вариантов
- `text` — текстовое поле (для пожеланий, комментариев)
- `profession_choice` — выбор профессий из справочника

### Условные вопросы

Вопросы могут показываться при определённых условиях. Например:
- Если оценка удобства ≤ 2 → показать вопрос «Что именно неудобно?»
- Если указано затруднение → показать уточняющий вопрос

Условие хранится в поле `condition` (JSON) у `SurveyQuestion`.

## Личный кабинет / QR

Адаптивный веб-интерфейс, доступный:
- В личном кабинете авторизованного пользователя (кнопка «Оставить отзыв»)
- По QR-коду с гостевым или OAuth-входом

### QR-ссылка

QR подключения панели создаётся через `POST /api/device/auth/qr` и содержит одноразовый
код в ссылке на мобильный фронтенд. Телефон выполняет гостевой или OAuth-вход и подтверждает
код через `/device/auth/confirm`. JWT пользователя остаётся на телефоне; ID анкеты определяется
выбранной активной анкетой, а не отдельным JWT в QR.

### Авторизация

- **Авторизованный пользователь** — видит кнопку «Оставить отзыв» в личном кабинете, ответы привязываются к профилю
- **Гость (по QR)** — получает гостевую пользовательскую сессию с обязательным согласием; ответы привязываются к этому User

### UI/UX

Аналогично ПАК, но адаптировано для веб-интерфейса (десктоп + мобильный):
- Один вопрос на экран
- Прогресс прохождения
- Навигация «Назад» / «Далее»
- После завершения — подтверждение, очистка данных

## Маршрут прохождения

Типовой маршрут посетителя (настраивается в анкете):

1. Приглашение оценить сервис и отображение ориентировочного времени прохождения
2. Оценка удобства, понятности и полезности сервиса
3. Условные уточняющие вопросы при низкой оценке или указанном затруднении
4. Выбор интересующих профессий, отраслей или карьерных направлений (необязательно)
5. Необязательное пожелание или комментарий
6. Необязательная контактная заявка с отдельным согласием на обработку персональных данных
7. Подтверждение сохранения, очистка введённых данных и возврат в основное приложение либо режим ожидания

## Источник прохождения

Каждый ответ (`SurveyResponse`) хранит информацию об источнике:

| Поле | Описание |
|------|----------|
| `source_id` | XML_ID устройства (ПАК, веб) |

Это позволяет в аналитике видеть, откуда собраны данные (по конкретному устройству).

## Согласие на обработку ПДн

При отправке анкеты с контактными данными пользователь принимает согласие. В `SurveyResponse` сохраняется `consent_version_id` — идентификатор той версии согласия, которую показал пользователю.

→ [Сущность согласия](../../entities/consent.md)


## Отправка анкеты с устройства

Состав активной анкеты читается по Device JWT с ролью 4. Для отправки
`POST /api/feedback/surveys/{survey_id}/respond` дополнительно требуется
X-Device-Connection-Id из /device/auth/user. Пользователь определяется по Redis-привязке;
проверяется действующая пользовательская сессия. user_id не передаётся в URL.
В теле остаются source_id, duration, consent_version_id и answers; user_id в JSON запрещён.
При отправке с телефона используется User JWT, заголовок подключения не требуется.


## Реальный старт и повторная отправка

Перед первым вопросом вызовите `POST /api/feedback/surveys/{survey_id}/start`:

```json
{"source_id": "feedback-terminal-01"}
```

Сервер создаёт SurveyResponse и возвращает id, survey_id, started_at,
completed_at=NULL. Сохраните id и передайте его в поле response_id запроса
`/respond`; source_id должен остаться тем же. При успешной отправке завершается
та же запись. Повтор respond с тем же id и ответами возвращает прежний результат,
изменённые ответы или источник дают 409. Каждый вызов start создаёт новую
анкету: после получения id не создавайте повторный старт для её отправки.

Для Device JWT сохраняются роль 4 и X-Device-Connection-Id, для User JWT
владелец определяется по токену. user_id и device_id из тела не принимаются.
duration по-прежнему передаётся для совместимости, но при известном started_at
время рассчитывает сервер. Без response_id старые клиенты продолжают сохранять
готовые анкеты и оценки, но без реального старта и защиты от повторной отправки.

При отказе окончание не отправляется; completed_at остаётся NULL. Не создавайте
старт при загрузке конфигурации или чтении анкеты — только когда пользователь
начинает заполнение. События: SURVEY_STARTED=7 и SURVEY_FINISHED=8.


## Тип анкеты и варианты выбора

`SURVEY_TYPE=1` соответствует `SurveyType.QUALITY_ASSESSMENT` — оценке качества.
Получить активную версию: `GET /api/feedback/surveys/1` по Device JWT с ролью 4.
В ответе type — число, id — версия анкеты. В каждом вопросе options содержит
id, question_id, text, order, profession_id; у TEXT и RATING_SCALE массив пуст.

Поле answers[].value остаётся строкой:

| Тип вопроса | Пример value | Смысл |
|------------|--------------|-------|
| RATING_SCALE (1) | `"4"` | Оценка в границах scale_min/max |
| SINGLE_CHOICE (2) | `"12"` | Один ID варианта |
| MULTIPLE_CHOICE (3) | `"[12,13]"` | Непустой массив уникальных ID вариантов |
| TEXT (4) | `"Комментарий"` | Произвольный текст |
| PROFESSION_CHOICE (5) | `"[14,15]"` | ID вариантов с profession_id, не ID профессий |

Используйте ID вариантов из загруженной версии. Сервер отклоняет чужие,
повторяющиеся и неизвестные варианты. Порядок ID при множественном выборе
не влияет на повторную отправку завершённой анкеты с response_id.

Для условия показа по ответу на вопрос выбора condition.value содержит числовой
ID варианта или массив таких ID. При копировании анкеты они заменяются на ID
новых вариантов. Пороговые значения RATING_SCALE при копировании не меняются.
