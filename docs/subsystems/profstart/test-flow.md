# Прохождение тестов

Пользователь выбирает активную версию теста любого типа и проходит весь закреплённый набор. Каждый тип можно завершить один раз, независимо от версии. Прерванную попытку можно начать заново; каждая попытка имеет отдельную TestSession; её успешное завершение и источник показателей образуют результат.

Прохождение, история и рекомендации требуют пользовательский access-токен с действующей серверной сессией. Сотрудник и устройство не могут проходить тест за пользователя или читать его личные данные. Активное устройство может читать справочник возрастов и каталог активных тестов без персонализации; каталог возвращает все активные тесты с session_status последней собственной сессии по типу теста среди всех версий. Необязательный фильтр session_status=1/2/3 выбирает последний статус; без сессий поле равно null. Продолжение архивной версии и доступ к её карточке сохраняются только у владельца начатого прохождения.

Одновременно у пользователя может быть только одно незавершённое прохождение, независимо от типа и версии теста. Пока оно имеет status=1 (in_progress), новый старт возвращает 409. Нужно продолжить текущую сессию либо прервать её через /abandon; после completed или abandoned можно начать следующую. Архивирование версии не освобождает это ограничение.

## Последовательность

1. Приложение на интерактивной панели или личный кабинет устанавливает контекст User через единый сервис идентификации, включая гостя.
2. Читает /profstart/me/sessions/active: при наличии сессии продолжает её, иначе получает справочник /profstart/age-groups и каталог /profstart/tests со всеми активными тестами и session_status последнего прохождения каждого типа независимо от версии; при необходимости передаёт фильтр session_status=1/2/3. Показывает название, инструкцию, число вопросов и доступность по возрасту. Выбранный ID берётся из справочника.
3. Получает карточку выбранного теста и создаёт /profstart/sessions: только test_id. user_id определяется сервером; возрастная группа используется в фильтре каталога и в сессии не хранится.
4. Получает один следующий неотвеченный вопрос через /profstart/question, без внутренних ключей. Сессия in_progress выбирается сервером по пользователю; ID не передаётся. Повтор чтения не продвигает сессию.
5. Отправляет выбранный answer_option_id через /profstart/answer без ID сессии; question_id можно не передавать — сервер выбирает следующий неотвеченный вопрос. После подтверждения запрашивает следующий вопрос через /question.
6. После последнего ответа получает status=2 (completed) в подтверждении /answer: сервер атомарно сохраняет ответ и результат. Клиент получает показатели групп, ответы и до 10 наиболее подходящих рекомендаций профессий этого теста через GET /profstart/sessions/{id}/result. Общий рейтинг по нескольким тестам загружается через /users/me/recommendations.
7. Просматривает /result, список своих сессий /profstart/me/sessions и историю результатов /profstart/me/results. Список сессий включает незавершённые, завершённые и прерванные прохождения; поддерживает status и пагинацию.
8. Получает общий рейтинг, рассчитанный при запросе, через /users/me/recommendations: до трёх профессий, источники и актуальные веса. При неполном наборе интерфейс показывает missing_sources и эффективные веса. До первого сохранённого источника профиль отсутствует: JSON null.

## Правила

Набор и порядок вопросов фиксированы. Уже принятый ответ нельзя изменить.

Выход через /abandon даёт abandoned без итогового результата. При таймауте бездействия киоск отправляет /abandon и очищает экран; таймаут — эксплуатационная настройка клиента. После потери сети запрос повторяется при восстановлении. Автоматический серверный таймаут не входит в этот контракт.

Пока сессия in_progress, повтор того же варианта, включая запрос без question_id, возвращает прежнее подтверждение без начисления и продвижения. При явном question_id другой вариант для отвеченного вопроса или ответ вне последовательности — 409. При автоматическом выборе вариант не из текущего вопроса — 422, без продвижения. Если собственной in_progress нет, /question и /answer возвращают 409, включая повтор ответа после completed/abandoned. Одновременные запросы последнего ответа создают один результат: после завершения второй запрос получает 409. Повтор /abandon — прежний статус; /abandon после completed — 409. В abandoned результат не рассчитывается.

## Восстановление и доступ

После переподключения клиент читает /profstart/me/sessions/active и получает вопрос через /profstart/question. Если активной сессии нет, /active возвращает 200 с JSON null, а /question и /answer — 409. Если подтверждение последнего ответа потерялось, завершённая сессия с её id доступна в /profstart/me/sessions; результат читается по ID этой сессии. Карточка /profstart/sessions/{id} сохраняет доступ к прогрессу и принятым ответам. Новая публикация не меняет текущую версию сессии; для новых стартов выбирается единственный active типа. Архивирование не запрещает продолжение и завершение уже начатой сессии. Дополнительные типы проходят тот же цикл и создают источник с показателями групп и профессий; их участие в итоговом рейтинге определяется SOURCE_WEIGHTS.

На интерактивной панели очищаются ответы и контекст прошлого участника. Гостевой результат принадлежит User и не становится публичным по известному ID. В личном кабинете доступен владельцу; административный просмотр требует права аналитики. QR общего сервиса идентификации не является публичной ссылкой на результат.

[Контракт API](../../api/profstart.md).


## Авторизация интерактивной панели

Посетитель подтверждает QR панели с телефона. Панель получает connection_id через
`/device/auth/user` и передаёт его в X-Device-Connection-Id вместе с Device JWT с ролью 3
в каждом личном запросе ПрофСтарта и `/users/me/recommendations`. User определяется по Redis;
user_id не передаётся. Проверяются актуальность подключения, User и AuthSession.
В каталоге заголовок необязателен; с ним session_status определяется по последней сессии подключённого пользователя и доступна своя
архивная версия. Без заголовка session_status=null; при фильтре session_status=1/2/3 список пуст. Вход по User JWT сохраняется и не требует заголовка подключения.
При новом посетителе фронтенд прекращает прежние действия и не заменяет их connection_id.


## Демонстрационное прохождение через API

Команда запускается внутри сервиса Docker `api`, используя существующие
DEMO_ADMIN_LOGIN, DEMO_ADMIN_PASS и DEMO_API_URL из `.env` окружения контейнера:

```sh
docker compose exec -T api python -m app.cli.simulate_profstart
```

Каждый запуск создаёт одного нового гостя и последовательно проходит все
активные тесты, включая дополнительные типы. Завершённый тип не проходится
повторно тем же гостем. Сначала администратор читает каталог и проверяет
состав вопросов через CMS API; затем все личные запросы выполняются с токеном
гостя. Устройство и QR-подключение не нужны для этого входа по User JWT.
Согласие выбирается автоматически общим клиентом demo-команд.

```sh
docker compose exec -T api python -m app.cli.simulate_profstart --answers random --seed 42 --report /app/storage/infra/profstart-run.json
docker compose exec -T api python -m app.cli.simulate_profstart --test-id 1 --test-id 2 --answers first
docker compose exec -T api python -m app.cli.simulate_profstart --test-code solomin
docker compose exec -T api python -m app.cli.simulate_profstart --test-code solomin,holland,dellinger --seed 42
```

В примере ID тестов следует заменить на активные из своей базы. JSON-отчёт
из `/app/storage/infra/` доступен на хосте в `storage/infra/` проекта;
существующий файл команда не перезаписывает.

| Параметр | Поведение |
|----------|-----------|
| `--test-id` | Пройти только указанный активный тест. Можно повторить для разных типов; порядок переданных ID сохраняется. Без --test-id и --test-code проходят все активные тесты в порядке test_code_type, id. Неактивный или отсутствующий ID не подменяется другим. |
| `--test-code` | Один код или список через запятую из profstart_test_types.code. По каждому коду выбирается единственная активная версия теста; порядок кодов сохраняется. Пробелы вокруг кодов убираются. Не сочетается с --test-id. Неизвестный код, отсутствие активной версии, несколько активных версий или повтор кода приводят к ошибке до создания гостя. |
| `--answers random` | По умолчанию: случайный допустимый вариант каждого вопроса. В профориентационных тестах нет правильных ответов. |
| `--answers first` | Первый вариант по order, id, независимо от порядка элементов в ответе API. |
| `--seed` | Начальное состояние локального генератора случайных ответов. Повторяет выбор при одинаковом составе и порядке тестов, вопросов и вариантов. Гость и сессии каждый раз новые. |
| `--report` | Новый JSON-файл: seed, ID гостя и согласия, выбранные тесты и сессии, принятые ответы, показатели групп, ID профессий, прогресс и ошибка. Пароли и токены не сохраняются. |
| `--base-url`, `--origin` | Как у demo-викторины: адрес из DEMO_API_URL и первый AUTH_ALLOWED_ORIGINS, если параметры не указаны. |

До создания гостя проверяются активность тестов, уникальность типов, число
вопросов и наличие допустимых вариантов. Вопросы читаются через
GET /profstart/question, ответы отправляются через POST /profstart/answer
с явным question_id. Команда проверяет ID сессии, подтверждённый вариант,
счётчики и следующий вопрос. После последнего ответа ожидается completed;
отдельный finish в ПрофСтарте не нужен.

Для каждого теста проверяются сохранённая сессия и GET /profstart/sessions/{id}/result:
все вопросы отвечены, ответы совпадают с отправленными и показатели групп рассчитаны.
В конце проверяются отсутствие активного прохождения, наличие результатов в истории
и собственный профиль GET /users/me/recommendations. is_complete этого профиля может
быть false из-за отсутствующих источников других модулей или при выборе части тестов;
это не мешает успешному прохождению выбранных тестов ПрофСтарта.

При ошибке сохраняется частичный отчёт, автоматического abandon и повторов
HTTP-запросов записи нет. Уже созданные гость, сессии и результаты остаются
в системе. Авторизации команды закрываются при выходе. Код 0 означает полное
прохождение выбранного набора; 1 — ошибку, 2 — ошибку параметров/настроек,
130 — прерывание пользователем.

Независимые проверки обеих demo-команд с HTTP-заглушками, без БД и Redis:

```sh
docker compose exec -T api python -m unittest discover -s tests/cli -v
```
