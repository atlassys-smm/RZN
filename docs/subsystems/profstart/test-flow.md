# Прохождение тестов

Пользователь выбирает активную версию одного из трёх поддерживаемых тестов и проходит весь закреплённый набор. Каждый тест и повтор создают отдельную TestSession; три теста не являются одной сессией.

## Последовательность

1. Киоск или личный кабинет устанавливает контекст User через единый сервис идентификации, включая гостя.
2. Получает /profstart/tests, показывает название, инструкцию, число вопросов и доступность по возрасту.
3. Получает карточку выбранного теста и создаёт /profstart/sessions: test_id и при необходимости age_group_id. user_id определяется сервером.
4. Загружает вопросы версии через /profstart/sessions/{id}/questions, без весов и ключей.
5. Последовательно отправляет выбранный вариант через сохранённый URL /profstart/sessions/{id}/answer; продвигается после подтверждения.
6. После последнего ответа вызывает /complete; сервер проверяет полноту и возвращает сохранённый результат.
7. Просматривает /result и историю /profstart/me/results.

## Правила

Набор и порядок фиксированы. Общего времени «7–12 минут» для всех методик нет. Время на вопрос не ограничивает баллы; time_spent_ms сохраняется для аналитики. Уже принятый ответ нельзя изменить.

Выход через /abandon даёт abandoned без итогового результата. При таймауте бездействия киоск отправляет /abandon и очищает экран; таймаут — эксплуатационная настройка клиента. После потери сети запрос повторяется при восстановлении. Автоматический серверный таймаут не входит в этот контракт.

Повтор того же варианта возвращает прежнее подтверждение без начисления. Другой вариант для отвеченного вопроса, ответ вне последовательности или новая запись в закрытую сессию — 409. Повтор /complete возвращает прежний результат; повтор /abandon — прежний статус. /complete после abandoned и /abandon после completed — 409.

## Восстановление и доступ

После переподключения клиент читает /profstart/sessions/{id} и продолжает с первого неотвеченного вопроса. Новая публикация не меняет текущую версию сессии; для новых стартов выбирается единственный active типа. Архивирование не запрещает продолжение и завершение уже начатой сессии. Для нового типа без алгоритма сервер возвращает 422 unsupported_test_type до создания сессии; итоговый расчёт поддерживает только solomin, holland, dellinger.

На киоске очищаются ответы и контекст прошлого участника. Гостевой результат принадлежит User и не становится публичным по известному ID. В личном кабинете доступен владельцу; административный просмотр требует права аналитики. QR общего сервиса идентификации не является публичной ссылкой на результат.
