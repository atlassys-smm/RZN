# Прохождение тестов

Пользователь выбирает активную версию одного из трёх поддерживаемых тестов и проходит весь закреплённый набор. Каждый тест и повтор создают отдельную TestSession; три теста не являются одной сессией.

Одновременно у пользователя может быть только одно незавершённое прохождение, независимо от типа и версии теста. Пока оно имеет status=1 (in_progress), новый старт возвращает 409. Нужно продолжить текущую сессию либо прервать её через /abandon; после completed или abandoned можно начать следующую. Архивирование версии не освобождает это ограничение.

## Последовательность

1. Киоск или личный кабинет устанавливает контекст User через единый сервис идентификации, включая гостя.
2. Читает /profstart/me/sessions/active: при наличии сессии продолжает её, иначе получает справочник /profstart/age-groups и каталог /profstart/tests. Показывает название, инструкцию, число вопросов и доступность по возрасту. Выбранный ID берётся из справочника.
3. Получает карточку выбранного теста и создаёт /profstart/sessions: test_id и при необходимости age_group_id. user_id определяется сервером.
4. Получает один следующий неотвеченный вопрос через /profstart/question, без весов и ключей. Сессия in_progress выбирается сервером по пользователю; ID не передаётся. Повтор чтения не продвигает сессию.
5. Отправляет выбранный answer_option_id через /profstart/answer без ID сессии; question_id можно не передавать — сервер выбирает следующий неотвеченный вопрос. После подтверждения запрашивает следующий вопрос через /question.
6. После последнего ответа получает status=2 (completed) в подтверждении /answer: сервер атомарно сохраняет ответ и результат. Клиент получает результат через GET /profstart/sessions/{id}/result.
7. Просматривает /result, список своих сессий /profstart/me/sessions и историю результатов /profstart/me/results. Список сессий включает незавершённые, завершённые и прерванные прохождения; поддерживает status и пагинацию.
8. Получает общий подбор через /profstart/me/recommendations: последние завершённые результаты и актуальные веса 40/40/20 либо настройка CMS. При неполном наборе интерфейс показывает missing_test_types и нормированные эффективные веса.

## Правила

Набор и порядок вопросов фиксированы. Уже принятый ответ нельзя изменить.

Выход через /abandon даёт abandoned без итогового результата. При таймауте бездействия киоск отправляет /abandon и очищает экран; таймаут — эксплуатационная настройка клиента. После потери сети запрос повторяется при восстановлении. Автоматический серверный таймаут не входит в этот контракт.

Пока сессия in_progress, повтор того же варианта, включая запрос без question_id, возвращает прежнее подтверждение без начисления и продвижения. При явном question_id другой вариант для отвеченного вопроса или ответ вне последовательности — 409. При автоматическом выборе вариант не из текущего вопроса — 422, без продвижения. Если собственной in_progress нет, /question и /answer возвращают 409, включая повтор ответа после completed/abandoned. Одновременные запросы последнего ответа создают один результат: после завершения второй запрос получает 409. Повтор /abandon — прежний статус; /abandon после completed — 409. В abandoned результат не рассчитывается.

## Восстановление и доступ

После переподключения клиент читает /profstart/me/sessions/active и получает вопрос через /profstart/question. Если активной сессии нет, /active возвращает 200 с JSON null, а /question и /answer — 409. Если подтверждение последнего ответа потерялось, завершённая сессия и её result_id доступны в /profstart/me/sessions; результат читается по ID этой сессии. Карточка /profstart/sessions/{id} сохраняет доступ к прогрессу и принятым ответам. Новая публикация не меняет текущую версию сессии; для новых стартов выбирается единственный active типа. Архивирование не запрещает продолжение и завершение уже начатой сессии. Для нового типа без алгоритма сервер возвращает 422 до создания сессии; итоговый расчёт поддерживает только solomin, holland, dellinger.

На киоске очищаются ответы и контекст прошлого участника. Гостевой результат принадлежит User и не становится публичным по известному ID. В личном кабинете доступен владельцу; административный просмотр требует права аналитики. QR общего сервиса идентификации не является публичной ссылкой на результат.
