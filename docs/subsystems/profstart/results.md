# Расчёт результатов и подбор профессий

Клиент передаёт один выбранный вариант. Вопросы и веса берутся из версии, закреплённой за сессией; группы и связи профессий — из текущей конфигурации её типа по test_code_type. Расчёт реализуется только для кодов solomin, holland и dellinger. Для новых типов без алгоритма итог и рекомендации не создаются: HTTP 422. Пользовательский каталог и старт исключают такие типы.

## Суммы

group_id и weight находятся в TestAnswerOption. TestQuestion.axis обозначает блок вопроса. В результате один показатель на группу; у Соломина веса ответов из want и can суммируются, отдельного axis в показателях и рекомендациях нет.

```text
raw_score(g) = сумма weight выбранных вариантов с group_id=g по всем вопросам
max_score(g) = сумма максимального возможного вклада каждого вопроса в группу g
normalized_score(g) = round_half_up(100 * raw_score(g) / max_score(g), 2)
```

Нормализация — отображение проекта, исходный балл сохраняется. Максимум зависит от полного ключа; для каждой группы он должен быть положительным.

| Тест | Исходная шкала | Полнота |
|---|---|---|
| Соломин | 0–18 по каждой группе | 42 ответа; по 3 want и 3 can на группу, общий показатель |
| Голланд | 0–15 по каждому типу | 15 ответов, сумма шести показателей равна 15 |
| Деллингер | 0 или 1 по каждой фигуре | Один ответ, ровно одна группа имеет 1 |

Неполное прохождение не создаёт итог. /answer после последнего вопроса атомарно сохраняет ответ и результат и переводит прохождение в completed. При ошибке расчёта последний ответ откатывается. Пока собственная сессия имеет status=1 (in_progress), повтор принятого варианта возвращает текущий прогресс без повторного начисления. После completed или abandoned, если собственной in_progress нет, POST /profstart/answer возвращает 409, в том числе при повторе последнего ответа. При одновременных отправках последнего ответа первый запрос завершает сессию, второй получает 409; создаётся один результат. Результат читается отдельным запросом GET /sessions/{id}/result.

## Ведущие группы

rank = 1 + количество групп с большим raw_score внутри категории: например, 1, 1, 3. Все положительные максимумы имеют is_leading=true. Если все значения нулевые, ведущих групп нет.

Соломин: максимумы общих баллов выбираются раздельно в subject и labor. При нулевых общих баллах всех групп любой из этих категорий список профессий пуст. Голланд: все равные максимумы сохраняются.

## Профессии

TestGroupProfession привязан к группе через test_code_type + group_code и содержит profession_id и coefficient (0 < c ≤ 1). Пример разметки: педагог — human_human и creative у Соломина, S у Голланда; бухгалтер — human_sign и executive, C; дизайнер — human_art и creative, A. Это примеры настройки, не автоматический ключ.

### Соломин

Профессия должна быть связана одновременно с ведущим subject и ведущим labor по общим баллам want + can.

```text
subject_contribution = max(round_half_up(normalized_score(g) * coefficient(g,p), 2))
                       среди связанных ведущих subject
labor_contribution   = max(round_half_up(normalized_score(g) * coefficient(g,p), 2))
                       среди связанных ведущих labor
profession_score     = round_half_up((subject_contribution + labor_contribution) / 2, 2)
```

Оба блока одинаково участвуют в сумме группы и подборе профессий. Формула объединения блоков и сочетания категорий — политика проекта.

### Голланд и фигуры

Кандидаты — профессии, связанные с ведущими группами. Балл — максимум round_half_up(normalized_score(g) * coefficient(g,p), 2). Для всех геометрических групп используются заданные CMS связи; отсутствие связи даёт пустой список без специального признака или переключателя.

### Сохранение

Группы и связи профессий общие для всех версий типа по `test_code_type`. Их подписи и коэффициенты можно менять независимо от статуса версии. Последний ответ использует согласованную конфигурацию типа на момент расчёта; изменения не пересчитывают сохранённые баллы и рекомендации. Общий профиль использует неизменяемые снимки источников и текущие веса типов.

Нормализация, вклад normalized_score × coefficient и итог округляются до двух знаков методом ROUND_HALF_UP на Decimal; float для промежуточных вычислений не используется. Например, 33,335 округляется до 33,34. Сначала рассчитывается и округляется итоговый score, затем рекомендации сортируются по нему по убыванию, при равенстве profession_id возрастает. Возвращается весь подходящий список без лимита в тесте; position назначается от 1 после сортировки.

reasons содержит только группы, чьи вклады вошли в итог. У Соломина это одна максимальная subject- и одна labor-группа по общим баллам, в таком порядке; contribution хранится до усреднения, score равен округлённому среднему этих двух вкладов. У Голланда/Деллингер это одна группа максимального вклада, score=contribution. При равенстве вкладов внутри одной категории выбирается наименьший group_id. Все равные ведущие остаются в scores, даже если конкретная рекомендация использует одну из них. Текст пояснения связи не хранится.

Если подходящих связей нет, professions=[]. Публикация требует полных пар каждой профессии Соломина, но не обязательного покрытия каждой комбинации или геометрической группы.

На последнем ответе проверяются структура банка, вопросы, варианты, веса и группы. Профессия Соломина без обеих категорий subject/labor исключается из рекомендаций и не блокирует завершение сессии. Все семь показателей сохраняются в scores; без подходящих полных пар professions=[]. /validate и /publish требуют полных пар. Сохранённые результаты не пересчитываются. Основные коды и категории групп защищены; дополнительные коды поддерживаемых типов запрещены.

## Общий подбор по трём тестам

TestType.recommendation_weight_percent задаёт влияние типа на итоговый рейтинг профессий. Стандарт:

| Тип | Вес |
|---|---|
| solomin | 40% |
| holland | 40% |
| dellinger | 20% |

CMS может менять распределение целыми процентами 0–100; сумма поддерживаемых типов обязана равняться 100. Новые типы без алгоритма имеют вес 0. Нулевой вес исключает тип из общего подбора, но сохраняет отдельные прохождения и результаты. Веса задают политику проекта и не являются оценкой научной точности методик.

### Источники профиля

Каждый тип можно полностью пройти один раз, включая новые версии. Прерванные попытки не создают источник и допускают новый старт. На последнем ответе одна транзакция сохраняет ответ, TestResult, показатели групп в JSON источника, рекомендации отдельного теста и общий профиль пользователя. Ошибка откатывает всю операцию.

Источник `profstart.solomin`, `profstart.holland` или `profstart.dellinger` хранит все показатели групп и полное соответствие профессиям на момент завершения. Для общего профиля учитываются все группы с положительным вкладом, включая неведущие. Применяются те же коэффициенты и выбор максимального вклада внутри категории. Соломину нужны положительные вклады обеих категорий subject/labor; неполные или нулевые пары исключаются. Исторические рекомендации отдельного TestResult по-прежнему используют ведущие группы.

Источники сохраняются также при весе 0. Позднейшее изменение весов может включить их в подбор. Названия, связи, коэффициенты и показатели снимка не меняются при редактировании CMS. Общий профиль хранится в отдельных таблицах и обновляется после нового завершения или изменения весов; GET только читает сохранённый профиль. Незавершённые и abandoned-попытки его не изменяют.

### Формула

Кандидаты — объединение profession_id из полных снимков profession_scores выбранных источников. Каждый тип участвует своим сохранённым score профессии 0–100. Если профессии в результате пройденного теста нет, его test_score=0. Знаменатель одинаков для всех профессий и включает веса всех выбранных результатов, в том числе результатов с пустыми рекомендациями.

```text
available_weight_percent = сумма recommendation_weight_percent выбранных типов
effective_weight_percent(t) = 100 * recommendation_weight_percent(t) / available_weight_percent
combined_score(p) = round_half_up(
    сумма test_score(t,p) * recommendation_weight_percent(t) / available_weight_percent,
    2
)
```

При полном наборе и стандартных весах: combined_score(p)=round_half_up(0.4*S(p)+0.4*H(p)+0.2*D(p),2). Веса ответов и coefficient связи «группа → профессия» уже учтены в score отдельного теста; в общей формуле повторно не применяются.

При неполном наборе используются только завершённые результаты с положительными весами. Например, если пройдены Соломин и Голланд, эффективное влияние каждого равно 50%; если только Соломин — 100%. Непройденный тест исключается из знаменателя, а пройденный тест без данной профессии остаётся в знаменателе с нулевым вкладом. Если результатов нет, ответ 200 содержит available_weight_percent=0, results=[], professions=[], is_complete=false; деления на ноль нет.

is_complete=true, когда получены результаты всех типов с положительным настроенным весом. missing_test_types перечисляет недостающие типы; типы с весом 0 не требуются. Пустой список рекомендаций при завершённых тестах не означает неполное прохождение.

Расчёт выполняется на Decimal с точной дробью веса; общий score округляется только после суммирования. В выдаче effective_weight_percent и contribution каждого теста округлены до двух знаков для отображения, поэтому их отображаемые суммы могут отличаться от точного итога на последнем знаке. При полном наборе score 80/60/100 даёт 76; при пройденных Соломине и Голланде с 80/60 — 70; если у профессии нет рекомендации Голланда при тех же двух пройденных тестах — 40.

### Выдача

Основной маршрут — GET `/users/me/recommendations`: сохранённый профиль или JSON null до первого завершённого теста. Он возвращает id, user_id, created_at, updated_at, is_complete, available_weight, weights, missing_sources, sources и professions. Коды источников содержат префикс модуля, например `profstart.holland`. [Контракт общего профиля](../../api/user-recommendations.md).

Совместимый GET `/profstart/me/recommendations` сохраняет поля calculated_at, is_complete, available_weight_percent, weights, results, missing_test_types и professions. calculated_at соответствует последнему обновлению профиля. Без профиля этот маршрут возвращает пустые results и professions. contributions содержит вклад каждого доступного источника, включая нулевой вклад профессии.

Профессии уникальны; сохраняются только положительные округлённые баллы. Порядок score DESC, profession_id ASC; position от 1. Возвращаются максимум три профессии, без гарантии полного набора и без случайного дополнения. Названия берутся из снимков источников. Пользователь не передаёт user_id, веса или исходные баллы.

## Примеры

- Соломин: ответы 1, 2, 3 в want и 0, 2, 1 в can одной группы дают общий raw_score=9, max_score=18 и normalized_score=50. Один результат группы, отдельные суммы блоков не выдаются.
- Голланд: шесть S из пятнадцати — 6/15 и 40; сумма всех исходных показателей — 15.
- Деллингер: выбран circle — 1/1 и 100 у круга, остальные нулевые; профессии берутся из связей circle.
- Пока сессия in_progress, повтор принятого варианта не меняет сумму. После завершения повтор последнего ответа получает 409; одновременные запросы последнего ответа создают один результат.

Показатели scores идут по id группы, по одной записи на группу: 7 у Соломина, 6 у Голланда, 5 у Деллингер, включая нули. Сервер проверяет точный уникальный набор групп, не только длину массива.

## Интерфейс и история

Соломин показывает семь общих показателей без разделения «Хочу»/«Могу», Голланд — шесть типов, Деллингер — выбранную фигуру. У профессии выводятся связанные группы и показатели. Название теста при необходимости читается из теста по test_id, в результате хранится test_code_type и test_version.

Название архивной версии доступно владельцу через GET /profstart/tests/{test_id}, если у него есть сессия этой версии; этот доступ не разрешает новый старт.

Время скрытия результата — настройка киоск-клиента, не теста. Очистка экрана не удаляет историю. Гостевой результат принадлежит User; после авторизации отдельный перенос не требуется.
