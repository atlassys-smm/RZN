# Расчёт результатов и подбор профессий

Клиент передаёт один выбранный вариант, сервер считает показатели по версии, закреплённой за сессией. Расчёт реализуется только для кодов solomin, holland и dellinger. Для новых типов без алгоритма итог и рекомендации не создаются: unsupported_test_type, HTTP 422. Пользовательский каталог и старт исключают такие типы.

## Суммы

group_id и weight находятся в TestAnswerOption, axis берётся из TestQuestion.

```text
raw_score(g,a) = сумма weight выбранных вариантов с group_id=g и осью вопроса a
max_score(g,a) = сумма максимального возможного вклада каждого вопроса в (g,a)
normalized_score(g,a) = round_half_up(100 * raw_score(g,a) / max_score(g,a), 2)
```

Нормализация — отображение проекта, исходный балл сохраняется. Максимум зависит от полного ключа; для каждой обязательной пары он должен быть положительным.

| Тест | Исходная шкала | Полнота |
|---|---|---|
| Соломин | 0–9 по каждой группе/оси | 42 ответа, want и can независимы |
| Голланд | 0–15 по каждому типу | 15 ответов, сумма шести показателей равна 15 |
| Деллингер | 0 или 1 по каждой фигуре | Один ответ, ровно одна группа имеет 1 |

Неполное прохождение не создаёт итог. /complete проверяет все вопросы и атомарно сохраняет результат; повтор возвращает ту же запись.

## Ведущие группы

rank = 1 + количество групп с большим raw_score внутри категории и оси: например, 1, 1, 3. Все положительные максимумы имеют is_leading=true. Если все значения нулевые, ведущих групп нет.

Соломин: максимумы выбираются раздельно в subject и labor на каждой оси. Несовпадение «Хочу» и «Могу» видно по показателям, отдельный признак не сохраняется. При нулевых want в любой категории список профессий пуст. Голланд: все равные максимумы сохраняются.

## Профессии

TestGroupProfession содержит profession_id и coefficient (0 < c ≤ 1). Пример разметки: педагог — human_human и creative у Соломина, S у Голланда; бухгалтер — human_sign и executive, C; дизайнер — human_art и creative, A. Это примеры настройки, не автоматический ключ.

### Соломин

Профессия должна быть связана одновременно с ведущим subject и ведущим labor оси want.

```text
subject_contribution = max(round_half_up(normalized_score(g,want) * coefficient(g,p), 2))
                       среди связанных ведущих subject
labor_contribution   = max(round_half_up(normalized_score(g,want) * coefficient(g,p), 2))
                       среди связанных ведущих labor
profession_score     = round_half_up((subject_contribution + labor_contribution) / 2, 2)
```

can показывается отдельно и не исключает профессию. Формула сочетания категорий — политика проекта.

### Голланд и фигуры

Кандидаты — профессии, связанные с ведущими группами. Балл — максимум round_half_up(normalized_score(g,general) * coefficient(g,p), 2). Для всех геометрических групп используются заданные CMS связи; отсутствие связи даёт пустой список без специального признака или переключателя.

### Сохранение

Нормализация, вклад normalized_score × coefficient и итог округляются до двух знаков методом ROUND_HALF_UP на Decimal; float для промежуточных вычислений не используется. Например, 33,335 округляется до 33,34. Сначала рассчитывается и округляется итоговый score, затем рекомендации сортируются по нему по убыванию, при равенстве profession_id возрастает. Возвращается весь подходящий список без лимита в тесте; position назначается от 1 после сортировки.

reasons содержит только группы, чьи вклады вошли в итог. У Соломина это одна максимальная subject- и одна labor-группа want, в таком порядке; contribution хранится до усреднения, score равен округлённому среднему этих двух вкладов. У Голланда/Деллингер это одна группа максимального вклада general, score=contribution. При равенстве вкладов внутри одной категории/оси выбирается наименьший group_id. Все равные ведущие остаются в scores, даже если конкретная рекомендация использует одну из них. Текст пояснения связи не хранится.

Если подходящих связей нет, professions=[]. Публикация требует полных пар каждой профессии Соломина, но не обязательного покрытия каждой комбинации или геометрической группы.

## Примеры

- Соломин: 1, 2, 3 в группе want дают 6/9 и 66,67; can независимо.
- Голланд: шесть S из пятнадцати — 6/15 и 40; сумма всех исходных показателей — 15.
- Деллингер: выбран circle — 1/1 и 100 у круга, остальные нулевые; профессии берутся из связей circle.
- Повтор ответа не меняет сумму, повтор /complete не создаёт второй результат.

Показатели scores идут по order группы и id; для каждой группы Соломина сначала want, затем can. Сервер проверяет точный уникальный набор пар группа/ось, не только длину массива.

## Интерфейс и история

Соломин показывает две диаграммы, Голланд — шесть типов, Деллингер — выбранную фигуру. У профессии выводятся связанные группы и показатели. Название теста при необходимости читается из теста по test_id, в результате хранится test_code_type и test_version.

Название архивной версии доступно владельцу через GET /profstart/tests/{test_id}, если у него есть сессия этой версии; этот доступ не разрешает новый старт.

Время скрытия результата — настройка киоск-клиента, не теста. Очистка экрана не удаляет историю. Гостевой результат принадлежит User; после авторизации отдельный перенос не требуется.
