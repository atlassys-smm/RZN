# Расчёт результатов и подбор профессий

Клиент передаёт один выбранный вариант, сервер считает показатели по опубликованной версии теста.

## Суммы

group_id и weight находятся в TestAnswerOption, axis берётся из TestQuestion.

```text
raw_score(g,a) = сумма weight выбранных вариантов с group_id=g и осью вопроса a
max_score(g,a) = сумма максимального возможного вклада каждого вопроса в (g,a)
normalized_score(g,a) = round(100 * raw_score(g,a) / max_score(g,a), 2)
```

Нормализация — отображение проекта, исходный балл сохраняется. Максимум зависит от полного ключа; для каждой обязательной пары он должен быть положительным.

| Тест | Исходная шкала | Полнота |
|---|---|---|
| Соломин | 0–15 по каждой группе/оси | 70 ответов, want и can независимы |
| Голланд | 0–N по каждому типу | N ответов, сумма шести показателей равна N |
| Деллингер | 0 или 1 по каждой фигуре | Один ответ, ровно одна группа имеет 1 |

Неполное прохождение не создаёт итог. /complete проверяет все вопросы и атомарно сохраняет результат; повтор возвращает ту же запись.

## Ведущие группы

rank = 1 + количество групп с большим raw_score внутри категории и оси: например, 1, 1, 3. Все положительные максимумы имеют is_leading=true. Если все значения нулевые, ведущих групп нет.

Соломин: максимумы выбираются раздельно в subject и labor на каждой оси. Несовпадение «Хочу» и «Могу» видно по показателям, отдельный признак не сохраняется. При нулевых want в любой категории список профессий пуст. Голланд: все равные максимумы сохраняются.

## Профессии

TestGroupProfession содержит profession_id и coefficient (0 < c ≤ 1). Пример разметки: педагог — human_human и creative у Соломина, S у Голланда; бухгалтер — human_sign и executive, C; дизайнер — human_art и creative, A. Это примеры настройки, не автоматический ключ.

### Соломин

Профессия должна быть связана одновременно с ведущим subject и ведущим labor оси want.

```text
subject_contribution = max(normalized_score(g,want) * coefficient(g,p))
                       среди связанных ведущих subject
labor_contribution   = max(normalized_score(g,want) * coefficient(g,p))
                       среди связанных ведущих labor
profession_score     = (subject_contribution + labor_contribution) / 2
```

can показывается отдельно и не исключает профессию. Формула сочетания категорий — политика проекта.

### Голланд и фигуры

Кандидаты — профессии, связанные с ведущими группами. Балл — максимум normalized_score(g,general) * coefficient(g,p). Для всех геометрических групп используются заданные CMS связи; отсутствие связи даёт пустой список без специального признака или переключателя.

### Сохранение

Баллы сортируются по убыванию, при равенстве profession_id возрастает. Возвращается весь подходящий список без лимита в тесте. Значения округляются до двух знаков. Рекомендации содержат профессию, балл и числовые вклады групп; текст пояснения связи не хранится.

Если подходящих связей нет, professions=[]. Публикация требует полных пар каждой профессии Соломина, но не обязательного покрытия каждой комбинации или геометрической группы.

## Примеры

- Соломин: 0, 1, 2, 3, 3 в группе want дают 9/15 и 60; can независимо.
- Голланд: четыре S из десяти — 4/10 и 40; сумма всех исходных показателей — 10.
- Деллингер: выбран circle — 1/1 и 100 у круга, остальные нулевые; профессии берутся из связей circle.
- Повтор ответа не меняет сумму, повтор /complete не создаёт второй результат.

## Интерфейс и история

Соломин показывает две диаграммы, Голланд — шесть типов, Деллингер — выбранную фигуру. У профессии выводятся связанные группы и показатели. Название теста при необходимости читается из теста по test_id, в результате хранится test_code_type и test_version.

Время скрытия результата — настройка киоск-клиента, не теста. Очистка экрана не удаляет историю. Гостевой результат принадлежит User; после авторизации отдельный перенос не требуется.
