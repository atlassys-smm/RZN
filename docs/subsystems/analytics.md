# Подсистема «Аналитика и отчётность»

Подсистема собирает внутренние события бэкенда в ClickHouse. Metabase читает
SQL-представления и выводит показатели в коллекциях и дашбордах.
Сейчас события отправляют индивидуальная викторина и командная игра
LED-медиаплатформы (`module_id=1` и `module_id=2`),
а также ПрофСтарт при старте, ответе, завершении, явном прерывании и сохранении
рекомендаций профессий (`module_id=4`). Обратная связь отправляет реальные старты,
итоговые оценки и окончания (`module_id=5`).

## Сбор и доставка

Сервисы вызывают `app.services.analytics.emit_event` после бизнес-операции.
Функция сериализует событие и помещает его в ограниченную `asyncio.Queue`;
HTTP-запрос пользователя не ждёт ClickHouse. Фоновый отправитель собирает пакеты,
отправляет их по HTTP и ждёт подтверждения записи. Неудачные попытки повторяются
с тем же содержимым и токеном вставки.

Очередь находится в памяти процесса API. При аварии, перезагрузке, переполнении
или исчерпании повторов события могут теряться. Постановка события не входит
в транзакцию бизнес-операции. Публичный HTTP API приёма событий от устройств
и внешних ПАК не реализован.

## События и хранилище

Все события записываются в физическую таблицу `analytics.events`.
SQL-представления выделяют данные подключённых модулей и учитывают повторы по ID события.
Числовые коды действий и функциональных модулей задаются
через IntEnum. UUID конкретного факта находится в `id`.
Контракт полей, payload и правила расчёта описаны в
[AnalyticsEvent](../entities/analytics.md), типы — в
[справочнике событий](../references/analytics-event-types.md).

| Событие | Что фиксирует |
|---|---|
| `1` — SESSION_STARTED | Фактический старт; для викторины — состав участников и команд, для ПрофСтарт — версия теста |
| `2` — PARTICIPANT_JOINED | Регистрацию нового участника |
| `3` — ANSWER_EVALUATED | Правильность оценённого ответа участника или команды |
| `4` — SESSION_FINISHED | Успешное завершение игры/теста и длительность; у ПрофСтарт — снимок показателей групп |
| `5` — PROFESSION_RECOMMENDED | Одну профессию из результата теста ПрофСтарт: тест, версия, профессия, score и позиция |
| `6` — ANSWER_SUBMITTED | Личный принятый ответ командной викторины без содержимого, вариант и время ответа ПрофСтарт либо итоговую числовую оценку rating_scale в анкете |
| `7` — SURVEY_STARTED | Реальное начало заполнения анкеты |
| `8` — SURVEY_FINISHED | Сохранение готовой анкеты и длительность |
| `9` — SESSION_ABANDONED | Явное прерывание ПрофСтарт пользователем или оператором |

Тексты, сложность, варианты вопросов, ответы и игровые баллы викторины
в аналитику не передаются. ПрофСтарт передаёт выбранный вариант, вклад ответа,
снимок показателей групп и нормированный score рекомендации. Его графики
подключены через четыре представления ClickHouse; [контракт и расчёты](analytics/dashboards/pak-detail/profstart.md).
Поле `is_guest` фиксирует гостевой статус на момент события; старые события
сохраняют NULL. Посещаемость считает уникальные user_id через `visitor_activity`,
включая участников стартового снимка викторины.
Срок хранения событий автоматически не ограничен. Производительность на целевом
объёме данных нагрузочными тестами пока не подтверждена.

## Отчёты и доступ

Metabase хранит пользователей, подключения, вопросы, дашборды и настройки
в своей базе `metabase` существующего PostgreSQL проекта. Показатели читает
из ClickHouse через пользователя `analytics_reader` с правом SELECT.

Корневая коллекция «Аналитика» содержит группы показателей административного
портала. Подключено 72 запроса: 28 для викторины, командной игры и общих
показателей LED, четыре для вовлечённости, девять детальных и два общих для
обратной связи, 13 для ПрофСтарт, 10 для сводки модулей, четыре для посещаемости
и два для тепловой диаграммы. Остальные 45 показателей — заготовки без запросов.
[Полный состав](analytics/clickhouse-metabase.md#коллекции-и-подключённые-показатели).

Бэкенд предоставляет `GET /api/analytics/catalog`: постоянные ключи связаны
с ID и type коллекций, дашбордов и графиков. Запрос требует действующий токен
любой сущности и читает локальный реестр. Описания объектов и результаты
запросов фронтенд получает непосредственно из Metabase с отдельной авторизацией.

## Конфигурация и развёртывание

Скрипты запускаются через `docker compose exec api python`, используют
окружение контейнера из корневого `.env` и внутренние адреса сервисов Compose.
SQL-миграции ClickHouse и JSON-файлы коллекций Metabase находятся в `infra`.
Журнал миграций, реестр ID, блокировки, резервные копии и диагностика —
в `storage/infra`, отдельно по компонентам.

Команды, настройки, порядок развёртывания и входа описаны на странице
[ClickHouse и Metabase](analytics/clickhouse-metabase.md).

## Требования к показателям

Состав показателей административного портала описан в
[требованиях к дашбордам](../interfaces/admin-portal/dashboards.md).
[Раздел дашбордов](analytics/dashboards.md) описывает целевой состав отчётов;
наличие показателя в требованиях не означает, что его источник данных подключён.
