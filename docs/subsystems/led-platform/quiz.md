# Викторина

Игровые сессии на LED-платформе. Вопросы с вариантами ответов на LED-экране, участники отвечают с мобильных устройств.

---

## Режимы

### Индивидуальная викторина

Основной режим — раунды с разными типами вопросов, как в командной игре. Отличие: участники отвечают персонально, рейтинг индивидуальный.

- Оператор выбирает шаблон сценария или настраивает раунды вручную (от 3 до 8 типов)
- Каждый участник отвечает самостоятельно за себя
- Запускается пользователями через QR-код на заставке (самообслуживание в режиме ожидания)
- Оператор может выбрать сценарий викторины с настройкой параметров
- По итогам — индивидуальный рейтинг участников

### Командная игра

Основной сценарный режим. Профориентационная игра на LED-экране:

- Формирование команд (от 2 до 8 команд, состав — от 2 до 10 человек)
- Оператор выбирает шаблон сценария из подготовленных в CMS или собирает раунды вручную
- Если выбран шаблон — используются заранее подобранные вопросы для каждого раунда
- Если шаблон не выбран — оператор выбирает от 3 до 8 типов раундов, система подбирает вопросы по фильтрам (сложность, возраст, теги)
- Раунды заданий, обсуждения, приём ответов
- Рейтинг и итоговый результат

**Командир:**
- Первый подключившийся к команде становится командиром
- Текущий командир может передать роль другому участнику команды
- Если командир отключился от игры, система назначает случайного командира из участников команды
- Оператор может сменить командира, выбрав нового из списка участников команды

## Статусы сессии

| Статус | Описание |
|--------|----------|
| `waiting` | Формирование команд. Игра ещё не началась. |
| `active` | Игра идёт. Оператор управляет раундами и вопросами. |
| `finished` | Сессия завершена. Показан финальный рейтинг. |

---

## Этапы командной сессии

### Подготовка (статус `waiting`)

1. Создание сессии оператором → статус `waiting`
2. Подключение и формирование команд
3. Инструктаж
4. Оператор нажимает «Начать игру» → статус `active`
5. Команды с нулевым количеством участников автоматически исключаются из сессии. Если после исключения остаётся менее 2 команд — игра не может быть начата

### Проведение (статус `active`)

5. Раунды заданий (от 3 до 8):
   - Показ вопроса на LED
   - Обсуждение в командах
   - Приём ответов (таймер вопроса)
   - Показ правильного ответа с методическим пояснением
   - Начисление баллов
6. Показ промежуточных результатов раунда (если `show_intermediate_results = true`)
7. Пауза между раундами (`between_rounds_delay`)
8. Следующий раунд

### Завершение

9. После последнего вопроса последнего раунда — показ финальных результатов
10. Оператор нажимает «Завершить» → статус `finished`
11. Сохранение статистики и возврат в режим ожидания

## Настройки сессии

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `auto_reveal` | Автоматический показ правильного ответа по истечении времени. Если `false` — оператор нажимает «Показать ответ» | `true` |
| `auto_next` | Автоматический переход к следующему вопросу после показа ответа | `false` |
| `auto_next_delay` | Задержка автоперехода в секундах | `5` |
| `between_rounds_delay` | Пауза между раундами в секундах | `10` |
| `show_intermediate_results` | Показывать промежуточный рейтинг после каждого раунда | `true` |

## Сущности

- **GameSession** — игровая сессия (режим, настройки, тайминги)
- **GameSessionTeam** — команда (название, цвет, командир, счёт)
- **GameSessionParticipant** — участник (пользователь/гость, команда, роль, счёт)
- **GameQuestion** — вопрос викторины (тип, текст, медиа, сложность, тип раунда, методическое пояснение)
- **GameAnswerOption** — вариант ответа
- **ScenarioTemplate** — шаблон сценария (набор раундов с вопросами для тематической сессии)
- **ScenarioTemplateRound** — раунд шаблона (тип раунда + порядок)
- **ScenarioTemplateRoundQuestion** — вопрос в раунде шаблона (конкретный вопрос из банка)

## Взаимодействие

- **Получает контент** из CMS (вопросы, медиа)
- **Отправляет события** в Аналитику (результаты сессий, ответы команд, тайминги)
- **Использует Идентификацию** для авторизации участников и привязки событий к профилям
