# Мой карьерный маршрут

Подбор профессий, учебных заведений и работодателей на основе данных профиля пользователя. Основой подбора профессий служат результаты ПрофСтарт. Профессии и организации берутся из справочников CMS.

---

## Источники данных для подбора

Основной источник рекомендаций — **результаты ПрофСтарт**. По умолчанию в итоговом подборе участвуют три встроенных типа тестов и просмотры профессий. Веса относительные; в таблице приведены веса ПрофСтарта:

| Тест | Результат | Вес в SOURCE_WEIGHTS |
|------|-----------|------------------------|
| Анкета «Ориентация» И. Л. Соломина (`solomin`) | Ориентация на предмет труда и характер деятельности | 40 |
| Тест на основе теории Дж. Голланда (`holland`) | Профессиональные интересы по шести типам RIASEC | 40 |
| Геометрический тест Сьюзен Деллингер (`dellinger`) | Предпочтения по пяти геометрическим типам | 15 |

Профиль `user_recommendations` принадлежит пользователю. Завершение любого типа ПрофСтарта, включая дополнительный тип из CMS, добавляет неизменяемый источник в `user_recommendation_sources`: `source_module=profstart`, `source_code` — код типа теста. Каждый тип можно завершить один раз, независимо от версии.

Источник сохраняет показатели всех групп в `group_scores` и полный снимок соответствия профессиям с основаниями подбора в `profession_scores`. Учитываются также неведущие группы с положительным вкладом. Изменение подписей групп и связей профессий в CMS не пересчитывает сохранённые источники.

Веса влияния заданы в `SOURCE_WEIGHTS` в `app/models/user_recommendations/weights.py` по паре `(source_module, source_code)`. В БД они не хранятся и через CMS не меняются. В итоговом рейтинге участвуют только настроенные источники с положительным весом; остальные сохраняются для истории. Изменение весов влияет на следующий запрос рекомендаций.

Дополнительные источники для расширения модели:

- **Выбранные профессии** — из сценариев LED-платформы, тестов, анкет
- **Интересы** — типы задач и деятельности, выявленные по ответам пользователя

Для этих активностей нужно реализовать поставщиков снимков и определить веса их пар `(source_module, source_code)` в `SOURCE_WEIGHTS`.

## Категории рекомендаций

### Профессии

Подбираются **до 3 профессий** из [справочника профессий](../../entities/professions.md) на основе сохранённых источников, включённых в `SOURCE_WEIGHTS`. Профессии располагаются по убыванию итоговой оценки соответствия. Если подходящих профессий меньше трёх, показывается доступное количество.

Для каждой профессии должны отображаться:

- Название и ссылка на описание профессии
- Итоговая оценка соответствия
- Основания подбора: использованные источники, связанные группы и вклад каждого источника в итоговую оценку

Учёт выбранных отраслей, компетенций и интересов из других активностей относится к дальнейшему расширению модели.

### Учебные заведения, работодатели и направления

По максимум трём профессиям из итогового рейтинга рассчитываются три отдельных списка: `employers` (до 5 работодателей типа 1), `educations` (до 5 учебных заведений типа 2) и `education_programs` (до 5 направлений подготовки). Работодатели определяются через profession_employers, учебные заведения — через profession_education_programs → education_programs → organization_education_programs → organizations. Направления подбираются непосредственно через profession_education_programs → education_programs, независимо от наличия организаций. В каждом списке сначала идут записи с большим числом различных совпавших профессий, затем с меньшим ID. Несколько программ одной профессии не увеличивают её вклад в рейтинг организации. Элементы списков организаций содержат `organization` (полные данные организации), `profession_ids` (по возрастанию ID), `profession_count` и `position` (1–5). В списке направлений вместо `organization` возвращается `education_program`: id, name, education_level, duration, base_class, created_at, updated_at; остальные поля совпадают. Общее направление возвращается один раз независимо от числа его организаций. Профессии, связи, программы и организации с deleted_at участвуют в расчёте для сохранённых рекомендаций. Данные и связи читаются в текущем состоянии при каждом GET; снимки этих трёх списков не сохраняются. При отсутствии профессий или соответствующих связей массивы пустые; до создания профиля ответ остаётся null.

## Рекомендательная модель

### Подбор профессий

1. После завершения теста ПрофСтарта рассчитываются показатели групп и оценки соответствия профессиям, которые сохраняются в источнике. CMS задаёт связи групп с профессиями; коэффициентов у связей нет. Оценка профессии определяется по лучшим нормированным баллам связанных групп по [правилам методики](../profstart/results.md#снимок-соответствия-профессиям).
2. При каждом GET `/api/users/me/recommendations` оценки из снимков объединяются с учётом текущих весов. Итоговый рейтинг не сохраняется в БД. Для каждой профессии оценка рассчитывается как взвешенное среднее:

    `Итоговая оценка = Σ(оценка профессии в источнике × вес источника) / Σ(веса имеющихся источников с положительным весом)`

    Ненастроенные источники и источники с нулевым весом не участвуют в расчёте. Если профессия отсутствует в снимке выбранного источника, её оценка по этому источнику принимается равной нулю; его вес остаётся в знаменателе, в том числе при пустом `profession_scores` у источника теста. Пустой источник views исключается из расчёта.

3. В подбор включаются существующие в справочнике профессии с положительной округлённой оценкой. Итог округляется до двух знаков методом ROUND_HALF_UP после суммирования взвешенных вкладов; при равных оценках порядок определяется по ID профессии по возрастанию.
4. В карьерном маршруте показываются первые **до 3 профессий** общего рейтинга, а не по три профессии от каждого теста.

### Неполное прохождение

Подбор доступен после первого сохранённого источника с положительным настроенным весом. Веса имеющихся источников нормализуются относительно их суммы: например, если пройден только тест Соломина с весом 40, его фактическое влияние на текущий подбор составляет 100%.

Полнота подбора определяется полем `is_complete`: нужны все обязательные источники с положительными настроенными весами. Просмотры professions/views необязательны и не входят в missing_sources; их пустой снимок исключается из расчёта. Ответ содержит `weights`, использованные `sources` с `effective_weight_percent` и недостающие пары модуля и кода в `missing_sources`. После добавления следующего источника новый запрос учитывает его в рейтинге. Результаты отдельных завершённых тестов доступны через историю ПрофСтарта.

До первого сохранённого источника GET возвращает JSON null. Если профиль существует, но учитываемых источников или подходящих профессий нет, `professions=[]`. Пустой рейтинг сам по себе не означает неполноту: при наличии всех ожидаемых источников `is_complete=true`. Интерфейс должен пояснять причину пустой выдачи и предлагать получить недостающие источники, если они есть.

### Дальнейшая доработка

    - Порядок отображения категорий

## Конструктор рекомендаций для сотрудника

HTML-страница открывается на адресе бэкенда: `/recommendations_constructor`
(локально `http://localhost:8000/recommendations_constructor`). На ней сотрудник
вводит логин (email) и пароль, ID пользователя и веса Соломина, Холланда и
Деллингер и просмотров профессий. Значения по умолчанию берутся из `SOURCE_WEIGHTS`: **40 / 40 / 15 / 5**.

Вход выполняется через POST `/api/recommendations_constructor/login` с JSON
`{"email":"name@example.com","password":"..."}`. Проверяется обычная учётная запись
сотрудника. Ответ аналогичен `/auth/login`, но refresh-cookie не устанавливается.
Страница хранит access-токен только в памяти вкладки; пароль очищается после
попытки входа. После перезагрузки страницы или истечения токена нужен новый вход.
Кнопка «Выйти» удаляет токен и результаты из вкладки.

По кнопке расчёта отправляется POST `/api/recommendations_constructor/preview` со Staff JWT
администратора, оператора или редактора:

```json
{"user_id":12,"weights":{"solomin":40,"holland":40,"dellinger":15,"views":5}}
```

`weights` и отдельные веса можно опустить — используются значения из кода.
Каждый вес — конечное число от 0 до 100, хотя бы один больше нуля. Сумма может
отличаться от 100; веса нормализуются относительно имеющихся источников.
Нулевой вес исключает источник. Неизвестные поля отклоняются с 422. Нет пользователя —
404; пользователь существует без профиля — 200 с JSON null. Пользовательский или
Device JWT не даёт доступа к этому инструменту.

Маршрут вызывает тот же `get_recommendations`, что пользовательский API, с весами
в аргументе текущего вызова. Отдельного алгоритма конструктора нет, глобальные веса
не меняются, в том числе при параллельных запросах. При необходимости общий сервис
обновляет сохранённый источник просмотров по правилу 6 часов.

Ответ имеет формат `UserRecommendations` из [API рекомендаций](../../api/user-recommendations.md). На странице одновременно
показаны отдельными разделами до трёх профессий с вкладом каждого источника и основаниями, до пяти работодателей,
до пяти учебных организаций с файлами и отдельно до пяти направлений. При
неполных результатах указаны недостающие тесты и фактическое влияние доступных.
Ссылки над выдачей перемещают к соответствующим разделам и не скрывают остальные.
Интерфейс компактный: заголовок находится в верхней панели, профессии показаны
рядом, остальные категории — колонками на широком экране. Баллы и краткие параметры
видны сразу; расчёт баллов, основания, описания, контакты и файлы доступны при
раскрытии карточки. По умолчанию подробности свёрнуты; на узких экранах разделы
перестраиваются в одну или две колонки.
Кнопка «Раскрыть все / Свернуть все» управляет подробностями всех карточек,
включая расчёт баллов. Состояние кнопки учитывает и раскрытие отдельных карточек.
Предпросмотр только читает данные: выбранные веса, результаты и рейтинг не
сохраняются. Обычный пользовательский запрос продолжает применять `SOURCE_WEIGHTS`.

### Покрытие выбранных профессий

Правило покрытия применяется отдельно к каждому из трёх списков: employers, educations, education_programs. Сначала формируется топ-5 по числу различных совпавших профессий DESC и ID организации или направления ASC. Затем проверяется покрытие каждой выбранной профессии. Если для неё есть связанные записи, но ни одна не попала в топ-5, лучшая из них заменяет последнюю запись, удаление которой не лишает покрытия другие профессии. Одна запись может покрывать несколько профессий. После замен сохраняется сортировка по рейтингу; лимит — 5 уникальных записей в каждом списке. Если соответствующих связей нет, покрытие этой профессии в данном списке не требуется.

Правило действует для `/users/me/recommendations` и `/organizations/recommendations`, в том числе для профессий, связей, программ и организаций с `deleted_at`.

## Просмотры профессий

Дополнительный источник `professions/views` имеет относительный вес 5 при
весах тестов 40/40/15. Сумма всех весов — 100. При первом запросе загружаются просмотры за 30 суток из
ClickHouse. Затем строго через более чем 6 часов добавляются события после
предыдущего updated_at. Счётчики накапливаются в group_scores, оценки профессий
в profession_scores пересчитываются относительно максимального количества
просмотров: максимум — 100, остальные пропорционально. Источник может дать
профессии без прохождения тестов и необязателен для is_complete. Ошибка аналитики
не сбрасывает сохранённые данные. [Хранение и правила](../../entities/user-recommendations.md#источник-просмотров-профессий).
