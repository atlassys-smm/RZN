# Аналитика анкет

В ClickHouse подключены события обратной связи. В Metabase развёртывается
дашборд **Аналитика → Детальная аналитика по каждому ПАК → Обратная связь**
(`pak.feedback`, на текущем сервере — `/dashboard/26`). Текстовых комментариев
в дашборде нет. Исходный шаблон —
`infra/metabase/collections/analytics/details/feedback/collection.json`.

## События и прохождение

Клиент вызывает `POST /api/feedback/surveys/{survey_id}/start` перед первым
вопросом, передавая source_id. Сервер создаёт SurveyResponse с started_at,
device_id (если известно устройство), completed_at=NULL и duration=0.
Полученный id передаётся как response_id в запросе respond. Новых таблиц
прохождений нет.
Существующие результаты сохраняются с прежним completed_at и started_at=NULL.

После commit старта отправляется `SURVEY_STARTED=7`. После commit ответов —
`ANSWER_SUBMITTED=6` для итоговых числовых оценок и `SURVEY_FINISHED=8` с
длительностью. Тип вопроса question_type=1 означает rating_scale. Текст вопроса
служит подписью графика; текстовые ответы и контактные данные в ClickHouse
не передаются. Остальные ответы продолжают сохраняться в PostgreSQL.

При завершении обновляется тот же SurveyResponse: completed_at и duration,
согласие и ответы. Повтор respond с тем же response_id и ответами возвращает
прежний результат без новых событий; изменённые ответы или источник дают 409.
Каждый вызов start создаёт новую запись: повтор старта не является повтором
завершения. После получения id клиент сохраняет его и использует для отправки.
Незавершённые записи исключены из CMS-списка готовых ответов.

`module_id=5`, `software_id=4`. В общем событии session_id равен ID SurveyResponse.
user_id берётся из авторизации. Device JWT даёт реальный ID устройства;
при User JWT без устройства device_id=NULL. device_type пока NULL.
`is_guest` передаётся отдельным nullable-полем события и фиксирует статус
пользователя при начале/отправке анкеты. Исторические события сохраняют NULL.
source_id — строка точки сбора из клиента; она не заменяет device_id и сама
не подтверждает принадлежность к физической точке.

Все события содержат survey_id (ID версии), survey_type, survey_name,
source_id. Оценка дополнительно содержит response_id, question_id,
question_type, question_text, rating, scale_min, scale_max. Окончание —
response_id, duration_ms и finish_reason="completed".
При реальном старте длительность рассчитывается сервером. Клиентский duration
остаётся обязательным для совместимости, но не определяет это время.

Без response_id старый запрос сохраняет готовую анкету с started_at=NULL:
создаются оценки и окончание, но реальный старт не выдумывается. Время берётся
из duration в секундах. Повтор такой отправки — отдельная анкета; для защиты
от повторов нужен response_id. Исторические результаты не выгружаются.

Проверяются принадлежность вопроса анкете, отсутствие повторов question_id,
целое значение rating_scale и попадание в шкалу. Пропуски не превращаются
в нулевые оценки. Условные вопросы не объявляются обязательными без учёта
условий; успешное сохранение анкеты считается завершением.

## Хранилище

Физическая таблица остаётся общей — `analytics.events`. Представления
`analytics.feedback_sessions` и `analytics.feedback_ratings` добавлены миграцией
ClickHouse `0004_feedback_views.sql`, читают `events_unique` и отбирают только
`software_id=4`, `module_id=5`. Повтор доставки одного UUID не увеличивает счётчики.

Сессия определяется по `(software_id, module_id, session_id)`. У событий старта,
окончания и оценки стабильные ключи `feedback:<session_id>:start`,
`feedback:<session_id>:finish`, `feedback:<session_id>:question:<question_id>`.
Сервисы не ждут HTTP-записи в ClickHouse: очередь и доставка остаются best effort.
Потеря отдельного события может влиять на завершённость и оценки.

## Подключённые графики

| График | Расчёт |
|---|---|
| Количество сессий/взаимодействий | Число прохождений по реальному старту; для старого потока без старта — по завершению |
| Сессии/взаимодействия по дням | Те же прохождения по московской дате |
| Среднее время | Среднее duration_ms / 60000 завершённых прохождений с известной длительностью; сравнение с предыдущим периодом той же длины |
| Доля завершённых | Завершённые с реальным стартом / все с реальным стартом × 100%; старые отправки без старта исключены из обеих частей |
| Уникальные пользователи | Различные user_id среди прохождений периода; гость также имеет user_id |
| Распределение оценок по вопросам | Количество итоговых rating_scale-ответов в завершённых анкетах по вопросу и исходной оценке |
| Вопросы с низкими оценками | Вопросы хотя бы с одной оценкой в нижней четверти шкалы, по возрастанию среднего нормированного балла; рядом число всех и низких оценок |
| Количество анкет по точкам | Количество завершённых прохождений по source_id |
| Сравнение рейтингов точек | Средний нормированный балл всех rating_scale-ответов, число оценок и число завершённых анкет по source_id |

Нормированный балл — `100 × (rating − scale_min) / (scale_max − scale_min)`.
На шкале 1–5 низкими считаются 1 и 2 (не выше 25% диапазона).
Нулевая оценка допустима, если входит в шкалу вопроса. Исходные шкалы разных
вопросов не усредняются вместе. Сравнение точек использует среднее по ответам,
а не среднее по людям или анкетам; анкета с большим числом оценок вносит больше
ответов. Анкеты без числовых оценок входят в число анкет, но не в средний рейтинг.
Версии различаются survey_id и вопросами; подписи графиков содержат ID вопроса.

## Фильтры и периоды

- Начало и конец периода включительно; без границ — последние 30 календарных
  дней, включая сегодня, Europe/Moscow.
- ID версии анкеты.
- Точка сбора (source_id/XML_ID).
- ID устройства; события с device_id=NULL не попадут в фильтр конкретного устройства.

Сессии, динамика, уникальные пользователи, средняя длительность и завершённость
используют период старта (завершения для старого потока без старта).
Оценки и сравнение точек используют период завершения анкеты.
Окончание после конца периода всё равно завершает сессию его когорты старта.
Сессия без окончания не объявляется прерванной автоматически.

При отсутствии данных счётчики равны 0, рейтинги и завершённость не определены.
Пустой текущий период времени не подменяется значением прошлого; сравнение
не показывается без предыдущего значения. Текстовые комментарии остаются
доступны в ответах CMS, но не отправляются в эту аналитику.
