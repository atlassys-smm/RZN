## Показатели

### Посещаемость

В коллекции **Главный Dashboard → Посещаемость** (`main.attendance`)
подключены четыре графика. Новые и повторные визиты оставлены заготовкой
без запроса. Это цифровая активность подключённых модулей, а не учёт физического
входа в ЦЗН: устройства без идентифицированного пользователя не дают посетителя.

| Показатель | Расчёт | Ключ графика |
|---|---|---|
| Количество посетителей за период | Разные user_id со взаимодействиями за период, включая неизвестный статус | `main.attendance.visitors` |
| Уникальные пользователи | Разные user_id с последним известным is_guest=false внутри выбранного периода | `main.attendance.users` |
| Уникальные гости | Разные user_id с последним известным is_guest=true внутри выбранного периода | `main.attendance.guests` |
| Динамика посещаемости | Разные user_id отдельно в каждом дне или неделе | `main.attendance.dynamics` |
| Новые vs повторные визиты | Отложено: границы визита и идентификация возвращения пока не определены | Заготовка |

#### Источники и статус пользователя

Источник — `analytics.visitor_activity` из миграции ClickHouse 0008:

- персональные события `events_unique` с известным `user_id`;
- `participants[]` стартового события индивидуальной или командной викторины.
  Сам старт общей игры не имеет user_id; посетителями являются участники.

Один user_id считается один раз за период между всеми выбранными модулями, даже
если он прошёл несколько тестов, ответил на много вопросов или получил
несколько рекомендаций. Сейчас охвачены викторины LED, ПрофСтарт и анкеты.
Новый гостевой аккаунт того же человека нельзя связать с прежним user_id.

`is_guest` — отдельная nullable-колонка события, снимок состояния пользователя
в момент действия. Старые события остаются NULL: их посетители входят в общий
итог, но не в категории. Поэтому сумма гостей и OAuth-пользователей может быть
меньше общего числа. Статус не заполняется по текущим данным PostgreSQL.

Для каждого user_id берётся последний **известный** статус в выбранном периоде.
Если человек начал гостем и затем вошёл через OAuth и совершил новое действие,
он учитывается только в авторизованных. NULL более позднего события не стирает
известный статус; при одинаковой метке времени OAuth имеет приоритет.
Значения исторических событий при этом не переписываются.

#### Динамика и фильтры

- Даты выбирают действия по `occurred_at`, а не по старту сессии. Продолжение
  теста на следующий день учитывает активность и в этом дне.
- `date_from`, `date_to` — границы периода, конец включительно. По умолчанию
  последние 30 календарных дней, часовой пояс `Europe/Moscow`.
- `module_id`, `device_id` — один или несколько кодов модулей и устройств.
  При фильтре устройства события с device_id=NULL не входят в выборку.
- `time_grain` — `day` (по умолчанию) или `week`, только для графика динамики.
  Неделя начинается с понедельника. Граничные недели включают только действия
  внутри выбранных дат. Иное значение даёт дневную группировку.
- Один посетитель за три дня даёт 1 в общем итоге и учитывается в каждом
  из трёх дневных значений. Неделя считается по уникальным user_id самостоятельно,
  а не суммированием дней. Пустые периоды не создают вымышленных посетителей.

В отсутствие событий три счётчика равны 0, линия динамики пуста. При наличии
только исторических событий с неизвестным статусом общий итог может быть
положительным, а оба категориальных счётчика — 0.

Все четыре графика поддерживают подписанное iframe-встраивание; параметры
доступны как locked. Метаданные и ID возвращаются в `GET /api/analytics/catalog`.

```bash
docker compose exec api python infra/clickhouse/scripts/update.py --verify
docker compose exec api python infra/metabase/scripts/deploy.py main.attendance --verify
docker compose exec api python infra/tests/attendance_queries.py
```

### Вовлечённость

- **Среднее время взаимодействия** с платформой (общее по ЦЗН) — карточка с числом в минутах + сравнение с предыдущим периодом
- **Доля завершённых сессий** (общая по ЦЗН) — круговая диаграмма с секторами «Завершены» и «Не завершены»
- **Среднее количество действий** на одного посетителя — карточка с числом
- **Для X человек подобраны профессии** — карточка с числом уникальных пользователей,
  для которых за выбранный период сформирован хотя бы один непустой подбор профессий.
  Повторные подборы для одного пользователя учитываются один раз.

#### Подключённые расчёты в Metabase

В коллекции **Главный Dashboard → Вовлечённость** подключены четыре
показателя. Сессионные время и завершённость используют `analytics.module_sessions`;
действия и подбор профессий — `analytics.events_unique`. Повторы доставки
одного факта учитываются один раз.

В первых двух показателях викторины без участников за всё время сессии
исключены по `has_participants`: наличие участников на старте или любой
факт присоединения достаточны, даже если участник пришёл после конца периода
отчёта. Период по-прежнему выбирается по старту. Время и завершённость
ПрофСтарта и анкет этот критерий не меняет. [Подробности учёта викторины](pak-detail/led-platform.md#общие-показатели).

| Показатель | Расчёт |
|---|---|
| Среднее время взаимодействия | Средний duration_ms / 60000 по стартовавшим в периоде сессиям с событием окончания и известной длительностью; сравнение с предыдущим периодом той же длины |
| Доля завершённых сессий | Круговая диаграмма: количество завершённых и незавершённых сессий среди стартовавших в периоде; доля завершённых = число с окончанием / все стартовавшие × 100% |
| Среднее количество действий на посетителя | Число PARTICIPANT_JOINED / число различных user_id в этих событиях за период; события без user_id исключаются из обеих частей |
| Для X человек подобраны профессии | Число различных user_id с PROFESSION_RECOMMENDED за период; пять профессий одного результата и повторные результаты одного пользователя дают одного человека |

Сессия определяется сочетанием `(module_id, session_id)`.
Первые два показателя используют действия 1 и 4 для викторин и ПрофСтарт,
7 и 8 для нового потока обратной связи с реальным стартом. Старые отправки анкет без старта в эти два расчёта не входят. Окончание может находиться позже
выбранного периода: результат относится к периоду старта. Без старта
окончание не входит в расчёт. Сессия без окончания остаётся в знаменателе
завершённости, но не объявляется прерванной автоматически. При неизвестной
длительности она исключается только из среднего времени.

Третий показатель пока отражает регистрации участников викторины,
а не все действия или посещения ЦЗН. Четвёртый использует рекомендации
тестов ПрофСтарт; результаты до подключения событий автоматически
не восстанавливаются. Пустой подбор не создаёт события рекомендации.

Фильтры: начало и конец периода включительно, код модуля (`module_id`),
ID устройства. Часовой пояс — Europe/Moscow. По умолчанию даты задают
последние 30 календарных дней, включая сегодня; каждая незаданная граница
получает своё значение по умолчанию. Предыдущий период непосредственно
предшествует выбранному и содержит столько же календарных дней.
При фильтре конкретного устройства события с device_id=NULL исключаются;
у ПрофСтарт устройство пока неизвестно.

При отсутствии данных среднее время не выводится, круговая диаграмма
завершённости пуста; действия на посетителя не определены (NULL), число людей
с подбором равно 0.
Если в текущем периоде нет известной длительности, карточка времени
не подставляет значение прошлого периода. Сравнение времени
не вычисляется при отсутствии предыдущего значения.

Вопрос `main.engagement.completion_percent` возвращает `status` и `sessions`: статус и количество сессий. Metabase показывает их доли на круговой диаграмме. При пустой выборке строк нет, диаграмма не рисует фиктивные 0% или 100%.

Четыре вопроса этой коллекции разрешены для подписанного iframe-встраивания Metabase. Фильтры `date_from`, `date_to`, `module_id`, `device_id` настроены как `locked` и передаются сервером в подписанном JWT. В Metabase должны быть включены static embeds и задан секрет подписи; секрет не хранится в шаблонах коллекций. Встроенные вопросы рисует сам Metabase.

Шаблон и запросы: `infra/metabase/collections/analytics/main/engagement/collection.json`.
Развёртывание только этой коллекции:

```bash
docker compose exec api python infra/metabase/scripts/deploy.py main.engagement --verify
```

### Обратная связь

В `main.feedback` подключены две карточки; контактные заявки остаются заготовкой.

| Показатель | Расчёт | Ключ |
|---|---|---|
| Количество заполненных анкет | Завершённые анкеты по `finished_at`, включая старый поток без старта; сравнение с предыдущим периодом той же длины | `main.feedback.responses` |
| Средняя оценка, % шкалы | Среднее нормированных баллов отдельных `rating_scale`-ответов завершённых анкет | `main.feedback.average_score` |

Источники — `feedback_sessions` и `feedback_ratings`, соединение по
`(module_id, session_id)`. Даты отбирают окончание анкеты,
даже если её старт или отдельный ответ были вне периода. Незавершённые анкеты
и оценки без события окончания не входят в обе карточки.
Нормирование каждого ответа: `100 × (rating − scale_min) / (scale_max − scale_min)`.
Среднее считается по ответам с равным весом, а не по людям или анкетам:
анкеты с большим числом оценочных вопросов влияют сильнее. Состав вопросов,
точек и версий может менять общий результат, поэтому процент сам по себе
не доказывает изменение удовлетворённости. Разные исходные шкалы приводятся
к 0–100%; некорректные шкалы и оценки вне диапазона исключает представление.
Анкеты без числовых ответов входят в число заполненных, но не в среднюю оценку.
Текстовые комментарии не передаются и не учитываются.

Фильтры: начало и конец периода включительно, ID версии анкеты, точка сбора,
ID устройства. По умолчанию последние 30 календарных дней, `Europe/Moscow`;
предыдущий период непосредственно предшествует выбранному и имеет ту же длину.
Фильтр устройства исключает неизвестный `device_id`. Без анкет счётчик равен 0;
без оценок среднее — NULL, а не 0%. При нулевом предыдущем счётчике относительный
рост не определён. Обе карточки поддерживают подписанное iframe-встраивание
с `locked`-параметрами; ключи и ID доступны через справочник аналитики.

Доставка best effort: потеря окончания исключает анкету из отчёта, потеря оценки
может исказить среднее. История автоматически не выгружается. Повторы доставки
одного факта устраняются, но повторная отправка старого клиента без `response_id`
может создавать отдельную анкету. [Подробности аналитики анкет](../surveys.md).

Безопасная проверка расчётов: `docker compose exec api python infra/tests/led_feedback_queries.py`.

### Востребованность профессий

- **Рейтинг профессий** по выбору пользователей (топ-10) — таблица с сортировкой (название, количество выборов)
- **Рейтинг отраслей** по интересам (топ-10) — таблица с сортировкой (название, количество интересов)
- **Рейтинг направлений** по интересам (топ-10) — таблица с сортировкой (название, количество интересов)
- **Динамика интереса к профессиям** — линейный график изменения популярности топ-5 профессий по времени (сколько раз выбирали/просматривали каждую профессию за период)

### Востребованность работодателей и учебных заведений

- **Рейтинг работодателей** по просмотрам (топ-10) — таблица с сортировкой (название, количество просмотров)
- **Рейтинг учебных заведений** по интересам (топ-10) — таблица с сортировкой (название, количество интересов)

- **Динамика интереса к учебным заведениям** — линейный график изменения популярности топ-5 учебных заведений по времени (количество событий `educational_institution_viewed` за период)

### Тепловая диаграмма посещаемости

В `main.heatmap` подключены тепловая матрица 7×24 и таблица всех пиковых
интервалов. Таблица дополняет подсветку максимумов на той же карте;
вторая тепловая карта не строится.

| Вопрос | Содержимое | Ключ |
|---|---|---|
| Активность по времени суток | Среднее почасовых уникальных пользователей для каждого дня недели и часа | `main.heatmap.activity` |
| Пиковые интервалы активности | Все ячейки с максимальным положительным средним, число календарных интервалов и сумма почасовых уникальных | `main.heatmap.peaks` |

**Единица активности.** Источник — `analytics.visitor_activity` над
дедуплицированными `events_unique`. За каждый конкретный календарный час
считаются разные известные `user_id` с хотя бы одним фактом. Пользователь
с несколькими ответами или рекомендациями за час учитывается один раз;
между выбранными модулями тоже один раз. При активности в разных часах или датах
он учитывается в каждом из них. Неизвестный `is_guest` не исключает пользователя.
Стартовый снимок викторины даёт активность каждому известному участнику,
хотя у общего события игры нет `user_id`.

**Среднее в ячейке.** Сначала считаются уникальные для каждой конкретной даты
и часа. Затем их сумма делится на число соответствующих календарных интервалов
в периоде. Например, «Пн, 10–11» усредняется по всем наступившим понедельникам
с этим часом, включая интервалы без событий. Человек, действовавший в два
понедельника, участвует в обоих наблюдениях, а не один раз за весь период.
Это устраняет перекос из-за разного числа дней недели. Сумма ячеек не является
числом уникальных посетителей за период или длительностью присутствия.

**Время и неполные интервалы.** Используется `occurred_at`, `Europe/Moscow`;
неделя начинается с понедельника, интервалы полуоткрытые: `[10:00; 11:00)`.
Фильтры дат включают конец выбранной даты. Данные отсекаются моментом выполнения
запроса; будущее не создаёт нулевые наблюдения и не входит в знаменатель.
Текущий начавшийся час включается с фактически накопленным числом пользователей
и одним календарным интервалом в знаменателе, без экстраполяции на полный час.
Его среднее может быть ниже из-за неполноты. Звёздочки у текущих дня недели
и часа отмечают **их пересечение**, содержащее неполное наблюдение. В таблице
пиков это явно указано отдельной колонкой. На точной границе часа, пока у него
нет прошедшей части относительно момента среза, неполное наблюдение не добавляется.

**Нули, пустые значения и пики.** Уже наступившие интервалы без событий входят
в среднее с нулём зарегистрированной активности. Если соответствующих
интервалов ещё не было в выбранном периоде, значение NULL: пустая серая ячейка,
а не ноль. При обратном или полностью будущем периоде вся матрица пуста.
Пики — все ячейки, равные максимальному положительному среднему до округления;
топы и произвольные пороги не используются. Все равные пики показываются.
При полностью нулевой или пустой выборке пиков нет.

**Отображение.** SQL матрицы возвращает ровно 168 строк с тремя колонками:
день недели, час и числовое среднее. Metabase разворачивает обычную SQL-таблицу
по часам (`table.pivot`); заголовки 00–23 обозначают начало интервала,
в таблице пиков показан полный диапазон часа. Условное форматирование задаёт общую линейную шкалу
от 0 до максимума всей матрицы. Нули белые, отсутствующие наблюдения серые,
положительные максимумы — самые тёмные. В таблице пиков не более 168 строк;
все максимумы показаны без LIMIT. Числа отображаются с двумя знаками после
запятой; расчёт и выбор пиков используют неокруглённые значения. Обе выборки
меньше технического порога Metabase в 2000 строк.

**Фильтры.** Начало и конец периода, один или несколько модулей (`module_id`),
одно или несколько устройств (`device_id`). По умолчанию последние 30
календарных дней, включая сегодня, МСК. Для обеих карточек настроены
подписанное iframe-встраивание и `locked`-параметры; ключи и ID доступны
через справочник аналитики.

**Охват и ограничения.** Сейчас события отправляют индивидуальная и командная
викторины LED, ПрофСтарт и анкеты. Остальные модули пока не покрыты. Это цифровая
зарегистрированная активность, а не физическая посещаемость ЦЗН, одновременное
присутствие людей, занятость оборудования или нагрузка сервера.

- У команды известен состав на старте; последующие ответы относятся к
  конкретному отвечавшему. Всю команду нельзя автоматически считать активной
  в каждом следующем часе.
- Оценки анкеты отправляются пакетом при завершении: почасовую активность
  внутри длительного заполнения восстановить нельзя.
- Нет аналитических событий непрерывного присутствия и ухода. Длительность
  сессии не распределяется по часам как подтверждённая активность.
- У ПрофСтарта `device_id` пока неизвестен. Фильтр конкретного устройства
  исключает его и другие события с неизвестным устройством.
- Разные гостевые аккаунты одного человека не объединяются. События без
  известного пользователя не дают посетителя.
- Доставка best effort может терять события. Ноль означает отсутствие
  зарегистрированной активности, но не подтверждает исправность сбора,
  работу оборудования или отсутствие людей. История до подключения событий
  не восстанавливается; сравнивать закономерности нужно на периоде с надёжным
  сбором и достаточной историей.

Проверка расчётов без записи рабочих данных:

```bash
docker compose exec api python infra/tests/heatmap_queries.py
```

Обновление существующего дашборда с сохранением ID:

```bash
docker compose exec api python infra/metabase/scripts/deploy.py main.heatmap --verify
```
