# Сводная аналитика по модулям

Сравнение функциональных модулей по количеству начатых сессий, длительности
и доле завершения. Категория определяется `module_id`, независимо от устройства.
При отсутствии фильтра устройства объединяются сессии одного модуля со всех
устройств, но разные модули остаются отдельными строками.

## Источники и охват

Общее представление ClickHouse `analytics.module_sessions` добавлено миграцией
`0007_module_sessions.sql`. Оно читает `analytics.events_unique` с устранением
повторной доставки по UUID факта. Сводные расчёты выполняются представлением без отдельной физической таблицы.

| module_id | Модуль | Подключение |
|---|---|---|
| 1 | Индивидуальная викторина | Старты и окончания |
| 2 | Командная викторина | Старты и окончания |
| 3 | Профессии в действии | Ещё не подключён |
| 4 | ПрофСтарт | Соломин, Голланд, Деллингер и другие опубликованные типы |
| 5 | Обратная связь | Анкеты |
| 6–12 | Аватар профессий, Древо профессий, Интерактивная карта региона, Профбаттл, Видео-окна, Видео-резюме, Заставка | Ещё не подключены |

Индивидуальная и командная викторины сравниваются отдельно; объединения в
LED-ПАК в сводке нет. Отсутствующие источники не получают фиктивных строк.

## Правила учёта

- Одна сессия определяется парой `(module_id, session_id)`.
  Совпадающие числовые ID разных модулей не объединяются.
- Одно взаимодействие — одна начатая сессия, независимо от числа участников,
  вопросов, ответов или рекомендаций. Три разных теста ПрофСтарт — три сессии;
  командная игра с несколькими участниками — одна.
- Для викторин (`module_id` 1 или 2) исключаются сессии без
  участников за всё время: `module_sessions.has_participants` должен быть true.
  Счётчик/состав на старте или факт присоединения, включая поздний и вне периода,
  подтверждают участие. Одна лишь непустая команда не подтверждает его.
  У остальных модулей флаг NULL: этот критерий к ним не применяется.
- Период отбирает сессии по реальному `started_at`. Окончание после конца
  выбранного периода учитывается для этих сессий. Исторические окончания без
  старта и события рекомендаций сами по себе не создают сессию.
- Обычные сценарии используют `SESSION_STARTED=1` и `SESSION_FINISHED=4`.
  Анкеты (`module_id=5`) используют `SURVEY_STARTED=7`
  и `SURVEY_FINISHED=8`.
- Достижение цели означает завершение сессии. Пропуски вопросов викторины
  не меняют этот признак. `SESSION_ABANDONED=9` не является завершением:
  такое прохождение ПрофСтарт остаётся в знаменателе.
- Среднее время берётся только по завершённым сессиям с известным `duration_ms`,
  в минутах, включая паузы. Среднее взвешено по числу сессий, а не по модулям.
  Нулевая известная длительность допустима; неизвестная не заменяется нулём.
- При отсутствии стартов общий счётчик равен 0, среднее и процент — NULL,
  сравнительные графики и таблица пусты.

## Общие показатели

Коллекция и дашборд `summary.common`.

| Показатель | Расчёт | Визуализация | Ключ графика |
|---|---|---|---|
| Количество сессий | Число сессий с реальным стартом | Карточка | `summary.common.sessions` |
| Среднее время сессии | Среднее `duration_ms / 60000` завершённых сессий | Карточка, минуты | `summary.common.average_minutes` |
| Доля завершённых сессий | Завершённые / начатые × 100% | Число и прогресс-бар до 100% | `summary.common.completion_percent` |

## Сравнительные метрики

Коллекция и дашборд `summary.comparison`.

| Показатель | Расчёт | Визуализация | Ключ графика |
|---|---|---|---|
| Количество взаимодействий по модулям | Число начатых сессий по `module_id` | Столбчатая диаграмма | `summary.comparison.interactions` |
| Среднее время взаимодействия по модулям | Среднее время завершённых сессий каждого модуля | Горизонтальные столбцы | `summary.comparison.average_minutes` |
| % достижения целей по модулям | Завершённые / начатые × 100% отдельно для каждого модуля | Горизонтальные полосы на шкале 0–100% | `summary.comparison.completion_percent` |
| Доля повторных визитов по модулям | TODO: согласовать идентификацию человека и границы визита | Заготовка без SQL | — |

Повторные визиты пока не рассчитываются. Разные тесты в одном посещении
не следует считать возвращениями пользователя. Новый гостевой аккаунт нельзя
автоматически связать с прежним человеком.

## Таблица сравнения

Коллекция и дашборд `summary.table`, график `summary.table.comparison`.
Одна строка на модуль; столбцы поддерживают сортировку в Metabase.

| Колонка | Содержимое |
|---|---|
| Код модуля | `module_id` |
| Модуль | Название функционального модуля |
| Взаимодействия | Число начатых сессий |
| Среднее время, мин | Средняя длительность завершённых с известным временем |
| % завершения | Завершённые / начатые × 100% |
| Повторные визиты (позже) | NULL до реализации; не 0% |

## Дополнительные графики

Коллекция и дашборд `summary.additional`.

| Показатель | Расчёт | Визуализация | Ключ графика |
|---|---|---|---|
| Доля каждого модуля в общем взаимодействии | Сессии модуля / сессии всех выбранных модулей × 100%; запрос возвращает количества для долей Metabase | Круговая диаграмма | `summary.additional.share` |
| Динамика популярности модулей | Стартовые сессии по календарным дням МСК | Линия на каждый модуль | `summary.additional.popularity_daily` |
| Активность по модулям по часам | Количество стартов по часу суток 0–23, суммарно за период, МСК | Линия на каждый модуль | `summary.additional.activity_hourly` |

Для почасового графика у представленных модулей часы без стартов заполнены нулями.
Это распределение по времени суток, а не хронология отдельных часов разных дат.

## Фильтры

Все десять графиков и четыре дашборда поддерживают:

- `date_from` — начало периода;
- `date_to` — конец включительно;
- `module_id` — один или несколько кодов модулей;
- `device_id` — одно или несколько устройств, дополнительное сужение выборки.

По умолчанию — последние 30 календарных дней, `Europe/Moscow`.
Сессии с неизвестным устройством входят в общую выборку, но не в фильтр
конкретного устройства. При фильтрации модулей доли пересчитываются внутри
выбранных модулей.

## Развёртывание и проверки

```bash
docker compose exec api python infra/clickhouse/scripts/update.py --verify
docker compose exec api python infra/metabase/scripts/deploy.py summary.common
docker compose exec api python infra/metabase/scripts/deploy.py summary.comparison
docker compose exec api python infra/metabase/scripts/deploy.py summary.table
docker compose exec api python infra/metabase/scripts/deploy.py summary.additional --verify
```

Обновления выполняются через PUT, сохраняя ID коллекций и дашбордов;
новые вопросы получают постоянные ключи из таблиц выше. Связи доступны через
`GET /api/analytics/catalog`. Повторное развёртывание сохраняет ID вопросов.

Проверка SQL без записи событий, временных таблиц, PostgreSQL и Redis:

```bash
docker compose exec api python infra/tests/module_summary_queries.py
```
