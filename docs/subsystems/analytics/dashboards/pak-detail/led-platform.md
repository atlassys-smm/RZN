## Общие показатели

Дашборд `led.common` охватывает индивидуальную и командную викторины:
`module_id IN (1, 2)`. Заставка и другие сценарии пока не подключены.
Одна реально начатая игра означает одно взаимодействие независимо от числа
участников. Одинаковые `session_id` разных режимов — разные игры.

| Показатель | Расчёт | Ключ |
|---|---|---|
| Количество сессий/взаимодействий | Реальные старты по `module_sessions` | `led.common.sessions` |
| Сессии по дням | Те же старты, сгруппированные по московской дате | `led.common.sessions_daily` |
| Среднее время | Средний `duration_ms / 60000` завершённых игр с известным временем, включая паузы; сравнение с предыдущим периодом той же длины | `led.common.average_minutes` |
| Доля завершённых | Игры с окончанием / все стартовавшие × 100% | `led.common.completion_percent` |
| Уникальные пользователи | Различные известные `user_id` по `visitor_activity` за период, включая участников снимка старта общей игры | `led.common.users` |

Сессионные показатели индивидуальной и командной викторины учитывают только
игры с `has_participants=true`. Признак из миграции ClickHouse
`0009_quiz_has_participants.sql` означает хотя бы одно свидетельство участия:
положительный `participant_count` или непустой `participants[]` на старте либо
событие `PARTICIPANT_JOINED=2` в любое время этой сессии. `user_id` может быть
неизвестен; отвечать на вопросы для учёта не обязательно. Пустые команды сами
по себе не дают участников.

Присоединения ищутся по полной паре `(module_id, session_id)`,
без ограничения датами отчёта. Приход после старта, в том числе после конца
выбранного периода, делает сессию учитываемой в периоде её старта. Пока
участников нет, незавершённая игра также исключается. Доставка best effort:
при потере всех свидетельств участия игра может быть исключена ошибочно.

`participant_count`, `team_count` и размеры команд сохраняют прежний смысл:
это снимок на старте, а не итог за всю игру. Поэтому учитываемая игра с поздним
присоединением может иметь нулевой `participant_count` на старте. Исходные
события сохраняются; правило пересчитывает и прошлые периоды. Пользователи
по времени действия и другие показатели активности, не основанные на когорте
сессий, не получают дополнительного ограничения по старту игры.

Сессии, динамика, длительность, завершённость и таблица игр за выбранный период
отбираются по старту. Таблица выводит игры без SQL-лимита количества строк,
с сортировкой от новых к старым; ключ `quiz.recent_sessions` сохранён. Окончание может быть позже периода; пропущенные вопросы
не мешают игре считаться завершённой. Без старта окончание не увеличивает
счётчик; без окончания игра остаётся незавершённой. У каждой игры равный вес
в среднем времени; неизвестные длительности исключены только из среднего.
Без стартов счётчик равен 0, динамика пуста, доля завершённых — NULL.
Без текущих известных длительностей карточка времени пуста и не подставляет
прошлое значение; без предыдущего значения сравнение не вычисляется.

Уникальные пользователи отбираются по времени действия, независимо от старта
сессии. Поэтому активность продолженной игры или регистрация без старта может
дать пользователя без новой сессии в периоде. Один `user_id` учитывается один раз
между режимами; неизвестный `is_guest` не исключает его. Это цифровая активность:
разные гостевые аккаунты одного человека не объединяются, пользователи без
идентификации не учитываются. Без активности счётчик равен 0.

Фильтры — начало и конец периода включительно и ID устройства. По умолчанию
последние 30 календарных дней, `Europe/Moscow`; таблица использует те же границы.
Предыдущий период непосредственно предшествует выбранному и имеет столько же
календарных дней. Фильтр устройства исключает неизвестный `device_id`.
Пять новых SQL-вопросов поддерживают подписанное iframe-встраивание с
`locked`-параметрами; их ключи и ID доступны через справочник аналитики.
Повторы факта устраняются через `events_unique`; доставка best effort может
терять события и искажать показатели. История автоматически не восстанавливается.

Безопасная проверка: `docker compose exec api python infra/tests/led_feedback_queries.py`.
Обновление: `docker compose exec api python infra/metabase/scripts/deploy.py led.common --verify`.

## Заставка (режим ожидания)

- **% времени в режиме заставки** — расчётная доля остатка от 8 часов за сутки
  после вычитания суммы времени сессий каждого устройства, кроме обратной связи.
  Ключ `led.screensaver.time_percent`; путь:
  **Аналитика / Детальная аналитика по модулям / LED-медиаплатформа / Заставка**.

Источник — `analytics.module_sessions`. Берётся время от старта до окончания
или явного прерывания, включая паузы. Сессии относятся к дате старта по Москве;
ночное рабочее окно не задаётся, пересекающиеся сессии просто суммируются.
Пустые викторины также учитываются. Сессии без старта, окончания/прерывания,
с отрицательным интервалом или неизвестным `device_id`, а также обратная связь
(`module_id=5`) и модуль заставки (`module_id=12`) исключаются. При сумме от 8 часов остаток равен нулю.

Устройства определяются по стартам сессий учитываемых модулей до конца выбранного периода.
Устройство только с обратной связью не добавляется в расчёт.
Каждому известному устройству отводится 8 часов на каждый день периода;
дни без сессий дают 100%. Общая доля — сумма остатков / (8 часов × число
устройств × число дней). Если устройств нет или период обратный — нет данных.
Фильтры: начало/конец периода включительно и ID устройства; по умолчанию
последние 30 календарных дней, `Europe/Moscow`.
Это приближённый расчёт: выключение устройства и отсутствие событий
не отличаются от работы заставки. Сейчас в расчёт входят события викторин
и ПрофСтарт; новые модули учитываются после подключения их
жизненного цикла с `device_id`.

Проверка: `docker compose exec api python infra/tests/screensaver_time_queries.py`.
Обновление: `docker compose exec api python infra/metabase/scripts/deploy.py led.screensaver --verify`.

### «Профессии в действии» (в режиме заставки)

- **Количество запусков профессий** — карточка с числом (сколько профессий запускалось всего)
- **Количество участников голосования** — карточка с числом + линейный график по времени (сколько человек участвовало в голосовании)
- **Популярные вакансии для голосования** — таблица с сортировкой (название профессии, количество участников голосования)

## Индивидуальная викторина

- **Количество запусков** — карточка с числом + столбчатая диаграмма по дням
- **Доля завершённых** — прогресс-бар 0–100%: игры с окончанием / все начатые; без стартов — нет данных. Ключ `quiz.individual.completed`, формула и ID сохранены.
- **% правильных ответов** — карточка с процентом
- **Среднее количество участников** — карточка с числом
- **Топ-5 личных результатов** — горизонтальная диаграмма лучших баллов каждого пользователя за период по дате завершения.

## Командная игра

- **Количество командных сессий** — карточка с числом + столбчатая диаграмма по дням (динамика)
- **Среднее количество команд** в сессии — карточка с числом + линейный график по времени (как менялось)
- **Среднее количество человек в команде** — карточка с числом + линейный график по времени
- **Среднее время игры** — карточка с числом в минутах + линейный график по времени
- **Распределение количества команд в сессии** — гистограмма (сколько сессий было с 2, 3, 4... командами)
- **Распределение количества человек в команде** — гистограмма (как распределялись размеры команд)
- **Распределение времени игры** — гистограмма с шагом 5 минут: 0–5, 5–10,
  10–15 минут и далее. Нижняя граница интервала включается, верхняя — нет;
  на оси X показана нижняя граница в минутах. Учитываются только завершённые
  командные игры с известной длительностью; период выбирается по старту игры.


### Правильность и личное участие

| Показатель | Расчёт | Ключ |
|---|---|---|
| Процент правильных ответов | Правильные итоговые ответы команд / все оценённые итоговые ответы × 100% | `quiz.team.correct` |
| Процент участников, ответивших хотя бы на один вопрос | Участники команд с личным принятым ответом / все участники команд × 100% | `quiz.team.answered_any` |

Оба показателя отбирают командные игры по старту и `has_participants`,
поддерживают начало/конец периода включительно (Europe/Moscow) и ID устройства.
Факты после конца периода входят в расчёт выбранных игр. Без заданных дат
используется вся история, как в остальных специальных показателях командной игры.

Правильность считается по `ANSWER_EVALUATED=3`: один итоговый ответ команды
на один вопрос. Обычные личные голоса не меняют правильность команды;
пропущенные вопросы не входят в знаменатель. Завершение сессии не обязательно.
При отсутствии оценённых ответов карточка пуста; если все ответы неверные — 0%.

Личное участие считается по `ANSWER_SUBMITTED=6`, отправляемому после принятия
ответа обычного участника или капитана. Текст/вариант ответа не передаётся;
раскрытие вопроса и правильность не требуются. Повторное обращение с уже
принятым ответом не создаёт факта. Ключ — вопрос сессии и participant_id.

Знаменатель участия — участники с ненулевым team_id в снимке на окончание
игры; поздние участники входят, участники без команды исключаются.
При переносе между командами participant_id учитывается один раз в сессии;
личный ответ в предыдущей команде также подтверждает участие. Капитан входит
на общих основаниях. Известный user_id не требуется. Один человек в двух
сессиях — две единицы. Это общий процент по участникам, а не среднее процентов
команд или игр: крупные команды имеют больший вес.

Только завершённые игры со стартовым `tracks_participant_answers=true` и
итоговым снимком `participants[]` подходят для процента участия. Маркер
отделяет игры, в которых сбор личных ответов работал с самого начала;
старые игры и игры, начатые до обновления, не дают ложного нуля.
Состав на старте в существующих графиках не меняется. Если подходящих
участников нет, карточка пуста; если они есть, но никто не ответил — 0%.
Доставка best effort может потерять ответы и занизить процент либо потерять
старт/окончание и исключить игру. История личных ответов не восстанавливается.
Новые персональные события также учитываются в событийной активности,
посещаемости и тепловой карте по существующим правилам.

Показатель «ответили на все вопросы» отложен; список вопросов для него
не собирается и карточка не создаётся.

Проверка без изменения данных:
`docker compose exec api python infra/tests/team_answer_queries.py`.
Обновление: `docker compose exec api python infra/metabase/scripts/deploy.py led.team --verify`.
