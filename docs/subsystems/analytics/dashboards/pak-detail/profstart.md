# Аналитика ПрофСтарт

Одна сессия TestSession — одно прохождение одного теста. Три методики у одного
пользователя — три прохождения. [API ПрофСтарт](../../../../api/profstart.md).

## Текущий этап

События старта, принятого ответа, завершения, прерывания и рекомендации
подключены к четырём представлениям ClickHouse (миграция 0006) и дашборду
Metabase `pak.profstart`. Его 13 SQL-вопросов заменяют прежние заготовки:
общие показатели, динамика по дням и восемь согласованных специальных графиков.
«Самые популярные вопросы» удалены. ID коллекции и дашборда сохраняются при PUT.
Отдельный HTTP API аналитики не добавляется; справочник /api/analytics/catalog
возвращает ключи, ID и ссылки графиков. Рекомендации в «Вовлечённости» продолжают
работать с прежним контрактом.

## События

Отправитель: `app/services/analytics/profstart.py`; точки вызова — сервис
прохождений `app/services/profstart/session_service.py`. Все события поступают
в общую асинхронную очередь только после успешного commit бизнес-операции.
ORM-объекты в очередь не передаются; payload формируется внутри транзакции
из сохранённых значений. HTTP-запрос не ждёт ClickHouse.

Во всех событиях software_id=3 (PROFSTART), module_id=4 (PROFSTART),
session_id — ID TestSession, user_id — пользователь прохождения.
device_id и device_type пока неизвестны и остаются NULL. Возраста в payload нет.

Общие параметры payload событий 1, 6, 4 и 9:

| Поле | Значение |
|---|---|
| test_id | ID закреплённой версии теста |
| test_type_id | ID типа теста |
| test_code_type | Код типа, например solomin, holland, dellinger |
| test_version | Номер закреплённой версии |
| test_name | Название версии на момент факта |
| question_count | Полное число вопросов прохождения |

### Начало: SESSION_STARTED = 1

После успешного `POST /profstart/sessions`. occurred_at берётся из сохранённого
started_at. Дополнительных полей к общему payload нет.
event_key: `profstart:<session_id>:start`. Отклонённый повтор старта не создаёт факта.

### Принятый ответ: ANSWER_SUBMITTED = 6

После первого успешного сохранения ответа через `POST /profstart/answer`.
occurred_at — сохранённый TestAnswer.answered_at.

| Дополнительное поле | Значение |
|---|---|
| question_id | ID вопроса закреплённой версии |
| question_order | Порядок вопроса |
| question_text | Текст вопроса для подписи в будущей таблице времени ответа |
| answer_option_id | ID принятого варианта |
| group_id | Группа выбранного варианта |
| group_code | Код группы; у Деллингера — square, triangle, circle, zigzag, rectangle |
| group_name | Снимок названия группы |
| category | Категория группы: subject/labor, riasec, geometry либо категория дополнительного типа |
| value | Вклад варианта: сохранённый value или 1, когда value=NULL |
| answered_count | Количество принятых ответов после операции |
| duration_ms | Интервал от старта или предыдущего принятого ответа в миллисекундах |

Первый ответ: `(answered_at - started_at) × 1000`.
Следующие: `(answered_at - предыдущий answered_at) × 1000`.
Предыдущий ответ берётся только из той же сессии, до добавления текущего.
Миллисекунды округляются вниз; отрицательный интервал заменяется нулём.
Паузы, время между запросами и возвращения в тест входят в интервал. Это не
измерение чистого времени просмотра вопроса. Отдельный запрос показа вопроса
или клиентский таймер не добавляются. Незавершённая сессия также может иметь ответы.

event_key: `profstart:<session_id>:answer:<question_id>`.
Повтор уже принятого варианта возвращает прежний прогресс без нового события;
неверный вариант и отклонённый запрос не создают факта.

### Успешное завершение: SESSION_FINISHED = 4

После сохранения последнего ответа и результата. occurred_at — completed_at.

| Дополнительное поле | Значение |
|---|---|
| answered_count | Итоговое число принятых ответов |
| finish_reason | completed |
| duration_ms | completed_at − started_at в миллисекундах, включая паузы |
| group_scores | Полный сохранённый снимок показателей групп, включая нули |

Каждый элемент group_scores содержит group_id, group_code, group_name,
category, raw_score, max_score, normalized_score, rank и is_leading.
Три поля баллов передаются JSON-числами, даже если в источнике результата
они сохранены строками Decimal. Используется снимок
user_recommendation_sources.group_scores, без повторного расчёта.

У Соломина семь общих показателей want + can, отдельного axis нет.
Пять subject и две labor рассматриваются отдельно. Нулевые значения сохраняются;
при нулях ведущих групп нет. Все положительные равные максимумы сохраняются
как is_leading=true. В Голланде сохраняются все шесть типов, у Деллингера — пять фигур.
Поддерживаются также дополнительные типы и их фактически сохранённые группы.

event_key: `profstart:<session_id>:finish`.
Событие создаётся и при пустом списке рекомендованных профессий. Последний ответ
даёт событие 6, затем 4, затем события 5 для профессий. Ошибка commit или расчёта
откатывает последний ответ и результат, ни один из этих фактов не отправляется.
Порядок доставки в ClickHouse не используется как источник времени или связей.

### Явное прерывание: SESSION_ABANDONED = 9

После перехода в ABANDONED через пользовательский
`POST /profstart/sessions/{id}/abandon` либо операторский
`POST /cms/profstart/sessions/{session_id}/abandon`.

| Дополнительное поле | Значение |
|---|---|
| answered_count | Прогресс на момент прерывания |
| finish_reason | abandoned |
| duration_ms | Интервал от started_at до явного прерывания |

occurred_at фиксируется сервером при переходе статуса; в PostgreSQL отдельный
abandoned_at пока не добавляется. event_key: `profstart:<session_id>:abandon`.
Повтор прерывания уже прерванной сессии не создаёт факт. Завершённую сессию
прервать нельзя. Закрытие вкладки без вызова API не объявляется прерыванием:
такая сессия остаётся in_progress. Прерванная попытка и повторный старт имеют разные ID.

### Рекомендации: PROFESSION_RECOMMENDED = 5

Существующий контракт сохраняется: по одному факту на profession_id из полного
сохранённого списка рекомендаций теста. Поля payload: test_id, test_type_id,
test_code_type, test_version, profession_id, profession_name, score, position.
occurred_at=completed_at. event_key:
`profstart_profession_recommended:<session_id>:<profession_id>`.
Пять профессий создают пять событий, но остаются одним прохождением и одним подбором.
Список не ограничивается тремя профессиями общего профиля; пустой список допустим.
Просмотр профессии не выводится из факта рекомендации.

### Повторы и ограничения доставки

GET состояния, вопроса и результата не создаёт событий. После завершения повтор
последнего ответа получает прежний 409 без новых фактов. Блокировки сервиса
сохраняют один переход при конкурирующих запросах. Стабильные ключи задают UUID
факта; представления используют дедуплицированные события и ключ
(software_id, module_id, session_id). Доставка остаётся best effort: при аварии,
переполнении или исчерпании повторов события могут теряться. Старые сессии,
ответы и результаты автоматически не выгружаются; для них нет выдуманных событий.

## Подключённые показатели

Период выбирает сессии по started_at; завершения и результаты этих сессий
учитываются и при завершении за пределами выбранного периода. Необходимо
сначала собрать состояние сессии, затем фильтровать по её старту.
Результаты считаются только по завершённым сессиям выбранной когорты.

| Показатель | Расчёт |
|---|---|
| Количество прохождений | Уникальные начатые session_id; разрезы по типу и версии, внутри — завершённые/незавершённые |
| Сравнение результатов | Внутри типа и версии по группе: число результатов, средние raw_score/normalized_score и доля is_leading; нули включаются |
| Процент незавершённых | (начатые − завершённые) / начатые × 100%; включает in_progress и abandoned, при нулевом знаменателе — нет данных |
| Среднее время ответа | Среднее duration_ms события 6 по вопросу, включая ответы незавершённых сессий; повтор не добавляет ответ |
| Рекомендуемые профессии, топ-10 | Число уникальных пар session_id + profession_id; доля от всех завершённых, средний score только среди рекомендаций этой профессии |
| Частота выбора фигур | Выборы пяти фигур среди завершённых сессий Деллингера; один результат — одна фигура, сумма долей 100% |
| Распределение типов Голланда | Число результатов с ведущим RIASEC-типом / все завершённые результаты Голланда; все равные максимумы учитываются, сумма долей может превышать 100% |
| Соломин | Семь общих показателей want + can; отдельные категории subject/labor, без разделения на «Хочу» и «Могу» |

График «Самые популярные вопросы» исключён из согласованного состава.
Группы разных методик не смешиваются. Число подборов по событию 5 не заменяет
число завершений: тест без рекомендаций всё равно завершён. Подписи групп и
профессий в событиях — снимки на момент факта, переименование справочника их
не изменяет. Общий подбор с весами 40/40/20 — отдельная логика профиля, не
частота профессий по результатам отдельных тестов.

## Представления и фильтры

| Представление | Данные |
|---|---|
| analytics.profstart_sessions | Старт, окончание, прерывание, прогресс и статус; completed определяется событием 4, не числом рекомендаций |
| analytics.profstart_answers | Принятые ответы с интервалами и снимками подписей вопросов |
| analytics.profstart_group_results | Развёрнутый group_scores из события 4, включая нули и равные ведущие группы |
| analytics.profstart_recommendations | Уникальные session_id + profession_id из событий 5 |

Все представления читают analytics.events_unique, software_id=3 и module_id=4.
Соединения используют все три части ключа (software_id, module_id, session_id).
Событие ответа или окончания без старта остаётся в представлениях, но не
попадает в когорту дашборда. Рекомендации старого потока без событий старта и
завершения также не становятся прохождениями. Исторические записи сохраняются;
задним числом старты и итоги не создаются.

Фильтры дашборда: date_from, date_to, test_code_type, test_version, test_id,
device_id. По умолчанию — последние 30 календарных дней, Europe/Moscow;
конец выбранной даты включителен. Только начало/только конец дополняются
соответствующей границей по умолчанию. Если конец раньше начала, когорта пуста.
Тип передаётся кодом (solomin, holland, dellinger либо дополнительный тип).
Тип, версия, ID теста и ID устройства поддерживают несколько значений.
При выборе неизвестного устройства или несовместимых фильтров данные отсутствуют.
События с device_id=NULL не попадают в выборку конкретного устройства.

Среднее время завершённых сравнивается с предыдущим периодом такой же длины.
Отсутствующий текущий результат не заменяется прошлым. Счётчики пустой когорты
дают 0, проценты — NULL, круговая диаграмма и среднее время — пустой результат.
Нули результатов групп входят в средние, исходные баллы разных версий и методик
не объединяются. На графиках групп и фигур версия обозначена отдельно.

## Ключи Metabase

| Ключ графика | Показатель |
|---|---|
| profstart.sessions | Количество прохождений |
| profstart.average_minutes | Средняя длительность и сравнение периодов |
| profstart.completion_percent | Круговая диаграмма завершённых/незавершённых |
| profstart.users | Уникальные пользователи |
| profstart.sessions_daily | Динамика прохождений по дням |
| profstart.attempts_by_type | Завершённые/незавершённые по типу и версии |
| profstart.result_comparison | Таблица сравнения групп внутри версии |
| profstart.solomin_groups | Семь общих результатов Соломина |
| profstart.holland_types | Доли ведущих типов Голланда |
| profstart.figures | Частота выбора фигур Деллингера |
| profstart.unfinished_percent | Процент незавершённых |
| profstart.answer_time | Среднее время ответа по вопросам |
| profstart.professions_top10 | Горизонтальный топ-10 рекомендуемых профессий |

Шаблон: `infra/metabase/collections/analytics/details/profstart/collection.json`.
Обновление через существующий контейнер API:

```bash
docker compose exec api python infra/clickhouse/scripts/update.py --verify
docker compose exec api python infra/metabase/scripts/deploy.py pak.profstart --verify
```

Проверка формул без записи событий и создания таблиц:

```bash
docker compose exec api python infra/tests/profstart_queries.py
```

Проверяются позднее завершение и ответ, московская граница даты, повторная
доставка, нулевые результаты, равные ведущие типы, несколько версий,
незавершённые сессии, пустые рекомендации, фильтры и отсутствие данных.
Скрипт использует встроенные события через CTE, рабочая таблица не меняется.
