# Аналитика «Аватар профессий»

Одна генерация — одно сохранённое задание `AvatarGeneration`. Каждый успешный
POST создаёт новое задание, даже с теми же параметрами. Повторы отправки в FaceAI,
опрос статуса и повторная доставка webhook не создают новых генераций.

## Источники и события

Отправитель — `app/services/analytics/avatar.py`. Снимок формируется внутри
транзакции; факты поступают в общую очередь только после успешного commit.
Доставка best effort, как в других модулях; очередь в памяти не является outbox.
Файлы, URL, селфи и токены в аналитику не передаются.

Для генераций `module_id=6`, `session_id=AvatarGeneration.id`, `user_id` —
владелец задания, `device_id` — терминал создания. `is_guest` — снимок статуса
пользователя на момент события, а не чтение текущего профиля при построении графика.

| event_id | Событие | occurred_at | event_key |
|---|---|---|---|
| 1 | SESSION_STARTED — задание создано | created_at | avatar:<id>:start |
| 4 | SESSION_FINISHED — результат сохранён | completed_at | avatar:<id>:finish |
| 13 | AVATAR_GENERATION_FAILED — ошибка | completed_at | avatar:<id>:failed |
| 14 | AVATAR_GENERATION_EXPIRED — истёк срок | completed_at | avatar:<id>:expired |
| 15 | AVATAR_UPLOADED — отдельно загружен готовый файл | UserAvatar.created_at | avatar:upload:<avatar_id> |

Общий payload генерации: `generation_id`, `profession_id`, `profession_name`,
`template_id`, `gender`, `status`. Завершающие события добавляют `duration_ms`,
`finish_reason` (`completed`, `failed`, `expired`) и `error_code`.
Длительность — `max(0, completed_at − created_at)` в миллисекундах.
Промежуточные статусы очереди и обработки не отправляются.

Успех и ошибки учитываются и при webhook, и при резервном опросе FaceAI.
Истечение срока учитывается при чтении задания, webhook и фоновом обходе.
Блокировка записи защищает от повторных завершений и гонки опроса с webhook;
стабильный event_key задаёт тот же UUID при повторной доставке факта.

Прямой `POST /api/users/avatars` имеет отдельное событие 15 с `avatar_id`,
`profession_id` и `profession_name`; `session_id` и `device_id` не заданы.
Факт не входит в показатели генераций. Удаление сохранённого изображения
не удаляет исторические события и не уменьшает число успешных генераций.
Исторические файлы, сохранённые до подключения событий, автоматически не переносятся.

Миграция `0013_avatar_views.sql` добавляет три представления:

- `analytics.avatar_generations` — одна строка на задание, старт, успешное
  завершение, ошибка, просрочка, длительность и снимок профессии на первом событии;
- `analytics.avatar_activity` — события генераций для уникальных пользователей;
- `analytics.avatar_uploads` — отдельные загрузки готовых изображений.

Представления читают `events_unique`, поэтому повтор UUID не увеличивает счётчики.
Общие `module_sessions` и `visitor_activity` также получают события модуля 6:
сводка считает созданные задания и их успешное завершение, посещаемость —
пользователей событий, включая отдельные загрузки.

## Графики Metabase

Коллекция и дашборд сохраняют ключ `pak.avatar` и существующие ID установки.
Восемь SQL-вопросов заменяют шесть текстовых заготовок: число генераций и
динамика представлены отдельными вопросами, добавлен отдельный счётчик загрузок.

| Ключ | График и расчёт |
|---|---|
| avatar.generations | Количество заданий с известным стартом в выбранном периоде |
| avatar.daily | Те же задания по дням Europe/Moscow |
| avatar.average_minutes | Среднее время только успешных заданий выбранной по старту когорты, включая очередь FaceAI; сравнение с предыдущим периодом той же длины |
| avatar.completion | Доля успешных среди всех созданных заданий; отдельные категории «Успешные», «В процессе», «Ошибки», «Истёк срок» |
| avatar.unique_users | Уникальные user_id с событиями генераций в периоде, включая гостей |
| avatar.professions | Полный рейтинг профессий по успешным генерациям выбранной по старту когорты; группировка по ID, подпись из снимка |
| avatar.user_types | Уникальные пользователи событий генераций: последний известный is_guest в периоде; при равном времени приоритет OAuth; NULL — «Неизвестно» |
| avatar.uploads | Число отдельных загрузок готовых изображений по времени события |

Период генераций выбирается по старту, результат может быть получен позже конца
периода. Пользователи и их типы выбираются по времени действия, как в посещаемости:
завершение ранее созданного задания входит в активность периода.
Один user_id попадает в одну категорию. Гостевые аккаунты одного физического
человека не объединяются. Результат без стартового события не увеличивает число
запусков, рейтинг и долю успеха, но его пользователь входит в активность.

Фильтры: `date_from`, `date_to` включительно, `device_id`, `profession_id`.
Даты и группировка — Europe/Moscow. Без дат — последние семь календарных дней,
включая сегодня. Для отдельных загрузок доступны только даты и профессия:
устройство в прежнем пути сохранения не фиксируется. Это указано в описании дашборда.
Фильтры устройства и профессии поддерживают несколько значений.

Пустые счётчики возвращают 0; диаграммы, рейтинг и среднее время — отсутствие
данных. Пустой период не отображается как 0% успеха или нулевое среднее.
Все вопросы разрешены для существующего API встраивания с enabled-параметрами;
новый HTTP API аналитики не добавляется. Ключи доступны через `/api/analytics/catalog`.

## PDF-отчёт

Страница 7 недельного и месячного отчёта использует те же SQL-вопросы:
число генераций, долю успеха, среднее время, уникальных пользователей,
их типы, отдельные загрузки и топ-5 профессий по успешным результатам.
KPI и рейтинг сравниваются с предыдущим календарным периодом отчёта;
среднее время берётся из последней строки соответствующей карточки.
Последующие страницы сдвинуты на одну позицию, всего 12 страниц.

## Обновление и проверки

```bash
docker compose exec api python infra/tests/avatar_queries.py
docker compose exec api pytest tests/avatar_generations/ -q
docker compose exec api python infra/clickhouse/scripts/update.py --plan
docker compose exec api python infra/clickhouse/scripts/update.py --verify
docker compose exec api python infra/metabase/scripts/deploy.py pak.avatar --plan
docker compose exec api python infra/metabase/scripts/deploy.py pak.avatar --verify
```

API-тесты запускаются только после проверки изоляции тестовых PostgreSQL и Redis.
SQL-проверки используют заданные события внутри SELECT и не пишут рабочие данные.
