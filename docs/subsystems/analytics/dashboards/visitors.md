# Аналитика по посетителям

Активность определяется по цифровым событиям с `user_id`. Один ID может
участвовать в нескольких модулях. Разные гостевые ID считаются отдельно.
Источники — ClickHouse для статистики и PostgreSQL для имени и аватарки.
Запросы профилей и токенов встраивания доступны сотрудникам ADMIN и ANALYST
и устройствам с ролью QUIZ_VIDEO (1).

## Вопросы Metabase

Коллекция **Аналитика → Посетители** описана в
`infra/metabase/collections/analytics/visitors/collection.json`.
Ключи появляются в `GET /api/analytics/catalog` после публикации коллекции.

| Ключ | Что возвращает | Параметры кроме периода, модуля и устройства |
|---|---|---|
| `visitors.list` | `user_id`, `visitor_type`, `first_activity_at`, `last_activity_at`, `active_days`, `modules`, `total` | `user_id` для точного отбора, `visitor_type`, `limit`, `offset` |
| `visitors.summary` | Тип, даты первой и последней активности, число активных дней и событий | `user_id` в фильтре |
| `visitors.daily` | `day`, `events` | `user_id` в фильтре |
| `visitors.modules` | `module_id`, `events` | `user_id` в фильтре |
| `visitors.views` | `kind`, `entity_id`, `organization_type`, `name`, `views` | `user_id` в фильтре |
| `visitors.activity` | Сессии и события, время последней активности, устройство, детали сессии и `total` | `user_id` в фильтре, `limit`, `offset` |

Для всех шести вопросов доступны `date_from`, `date_to`, `module_id` и
`device_id`. Даты передаются в формате YYYY-MM-DD и включаются целиком по
Москве. По умолчанию `date_to` — сегодня, `date_from` — за шесть дней до
`date_to`. При фильтре по устройству события без устройства исключаются.

Для списка и истории размер страницы по умолчанию равен 20, максимум — 100.
`total` содержит размер отфильтрованной выборки в каждой строке. При пустой
странице Metabase возвращает пустой массив строк. Фронтенд сбрасывает
`offset` при смене фильтров и определяет наличие следующей страницы по
`total` из непустой страницы.

## Как фронтенд получает данные

1. Запросить токены через `POST /api/analytics/embed-tokens`, передав только
   нужные ключи, например `{"keys":["visitors.list","visitors.summary","visitors.daily"]}`.
2. Для каждого токена читать
   `GET {METABASE_URL}/api/embed/card/{token}/query`. Для карточки передавать
   `user_id` в параметрах запроса вместе с датами и остальными фильтрами.
   Колонки находятся в `data.cols`, строки — в `data.rows`. Токен относится к
   вопросу Metabase и переиспользуется для разных посетителей и периодов.
   Если для карточки не передать ID, она вернёт пустые данные или нулевую сводку.
3. Загрузить профили через `POST /api/analytics/visitors/profiles` с телом
   `{"user_ids":[42,57]}`. Запрос принимает от 1 до 100 ID. Ответ содержит
   объект `profiles` с ключами ID и полями `first_name`, `last_name`, `file`.
   Повторы объединяются. Отсутствующие профили не включаются в ответ. В `file`
   возвращается стандартный объект файла с подписанной ссылкой или `null`.

## Правила расчёта

Список, сводка и два графика активности используют
`analytics.visitor_activity`. Представление объединяет персональные события
из `analytics.events_unique` и участников из снимка старта викторины.
Тип `user` или `guest` определяется по последнему известному `is_guest`
в периоде. При отсутствии известного типа возвращается `unknown`. Активные
дни считаются по календарным датам Москвы.

Просмотры берутся из событий профессий, образовательных программ и организаций.
Отрасль учитывается из снимка просмотра профессии. В выдаче до десяти объектов
на вид, отдельно по типам организаций.

В истории одна строка сессии соответствует паре `(module_id, session_id)`.
Время строки — последняя активность посетителя в выбранной выборке. Даты начала,
окончания и результат берутся по всей сессии и могут выходить за границы
периода. Просмотры и прямые загрузки аватаров возвращаются отдельными
событиями. Баллы ПрофСтарта и оценки анкет выдаются в JSON-строках
`group_scores_json` и `ratings_json` при наличии. Полные ответы анкет
доступны через `GET /api/cms/surveys/responses?user_id=…`.

## Какие показатели можно получить

### Список и охват — `visitors.list`

Одна строка соответствует одному `user_id` с активностью после применения
фильтров. По умолчанию первыми идут посетители с наиболее свежей активностью.

| Показатель | Как получить |
|---|---|
| Число посетителей в выборке | Взять `total` из любой строки. Значение уже учитывает фильтры и содержит число уникальных посетителей на всех страницах |
| Число гостей, пользователей или посетителей с неизвестным типом | Запросить список с `visitor_type=guest`, `user` или `unknown` и взять `total`. Для общего обзора можно использовать готовые карточки [посещаемости](general.md#посещаемость) |
| Первая и последняя активность посетителя | `first_activity_at` и `last_activity_at` внутри выбранного периода, модуля и устройства |
| Число дней активности | `active_days`. Несколько событий в один календарный день дают один день |
| Модули, которыми пользовался посетитель | `modules` содержит уникальные коды модулей в выборке. Длина массива показывает число модулей |

Тип определяется по последнему известному `is_guest` в выборке. Например,
если гость авторизовался в течение периода и после этого совершил действие,
его строка получает тип `user`. При пустой первой странице охват равен нулю.
Если пустая страница запрошена с ненулевым `offset`, вернуться к первой странице,
чтобы узнать актуальный `total`.

### Сводка и графики активности

Для всех вопросов карточки передавать один `user_id` и одинаковые фильтры.

| Показатель | Вопрос | Как получить |
|---|---|---|
| Всего событий, активные дни, первая и последняя активность | `visitors.summary` | Взять `events`, `active_days`, `first_activity_at` и `last_activity_at`. Без событий счётчики равны нулю, даты пустые |
| Среднее число событий за активный день | `visitors.summary` | Разделить `events` на `active_days`, если активных дней больше нуля |
| Активность по дням | `visitors.daily` | Ось X — `day`, ось Y — `events`. Для непрерывной шкалы фронтенд может добавить пропущенные даты с нулём |
| Активность по модулям | `visitors.modules` | Показать `events` по `module_id`. Для доли модуля разделить его `events` на общий счётчик из сводки с теми же фильтрами |

Сумма `events` по дням и сумма по модулям дают общий счётчик событий при
одинаковых фильтрах. Одно прохождение может создать события старта, ответов и
завершения. Для числа игр, тестов и анкет следует считать строки сессий в
`visitors.activity`.

### Просмотры каталога — `visitors.views`

| Что показать | Какие строки взять |
|---|---|
| Просмотренные профессии | `kind=profession` |
| Отрасли по просмотрам профессий | `kind=industry` |
| Просмотренные образовательные программы | `kind=education_program` |
| Просмотренные работодатели | `kind=organization` и `organization_type=1` |
| Просмотренные учебные заведения | `kind=organization` и `organization_type=2` |

Для таблицы или горизонтальной диаграммы использовать `name` и `views`.
`entity_id` можно использовать для перехода к объекту. Повторное открытие
карточки увеличивает счётчик. Просмотр профессии может одновременно попасть
в строку профессии и её отрасли. Каждая категория содержит до десяти
позиций, поэтому сумма `views` по ней показывает объём просмотров топа.
Для полного числа просмотров нужны строки соответствующих событий из
`visitors.activity`.

### Прохождения и история — `visitors.activity`

`kind=session` означает строку сессии с ключом `(module_id, session_id)`.
`kind=event` означает отдельное событие с ключом `event_uuid`. Для временной
шкалы использовать `occurred_at`. У сессии это время последнего учтённого
действия посетителя в выборке. У отдельного события это время самого события.

| Показатель | Какие строки считать или показать |
|---|---|
| Сколько викторин сыграл посетитель | `kind=session`, `module_id=1` или `2`, есть `started_at`. Для числа игр с зафиксированным окончанием добавить `status=completed`. Для личных баллов взять `score` из строк индивидуальной викторины (`module_id=1`) |
| Какие тесты ПрофСтарта проходил | `kind=session`, `module_id=4`. `name` и `test_version` показывают название и версию. `answered_count` и `question_count` дают прогресс, если число вопросов известно |
| Сколько тестов ПрофСтарта завершил | Из строк ПрофСтарта считать `status=completed`. `abandoned` показывает прерванные прохождения. Для графика результата разобрать `group_scores_json` и взять `group_name` и `normalized_score`. Доступны также набранные и максимальные баллы `raw_score` и `max_score` |
| Сколько анкет отправил | `kind=session`, `module_id=5`, `status=completed`. `name` — анкета, `source_id` — источник. Из `ratings_json` можно показать вопросы и числовые оценки |
| Сколько раз запускал генерацию аватара | `kind=session`, `module_id=6`, есть `started_at`. Для успешных генераций считать `status=completed`; `failed` и `expired` показывают ошибки и истечение срока. Прямые загрузки считать отдельно по `kind=event`, `event_id=15` |
| Сколько раз открывал карточки каталога | `kind=event`: `event_id=10` — организация, `11` — профессия, `12` — образовательная программа. Для разделения организаций использовать `organization_type` |
| Длительность конкретной сессии | `duration_ms` при наличии. Для минут разделить на 60 000. Для общей викторины поле содержит длительность игры |

Для счётчиков нужно собрать **все страницы** истории с одинаковыми фильтрами.
`total` в истории содержит число строк вместе с отдельными событиями и
сессиями в разных состояниях. Например, чтобы получить «3 викторины,
2 завершённых теста, 1 отправленная анкета», сначала отобрать строки
`kind=session`, затем применить условия из таблицы отдельно к каждому модулю.

История отбирает сессию по наличию активности посетителя в периоде. Её
`started_at` и `ended_at` могут находиться за пределами периода. Для
показателя «завершено в эти даты» дополнительно проверить `ended_at` по
московскому времени. Сессии без учтённой активности посетителя в периоде в
этот отбор не попадут. Для викторины `completed` означает зафиксированное
окончание игры. Сумма длительностей сессий не определяет время пребывания.

Коды модулей в текущих данных: `1` — индивидуальная викторина, `2` —
командная, `4` — ПрофСтарт, `5` — обратная связь, `6` — аватар профессий,
`13` — организации, `14` — профессии, `15` — образовательные программы.
