## Миграция загрузки бэкенда

Миграция `0075_seed_professions_data` использует фиксированную копию JSON в
`app/migrations/data/professions_data.json`, независимо от следующих изменений документации.
Перед загрузкой она устанавливает `deleted_at=now()` всем предыдущим записям таблиц:
`industries`, `directions`, `industry_branches`, `professions`, `organizations`,
`education_programs`, `profession_employers`, `profession_education_programs`,
`profstart_test_group_professions`.

Новые строки получают автоинкрементные ID. Исходные ID используются только для построения
соответствий новым ID и переноса внешних ключей. Работодатели (`type=1`) и учебные заведения
(`type=2`) имеют отдельные соответствия, поскольку их исходные ID пересекаются.
В фактическом файле у программ нет `id`: связи ссылаются на позиции в массиве с единицы.
Названия из связей не используются для поиска, поэтому варианты написания работодателей
и одинаковые названия программ у разных учебных заведений не меняют привязку.

Профессиональные направления `directions` в файле отсутствуют. Существующие направления
помечаются удалёнными, а новые профессии загружаются с `direction_id=NULL`.
Индустрия работодателя определяется через `industry_branch_id`; его дополнительные исходные
`industry_id` и `industry` не переносятся. Отсутствующие необязательные сведения остаются NULL.

Откат `0075` устанавливает `deleted_at=now()` всем текущим строкам перечисленных таблиц,
включая записи, созданные после загрузки. Он не восстанавливает старые записи и не удаляет
строки физически. Последовательности ID не сбрасываются.

Миграция требует подключения к БД для получения новых ID; формирование offline SQL загрузки
не поддерживается. Подготовка файла миграции не означает её применение. Справочные CRUD-методы исключают строки с `deleted_at`; физическое удаление заменено мягким.


### Связи профессий с группами ПрофСтарта

`0074_add_profstart_group_profession_deleted_at` добавляет nullable timestamp with time zone
`deleted_at` в `profstart_test_group_professions`; загрузка выполняется отдельно в `0075`.
В JSON добавлены `profstart_test_types`, `profstart_test_groups` и `profstart_test_group_professions`.
Типы и группы создаются только при отсутствии: существующие названия, описания и файлы CMS сохраняются.
Несоответствие категории существующей группы останавливает загрузку с откатом транзакции.
Связи содержат `test_code_type`, `group_code` и исходный `profession_id`.
Тип и группа определяются по кодам; профессия — по карте исходный ID → только что созданный ID.
ID записей связей также выдаёт автоинкремент. Названия для связывания не используются.

Загружаются 386 связей для 94 профессий: Соломин — 188 (по одной subject и labor),
Голланд — 94, Деллингер — 104 (основная фигура плюс 10 дополнительных связей rectangle).
Демонстрационный тип `practical_interests` не заполняется.

Для `dellinger.rectangle` выбраны: Оператор технической поддержки, Веб-разработка,
Информационные системы и программирование, Робототехника, Археология, Биотехнология,
Эколог, Дизайн, Специалист по туризму, Социально-культурная деятельность.
Это редакционная подборка для знакомства с разными областями при поиске направления.
[Официальный PsychoGeometrics](https://psychogeometrics.com/resources/blog/i-dont-know-said-the-rectangle/)
описывает прямоугольник как временное состояние перемен, открытости новому и поиска;
фиксированного профессионального ключа для него источник не задаёт.

CMS выдаёт только активные связи с активными профессиями. DELETE устанавливает `deleted_at`;
повторный DELETE возвращает 404. POST удалённой пары восстанавливает её прежний ID,
а повтор активной пары возвращает 409. Удалённые связи не участвуют в новых рекомендациях
и проверке полноты пар Соломина; сохранённые результаты остаются прежними.
