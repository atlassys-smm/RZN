# API рекомендаций пользователя

GET `/api/users/me/recommendations` принимает User JWT либо Device JWT с ролью 3 и действующей QR-привязкой. Для устройства обязателен X-Device-Connection-Id из /device/auth/user; пользователь определяется по Redis-привязке. При User JWT используется владелец токена. user_id в запрос не передаётся. До первого сохранённого источника ответ 200 содержит JSON null. Исходные баллы и веса клиент не передаёт. Итоговый рейтинг рассчитывается при каждом запросе из снимков источников и не сохраняется.

| Поле | Назначение |
|---|---|
| `id`, `user_id` | Профиль и его владелец |
| `created_at`, `updated_at` | Создание профиля и последнее добавление или обновление источника |
| `is_complete` | Получены все обязательные источники с положительным весом; views необязателен |
| `available_weight` | Сумма весов имеющихся источников с положительным весом |
| `weights` | Модуль source_module, код source_code и вес weight из кода |
| `missing_sources` | Недостающие обязательные источники с положительным весом: объекты source_module и source_code |
| `sources` | Использованные источники: id, source_module, source_code, source_reference, updated_at, weight и effective_weight_percent |
| `professions` | До трёх профессий: profession_id/name, description, file, score, position, contributions |
| `employers` | До пяти работодателей по профессиям итогового рейтинга |
| `educations` | До пяти учебных заведений по профессиям итогового рейтинга |
| `education_programs` | До пяти направлений подготовки по профессиям итогового рейтинга |

В каждой профессии `description` — текущее описание из справочника профессий или `null`, если оно не заполнено. Изменение описания видно в следующем GET без пересчёта баллов и изменения снимков источников. Описание возвращается также для мягко удалённых профессий из сохранённых рекомендаций.

contributions содержит source_id, source_module, source_code, weight, effective_weight_percent, test_score, contribution и reasons каждого источника. reasons — снимок объяснений поставщика источника; ПрофСтарт сохраняет группы и нормированные показатели. Десятичные поля этих вложенных объяснений могут быть строками. Нулевая оценка профессии в пройденном источнике не исключает его вес из знаменателя.

Источник определяется парой source_module и source_code: например, profstart и solomin. Одинаковые коды разных модулей независимы. Последний ответ любого типа атомарно добавляет источник с показателями групп и профессий. Источники дополнительных типов сохраняются наравне со встроенными, но без настройки в SOURCE_WEIGHTS не участвуют в итоговом рейтинге. Веса заданы в `app/models/user_recommendations/weights.py`: 40/40/15 для Соломина, Голланда и Деллингера и относительный вес 5 для professions/views; через CMS не меняются. Изменение весов в коде влияет на следующий GET. Изменение связей профессий, подписей групп или названий не пересчитывает старые источники. Каждый тип можно завершить один раз, независимо от версии. Источник с весом 0 сохраняется, но не входит в sources текущей выдачи.

Порядок профессий: score DESC, profession_id ASC. Полный набор из трёх не гарантируется; возможен пустой массив professions при существующем профиле. Наличие всех источников может давать is_complete=true даже при пустом рейтинге. Ошибка авторизации — 401.

Исторический результат отдельного теста доступен через `/api/profstart/sessions/{id}/result` с массивом scores.

[Сущности](../entities/user-recommendations.md) · [Формулы](../subsystems/profstart/results.md).

Мягкое удаление профессии (`deleted_at`) не исключает её из ранее сохранённых рекомендаций: ID, название и исходные баллы берутся из снимка источника. При новом прохождении подбираются только активные профессии по активным связям.

## Рекомендации организаций и направлений

По максимум трём профессиям из итогового рейтинга рассчитываются три отдельных списка: `employers` (до 5 работодателей типа 1), `educations` (до 5 учебных заведений типа 2) и `education_programs` (до 5 направлений подготовки). Работодатели определяются через profession_employers, учебные заведения — через profession_education_programs → education_programs → organization_education_programs → organizations. Направления подбираются непосредственно через profession_education_programs → education_programs, независимо от наличия организаций. В каждом списке сначала идут записи с большим числом различных совпавших профессий, затем с меньшим ID. Несколько программ одной профессии не увеличивают её вклад в рейтинг организации. Элементы списков организаций содержат `organization` (полные данные организации), `profession_ids` (по возрастанию ID), `profession_count` и `position` (1–5). В списке направлений вместо `organization` возвращается `education_program`: id, name, education_level, duration, base_class, created_at, updated_at; остальные поля совпадают. Общее направление возвращается один раз независимо от числа его организаций. Профессии, связи, программы и организации с deleted_at участвуют в расчёте для сохранённых рекомендаций. Данные и связи читаются в текущем состоянии при каждом GET; снимки этих трёх списков не сохраняются. При отсутствии профессий или соответствующих связей массивы пустые; до создания профиля ответ остаётся null.

## Организации и направления по выбранным профессиям

GET `/api/organizations/recommendations?profession_ids=1&profession_ids=2&profession_ids=3`
принимает от 1 до 3 различных ID профессий. Достаточен действующий JWT пользователя,
гостя, сотрудника любой роли или активного устройства; сохранённый профиль не требуется.

Ответ содержит `employers`, `educations` и `education_programs` в том же формате и с теми же правилами ранжирования, что и `/users/me/recommendations`: до пяти организаций каждого типа и отдельно до пяти направлений. Выше больше различных совпавших профессий, затем ID организации или направления по возрастанию. Направления выбираются по прямым связям с профессиями, независимо от организаций; поле `education_program` содержит полные данные направления, рядом возвращаются `profession_ids`, `profession_count` и `position`. Учитываются профессии, связи, программы и организации с `deleted_at`. Результат не сохраняется.

Отсутствие связей даёт пустые массивы. Неизвестный ID — 404; отсутствующий параметр,
повторяющиеся ID, больше трёх ID или неверный формат — 422; недействительный JWT — 401.

### Покрытие выбранных профессий

Правило покрытия применяется отдельно к каждому из трёх списков: employers, educations, education_programs. Сначала формируется топ-5 по числу различных совпавших профессий DESC и ID организации или направления ASC. Затем проверяется покрытие каждой выбранной профессии. Если для неё есть связанные записи, но ни одна не попала в топ-5, лучшая из них заменяет последнюю запись, удаление которой не лишает покрытия другие профессии. Одна запись может покрывать несколько профессий. После замен сохраняется сортировка по рейтингу; лимит — 5 уникальных записей в каждом списке. Если соответствующих связей нет, покрытие этой профессии в данном списке не требуется.

Правило действует для `/users/me/recommendations` и `/organizations/recommendations`, в том числе для профессий, связей, программ и организаций с `deleted_at`.

Профессия связана с общим направлением независимо от организации. Для каждого выбранного направления учитываются все его учебные заведения через organization_education_programs; отдельная привязка профессии к каждому заведению не требуется.

В каждой профессии возвращается `file`: собственный файл, а при пустом media_id — male_photo_file_id её шаблона аватара; если файлов нет, null. Правило совпадает с карточкой профессии. Данные файла читаются при GET, в снимки источников не записываются.

## Просмотры в рекомендациях

Перед расчётом сервер обновляет источник `professions/views`, если он отсутствует
или старше 6 часов. Первый импорт охватывает 30 суток, следующие — события
`[updated_at, начало выборки)`, которые прибавляются к накопленным количествам.
Оценка профессии — `100 × просмотры / максимум просмотров` по всему источнику.
Пустой источник исключён из расчёта; отсутствие просмотров не препятствует полноте
профиля. При сбое ClickHouse используются прежние данные без сдвига updated_at.
Поле `sources[].updated_at` позволяет определить актуальность сохранённого снимка.
Подробности хранения и точных границ — в [сущности источника](../entities/user-recommendations.md#источник-просмотров-профессий).
