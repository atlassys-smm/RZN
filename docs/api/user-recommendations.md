# API рекомендаций пользователя

GET `/api/users/me/recommendations` принимает User JWT либо Device JWT с ролью 3 и действующей QR-привязкой. Для устройства обязателен X-Device-Connection-Id из /device/auth/user; пользователь определяется по Redis-привязке. При User JWT используется владелец токена. user_id в запрос не передаётся. До первого сохранённого источника ответ 200 содержит JSON null. Исходные баллы и веса клиент не передаёт. Итоговый рейтинг рассчитывается при каждом запросе из снимков источников и не сохраняется.

| Поле | Назначение |
|---|---|
| `id`, `user_id` | Профиль и его владелец |
| `created_at`, `updated_at` | Создание профиля и последнее добавление источника |
| `is_complete` | Получены все ожидаемые источники с положительным весом |
| `available_weight` | Сумма весов имеющихся источников с положительным весом |
| `weights` | Модуль source_module, код source_code и вес weight из кода |
| `missing_sources` | Недостающие источники с положительным весом: объекты source_module и source_code |
| `sources` | Использованные источники: id, source_module, source_code, source_reference, weight и effective_weight_percent |
| `professions` | До трёх профессий: profession_id/name, score, position, contributions |
| `employers` | До пяти работодателей по профессиям итогового рейтинга |
| `educations` | До пяти учебных заведений по профессиям итогового рейтинга |

contributions содержит source_id, source_module, source_code, weight, effective_weight_percent, test_score, contribution и reasons каждого источника. reasons — снимок объяснений поставщика источника; ПрофСтарт сохраняет группы и нормированные показатели. Десятичные поля этих вложенных объяснений могут быть строками. Нулевая оценка профессии в пройденном источнике не исключает его вес из знаменателя.

Источник определяется парой source_module и source_code: например, profstart и solomin. Одинаковые коды разных модулей независимы. Последний ответ любого типа атомарно добавляет источник с показателями групп и профессий. Источники дополнительных типов сохраняются наравне со встроенными, но без настройки в SOURCE_WEIGHTS не участвуют в итоговом рейтинге. Веса заданы в `app/models/user_recommendations/weights.py`: 40/40/20 для Соломина, Голланда и Деллингера; через CMS не меняются. Изменение весов в коде влияет на следующий GET. Изменение связей профессий, подписей групп или названий не пересчитывает старые источники. Каждый тип можно завершить один раз, независимо от версии. Источник с весом 0 сохраняется, но не входит в sources текущей выдачи.

Порядок профессий: score DESC, profession_id ASC. Полный набор из трёх не гарантируется; возможен пустой массив professions при существующем профиле. Наличие всех источников может давать is_complete=true даже при пустом рейтинге. Ошибка авторизации — 401.

Исторический результат отдельного теста доступен через `/api/profstart/sessions/{id}/result` с массивом scores.

[Сущности](../entities/user-recommendations.md) · [Формулы](../subsystems/profstart/results.md).

Мягкое удаление профессии (`deleted_at`) не исключает её из ранее сохранённых рекомендаций: ID, название и исходные баллы берутся из снимка источника. При новом прохождении подбираются только активные профессии по активным связям.

## Рекомендации организаций

По максимум трём профессиям из итогового рейтинга рассчитываются employers (до 5 работодателей типа 1) и educations (до 5 учебных заведений типа 2). Связи: profession_employers и profession_education_programs → education_programs → organizations. Порядок внутри каждого типа: число различных совпавших профессий DESC, ID организации ASC. Несколько программ одной профессии не увеличивают её вклад. Каждая запись содержит organization (полные данные организации), profession_ids (по возрастанию ID), profession_count и position (1–5). Профессии, связи, программы и организации с deleted_at участвуют в расчёте для сохранённых рекомендаций. Организации и связи читаются в текущем состоянии при каждом GET; снимок организаций не сохраняется. При отсутствии профессий или связей массивы пустые; до создания профиля ответ остаётся null.

## Организации по выбранным профессиям

GET `/api/organizations/recommendations?profession_ids=1&profession_ids=2&profession_ids=3`
принимает от 1 до 3 различных ID профессий. Достаточен действующий JWT пользователя,
гостя, сотрудника любой роли или активного устройства; сохранённый профиль не требуется.

Ответ содержит `employers` и `educations` в том же формате и с теми же правилами ранжирования,
что и `/users/me/recommendations`: до пяти организаций каждого типа, выше больше различных
совпавших профессий, затем ID организации по возрастанию. Учитываются профессии, связи,
программы и организации с `deleted_at`. Результат не сохраняется.

Отсутствие связей даёт пустые массивы. Неизвестный ID — 404; отсутствующий параметр,
повторяющиеся ID, больше трёх ID или неверный формат — 422; недействительный JWT — 401.

### Покрытие выбранных профессий

Сначала формируется обычный топ-5 по числу различных совпавших профессий DESC и ID организации ASC. Затем проверяется покрытие каждой выбранной профессии в каждом типе организаций. Если для профессии есть связанные организации, но ни одна не попала в топ-5, лучшая из них заменяет последнюю организацию, удаление которой не лишает покрытия другие профессии. Одна организация может покрывать несколько профессий. После замен сохраняется сортировка по рейтингу; лимит — 5 уникальных организаций каждого типа. Если связей данного типа нет, покрытие для этой профессии не требуется.

Правило действует для `/users/me/recommendations` и `/organizations/recommendations`, в том числе для профессий, связей, программ и организаций с `deleted_at`.
