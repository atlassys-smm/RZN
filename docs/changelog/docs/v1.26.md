## Изменения

### Задержки вместо флагов

Удалены булевы `auto_reveal` и `auto_next`. Вместо них — nullable-задержки:

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `auto_reveal_delay` | integer, nullable | `0` | Задержка от закрытия приёма до показа ответа |
| `auto_next_delay` | integer, nullable | `null` | Задержка от показа ответа до следующего вопроса |
| `between_rounds_delay` | integer, nullable | `10` | Задержка между раундами |

**Значения:**
- `null` — действие отключено
- `0` — выполнить без ожидания
- положительное число — задержка в секундах

Задержки отсчитывает клиент перед вызовом API. Сервер не проверяет время и не сохраняет временные метки. Миграция 0058 переносит старые флаги в задержки.

### Финальный раунд

`POST /api/quiz/sessions/{id}/final-round` — добавляет и запускает финальный раунд:
- Доступен после раскрытия последнего вопроса последнего раунда
- Создаёт раунд типа `FINAL = 9` с вопросами
- Поддерживает `question_ids` или `question_count` с фильтрами
- `can_start_final_round` — вычисляемое поле в состоянии сессии
- Добавить финал можно один раз; повторный запрос → 409
- После финала — обычный `/finish`

### Раскрытие ответа: `current_question.revealed`

В объекте текущего вопроса добавлен `revealed` (boolean):
- `false` до раскрытия и при запуске нового вопроса
- `true` после ручного или автоматического reveal
- Одинаков для всех ролей, независимо от `select`
- В `waiting`/`finished` объекта `current_question` нет

### Досрочное закрытие: `all_answered`

После ответа последнего участника (индивидуальная) или капитана последней непустой команды (командная):
- Приём ответов закрывается автоматически
- Отправляется событие `all_answered` (только `type`)
- Применяется обработка как при окончании таймера через `/led/next`
- Голос капитана всегда решающий, независимо от `is_final`

### Сессии устройства (WebSocket)

`/api/device/sessions/ws?token=<device_jwt>` — уведомления о сессиях устройства:
- `session_started` — создана викторина или запущен показ видео
- `session_finished` — завершена викторина или видео
- Payload: `device_id`, `session_id`, `module` (`quiz`/`interactive_video`)
- Доступен любым активным устройствам (включая без ролей)
- Только свои сессии; User и StaffUser не допускаются

### Имена участников

Имена в REST-состоянии берутся из `users.first_name` и `users.last_name`:
- Для гостя: `first_name="Гость"`, `last_name=str(users.id)`
- Отображается как «Гость {id}»
