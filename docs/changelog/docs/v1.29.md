## Изменения

### Чтение групп ПрофСтарт пользователем

Новые эндпоинты для отображения информации о группах на экране результата:
- `GET /api/profstart/test-types/{test_code_type}/groups` — список групп с пагинацией
- `GET /api/profstart/test-types/{test_code_type}/groups/{group_id}` — карточка группы

Доступно по User JWT (включая гостя) и Device JWT с ролью ПрофСтарт (3), без QR-привязки. Группы являются общим справочником, доступны независимо от статуса версии теста.

### Изображения тестов и групп ПрофСтарт

- Миграции 0063 и 0064: `media_id` (nullable FK → files) в `profstart_tests` и `profstart_test_groups`
- Создание и PATCH тестов/групп в CMS переведены на `multipart/form-data`: `file`, `file_preview`, `file_title`, `file_description`
- `age_group_ids` передаётся JSON-массивом в текстовом поле
- Все ответы содержат объект `file` с подписанными ссылками или null
- При копировании теста сохраняется ссылка на файл; PATCH без нового файла сохраняет вложение

### Возрастные группы — enum вместо таблицы

- Таблица `age_groups` и ORM-модель заменены enum `AgeGroup` в коде
- Фиксированные значения: `1` — 12–14 лет, `2` — 15–17 лет
- Миграция 0065 удаляет таблицу `age_groups`
- Пользовательский и CMS-справочники сохраняют маршруты и формат ответов
- Проверка ID использует enum без запросов к таблице

### Каталог ПрофСтарт — статус прохождения

`GET /api/profstart/tests` теперь возвращает все активные тесты (включая завершённые и без сессий):
- Новое поле `session_status` — статус последней сессии пользователя по типу теста (1/2/3 или null)
- Фильтр `session_status=1/2/3` — оставить только тесты с соответствующим статусом
- Статус берётся среди всех версий по `started_at DESC, id DESC`
- Устройство без QR-привязки получает `session_status=null`; с привязкой — историю подключённого пользователя

### Список вопросов сессии викторины для оператора

`GET /api/quiz/sessions/{session_id}/questions` — все вопросы всех раундов сессии:
- Доступен admin/operator
- Порядок по раундам и вопросам, включая финальный раунд
- Вычисляемый `GameSessionQuestionStatus`: 1 — пройден, 2 — текущий, 3 — будущий
- До старта все вопросы будущие; pause/reveal/stop сохраняют текущий вопрос до перехода
- GET не меняет состояние игры
