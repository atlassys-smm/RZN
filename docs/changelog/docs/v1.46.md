## Изменения

### Список сотрудников

`GET /api/staff?limit=20&offset=0` — список сотрудников (только администратор):
- Возвращает активных и заблокированных сотрудников в порядке ID
- Ответ `{items, total}`; `total` считается до пагинации
- Поля: `id`, `email`, `first_name`, `last_name`, `role`, `status`
- Хеши паролей и токены не возвращаются
- `limit` по умолчанию 20, `offset` — 0

### Удаление сотрудников

`DELETE /api/staff/{staff_id}` — физическое удаление (только администратор):
- В одной транзакции: refresh-токены → сессии авторизации → учётная запись
- Access/refresh-токены удалённого сотрудника перестают работать
- Email освобождается для повторной регистрации
- Другие сотрудники и пользовательские данные не затрагиваются
- Собственную учётную запись удалить нельзя — `409`
- Отсутствующий или уже удалённый ID — `404`
- Статуса DELETED нет; остаются ACTIVE=1 и BLOCKED=2
- Миграция БД не требуется

### Обновление документации ролей и статусов

Роли и статусы сотрудников приведены к integer enum:
- Роли: `1` — admin, `2` — operator, `3` — analyst, `4` — content_editor
- Статусы: `1` — active, `2` — blocked
- Таблица запросов сотрудников в auth-sessions.md
