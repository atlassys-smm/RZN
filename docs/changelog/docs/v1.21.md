## Изменения

### WebSocket викторины — переработка протокола

Все WebSocket-события викторины теперь содержат **только `type`**, без `data`. Состояние игры по сокету не передаётся — клиент запрашивает его через REST после каждого события.

**Было:** `{"type": "session_state", "data": {...}}`
**Стало:** `{"type": "session_state"}`

#### Новые события

Добавлены уведомления об операциях с командой и таймером:

| Событие | Описание |
|---------|----------|
| `participant_joined` | Участник вошёл в сессию |
| `participant_team_changed` | Выбор команды или перенос оператором |
| `captain_changed` | Назначение капитана |
| `team_renamed` | Изменение названия команды |
| `timer_paused` | Таймер на паузе |
| `timer_resumed` | Отсчёт возобновлён |
| `timer_updated` | Добавлено время |
| `timer_stopped` | Приём ответов закрыт оператором |
| `timer_expired` | Приём ответов закрыт по времени |

Удалена подписка через `subscribe` — канал получает все события сессии.

#### Порядок работы клиента

1. Подключение к WebSocket
2. Запрос состояния: `GET /quiz/sessions/active?device_id=...&select=teams&select=participants`
3. При получении события — повторный запрос REST для обновления

Начальный `session_state` при подключении **не отправляется**.

### REST API — счётчики и select

- `GET /quiz/sessions/active` и `GET /quiz/sessions/{id}` возвращают:
  - `round_count` — общее количество раундов
  - `current_round_question_count` — число вопросов в текущем раунде (до старта — в первом)
- Параметр `select` теперь `explode: true` — повторяющиеся значения: `select=teams&select=participants`
- Капитан получает ответы команды через `GET /quiz/sessions/{id}?participant_id={captainParticipantId}`

### WebSocket видеосценариев

- Проверка существования сессии до принятия WebSocket (несуществующая → HTTP 403 при handshake)
- Начальное состояние клиент запрашивает через REST (`/state` или `/voting`)

### OpenAPI — расширение x-websocket-channels

Добавлено расширение `x-websocket-channels` для машиночитаемого описания WebSocket-каналов:

- `quiz-session` — канал викторины
- `interactive-video-session` — канал видеосценариев

Схемы событий: `QuizWebSocketEvent`, `InteractiveVideoWebSocketEvent`.

### Обновлённые интерфейсы

- **LED-экран (викторина)** — после каждого события запрашивает REST, сокет содержит только тип
- **Планшет оператора** — добавлены события таймера и команды, запрос REST с `select=teams&select=participants`
