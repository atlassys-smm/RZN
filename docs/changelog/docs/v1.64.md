## Изменения

### Сохранение рекомендаций

Последняя персональная подборка теперь хранится в PostgreSQL:
- Новая таблица `user_recommendations_result` хранит одну последнюю подборку на пользователя
- Поля: `user_id`, `result` (jsonb), `input_fingerprint`, `created_at`, `updated_at`, `refresh_after`
- Пересчёт запускается при:
  - Новом источнике
  - Изменении `updated_at` источника
  - Изменении весов или справочников
  - Истечении суток с последнего расчёта
- Три списка организаций (`employers`, `educations`, `education_programs`) сохраняются вместе с рейтингом профессий

### Отчёты по карьерным маршрутам

Новые эндпоинты для аналитики рекомендаций:

**`GET /api/analytics/recommendations`** — JSON отчёт:
- Рейтинги профессий, отраслей, работодателей и учебных заведений за выбранную неделю или месяц
- Список участников определяется по действиям за период в `analytics.visitor_activity`
- Для каждого активного участника берётся последняя сохранённая подборка
- Учитываются обычные и гостевые пользователи с положительными баллами профессий
- Служебные аккаунты исключаются
- Охват — доля уникальных участников
- Доля маршрутов учитывает нормализованные баллы профессий
- Вес профессии делится между организациями отдельно для обучения и работы
- `salary_ranges` — доли маршрутов по зарплатным диапазонам:
  - `under_50` — ниже 50 тыс. ₽
  - `50_to_100` — от 50 до 100 тыс. ₽ включительно
  - `over_100` — свыше 100 тыс. ₽
  - `unknown` — отсутствующая зарплата
- Доступ: администратор и аналитик

**`GET /api/analytics/recommendations/report`** — PDF отчёт:
- Границы периода и агрегаты совпадают с JSON
- Рейтинги отраслей и десяти ведущих профессий
- Лидеры среди учебных заведений и работодателей
- В приложении для каждой профессии — все связанные учебные заведения и работодатели
- В карточке профессии — исходные границы зарплаты из `salary_range`
- Русское имя файла в `Content-Disposition`

### Доступ к рекомендациям пользователя для сотрудников

`GET /api/users/me/recommendations` расширен:
- Принимает Staff JWT администратора или аналитика
- Администратор и аналитик указывают пользователя в query-параметре `user_id`
- Отсутствующий `user_id` для сотрудника → 422
- Неизвестный пользователь → 404
