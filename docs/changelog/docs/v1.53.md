## Изменения

### Улучшения PDF-отчёта

Обновлены колонтитулы PDF-отчёта аналитики:
- Слева — «Аналитика», справа — тип периода, номер календарной недели (для недельного), фактические даты
- Год выводится после конечной даты; при пересечении границы года — у обеих дат

### Редактирование сотрудников

`PATCH /api/staff/{staff_id}` — частичное обновление (только администратор):
- Поля: `first_name`, `last_name`, `email`, `role`, `status`
- Хотя бы одно поле обязательно; пропущенные сохраняются
- Email нормализуется (lowercase), занятый → 409
- Смена роли учитывается со следующего запроса
- Блокировка (status=2) отзывает все сессии; после разблокировки нужен новый вход
- Нельзя понизить собственную роль или заблокировать себя → 409
- Пароль этим запросом не меняется

### Фильтр активности устройств

`GET /api/cms/devices?is_active=true|false`:
- `true` — только активные устройства
- `false` — только неактивные
- Без параметра — все устройства (прежний порядок по дате создания)

### Привязка типов анкет к модулям

Новая таблица `survey_module_links` (миграция 0100):
- Составной PK: `(module_id, survey_type)`
- `SurveyModuleType`: 1 — инд. викторина, 2 — командная, 3 — профессии в действии, 4 — ПрофСтарт, 6 — аватар

**API управления привязками:**
- `GET /api/cms/surveys/module-links` — чтение (admin/content_editor/analyst)
- `PUT /api/cms/surveys/module-links/{module_id}/{survey_type}` — добавление (admin/content_editor), идемпотентный
- `DELETE /api/cms/surveys/module-links/{module_id}/{survey_type}` — удаление (admin/content_editor), 204

**Фильтр module_id в списках анкет:**
- `GET /api/feedback/surveys?module_id=4` и `GET /api/cms/surveys?module_id=4`
- Фильтрация до пагинации, `total` учитывает фильтр
- Кеш разделён по модулю; изменение привязок инвалидирует кеш

### Поиск вопросов викторины

`GET /api/cms/quiz/questions?query=...`:
- Поиск по подстроке текста вопроса без учёта регистра
- Пробелы по краям удаляются; пустой query не фильтрует
- Символы `%` и `_` ищутся буквально
- Сочетается с другими фильтрами; учитывается в `total` до пагинации

### ClickHouse в каталоге хоста

Новая настройка Compose `CLICKHOUSE_DATA_PATH`:
- Позволяет хранить данные ClickHouse в каталоге хоста вместо Docker-тома
- Без значения сохраняется прежний том `clickhouse_data`
- Перенос данных и изменение рабочего окружения автоматически не выполняются

### Развёртывание с данными на хосте

Новый файл `docs/subsystems/deployment-host-storage.md`:
- Инструкция по размещению PostgreSQL, ClickHouse, Metabase и API данных в `/srv/profnavigator`
- Дополняет основное развёртывание; выбирается до первого запуска контейнеров
