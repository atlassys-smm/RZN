## Изменения

### Генерация аватаров через FaceAI

Интеграция с внешним сервисом FaceAI v2 для генерации аватаров профессий:

**`POST /api/users/avatar-generations`** — создание задания:
- Активное устройство с ролью 2 и действующая QR-привязка
- Multipart: `template_id`, `gender` (1/2), `photo` (JPEG/PNG)
- Каждый POST создаёт отдельное задание с новым `request_id` (UUID)
- Несколько активных генераций на пользователя; срок — 24 часа
- Эталон используется по исходному File.id без копирования
- Ответ 202; до настройки FaceAI задание создаётся в ожидании

**`GET /api/users/avatar-generations/{request_id}`** — статус и результат:
- Device JWT с ролью 2 и QR-привязка владельца
- При успехе: `avatar_id`, `qr_token`, объект `file`
- При ошибке: `error_code`; просроченное задание → статус 6
- Чужое задание → 404

**`POST /api/faceai/webhook`** — приём результата FaceAI:
- Отдельный Bearer-токен `FACEAI_WEBHOOK_TOKEN`
- Проверка request_id, job_id, пользователя, образа, версии, совпадения event_id
- Повтор определяется по статусу заблокированной записи
- Успех сохраняет JPEG, UserAvatar и статус одной транзакцией
- Webhook может прийти раньше HTTP-ответа создания

**WebSocket `/api/avatar/ws`** — уведомления:
- Device JWT с ролью 2; события только своих генераций
- `generation_status_changed` после коммита: статусы 1–6
- Payload: user_id, generation_id, request_id, job_id, device_id, status
- Постоянный REST-опрос не нужен; после reconnect — GET статуса

**Фоновый обработчик:**
- Повтор после сетевых сбоев и 429 с учётом Retry-After
- Резервный опрос FaceAI и скачивание JPEG при пропущенном webhook
- Временная аренда задания (120 сек); восстановление после перезапуска
- Дедлайн 24 часа обрабатывается фоном даже без настройки FaceAI

### Файл профиля пользователя

Миграция 0085: `users.avatar_url` → `users.media_id` (FK → files.id):
- Профиль и ответы привязки возвращают стандартный объект `file` с подписанными ссылками
- `PATCH /api/user/info` принимает `multipart/form-data`: `file`, `file_preview`, `file_title`, `file_description` + поля профиля
- JSON-обновление полей сохранено
- OAuth Яндекс/VK скачивает изображение в хранилище; при ошибке — 503 без изменения пользователя
- При следующем входе изображение скачивается заново; отсутствующее не стирает текущий файл

### Превью аватаров профессий

CMS API создания и обновления эталонных образов:
- `male_file_preview` и `female_file_preview` — необязательные превью
- При обновлении превью передаётся вместе с соответствующим исходником
- Превью без исходника → 422
- Проверка MIME-типа и сигнатуры JPEG/PNG без декодирования

### Аватары пользователя — обновления

`GET /api/me/avatars`:
- Необязательный фильтр `profession_id`
- Пагинация: `limit` (по умолчанию 20), `offset`
- `total` учитывает пользователя и профессию до пагинации

`DELETE /api/me/avatars/{avatar_id}`:
- Удаляется аватар и итоговый файл; исходники генерации сохраняются
- Поздний webhook не восстанавливает удалённый аватар

### Автоматическое включение Metabase embedding

`infra/metabase/scripts/deploy.py` включает `enable-embedding-static` перед созданием карточек, в том числе при `--init`. Это предотвращает ошибку `Embedding is not enabled` на новой установке. `--plan`, `--verify` и `--check-env` не изменяют настройки.
