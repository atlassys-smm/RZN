## Изменения

### Система авторизации и аутентификации

Полная реализация управления доступом для сотрудников, посетителей и устройств.

#### Сотрудники (StaffUser)

- Вход по email/паролю (`POST /api/auth/login`)
- Роли: `1` — admin, `2` — operator, `3` — analyst, `4` — content_editor
- Статусы: `1` — active, `2` — blocked
- Создание нового сотрудника — только администратором (`POST /api/auth/staff`)
- Интерактивная команда создания первого администратора: `python -m app.cli.create_admin`

#### Посетители и OAuth

- **Гостевой вход** (`POST /api/auth/user/guest`) — создание гостя на 24 часа с согласием
- **OAuth Яндекс ID / VK ID** (`GET /api/auth/user/oauth/{provider}`) — обмен одноразового кода на сервере
- Привязка действующего гостя к OAuth-аккаунту
- Поиск пользователя по паре `(oauth_provider, oauth_provider_id)`, без объединения по email
- Сохранение профиля: `first_name`, `last_name`, email, пол, дата рождения, `avatar_url`

#### Серверные сессии и токены

- **Access** — JWT (максимум 30 минут) с `sub`, `type`, `sid`, `iat`, `exp`, `iss`, `aud`, `jti`
- **Refresh** — криптографически случайная строка, только в HttpOnly cookie
- Сессия сотрудника/OAuth — 7 дней, гостя — 24 часа
- Ротация refresh: повтор использованного токена отзывает всю сессию
- Logout отзывает текущую сессию (`POST .../logout`)
- Cookie: `staff_refresh` (Path `/api/auth`), `user_refresh` (Path `/api/auth/user`)
- Проверка Origin/Referer для защиты от CSRF

#### Роли устройств

- Таблица `device_roles`: одно устройство может работать в нескольких модулях
- Роли: `1` — викторина и профессии в действии, `2` — аватар, `3` — ПрофСтарт, `4` — обратная связь
- Управление ролями: `PUT /api/cms/devices/{device_id}/roles`
- Device-маршруты проверяют нужную роль по актуальным данным БД

#### Подключение пользователя к устройству (QR)

- `POST /api/device/auth/qr` — создание QR-кода для подключения пользователя
- `GET /api/device/auth/qr/{code}` — открытие QR и переход на мобильный фронтенд
- `POST /api/device/auth/confirm` — подтверждение подключения с телефона
- `GET/DELETE /api/device/auth/user` — получение/завершение подключённого пользователя
- WebSocket `/api/device/auth/ws` — уведомления о событиях подключения
- Привязка хранится в Redis (до часа), QR действует 2 минуты
- Передаётся `X-Device-Connection-Id` для личных действий

### Авторизация WebSocket

- Сокеты викторины и видео требуют JWT в query `token`
- Поддерживаются User, Device и StaffUser
- Проверка выполняется только при подключении (до accept)
- Device требуется роль 1 и своё устройство
- В викторине User должен быть участником

### Изменения игровых контрактов

- `POST /quiz/sessions/{id}/join` и `/interactive-video/sessions/{id}/join` — требуют пользовательский access, не создают гостя
- В викторине повторный join сохраняет одного участника на User и сессию
- Вступление в команду не требует тела
- Ответ викторины принимает только `answer` и `is_final`
- Капитан определяется по access-токену (не query-параметру)
- `/led/next` и `/advance` требуют токен устройства-владельца сессии
- Видео `/voting` не требует `participant_id`, `/vote` принимает только `branch_id`
