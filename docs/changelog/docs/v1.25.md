## Изменения

### Профили пользователя и сотрудника

**Сотрудник:**
- `GET /api/staff/info` — профиль текущего сотрудника (ID, email, имя, фамилия, роль, статус)
- `PATCH /api/staff/info` — обновление имени/фамилии (до 100 символов)
- Доступен сотрудникам всех ролей по Staff JWT

**Пользователь:**
- `PATCH /api/user/info` — обновление имени/фамилии пользователя (включая гостя)
- До 255 символов; при следующем OAuth-входе данные могут обновиться от провайдера
- Удалён `/users/me` (заменён на `/user/info`)

**Новые схемы:**
- `StaffInfoResponse` — id, email, first_name, last_name, role (1-4), status (1-2)
- `UserInfoResponse` — id, is_guest, email, first_name, last_name, avatar_url

### Правильный ответ для сотрудника

Сотрудник (Staff JWT) получает `current_question.correct_answer` **сразу**, включая пояснение:
- Чтение по ID и активной сессии
- Операторские next/skip/timer-stop

User и Device получают правильный ответ **только после reveal**. Просмотр сотрудником не раскрывает ответ для игроков и не меняет состояние игры.

### Счётчик подключений к видеосессии

- `participant_count` в `interactive_video_sessions` (миграция 0057)
- Каждый успешный `POST /interactive-video/sessions/{id}/join` атомарно увеличивает счётчик
- Повторный join того же пользователя тоже учитывается
- Возвращается в `voting_point.participant_count` запросов state и voting
- Хранится в PostgreSQL, не сбрасывается при потере Redis

### Число голосов в интерактивном видео

В `voting_point` добавлены счётчики:
- `voted_count` — число уникальных пользователей, проголосовавших в текущей точке выбора
- `participant_count` — общее число join (может быть больше voted_count, т.к. голосование без join разрешено)
