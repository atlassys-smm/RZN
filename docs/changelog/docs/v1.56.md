## Изменения

### Справочник типов анкет

Новая сущность `SurveyType` — справочник типов анкет:
- Таблица `survey_types` с полями `id`, `name`, `deleted_at`
- Миграции 0101–0103: создание справочника, сохранение ID 1 для «Оценки качества», внешние ключи
- Поля `type` и `survey_type` остаются числовыми

**CMS API для управления типами:**
- `GET /api/cms/survey-types` — список (admin/content_editor/analyst), `include_deleted` для истории
- `POST /api/cms/survey-types` — создание (admin/content_editor)
- `GET /api/cms/survey-types/{type_id}` — получение (включая удалённые)
- `PUT /api/cms/survey-types/{type_id}` — переименование (admin/content_editor)
- `DELETE /api/cms/survey-types/{type_id}` — мягкое удаление (admin/content_editor)

**Правила удаления:**
- При активной анкете удаление её типа возвращает `409`
- Мягкое удаление сохраняет тип, старые анкеты, ответы и связи с модулями
- Удалённые типы доступны для просмотра истории
- Публикация и удаление блокируют одну запись типа для защиты от одновременных запросов

### Статус прохождения в анкетах

В пользовательских списках и получении анкет добавлено поле `completed`:
- Показывает, отправил ли текущий пользователь ответ на эту версию анкеты
- Статус считывается отдельно от общего кеша на каждом запросе
- Ответы содержат `Cache-Control: no-store`

### Фильтр type в списке анкет

`GET /api/feedback/surveys` поддерживает фильтр `type`:
- Фильтрация по ID типа анкеты
- Сочетается с фильтром `module_id` — действуют оба
- `total` считается после фильтрации до пагинации

### Удаление маршрута по типу для LED

`GET /api/feedback/surveys/type/{type}` удалён:
- LED получает анкеты после QR-привязки через общий список с фильтром `type`
- Авторизация и требования QR-привязки сохраняются
