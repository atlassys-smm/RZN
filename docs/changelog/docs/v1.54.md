## Изменения

### CDN для подписанных файлов

Добавлен CDN на Nginx + njs для кэширования и выдачи подписанных файлов:

**Архитектура:**
- Файл запрашивается с основного API при отсутствии в дисковом кэше
- Подпись HMAC-SHA256 и срок действия проверяются при каждом запросе, включая попадание в кэш
- Неверная или истёкшая подпись возвращает `403`
- Ключ кэша разделяет исходники, размеры изображений и диапазоны байтов
- Видео кэшируется диапазонами по 1 МиБ, поддерживаются `Range`, ответы `206` и перемотка

**Версионирование превью:**
- В `preview_url` добавлена версия `v` — SHA-256 уникального пути превью
- Версия входит в HMAC-подпись и ключ кэша CDN
- При замене превью UUID исходника сохраняется, новая ссылка получает отдельный кэш
- На MISS запрос уже заменённой версии к основному API возвращает 404
- Старые закэшированные версии живут до истечения TTL; ссылки без версии используют BYPASS

**Уведомления и кэши:**
- Уведомление после commit публикует текущую версию превью в Redis
- Кэши викторины, видеосценариев, ПрофСтарта, анкет и рекомендаций обновляют версию перед выдачей ссылки без пересчёта содержимого
- Уведомления читают текущий путь под блокировкой строки

**Развёртывание:**
- Сервис `cdn` определён только в основном `docker-compose.yml` с профилем `cdn`
- Обычные сборка и запуск его не включают
- Команда `docker compose --profile cdn up -d --no-deps --build cdn` собирает и запускает только CDN
- Настройки в корневом `.env`, примеры — в `.env.example`
- Origin по умолчанию — `http://api:8000`, порт — `127.0.0.1:8090`
- Постоянный кэш — в томах `cdn_cache` и `cdn_cache_long`
- Ключ подписи монтируется как Docker secret

**Подписи и сроки:**
- API возвращает `file.url` и `file.preview_url` только как относительные пути `/api/files/...`
- Домен CDN подставляет фронтенд
- Новые ссылки подписываются отдельным `FILE_SIGNING_SECRET` (должен отличаться от JWT-ключа)
- Без отдельного ключа сохранена прежняя подпись JWT-ключом
- Срок ссылок и TTL CDN задаются по фактическому `files.module`:
  - `avatars`, `avatar_generation_inputs` — 1 день
  - Остальные — 90 дней
- Параметр `ttl` включён в подпись и передаётся через `X-Accel-Expires`

**Браузерный кэш:**
- Успешные ответы CDN возвращают `private, max-age=N, must-revalidate`
- N ограничен остатком срока подписи и политикой файла
- Ошибки сохраняют `no-store`
- Превью без версии получают `max-age=0` с обязательной перепроверкой

**Переиспользование ссылок:**
- Каждая ссылка получает собственный полный срок от создания — 1 или 90 дней
- Суточная обновляется при остатке часа или меньше, 90-дневная — дня или меньше
- До этого `sig` и `expires` сохраняются, а ранее выданная ссылка действует до своего `expires`
- Замена превью, политики срока или ключа подписи сразу меняет ссылку
- Сроки хранятся в памяти процесса API; после перезапуска первая выдача создаёт новую ссылку

**Настройки кэша:**
- `CDN_SHORT_CACHE_MAX_SIZE=30g` для суточной зоны
- `CDN_LONG_CACHE_MAX_SIZE=70g` для 90-дневной
- При превышении менеджер кэша вытесняет старые копии
- Просроченные записи кэша подписанных ссылок очищаются фоновой задачей ежедневно в 02:00 по Москве

**CDN Manifest:**
- `GET /api/cms/files/cdn-manifest` — относительные подписанные пути в text/plain
- Только для файлов с 90-дневной политикой, связанных с активным контентом
- Суточные файлы исключены даже при привязке к викторине или другому модулю
- Поддержаны фильтры modules/sizes и текущие v

**Прогрев кэша:**
- `CDN/warmup.sh` установлен в образ CDN как `cdn-warmup`
- Запуск: `docker compose --profile cdn exec cdn cdn-warmup ...`
- Скрипт запрашивает логин и пароль администратора в консоли
- Есть выбор модулей/размеров, ограничение параллелизма, повторы временных сбоев и `--dry-run`
- Подтверждаются полное чтение тела и X-Cache
