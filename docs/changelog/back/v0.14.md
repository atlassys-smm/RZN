# Версия 0.14

Дата: 14.10.2026

## Аналитика викторины и Metabase

- ClickHouse 26.9.5.2: универсальная таблица `analytics.events`, числовые enum
  действий, модулей, программных комплексов и оборудования; UUID факта в `id`.
  Неизвестные `device_type` и `device_id` сохраняются как NULL.
- `app/services/analytics`: ограниченная очередь в памяти, пакетная HTTP-доставка
  и повторы со стабильными ID. Бизнес-запрос не ждёт ClickHouse. Доставка best effort:
  авария, переполнение или исчерпание повторов могут приводить к потере событий.
- События индивидуальной и командной викторины: старт с составом участников,
  регистрация, правильность оценённого ответа и окончание с длительностью.
  Завершённость определяется фактом завершения сессии, независимо от пропусков
  вопросов. Содержимое вопросов, ответы и баллы не отправляются.
- ПрофСтарт: `PROFESSION_RECOMMENDED=5` после commit результата теста,
  по одному событию на профессию со стабильным ключом результата и профессии.
  Передаются тест, его тип и версия, профессия, score и позиция;
  selection_size отсутствует, устройство неизвестно (NULL).
  Пустые результаты событий рекомендации не создают.
- Миграция PostgreSQL `0059_add_game_session_started_at.py` добавляет nullable `started_at` в `game_sessions`,
  без заполнения исторических строк.
- Metabase 0.63.18.5 хранит настройки в отдельной базе существующего PostgreSQL;
  к ClickHouse подключается с правами чтения. В коллекциях «Аналитики» описаны
  22 дашборда, 70 SQL-вопросов (26 для викторины и общих показателей LED,
  четыре для «Вовлечённости», девять для детальной обратной связи, две карточки
  обратной связи на главном дашборде, 13 для ПрофСтарта, 10 сводных и четыре
  для посещаемости, два для тепловой диаграммы) и 50 текстовых заготовок без запросов.
- Обратная связь: PostgreSQL `0060_add_survey_response_fields.py` добавляет device_id и started_at
  в survey_responses, completed_at пуст до отправки. start создаёт запись,
  respond с response_id завершает её и защищает повторы. Прежняя отправка
  готовой анкеты поддерживается без выдуманного старта. После commit
  отправляются SURVEY_STARTED=7, rating_scale (ANSWER_SUBMITTED=6)
  и SURVEY_FINISHED=8.
  ClickHouse 0004 добавляет feedback_sessions/feedback_ratings. Дашборд
  pak.feedback подключён без текстовых комментариев, с фильтрами анкеты,
  точки, устройства и дат; рейтинг точек нормирован по шкале вопроса.
- Главный Dashboard → Вовлечённость: средняя длительность со сравнением
  периодов, круговая диаграмма завершённых и незавершённых сессий,
  регистрации на уникального пользователя
  и число людей с рекомендациями профессий. Фильтры дат, ПАК и устройства;
  по умолчанию последние 30 календарных дней, Europe/Moscow.
- Файлы `infra/metabase/collections/**/collection.json` развёртываются независимо:
  существующие объекты обновляются через PUT с сохранением ID и размещений.
  Дочерние коллекции и посторонние отчёты не удаляются.
- Независимые Python-скрипты ClickHouse и Metabase запускаются через контейнер `api`.
  ClickHouse применяет SQL-миграции по порядку и проверяет контрольные суммы.
  Блокировки компонентов и атомарная запись реестров защищают от параллельного запуска.
- Единый корневой `.env`; скрипты проверяют обязательные параметры окружения
  и сообщают ошибки без вывода секретов. Реестры, резервные копии и диагностика
  разделены по компонентам в `storage/infra` и исключены из Git.
- `GET /api/analytics/catalog` пока без авторизации возвращает ключи, ID,
  веб- и API-ссылки Metabase. Читает актуальный реестр без запроса к Metabase;
  отсутствующее или повреждённое состояние возвращает 503. Контракт добавлен
  в раздел «Аналитика» OpenAPI.


## Типы анкет и варианты ответов

- PostgreSQL `0061_use_survey_type.py`: surveys.external_id заменён на type (IntEnum,
  QUALITY_ASSESSMENT=1); не более одной активной версии каждого типа.
  API создания и фильтров принимает type; LED читает `/feedback/surveys/{type}`.
- PostgreSQL `0062_create_survey_answer_options.py`: survey_answer_options с text, order и nullable FK profession_id.
  Варианты доступны в questions[].options и через CMS CRUD. PROFESSION_CHOICE
  требует профессию из справочника, остальные типы выбора её не принимают.
- Ответы проверяются по ID вариантов своего вопроса. Поле value остаётся строкой:
  один ID для SINGLE_CHOICE, JSON-массив для MULTIPLE_CHOICE/PROFESSION_CHOICE.
  Копирование пересоздаёт ID вопросов/вариантов и parent_id. Версии с прохождениями
  защищены от правки вопросов и вариантов.
- События анкет содержат числовой survey_type. ClickHouse 0005 сохраняет
  исторические события при обновлении feedback_sessions; графики не меняются.

- Вопросы анкет: POST/PUT принимают answer_options JSON-строкой в multipart/form-data.
  Вопрос и полный состав вариантов сохраняются одной транзакцией; при PUT id
  сохраняет существующий вариант, без id создаётся новый, отсутствующие в списке
  удаляются. Без поля список не меняется; [] очищает его.

## События ПрофСтарт

- После commit: SESSION_STARTED=1, впервые принятый ANSWER_SUBMITTED=6,
  SESSION_FINISHED=4 и новое явное SESSION_ABANDONED=9. Прерывание доступно
  пользователю и оператору; повторы не создают фактов.
- Ответ содержит вопрос, вариант, группу, вклад и время от старта/предыдущего
  ответа, включая паузы. Завершение содержит полный сохранённый group_scores
  с нулями; Соломин уже объединяет want+can. Рекомендации события 5 сохранены.
- Возраст отложен и отмечен TODO.


## Графики ПрофСтарт

- ClickHouse 0006: profstart_sessions, profstart_answers, profstart_group_results
  и profstart_recommendations на общей analytics.events_unique; существующие
  события и представления сохраняются.
- pak.profstart: 13 SQL-вопросов вместо заготовок, шесть фильтров; даты по
  реальному старту с учётом позднего завершения. Подключены согласованные

- Развёртывание сохраняет ID коллекции/дашборда и посторонние отчёты.
  Добавлена проверка SQL на встроенных событиях без записи в рабочие таблицы.

## Сводная аналитика по ПАК

- ClickHouse `0007_pak_sessions.sql` добавляет представление `pak_sessions`
  над общей таблицей событий без изменения существующих данных. ПАК —
  `software_id`, идентичность сессии — `(software_id, module_id, session_id)`.
- В четырёх существующих дашбордах `summary.*` подключены 10 SQL-вопросов.
  Взаимодействие — начатая сессия, достижение цели — завершение. Период по
  реальному старту, даты и часы МСК; доступны фильтры ПАК и устройства.
- Повторные визиты отложены: отдельный график остаётся заготовкой, колонка
  таблицы возвращает NULL. Источники без подключённых стартов не показывают
  фиктивные нули. ID существующих объектов Metabase сохраняются.

## Размеры графиков Metabase

- Пересмотрены размещения всех 22 дашбордов в шаблонах коллекций. Таблицы
  занимают полную ширину сетки (24 колонки), высота — 10–12 строк. Сравнение
  ПАК увеличено с 12×5 до 24×10; таблицы игр и рейтинга обратной
  связи тоже расширены на всю ширину.
- Числовые карточки сгруппированы компактно, временные графики, длинные
  рейтинги и диаграммы получили больше места для подписей. Размеры заготовок
  соответствуют планируемым визуализациям.
- Развёрнуты только координаты и размеры. SQL, фильтры, настройки визуализаций,
  ID дашбордов, вопросов и размещений сохранены.

## Посещаемость и гостевой статус событий

- ClickHouse `0008_visitor_activity.sql`: отдельная колонка `events.is_guest`
  типа Nullable(Bool), старые данные сохраняют NULL. Представление
  `visitor_activity` объединяет персональные события и состав старта викторины.
- Викторины, ПрофСтарт и анкеты фиксируют статус пользователя до commit;
  отправка остаётся асинхронной после commit. Общая игра не получает статус
  одного участника; каждый участник в participants[] содержит свой снимок.
- В `main.attendance` подключены четыре SQL-вопроса: общий итог посетителей,
  уникальные OAuth-пользователи, гости и динамика по дням/неделям МСК.
  Категория — последний известный статус в периоде, без двойного учёта после
  OAuth. Исторический неизвестный статус входит только в общий итог.
- Новые и повторные визиты отложены. ID существующих объектов сохраняются;
  новые ключи доступны через справочник аналитики. Добавлены API-проверки
  снимков true/false/NULL и безопасные SQL-проверки без записи рабочих данных.

## Уточнения после ревью аналитики

- В общих показателях LED объявлены фильтры дат и устройства, к которым
  привязана таблица игр. Описания дашбордов викторины приведены
  к действующему правилу: завершение определяется окончанием сессии,
  независимо от пропущенных вопросов.

## Общие показатели LED и обратная связь на главном дашборде

- В `led.common` подключены четыре показателя вместо заготовок: число сессий
  с динамикой по дням, средняя длительность со сравнением периодов,
  завершённость и уникальные пользователи. Охват — индивидуальная и командная
  викторины. Сессии отбираются по старту, пользователи — по времени действия.
- Таблица игр использует те же границы дат, по умолчанию последние
  30 календарных дней МСК; её ключ сохранён.
- В `main.feedback` подключены число завершённых анкет со сравнением периодов
  и средняя оценка по отдельным ответам в шкале 0–100%, по дате окончания.
  Анкеты с большим числом оценочных вопросов имеют больший вес; отсутствие
  оценок не превращается в 0%. Контактные заявки остаются заготовкой.
- Добавлены описания охвата, периодов, весов, пустых данных и потерь доставки,
  фильтры и подписанное встраивание семи новых SQL-вопросов. Существующие
  дашборды обновляются через PUT с сохранением ID. Новых событий и миграций нет.
- Расчёты проверяются отдельным SQL-скриптом на встроенных синтетических данных
  без изменения рабочих таблиц PostgreSQL, Redis или ClickHouse.
- Исправлено первое развёртывание вопросов с встраиванием: настройки,
  игнорируемые Metabase при POST, применяются отдельным PUT после сохранения ID.
  Повтор после ошибки сохраняет созданный вопрос и завершает его настройку.

## Ограничения числа строк в запросах дашбордов

- Из `quiz.recent_sessions` удалён `LIMIT 100`; таблица переименована в
  «Игры за выбранный период» и выводит игры по выбранным датам и устройству
  с сортировкой от новых к старым. Ключ, ID вопроса и размещения сохраняются.
- Проверены все 68 управляемых SQL-запросов и используемые представления.
  Других произвольных ограничений числа строк не обнаружено. Сохранён
  `LIMIT 10` у рекомендуемых профессий ПрофСтарта: он прямо предусмотрен
  требованиями. Топ-5 главного дашборда пока остаются заготовками без SQL.
- В документации закреплено: ограничение числа строк допускается только
  для явно предусмотренных топ-5 и топ-10. Фильтры периода сохраняются.

## Детализация статусов ПрофСтарт и завершённость викторины

- Круговая диаграмма ПрофСтарт разделена на завершённые, в процессе и явно
  прерванные прохождения. Все доли считаются от всех начатых сессий когорты;
  последние две в сумме дают прежний общий процент незавершённых.
- В графике по типам и версиям те же три состояния показаны отдельными сериями
  составных столбцов; колонка unfinished сохранена в SQL для совместимости.
- Завершённость индивидуальной викторины отображается прогресс-баром 0–100%
  вместо числовой карточки. Формула и фильтры сохранены; без стартов нет данных.
- Используются существующие вопросы и размещения без новых миграций и событий.
  ID сохраняются при обновлении через PUT. Расчёты статусов проверяются
  read-only SQL-проверками на встроенных синтетических данных.

## Тепловая диаграмма активности и пиковые интервалы

- В `main.heatmap` вместо двух заготовок подключены матрица 7×24 и таблица
  всех равных положительных пиков. Источник — `visitor_activity`, без новых
  событий и миграций. Один user_id учитывается один раз в конкретном часе
  между выбранными ПАК; среднее считается по календарным интервалам.
- Интервалы без событий входят с нулём, отсутствующие и будущие наблюдения —
  NULL. Текущий неполный час включён без прогноза и отмечен на карте и в пиках.
- Описаны ограничения командных игр, пакетной отправки анкет, неизвестных
  устройств, неполной истории и best-effort доставки. Карта показывает
  зарегистрированную активность, а не физическое или одновременное присутствие.
- Добавлены фильтры дат, ПАК и устройств, подписанное встраивание, общая
  цветовая шкала и read-only проверки SQL по независимой календарной модели.
  Существующий дашборд обновляется через PUT с сохранением ID.

## Типы объектов в справочнике аналитики

- В `GET /api/analytics/catalog` элементы `collections`, `dashboards` и `charts`
  возвращают только `id` и `type`: `collection`, `dashboard` и `question`
  соответственно. Поля `url` и `api_url` удалены из элементов ответа.
- Ответ содержит только `collections`, `dashboards` и `charts`. Поля
  `metabase_url` и `revision` остаются в реестре, но не возвращаются через API.
  Обновлены схема ответа, исходный и собранный OpenAPI, документация интеграции
  и изолированные API-проверки.
- `read_catalog` больше не читает и не проверяет `metabase_url` и `revision`;
  корректные словари объектов доступны независимо от этих внутренних метаданных.

## Реестр Metabase без версии формата

- Из `storage/infra/metabase/state.json` и шаблона нового реестра удалено поле
  `version`. Удалены проверки версии в чтении каталога и скрипте обновления
  Metabase; проверки необходимых полей, структуры и ID сохранены.
