Дата: 05.10.2026

## Новые возможности

### Загрузка файлов и единый ответ API

- Вопросы и варианты ответов викторины, вопросы анкет, ветки видеосценариев и аватары принимают файлы непосредственно в `multipart/form-data`. ID файлов остаются внутренними связями БД и не передаются вместо загрузок в этих запросах.
- Файлы сохраняются через общий сервис `save_file`. Новые файлы и использующая их сущность сохраняются в общей транзакции; при ошибке новые загрузки удаляются из хранилища.
- Вместо `image_url`, `media_url` и ID медиа в затронутых ответах возвращается объект `file` с полями `url`, `preview_url`, `mime_type`, `title`, `description`. При отсутствии файла возвращается `null`.
- У аватаров профессий используются объекты `male_file` и `female_file`. Универсальный ответ также используется в состоянии викторины, состоянии интерактивного видео и пользовательском API анкет.

### Превью видео

- При загрузке видео без переданного превью первый кадр извлекается FFmpeg и сохраняется в PNG. Для остальных типов файлов автоматическое превью не создаётся.
- Вопросы викторины, вопросы анкет и ветки видеосценариев принимают необязательный `file_preview`. Переданная картинка JPEG, PNG, WebP или GIF сохраняется без конвертации вместо извлечения кадра.
- Для файлов вариантов ответа используются `answer_option_file_previews[n]`. Превью передаётся вместе с соответствующим новым файлом; передача превью без основного файла возвращает 422.
- Запросы аватаров профессий и пользователей не принимают отдельные поля превью.
- Основной файл и превью скачиваются по подписанным ссылкам через `GET /files/{file_uuid}`. Идентификатор превью имеет суффикс `_preview`; отдельный query-параметр для выбора превью не требуется. Подпись учитывает полный идентификатор.
- `preview_url` равен `null`, если превью отсутствует. Превью существующих файлов автоматически не заполняются. При удалении файла удаляется и его превью.

### Сценарии сессии для LED

- Добавлен `GET /interactive-video/sessions/{session_id}/scenarios`: возвращает массив сценариев в порядке `settings.scenario_ids`.
- Каждый сценарий содержит `id`, `title`, `description`, `profession_id` и `first_branch` — стартовую ветку с `parent_id = null`, включая объект `file`. LED может использовать `first_branch.file.preview_url` для карточки сценария.
- Запрос доступен для активных и завершённых сессий и не меняет состояние воспроизведения. Без стартовой ветки возвращается `first_branch: null`; удалённые сценарии пропускаются. Неизвестная сессия возвращает 404.

## Изменения API

Все пути ниже указаны без общего префикса `/api`.

- `POST /cms/quiz/questions`, `PUT /cms/quiz/questions/{question_id}` — поля вопроса в форме, основной файл в `file`, файлы вариантов в `answer_option_files[n]`, необязательные превью в `file_preview` и `answer_option_file_previews[n]`.
- `POST /cms/surveys/{survey_id}/questions`, `PUT /cms/surveys/{survey_id}/questions/{question_id}` — поля вопроса в форме, файл в `file`, превью в `file_preview`.
- `POST /cms/video-scenarios/{scenario_id}/branches`, `PUT /cms/video-scenarios/{scenario_id}/branches/{branch_id}` — поля ветки в форме, файл в `file`, превью в `file_preview`.
- `POST /avatars`, `PUT /avatars/{profession_id}` — файлы в `male_photo` и `female_photo`, метаданные в `male_file_title`, `male_file_description`, `female_file_title`, `female_file_description`.
- `POST /users/{user_id}/avatars` — изображение в `photo`, метаданные в `file_title` и `file_description`; `profession_id` остаётся query-параметром.
- Сложные поля `answer_options`, `answer_key` и `condition` передаются JSON в отдельных текстовых полях формы; `tags` — повторяемыми полями.

### Совместимость клиентов

- Клиентам затронутых запросов необходимо перейти с JSON и ID медиа на поля формы и загрузку файлов, а также читать новый объект файла вместо прежних полей ответа.
- Для необязательных файлов отсутствие загрузки при обновлении сохраняет существующую связь. Метаданные текущего файла без новой загрузки не меняются.
- Прежние файлы при замене сохраняются: они могут использоваться другими сущностями и копиями анкет.

## Миграции

- **0036** — в таблицу `files` добавлено nullable-поле `file_preview_path` (`varchar(1024)`). Существующие записи сохраняются с пустым путём превью.

## Исправления

- Исправлено обращение к `jwt_secret_key` при создании и проверке подписанных ссылок на файлы.
- Исправлен разбор `answer_options` из Scalar: поддерживаются JSON-массив и повторяемые поля с отдельными JSON-объектами. Пустые необязательные JSON-поля игнорируются.
- При обновлении вопроса анкеты проверяется его принадлежность указанному `survey_id`.
- Исправлены ссылки раздела «Обратная связь — CMS» в OpenAPI. Удалено повторное объявление `/feedback/surveys/{external_id}`; путь LED использует актуальную схему `FeedbackSurveyResponse`.

## Инфраструктура и тесты

- Добавлена зависимость `imageio-ffmpeg`, поставляющая бинарник FFmpeg для генерации кадров. Извлечение выполняется в рамках запроса с таймаутом 60 секунд; повреждённое видео возвращает 422, недоступный генератор — 503.
- Добавлены изолированные HTTP- и ORM-тесты загрузок, превью, подписанных ссылок, очистки файлов при ошибках и списка сценариев сессии. Проверки используют временные каталоги, mock-сессии или SQLite в памяти.
- Обновлены API-тесты под multipart-запросы и новый формат ответа. В основных тестовых фикстурах файловое хранилище перенаправлено во временный каталог.
- Обновлены документация сущностей, исходные схемы OpenAPI и собранная спецификация.
