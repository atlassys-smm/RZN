# Версия 0.9

Дата: 07.10.2026

---

## ПрофСтарт

Реализован backend для управления профориентационными тестами и их прохождения. Типы тестов расширяемы; расчёт результатов поддерживает `solomin`, `holland`, `dellinger`.

- CMS: CRUD типов, версий, групп, вопросов, вариантов и связей с существующими профессиями. Вопросы и варианты поддерживают загрузку файлов через multipart по общему механизму проекта.
- Только тест имеет статусы `draft`, `active`, `archived`. Состав изменяется в черновике; публикация проверяет банк и атомарно архивирует предыдущий активный тест того же типа. Копирование создаёт новую версию с собственными ID вопросов, вариантов и групп.
- Пользователь: каталог активных тестов, старт, восстановление прохождения, последовательные ответы с автоматическим завершением после последнего вопроса, прерывание и собственная история результатов. Повторы ответов не создают дубликаты; конкурентные операции согласованы блокировками и ограничениями БД.
- Результат сохраняет общие показатели групп, ранги и рекомендации профессий. Для Соломина блоки «Хочу» и «Могу» суммируются. Исторические результаты не меняются при редактировании справочников или влияния типов.
- Общий подбор использует последний завершённый результат каждого типа и текущие проценты влияния. Стандарт — 40/40/20; CMS может атомарно перераспределить все три процента с суммой 100. Непройденные тесты исключаются из знаменателя; отсутствие профессии в пройденном тесте даёт нулевой вклад.

Пользовательские маршруты проверяют Bearer-токен и владельца данных. CMS следует существующей архитектуре проекта: отдельная проверка административных прав в backend пока отсутствует.

## Миграции и начальный банк

Создание каждой таблицы вынесено в отдельную миграцию; seed отделён от схемы.

| Ревизия | Таблица или данные |
|---|---|
| `0037` | `test_types` |
| `0038` | `profstart_tests` |
| `0039` | `test_groups` |
| `0040` | `test_questions` |
| `0041` | `test_answer_options` |
| `0042` | `test_group_professions` |
| `0043` | `test_sessions` |
| `0044` | `test_answers` |
| `0045` | `test_results` |
| `0046` | `test_result_scores` |
| `0047` | `test_result_professions` |
| `0048` | Три предзаданных типа с влиянием 40/40/20 |
| `0049` | Три черновика: 18 групп, 58 вопросов и 263 варианта |

В `app/migrations/data/profstart_v1` хранится только `bank.json`. Seed не зависит от файлов документации, не создаёт файлов и не перезаписывает существующие версии. Миграция банка требует подключения к БД. Откат seed запрещён, поскольку типы и версии могут уже использоваться.

Привязки к профессиям и изображения пяти фигур Деллингер задаются в CMS. Seed не публикует тесты; перед использованием нужно завершить наполнение и опубликовать версии. Миграции подготовлены, к рабочей БД в рамках реализации не применялись.

Маршруты используют обычные параметры `int` и стандартные ошибки FastAPI через `HTTPException` с полем `detail`. Отдельные классы ошибок, обработчик маршрутов, ограничения пределов `int64` и повторная проверка вычисляемых полей схемами ответов удалены. Проверки правил тестов, доступа владельца и конкурентных операций сохранены.

Явные `operation_id` и `summary` из роутеров удалены: основная спецификация OpenAPI ведётся отдельно в документации, а встроенный Swagger FastAPI использует автоматически сформированные значения.

Сервисы разделены по работе с типами, тестами, группами, вопросами, прохождениями и результатами. Универсальные `mutate_item`, `list_items` и `get_item` заменены отдельными именованными операциями. Проверка банка, расчёт баллов и формирование ответов вынесены в самостоятельные модули; функции имеют аннотации типов и читаемые имена переменных.

Статусы оформлены через IntEnum и хранятся в `status integer`: TestStatus (draft=1, active=2, archived=3) и TestSessionStatus (in_progress=1, completed=2, abandoned=3). Миграции `0038` и `0043` сразу создают числовые поля, ограничения и индекс; seed `0049` создаёт тесты со status=1. Числовые статусы используются также в API и фильтрах CMS; документация и OpenAPI согласованы.

Расчёт результата выполняется внутри `/answer` после последнего вопроса; отдельный `/complete` удалён. Ответ, результат и переход в completed сохраняются одной транзакцией. Подтверждение содержит статус прохождения; сам результат читается через GET `/sessions/{id}/result`. Пустые строки в функциях отделяют загрузку данных, проверки, изменения и формирование ответа.

## Проверки

Проверки ПрофСтарта: **40 passed**. Добавлены 40 проверок модуля: расчёт и округление, API и владение данными, числовые статусы и фильтры, автоматический расчёт после последнего ответа и откат при ошибке расчёта, стандартные ошибки и PATCH, загрузка файлов и откат при ошибках, конкурентные запросы, соответствие схемы ORM и отдельные seed-миграции. Миграции проверены в изолированной тестовой БД; загрузка файлов — во временном каталоге. Проверено, что миграции создания формируют status integer, а seed не создаёт записей File и оставляет media_id пустым.

Два предупреждения относятся к существующему использованию HTTPX/Starlette и циклу внешних ключей таблиц викторины.
