# 0.34 — CDN для подписанных файлов

10.11.2026

- Добавлен CDN на Nginx + njs: файл запрашивается с основного API при отсутствии
  в дисковом кэше и затем выдаётся из кэша по действующим подписанным ссылкам.
- Подпись HMAC-SHA256 и срок действия проверяются при каждом запросе, включая
  попадание в кэш. Неверная или истёкшая подпись возвращает `403`.
- Ключ кэша разделяет исходники, размеры изображений и диапазоны байтов.
  Подпись и срок ссылки не создают отдельные копии файла. Видео кэшируется
  диапазонами по 1 МиБ, поддерживаются `Range`, ответы `206` и перемотка.
- В `preview_url` добавлена версия `v` — SHA-256 уникального пути превью; она входит
  в HMAC-подпись и ключ кэша CDN. При замене превью UUID исходника сохраняется,
  новая ссылка получает отдельный кэш по политике файла, включая уменьшенные варианты.
  На MISS запрос уже заменённой версии к основному API возвращает 404. Старые
  закэшированные версии живут до истечения TTL; ссылки без версии используют
  BYPASS. Ошибки origin не кэшируются.
- Уведомление после commit публикует текущую версию превью в Redis. Кэши викторины,
  видеосценариев, ПрофСтарта, анкет и рекомендаций обновляют версию перед выдачей
  ссылки без пересчёта содержимого; уведомления читают текущий путь под блокировкой
  строки, чтобы конкурентная замена не вернула старую версию в Redis.
- Сервис `cdn` определён только в основном `docker-compose.yml` с профилем `cdn`.
  Обычные сборка и запуск его не включают. Отдельная команда
  `docker compose --profile cdn up -d --no-deps --build cdn` собирает и запускает
  только CDN, без запуска API, его миграций, PostgreSQL или Redis.
- Настройки хранятся в корневом `.env`, примеры — в корневом `.env.example`.
  Origin по умолчанию — `http://api:8000`, порт — `127.0.0.1:8090`, постоянный
  кэш — в томах `cdn_cache` и `cdn_cache_long`, ключ подписи монтируется как Docker secret.
- API возвращает `file.url` и `file.preview_url` только как относительные пути
  `/api/files/...` с параметрами подписи и срока; домен CDN подставляет фронтенд.
  Новые ссылки подписываются отдельным `FILE_SIGNING_SECRET`, который должен
  отличаться от JWT-ключа. Без отдельного ключа сохранена прежняя подпись.
  Уже выданные прямые ссылки API продолжают
  проверяться JWT-ключом до истечения срока; CDN принимает только ключ файлов.
- Срок ссылок и TTL CDN задаются по фактическому `files.module`: `avatars`,
  `avatar_generation_inputs`, `users`, `general` — 1 день; остальные — 90 дней.
  Оригиналы, превью и размеры имеют одинаковую политику. Параметр `ttl` включён
  в подпись и передаётся через `X-Accel-Expires`. При скачивании используется
  проверенный подписанный срок, без ttl — 1 день. Модуль учитывается при создании
  ссылки; несовпадение с текущим модулем не вызывает отказа в скачивании.
  Кэши разделены на зоны/тома с `inactive` 1 и 90 дней. Ранее выданные ссылки
  без `ttl` сохраняют прежний срок и суточный кэш. Ограничения размера нет.
- Кэшированные ответы модулей хранят модуль файла. В старых снимках недостающая
  информация дополняется из БД без пересоздания вопросов, ответов и сессий.
- Добавлен административный `GET /api/cms/files/cdn-manifest`: относительные
  подписанные пути в text/plain только для файлов с 90-дневной политикой,
  связанных с активным контентом. Суточные файлы исключены даже при привязке
  к викторине или другому модулю. Поддержаны фильтры modules/sizes и текущие v.
- Добавлен `CDN/warmup.sh` для запуска на отдельном CDN-сервере. Основной API
  только выдаёт список; скрипт делает полные GET к CDN, читая большие ответы
  потоком в /dev/null. Нужны sh, curl и стандартные Unix-утилиты.
- Скрипт автоматически входит по `DEMO_ADMIN_LOGIN`/`DEMO_ADMIN_PASS` из корневого
  .env или --env-file. Origin берётся из AUTH_ALLOWED_ORIGINS либо --origin.
  После получения списка закрывается именно созданная скриптом сессия.
  Секреты и подписанные URL не печатаются, .env не выполняется как shell-код.
- У прогрева есть выбор модулей/размеров, ограничение параллелизма, повторы
  временных сбоев и --dry-run. Подтверждаются полное чтение тела и X-Cache;
  код завершения отражает ошибки. Скрипт принимает только 90-дневные ссылки.
- Удаление исходника на API не отзывает
  кэшированную копию немедленно: она может выдаваться до истечения TTL по
  действующей ссылке. Механизм мгновенного отзыва в эту версию не входит.
- Добавлены инструкция и проверка планов Compose. Проверены исключение CDN из
  стандартной сборки и запуска и отдельная сборка образа. Добавлены изолированные
  проверки генерации ссылок, перехода со старых подписей, настроек и скачивания
  через файловый маршрут API с поддержкой Range. Миграции БД не требуются.
