# 0.38 — Служебные аккаунты

16.11.2026

- Добавлено поле `users.service_user` — nullable unique integer. Значения 1–5
  обозначают служебные аккаунты ПрофСтарта, 6–10 — аватара; null — обычного
  пользователя. Миграция `0099_add_service_users` добавляет поле и в той же
  миграции создаёт по пять активных аккаунтов для каждого модуля. Служебные
  аккаунты не являются гостями и не могут привязываться к OAuth.
- Добавлен `POST /api/auth/user/service`: `module=1` — ПрофСтарт, `module=2` —
  аватар. Доступ разрешён активному администратору и активному устройству любой
  роли. Ответ `201` содержит `user_id`, `service_user`, `access_token`,
  `token_type` и `expires_in`; refresh устанавливается в HttpOnly cookie.
- Аккаунт выбирается по самой ранней дате последнего входа
  `MAX(auth_sessions.created_at)`. Не использованные ранее идут первыми,
  при равенстве выбирается меньший `service_user`. Блокировки и резервирования
  пула нет. Предыдущие auth-сессии отзываются, но сохраняются для порядка выдачи.
- Перед выдачей очищаются профиль, согласия, прохождения и ответы ПрофСтарта,
  источники рекомендаций, задания генерации, аватары и собственные файлы
  выбранного аккаунта. Общие шаблоны сохраняются. Поздний webhook удалённого
  задания не восстанавливает результат.
- При входе очищается только персональный кеш выбранного аккаунта.
  Рекомендации используют общий механизм кеширования и учёта просмотров.
  При невозможности очистить кеш выдача возвращает `503`, изменения БД
  откатываются.
- Служебный пользователь аватара работает через существующую привязку
  к устройству. Создание и чтение `/api/users/avatar-generations` требуют
  Device JWT с ролью AVATAR и `X-Device-Connection-Id`; при создании задания
  передаётся `device.id`. Повторная выдача аккаунта отзывает прежнюю auth-сессию
  и делает старую привязку устройства недействительной.
- В `GET/PATCH /api/user/info` возвращается `service_user`. Обновлены исходный
  и bundled OpenAPI, описания пользователей и авторизации. Добавлены API-проверки
  ротации, прав доступа, сброса данных и кеша, привязки к устройству и поздних webhook.
