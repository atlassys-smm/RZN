# Версия 0.20

Дата: 26.10.2026

- `GET /api/organizations/{id}` создаёт событие ORGANIZATION_VIEWED=10 только
  при авторизации JWT пользователя, включая гостя. Сотрудники, устройства,
  ошибки и списки просмотрами не считаются. Каждый успешный повторный GET
  учитывается отдельно, без view_id.
- Добавлен модуль аналитики ORGANIZATIONS=13 и представление ClickHouse
  organization_views (миграция 0010). В событиях сохраняются ID, название
  и тип организации, пользователь и признак гостя.
- Подключены четыре карточки Metabase main.organizations: рейтинги топ-10
  работодателей и учебных заведений, дневная динамика фиксированного топ-5
  каждого типа. Общий период по московскому времени; нулевые дни не пропускаются.
- Обновлены OpenAPI и правила аналитики; добавлены API-проверки авторизации
  просмотров и проверки SQL на встроенных данных без записи рабочих событий.

- Добавлены пользовательские просмотры профессий (PROFESSION_VIEWED=11) и направлений
  образования (EDUCATION_PROGRAM_VIEWED=12). В событии профессии сохраняется
  снимок отрасли через industry_id; служебные JWT просмотров не создают.
- Миграция ClickHouse 0011 добавляет profession_views и education_program_views.
- В main.professions подключены шесть карточек: рейтинги топ-10 и дневная динамика
  топ-5 профессий, отраслей и направлений образования. Отрасли считаются по просмотрам
  профессий. Направления учитываются по ID независимо от совпадения названий
  и числа связанных учебных заведений.
- Обновлены OpenAPI, статусы реализации дашбордов и контракты событий;
  добавлены API-проверки и безопасные SQL-проверки на встроенных данных.

- Добавлены коллекция Metabase «Для заставки» и дашборд «Показатели для заставки»
  с ключом led.showcase по исходным требованиям публичного LED-режима:
  посетители, среднее время, люди с подобранными профессиями, популярные профессии
  и обратная связь. Переиспользованы семь существующих карточек с общими фильтрами
  дат; топ личных баллов подключён отдельной общей карточкой. В документации указаны ограничения
  существующих расчётов и выбор периода для посетителей сегодня/за месяц.

- В SESSION_FINISHED индивидуальной викторины добавлен results[] со снимком
  participant_id, user_id и сохранённого total_score. Командные события и
  ANSWER_EVALUATED не меняются; повторное завершение не создаёт новый факт.
- Миграция ClickHouse 0012 добавляет quiz_individual_results. Карточка
  quiz.individual.top_scores показывает топ-5 лучших результатов пользователей
  по дате завершения и переиспользуется в индивидуальной викторине и «Для заставки».
  Старые события без результатов исключаются; нулевые баллы учитываются.
  По умолчанию топ выбирается за полный вчерашний день по Europe/Moscow.

- GET /api/cms/video-scenarios поддерживает select=profession для получения
  вложенного profession с полными данными связанной профессии; profession_id сохранён.
  Без select=profession поле отсутствует и профессии не загружаются; при выборе
  без привязки возвращается null. Профессии загружаются вместе со списком.
  Обновлены схемы API, документация и проверки select, фильтрации, пагинации и пустых связей.

- В GET /api/cms/video-scenarios/{id} добавлен select=profession: полные данные
  профессии возвращаются по запросу вместе с деревом веток; без привязки — null.
  По умолчанию поле отсутствует и профессия не загружается.
  Обновлены документация, OpenAPI и API-тесты.

- В Metabase подключён показатель led.screensaver.time_percent: процент времени
  заставки как остаток от 8 часов за каждый день и устройство после вычитания
  суммы времени сессий, кроме обратной связи (module_id=5). Устройства только
  с обратной связью в расчёт не входят. Добавлены фильтры периода/устройства и SQL-проверки;
  в документации описаны формула, источники и приближённость расчёта.

- В CMS веток видеосценариев добавлен необязательный `reference_branch_id` на существующую ветку того же сценария. Ссылочная ветка сохраняет свой текст ответа и не требует видео. Поле возвращается в ответах веток и дереве.
- После выбора ссылки backend сразу переходит к конечной цели цепочки, используя её видео, вопрос и дочерние варианты. Позиция цели сохраняется для восстановления после потери Redis. Голоса учитываются за исходный вариант.
- Добавлены проверки цели и циклов, в том числе через обычные переходы. Ссылочные ветки — дочерние листья; стартовая ветка остаётся обычной. В PUT отсутствие поля сохраняет ссылку, пустое значение снимает её при наличии собственного видео.
- Проверка циклов с ошибкой 400 выполняется при сохранении в CMS. Во время показа обход циклических ссылок завершается без ошибки: используется последнее встреченное собственное видео или повторяется текущая ветка, если у ссылок видео нет. Добавлены API-проверки самоссылки, замкнутой цепочки и возврата к предыдущему видео.
- Миграция PostgreSQL 0081 добавляет nullable-ссылку и индекс, разрешает nullable `media_id`; существующие ветки не изменяются. Удаление сценария учитывает внутренние ссылки.
- Обновлены исходные схемы OpenAPI, описание CMS и сущности. Добавлены API-тесты ссылочных веток, переходов по таймеру и досрочному голосованию, цепочек, общего поддерева и восстановления.
- В профессии ответа `GET /api/users/me/recommendations` добавлено nullable-поле `description` из текущего справочника. Изменение описания не требует пересчёта результатов; название и баллы остаются из снимков источников. Сохранённые рекомендации мягко удалённых профессий также возвращают описание. Обновлены общий формат предпросмотра конструктора, OpenAPI и API-тесты. Миграция не требуется.
- В результат ПрофСтарта `GET /api/profstart/sessions/{id}/result` и элементы истории `GET /api/profstart/me/results` добавлен полный список `professions` из снимка источника этого прохождения. Возвращаются сохранённые названия, баллы, позиции и пояснения, а также текущее описание профессии. Веса общего рейтинга и ограничение до трёх не применяются. Добавлены API-проверки; обновлены схемы и документация. Миграция не требуется.
- Миграция 0082 добавляет nullable media_id профессии, FK на files и индекс. Во всех ответах с профессией добавлен file: собственный файл, затем male_photo_file_id шаблона аватара, иначе null. POST/PUT профессии принимают поля и необязательный файл в multipart/form-data по образцу организаций; отдельных маршрутов файла нет. Подстановка не записывается в БД и снимки результатов. Обновлены схемы, документация и API-тесты.
- В результате отдельного теста ПрофСтарта и элементах истории возвращается максимум 10 наиболее подходящих профессий: score DESC, при равенстве profession_id ASC. Лимит задаётся в подборе при чтении, без ограничения в схеме ответа; полный снимок user_recommendation_sources сохраняется для общего рейтинга. Лимит общего рейтинга остаётся равным трём. Обновлены OpenAPI, описания и целевые API-тесты.
