# 0.28 — Кэширование часто используемых запросов

02.11.2026

## Викторина

- Структура сессии и содержимое вопросов кэшируются в Redis на 1 час.
  Попадания в кэш и добавление вопросов в hash не продлевают его срок.
- При прогретом кэше базовый GET активной игры выполняет 2 SQL-запроса вместо 6,
  без учёта авторизации и проверки участия.
- Добавление финального раунда сбрасывает структуру после commit до рассылки;
  завершение очищает кэш. Промах восстанавливается из PostgreSQL.
- Таймер, раскрытие, голоса, роли и состав команд остаются актуальными;
  подписанные ссылки файлов формируются заново. REST/WebSocket-контракты сохранены.

## Профессии в действии

- Общий Redis-кэш содержимого видеосценария и дерева веток с TTL 24 часа;
  попадания в кэш не продлевают срок. Подписанные ссылки формируются при выдаче.
- Инвалидация по версии после commit при изменениях сценария и веток; проверка версии защищает
  от повторного заполнения старым параллельным чтением.
- Состояние, таймеры, голоса и количество участников остаются актуальными.
  REST/WebSocket-контракты и восстановление позиции сохранены.
- Убрано повторное чтение дочерних веток в голосовании; имя профессии читается
  без лишней загрузки ORM-связей.


## ПрофСтарт

- Общий Redis-кэш неизменяемого банка опубликованной версии теста на 24 часа:
  вопросы, варианты и метаданные файлов; свежие подписи ссылок при выдаче.
- Карточка, каталог, текущий вопрос и чтение состояния прохождения используют
  кэш. Статусы, доступ, прогресс и ответы остаются актуальными; новые версии
  получают отдельные ключи. Черновики и CMS не кэшируются.
- Группы, связи профессий, запись ответов и расчёт результата остаются в БД.
  Промах или недоступность Redis восстанавливаются чтением из PostgreSQL.
- REST-контракты сохранены; проверки TTL, SQL, прогресса, публикаций и медиа.


## Рекомендации пользователя

- Персональный кэш итоговой подборки на 24 часа без продления TTL при чтении;
  формат ответа и свежие подписи файлов сохранены.
- Новая версия появляется только при сохранении нового источника ПрофСтарта
  в транзакции результата. Викторина и просмотры не инвалидируют подборку.
- Ключи учитывают веса и правки справочников; старые параллельные расчёты
  не подменяют новую версию. Блокировка предотвращает одновременные пересчёты.
- При недоступности Redis расчёт работает через БД; конструктор без кэша.


## Подбор по ID профессий

- Общий кэш `/organizations/recommendations` на 24 часа по отсортированному списку
  ID, текущим весам SOURCE_WEIGHTS и версии справочников; TTL не продлевается.
- Успешное попадание исключает запросы подбора к PostgreSQL. Проверки доступа,
  валидация и структура ответа сохранены; ошибки не кэшируются.
- Сброс после правок справочников, новые подписи файлов, защита параллельных
  промахов и расчёт через БД при недоступности Redis.

## Общий Redis-клиент

- Викторина, видеосценарии, ПрофСтарт и рекомендации используют общий клиент
  и пул соединений на цикл событий вместо четырёх отдельных пулов.
- При завершении приложения пул закрывается один раз, в том числе при ошибке
  остановки фоновых задач; тесты закрывают его до возврата рабочих настроек.

## Опубликованные анкеты

- Кэш списка, анкеты по ID и LED-анкеты по типу на 24 часа через общий Redis-клиент.
  Вопросы, условия и варианты ответов возвращаются без изменения формата.
- Публикация новой версии после commit инвалидирует все варианты чтения; старые
  параллельные расчёты изолированы версией ключа. TTL при чтении не продлевается.
- Свежие подписи файлов, прежние проверки доступа и QR-привязки, чтение БД при
  сбое Redis; запись прохождений и ответов остаётся без кэша.

## Список шаблонов викторины

- Общее количество шаблонов считается через SQL COUNT с тем же фильтром статуса.
  Шаблоны, раунды и вопросы загружаются только для запрошенной страницы.

## История результатов ПрофСтарта

- История загружает прохождения текущей страницы, ответы, источники результатов,
  тесты и вопросы пакетно вместо отдельного вызова загрузки каждого результата.
- Профессии и их медиа загружаются общей выборкой для страницы. История и одиночный
  результат используют общую сборку ответа; фильтры, сортировка и пагинация сохранены.
