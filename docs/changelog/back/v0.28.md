# 0.28 — Кэширование викторины и видеосценариев

02.11.2026

## Викторина

- Структура сессии и содержимое вопросов кэшируются в Redis на 1 час.
  Попадания в кэш и добавление вопросов в hash не продлевают его срок.
- При прогретом кэше базовый GET активной игры выполняет 2 SQL-запроса вместо 6,
  без учёта авторизации и проверки участия.
- Добавление финального раунда сбрасывает структуру после commit до рассылки;
  завершение очищает кэш. Промах восстанавливается из PostgreSQL.
- Таймер, раскрытие, голоса, роли и состав команд остаются актуальными;
  подписанные ссылки файлов формируются заново. REST/WebSocket-контракты сохранены.

## Профессии в действии

- Общий Redis-кэш содержимого видеосценария и дерева веток с TTL 24 часа;
  попадания в кэш не продлевают срок. Подписанные ссылки формируются при выдаче.
- Инвалидация по версии после commit при изменениях сценария и веток; проверка версии защищает
  от повторного заполнения старым параллельным чтением.
- Состояние, таймеры, голоса и количество участников остаются актуальными.
  REST/WebSocket-контракты и восстановление позиции сохранены.
- Убрано повторное чтение дочерних веток в голосовании; имя профессии читается
  без лишней загрузки ORM-связей.
