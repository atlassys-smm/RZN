# Версия 0.13

Дата: 16.10.2026

---

## Викторина

- Вместо `auto_reveal` и `auto_next` используются nullable-задержки `auto_reveal_delay`, `auto_next_delay`, `between_rounds_delay`: `null` отключает действие, `0` выполняет его сразу, положительное число задаёт ожидание в секундах. Удалённые флаги и отрицательные задержки отклоняются API.
- В запросах создания сессии явный `null` сохраняется; пропущенные поля наследуются из CMS. В обновлении стандартных настроек пропущенные поля остаются без изменений.
- Задержки отсчитывает клиент перед вызовом API. Новые проверки времени на бэкенд не добавлены, дополнительные временные метки в Redis не сохраняются. Между раундами используется только `between_rounds_delay`; сессию после последнего вопроса завершает оператор.
- Миграция `0058` переносит стандартные настройки и JSON-снимки существующих сессий: включённый автопоказ становится задержкой `0`, выключенные действия — `null`, включённый автопереход сохраняет свою задержку. Старые флаги удаляются после переноса. Миграция требует применения перед использованием обновлённого API.

- При переносе капитана оператором новый капитан старой команды выбирается случайно из оставшихся участников; у опустевшей команды `captain_id` становится `null`.
- В целевой команде без капитана роль получает перенесённый участник; действующий капитан сохраняется. Перенос и назначения сохраняются одной транзакцией, конкурирующие операции состава сессии выполняются последовательно.
- После переноса отправляется только `participant_team_changed`; клиент по нему обновляет составы и капитанов команд. Повторный перенос в ту же команду не меняет состояние и не отправляет события; заполненная целевая команда отклоняет перенос без изменений.

- Добавлено досрочное закрытие вопроса после ответов всех участников индивидуальной игры или ответов капитанов всех непустых команд. Сервер отправляет `all_answered` один раз и применяет обработку окончания таймера `/led/next`; любой ответ капитана решающий независимо от `is_final`, предварительные голоса остальных участников не закрывают приём. Новые проверки времени и временные метки не добавлены.

- Имена участников викторины в составе сессии, ответах и индивидуальных результатах берутся из `users.first_name` и `users.last_name` одним запросом вместе с участниками. При регистрации гостя сохраняются `first_name="Гость"` и `last_name=str(users.id)`.

- Добавлен операторский `POST /api/quiz/sessions/{id}/final-round`: после раскрытия последнего вопроса основных раундов добавляет `FINAL = 9` и его вопросы в текущую сессию, сразу запускает первый вопрос. Поддерживаются явные `question_ids` или `question_count` с необязательными фильтрами; после 8 основных раундов разрешён девятый финальный.
- Состояние содержит вычисляемый `can_start_final_round`; финал добавляется только один раз, повторные и параллельные запросы не создают дубликатов. Сохраняются участники, команды и баллы; действуют существующие финальный множитель и события вопросов. После финала используется обычный `/finish` без повторного выбора. Новых миграций и временных меток нет.

## Сессии устройства

- Добавлен `/api/device/sessions/ws?token=<device_jwt>` для любых активных устройств независимо от ролей, включая устройства без ролей. Устройство получает только свои события `session_started` / `session_finished` с `payload.device_id`, `payload.session_id`, `payload.module` (`quiz` / `interactive_video`).
- Начало викторины сообщается при создании в waiting, видео — при запуске в active. Завершение сообщается при finish викторины, ручной остановке видео и естественном окончании последнего сценария; повторное завершение не дублирует событие.
- Канал использует существующую проверку JWT и Origin; БД освобождается до ожидания сообщений. История не воспроизводится, после переподключения клиент читает активные сессии через REST.
