# 0.37 — Настройки экрана

13.11.2026

- Добавлена таблица `screen_settings`: одна общая запись без `id` и первичного ключа и 12 отдельных колонок с заданными значениями по умолчанию, без описаний.
- Миграция `0098_create_screen_settings` создаёт таблицу и добавляет начальную запись через `INSERT INTO screen_settings DEFAULT VALUES`.
- Добавлены `GET /api/cms/led/settings` и `PUT /api/cms/led/settings`, доступные только активному администратору со Staff JWT. В JSON сохранены имена в camelCase, ответ содержит только значения настроек.
- Чтение и обновление работают с единственной записью без идентификатора. PUT изменяет переданные колонки, сохраняя остальные. Длительности допускают дробные значения >= 0, количество заставок — целое >= 1; null, нечисловые значения и неизвестные поля отклоняются.
- Обновлены OpenAPI, описание сущности и проверки прав; добавлены изолированные API-тесты.

- Аватар Яндекс/VK скачивается и устанавливается только при пустом `users.media_id`. Установленная фотография сохраняется при повторном входе, включая загруженную пользователем; CDN аватара в этом случае не запрашивается. Добавлены API-проверки сохранения и заполнения отсутствующего аватара.

- В таймер викторины и `voting_point.timer` «Профессий в действии» добавлено `remaining_ms`: неотрицательный остаток в миллисекундах, рассчитанный по времени сервера при формировании ответа. На паузе викторины возвращается `remaining_at_pause * 1000`, при остановке — `0`. Значение пересчитывается для каждого ответа и не сохраняется. Обновлены схемы, документация и API-тесты; миграция не требуется.

- `PUT /api/quiz/sessions/{id}/teams/{teamId}/captain` принимает User JWT текущего капитана команды: он может передать роль участнику той же команды. Используется существующая `get_current_identity`; проверка текущего капитана выполняется в сервисе под блокировкой сессии. Права оператора и администратора сохранены, Device JWT не допускается. Ответы и отметки решающего ответа не сбрасываются. Добавлены API-проверки доступа и передачи; миграция не требуется.

- Добавлен `DELETE /api/quiz/sessions/{id}/participants/{participantId}` для оператора и администратора в обоих режимах викторины (204). Удаляются участник и его текущий ответ; при удалении капитана выбирается другой участник команды либо null. До закрытия приёма и раскрытия ответа снимается отметка решающего ответа команды удалённого капитана. Проверка «все ответили» повторяется по оставшемуся составу, включая паузу; пустые команды не учитываются. Начисленные очки команды и история оценённых ответов сохраняются. Добавлены событие `participant_removed`, документация и API-тесты; миграция не требуется.
