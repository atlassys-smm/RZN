# Версия 0.23

Дата: 27.10.2026

- Добавлена интеграция FaceAI v2: терминал создаёт задание через
  `POST /api/users/avatar-generations` и получает статус и файл через
  `GET /api/users/avatar-generations/{request_id}`. Требуются device-токен с ролью 2,
  действующая QR-привязка. Каждый POST создаёт отдельное задание.
- Задания хранятся в PostgreSQL; миграция 0084 создаёт avatar_generations.
  Для ограничения времени используется только deadline_at; срок FaceAI не сохраняется.
  Повтор результата определяется по статусу задания под блокировкой его записи.
  Допускается несколько активных заданий на пользователя, срок каждого — 24 часа. Исходники сохраняются без автоматического удаления.
- Фоновый обработчик отправляет сохранённое селфи и исходный файл эталона с неизменным UUID,
  повторяет запросы после сетевых сбоев и 429 с учётом Retry-After, восстанавливает
  задания после перезапуска. Резервный опрос FaceAI и скачивание JPEG сохраняют
  результат при пропущенном webhook.
- `POST /api/faceai/webhook` использует отдельный Bearer-токен, проверяет данные
  задания и идентификатор события. Повторы, конкурентные доставки, ранний webhook
  и гонка с резервным скачиванием не создают дубликатов UserAvatar.
- В env добавлены адрес, API-ключ FaceAI, отдельный токен webhook и параметры
  обработчика. До настройки адреса и API-ключа отправка отключена; задания создаются в ожидании.
- Отдельные ограничения размера и числа пикселей FaceAI отсутствуют; прежние общие файловые лимиты сохранены.
- Исходные эталоны и селфи проверяются по MIME-типу и сигнатуре JPEG/PNG;
  результат — JPEG. Декодирование и зависимость Pillow удалены. При создании
  задания нет повторной проверки размера эталона. В CMS добавлены необязательные `male_file_preview` и
  `female_file_preview`; ссылки возвращаются общим объектом файла.
- Обновлены исходный и bundled OpenAPI, документация подсистемы и сущностей.
  Проверки интеграции выполняются с HTTP-моками по документированному контракту;
  развёрнутый FaceAI пока недоступен.

- В `GET /api/me/avatars` добавлен необязательный фильтр `profession_id`;
  `total` учитывает пользователя и профессию до пагинации. Проверены список
  и удаление своих результатов FaceAI через `DELETE /api/me/avatars/{avatar_id}`,
  защита владельца, сохранение исходников и отсутствие восстановления по повторному webhook.

- Добавлен `/api/avatar/ws?token=<device_jwt>`: активное устройство с ролью 2
  получает `generation_status_changed` только своих генераций. Payload содержит
  user_id, generation_id, request_id, job_id, device_id, status. События отправляются
  после коммита при создании и смене статуса; повторы и откаты не рассылаются.
  GET статуса сохранён для получения результата и восстановления после reconnect.

- Копирование эталона при создании задания убрано: reference_file_id хранит
  исходный File.id шаблона.

## Автоматическое включение встраивания Metabase

- `infra/metabase/scripts/deploy.py` включает `enable-embedding-static` перед
  созданием и обновлением карточек, в том числе при `--init`. Это предотвращает
  ошибку `Embedding is not enabled` на новой установке Metabase.
- Ключ подписи не меняется. `--plan`, отдельный `--verify` и `--check-env`
  не изменяют настройки Metabase.
- Добавлены изолированные проверки первого и повторного развёртывания, а также
  отсутствия изменений в режимах просмотра плана и проверки.
