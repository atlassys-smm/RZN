# Версия 0.12

Дата: 15.10.2026

---

## Обновление данных пользователя

- Добавлен `PATCH /api/user/info` с универсальной сервисной функцией обновления профиля. Принимает `first_name` и `last_name` владельца User JWT, включая гостя с действующей сессией, и возвращает обновлённый профиль.
- Можно изменить имя, фамилию или оба поля. Хотя бы одно поле обязательно; пропущенные поля и остальные данные сохраняются.
- Пробелы по краям удаляются; допустимы строки от 1 до 255 символов. Пустые строки, `null`, неверный тип, пустое тело и лишние поля возвращают 422; отсутствие действующего User JWT — 401.
- Ответ содержит `Cache-Control: no-store` и `Pragma: no-cache`.
- Обновлены исходный и собранный OpenAPI; добавлены API-тесты частичного обновления, валидации и доступа.


## Профиль сотрудника

- В новом модуле `app/api/staff` добавлены `GET /api/staff/info` и `PATCH /api/staff/info` для владельца действующего Staff JWT любой роли.
- GET возвращает ID, email, имя, фамилию, роль и статус. PATCH частично обновляет имя и фамилию, длина каждого — от 1 до 100 символов после удаления пробелов по краям. Пропущенные поля сохраняются; пустое тело, `null` и лишние поля отклоняются.
- Дополнительные проверки выполняются в сервисе через `HTTPException(422)`, без валидаторов модели. Ответы, включая ошибки, не кэшируются.
- Обновлены OpenAPI и описание CMS; добавлены API-тесты профиля, частичного обновления, прав доступа и валидации.

## Число голосов в интерактивном видео

- В `voting_point` ответов `GET /interactive-video/sessions/{id}/state` и `GET /interactive-video/sessions/{id}/voting` добавлено `voted_count` — число уникальных пользователей, проголосовавших в текущей точке выбора. До первого голоса — 0; в фазе воспроизведения `voting_point=null`.
- Счётчик использует существующее распределение голосов в Redis и также доступен в ответах с общей схемой состояния (`active`, `advance`). Один пользователь учитывается один раз в каждой точке выбора.
- Общее число потенциальных голосующих неизвестно: join не сохраняет участников, голосование не требует join или WebSocket. Число соединений не является числом уникальных зрителей.
- Обновлён OpenAPI и добавлены изолированные API-тесты счётчика.

## Правильный ответ для сотрудника

- В состоянии активной викторины `current_question.correct_answer` возвращается сотруднику сразу, включая пояснение: чтение по ID и активной сессии, ответы операторских next/skip/timer-stop.
- Для User и Device правильный ответ доступен только после reveal. Просмотр сотрудником не меняет Redis-флаг раскрытия, таймер, приём ответов или WebSocket-события.
- Обновлены OpenAPI, инструкция оператора и API-тесты разграничения видимости.
