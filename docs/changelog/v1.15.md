### Миграция enum → integer (справочники)

Все строковые enum-значения в API и сущностях переведены на числовые ID:

**Викторина:**
- `question_type`: строка → integer (1–18, см. [справочник](../references/quiz-question-types.md))
- `difficulty`: `easy`/`medium`/`hard` → `1`/`2`/`3`
- `age_group`: строка → integer (см. [справочник](../references/profstart-age-groups.md))
- `round_type`: строка → integer (1–9, см. [справочник](../references/scenario-round-types.md))
- `template.status`: `draft`/`published` → `1`/`2`
- `mode`: `individual`/`team` → `1`/`2`

**GameSession:**
- `status`: `waiting`/`active`/`finished` → `1`/`2`/`3`
- `mode`: `individual`/`team` → `1`/`2`
- `round_type`: строка → integer

**ProfStart (тесты):**
- `age_group`: строка → integer

### User: новые статусы

Статусы пользователя изменены с 2 на 4:

| Значение | Статус | Описание |
|----------|--------|----------|
| 1 | `guest` | Гостевой режим: есть `guest_id`, 24 часа на авторизацию |
| 2 | `active` | Авторизован через OAuth |
| 3 | `anonymized` | Гость не авторизовался за 24ч, данные обезличены |
| 4 | `deactivated` | Деактивирован администратором |

Ранее гость создавался со `status = active` и определялся по полям `guest_id`/`guest_expires_at`. Теперь гость — отдельный статус `guest`.

Обновлены: `docs/entities/users.md`, `docs/concept/explanatory-note.md`, `docs/concept/registration-profile.md`

### GameSession: привязка к устройству, упрощение модели

- Добавлено поле `device_id` (integer, int64) — LED-устройство, на котором проводится сессия
- На одном устройстве может быть только одна незавершённая сессия (`status` 1 или 2)
- Удалён `scoring` JSON из `settings` — система баллов упрощена, настройки удалены из документации
- API создания сессии: добавлен `device_id` (обязательный), убран `template_id` (клиент переносит раунды из шаблона вручную)
- Удалён отдельный файл `docs/entities/timer-state.md` — логика таймера перенесена в `game-session.md`

### Викторина: уточнения модели

**Вопросы:**
- Добавлено поле `answer_key` (object) — эталонный ответ для структурированных типов вопросов
- Для вариантов ответов добавлено поле `side` (integer, 1/2) — сторона элемента для вопроса типа `matching`
- `time_limit` — обязательное поле (было опциональным)
- Нельзя редактировать/удалить вопрос, используемый незавершённой сессией (409 Conflict)

**Шаблоны:**
- Удалено ограничение на удаление шаблона, использованного в сессиях (сессии хранят собственный снапшот)
- Удалено действие «Копировать» из CMS

**Командная игра:**
- Участники отправляют предварительные ответы через `answer`; капитан видит ответы команды
- Капитан отдельно отправляет решающий ответ с `is_final = true`; только он засчитывается команде
- Уточнены ограничения: после исключения пустых команд должны остаться ≥2 команд, в каждой ≥2 участника

**Redis-состояние:**
- Ключи таймера: `timer_ends_at`, `timer_remaining_at_pause`, `timer_running` (отдельные ключи вместо hash)
- `answers` (hash) вместо `votes` — хранит принятые ответы
