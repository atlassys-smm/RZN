# Расчёт результата

При отправке последнего ответа через POST /profstart/answer клиент показывает индикатор до получения подтверждения. Сервер атомарно сохраняет ответ и результат и возвращает status=2 (completed). После подтверждения клиент получает результат через GET /profstart/sessions/{id}/result. ID сессии в запросе ответа не передаётся; используется текущая собственная in_progress. После completed или abandoned, если собственной in_progress нет, повтор ответа возвращает 409. При одновременных отправках последнего ответа создаётся один результат: второй запрос получает 409.

Целевое время расчёта — до 3 секунд, формирования итогового экрана — до 5 секунд. При потере подтверждения клиент читает GET /profstart/sessions/{id}, используя сохранённый ID начатой сессии. Если status=2 (completed), получает сохранённый результат через GET /profstart/sessions/{id}/result. Если сессия in_progress, читает GET /profstart/question и восстанавливает прохождение; повторяет тот же ответ, когда его сохранение ещё не подтверждено. Новый тест автоматически не создаётся.

При 409 клиент проверяет статус известной сессии: completed ведёт к результату, abandoned — к стартовому экрану, in_progress — к следующему вопросу. При 422 из-за неверной конфигурации банка последний ответ не сохраняется и результат отсутствует; клиент показывает ошибку, не подменяя её произвольным результатом.

После успешного ответа открывается [экран результата](result.md).
