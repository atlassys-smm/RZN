# Управление раундом

Универсальный экран активной сессии. Используется для индивидуальной викторины и командной игры.

---

## Восстановление сессии

При перезапуске планшета приложение вызывает `GET /quiz/sessions/active` для восстановления текущей сессии. Если активной сессии нет — возврат на экран создания сессии.

Запрос требует `device_id`. `round_count` возвращает общее число раундов,
`current_round_question_count` — число вопросов в текущем раунде (до старта — в первом).
Для восстановления состава передаются `select=teams&select=participants`.

При запросе со Staff JWT `current_question.correct_answer` возвращается сразу,
включая пояснение. Игрок и LED получают его только после `reveal`.
Просмотр ответа сотрудником не завершает приём ответов и не раскрывает его игрокам.

---

## Получение обновлений

Планшет подключается к WebSocket `ws://host/api/quiz/sessions/{id}/ws?token=<jwt>` для получения обновлений в реальном времени:
- Подключение новых участников
- Обновление таймера
- Результаты голосования
- Изменение состояния сессии
- Пауза, возобновление, добавление времени и закрытие приёма ответов
- Смена команды участника, капитана и названия команды

После подключения, переподключения и каждого события клиент запрашивает
`GET /quiz/sessions/active?device_id=...&select=teams&select=participants`.
По сокету передаётся только тип события, без данных. Полный список событий и порядок обновления
данных описаны в [WebSocket API](../../api/websocket.md#викторина).

---

## Голосование текущего вопроса

`select=answers` добавляет в ответ сессии корневое поле `answers`:
голоса участников (`participant_answers`), решающие ответы и статусы команд
(`team_answers`), счётчики по вариантам (`option_counts`). Сотрудник видит все команды.
Параметр можно объединять с `select=teams&select=participants`; списки повторно не загружаются.
Без параметра блок отсутствует. До старта и после завершения игры `answers=null`.

---

## Статусы сессии

| Статус | Поведение планшета |
|--------|-------------------|
| 1 (`waiting`) | Экран формирования команд. Кнопка «Начать игру» → переход в status `2` (`active`). |
| 2 (`active`) | Экран управления раундом (этот экран). |
| 3 (`finished`) | Экран итоговых результатов. |

## Элементы управления

### Информация о раунде

| Элемент | Описание |
|---------|----------|
| Номер раунда | Текущий раунд из общего количества (например, «Раунд 2 из 6») |
| Тип раунда | Название типа текущего раунда |
| Прогресс вопросов | Текущий вопрос из общего количества в раунде |

### Таймер

Основной элемент управления во время раунда.

| Действие | Описание |
|----------|----------|
| Пауза | `POST /quiz/sessions/{id}/timer/pause`; продолжить через `/timer/resume` |
| Завершить досрочно | `POST /quiz/sessions/{id}/timer/stop` — закрыть приём ответов текущего вопроса |
| Добавить время | `POST /quiz/sessions/{id}/timer/add-time` с положительным числом секунд |

Таймер отображается на LED-экране.

### Статус приёма ответов

Индикация: сколько команд (или участников) отправили ответ.

## Показ ответа

После завершения приёма ответов (таймер или досрочное завершение):

### Если `auto_reveal_delay` задан числом
Правильный ответ показывается автоматически через заданное число секунд после закрытия приёма ответов. Значение по умолчанию `0` означает показ сразу.

### Если `auto_reveal_delay = null`
Оператор нажимает кнопку **«Показать ответ»** → показ правильного ответа.

### На LED-экране
- Правильный ответ
- Методическое пояснение

### На планшете оператора
- Правильный ответ
- Методическое пояснение
- Кнопка **«Следующий вопрос»** → переход к следующему вопросу
- Кнопка **«Пропустить»** → `POST /quiz/sessions/{id}/skip`, пропустить показ ответа и перейти дальше

### Автопереход
Если `auto_next_delay` задан числом, следующий вопрос внутри раунда показывается через указанное количество секунд после показа ответа; `0` означает переход без ожидания. При `null` автопереход отключён. Оператор может перейти вручную до окончания задержки. Между раундами действует только `between_rounds_delay`.

Отсчёт задержек выполняет клиент. LED вызывает `POST /quiz/sessions/{id}/led/next` после нужного ожидания; при `null` автоматический вызов не выполняется. Сервер не проверяет сроки этих задержек. После ручной остановки при положительном `auto_reveal_delay` клиент вызывает `reveal` по окончании задержки; `0` раскрывает ответ сразу, `null` оставляет показ оператору.

Методическое пояснение берётся из поля `explanation` вопроса ([GameQuestion](../../entities/quiz.md)).

## Командный режим — дополнительные элементы

Доступна панель управления командами — та же, что на экране [формирования команд](team-formation.md#team-actions): переименование, перенос участников, смена капитана.

---

## Состояния между раундами

После последнего вопроса текущего раунда:

- Результаты отображаются на LED-экране
- Если `between_rounds_delay` задан числом — переход к следующему раунду через указанное количество секунд после показа ответа; `0` — без ожидания, `null` — только ручной переход
- На планшете — кнопка **«Следующий раунд»** → запуск следующего раунда
- После последнего раунда — кнопка **«Итоги»** → переход к [итоговым результатам](final-results.md).
- Оператор завершает сессию явно через `POST /quiz/sessions/{id}/finish` → status `3` (`finished`)

## Индивидуальная викторина

Экран работает в том же режиме, но без командной части:

- Нет панели управления командами
- Отображается общая статистика: количество ответивших, процент правильных ответов
- После последнего раунда — кнопка «Итоги» → переход к [итоговым результатам](final-results.md)
- По итогам — рейтинг участников (кто сколько баллов набрал)



Передавайте staff access JWT в token. Проверка авторизации выполняется только при подключении.
