# Профессии в действии

Запуск интерактивного видеосценария с точками выбора на LED-экране.

---

## Восстановление сессии

При перезапуске планшета приложение вызывает `GET /interactive-video/sessions/active` для восстановления текущей сессии. Если активной сессии нет — возврат на главный экран.

---

## Элементы

| Элемент | Описание |
|---------|----------|
| Количество профессий | Выбор: сколько профессий показать за сеанс (от 1 до 10, по умолчанию 3) |
| Видеосценарии | Опциональный выбор конкретных сценариев. Если не выбраны — система выбирает случайные |

---

## Действия

| Действие | Описание | API |
|----------|----------|-----|
| Запустить | Запуск показа профессий на LED-экране | `POST /interactive-video/sessions` |
| Завершить | Остановка показа, возврат LED в режим ожидания | `POST /interactive-video/sessions/{id}/stop` |

---

## Примечания

- Если `scenario_ids` не указан — система выбирает профессии случайным образом из доступных видеосценариев
- Во время показа зрители голосуют за вариант продолжения через мобильные устройства (QR-код на LED-экране)
- Если таймер истёк и никто не выбрал — система выбирает продолжение автоматически
- После завершения всех профессий LED автоматически возвращается в режим ожидания
- Оператор может завершить показ досрочно через кнопку «Завершить»

## Демонстрационное прохождение через API

Команда использует DEMO_ADMIN_LOGIN, DEMO_ADMIN_PASS и DEMO_API_URL из
окружения контейнера Docker `api`:

```sh
docker compose exec -T api python -m app.cli.simulate_video
docker compose exec -T api python -m app.cli.simulate_video --scenario-id 1,2 --device-id 3 --answers first
docker compose exec -T api python -m app.cli.simulate_video --profession-count 2 --seed 42 --report /app/storage/infra/video-run.json
```

В примере ID следует заменить на существующие. Каждый запуск создаёт одного
нового гостя и одну видеосессию. Без выбора ID берётся до трёх случайных
существующих сценариев с путём к конечной ветке. Новые сценарии, ветки и
устройства не создаются.

| Параметр | Поведение |
|----------|-----------|
| `--scenario-id` | Один ID или список через запятую; порядок сохраняется. Некорректный сценарий не заменяется другим. |
| `--profession-count` | Количество случайных сценариев, не больше числа подходящих в базе; по умолчанию до 3. Не сочетается с --scenario-id. |
| `--device-id` | Активное устройство с ролью QUIZ_VIDEO (1). Без параметра выбирается случайное свободное устройство; незавершённые викторины и видеосессии не затрагиваются. |
| `--answers random` | Случайный вариант среди продолжений, позволяющих закончить сценарий без повторного вопроса. Используется по умолчанию. |
| `--answers first` | Первый допустимый вариант по branch_id. Правильных ответов в этом модуле нет. |
| `--seed` | Повторяет выбор сценариев, устройства и ответов при одинаковых исходных данных. |
| `--report` | Новый JSON-файл с ID гостя, устройства, согласия, сессии, сценариями, пройденными ветками, принятыми голосами и прогрессом. Пароли и токены не сохраняются. |
| `--base-url`, `--origin` | Как в остальных demo-командах: DEMO_API_URL и первый AUTH_ALLOWED_ORIGINS по умолчанию. |

Администратор читает CMS и создаёт сессию. Токен выбранного устройства
получается через штатный POST /cms/devices/{id}/refresh-token; этот маршрут
выдаёт JWT без отзыва существующих токенов. Клиент устройства вызывает
/interactive-video/sessions/{id}/advance, имитируя окончание видео, без
ожидания длительности файла. Реальный плеер, загрузка видео и WebSocket для
этой проверки API не используются.

Гость вступает в сессию ровно один раз, получает /voting и отправляет /vote.
Для одного участника принятый голос сразу завершает голосование и запускает
выбранную ветку. Ссылочный вариант отправляется по своему исходному ID;
команда проверяет фактический переход к конечной цели ссылки. Циклические
цепочки и варианты без пути к завершению не выбираются. В одной сессии
проходится один маршрут каждого сценария, а не все альтернативные ветки.

После конечной ветки /advance запускает следующий сценарий; после последнего
штатно завершает сессию (status=2). Команда проверяет завершение всех выбранных
сценариев и отсутствие активной видеосессии на устройстве. Досрочный /stop
для успешного прохождения не вызывается. Сценарий без вариантов выбора
корректно завершается без голосов; вопросы искусственно не добавляются.

До создания гостя проверяются сценарии, свободное устройство, доступ к его
токену и действующее согласие. В новой сессии voting_duration=300 даёт запас
для запросов, result_display_duration=0; ждать таймер не требуется.
Если подключился ещё один участник, состояние изменилось неожиданно или
произошла ошибка API, выполнение прекращается с частичным отчётом и ID сессии.
Автоматических повторов записи и /stop при ошибке нет. Авторизации гостя и
администратора закрываются, Device JWT не является пользовательской AuthSession.

Код выхода: 0 — все выбранные сценарии завершены; 1 — ошибка выполнения,
2 — ошибка параметров/настроек, 130 — прерывание. Отчёт из /app/storage/infra/
доступен на хосте в storage/infra/ проекта; существующий файл не перезаписывается.
Созданные гость и сессия остаются в системе.

Независимые проверки demo-команд, без БД и Redis:

```sh
docker compose exec -T api python -m unittest discover -s tests/cli -v
```
