# Техническое задание

## Оказание услуг по формированию программного контура единой платформы для автоматизированного развертывания на вычислительном оборудовании

---

## 1. Цели и основание работ

### 1.1. Наименование закупки

Оказание услуг по формированию программного контура единой платформы для автоматизированного развертывания на вычислительном оборудовании.

### 1.2. Основание для выполнения работ

Единый программно-аппаратный комплекс «ПрофНавигатор» представляет собой сложный программный массив, включающий множество взаимосвязанных компонентов: медиаплатформу, систему управления контентом, модули аналитики, сервисы идентификации, подсистемы обратной связи и иные программные модули. Каждый компонент имеет собственный набор зависимостей, версий библиотек и конфигураций, которые должны быть согласованы между собой для корректной совместной работы.

По классической архитектуре для развёртывания подобной системы требуется выделенный физический сервер с предварительно настроенной операционной системой, ручная установка и конфигурирование каждого программного компонента, а также квалифицированный персонал для сопровождения. На практике развёртывание одного экземпляра платформы занимает от нескольких рабочих дней до недели: установка операционной системы, настройка системных зависимостей, установка и конфигурирование базы данных, развёртывание каждого сервиса, настройка сетевого взаимодействия между компонентами, проверка работоспособности.

Дополнительные проблемы возникают при необходимости переноса системы на другое оборудование: необходимо повторять весь цикл настройки, при этом неизбежны расхождения в конфигурациях, что приводит к различиям в поведению системы на разных экземплярах. При выходе из строя оборудования восстановление работоспособности требует привлечения квалифицированного специалиста и занимает значительное время.

Ситуация усугубляется тем, что оборудование может поставляться разными партиями с незначительными различиями в конфигурации (версия ядра, набор предустановленных пакетов, параметры файловой системы). При классическом подходе каждое такое различие требует индивидуальной адаптации процесса развёртывания, что делает его непредсказуемым по срокам и результату.

### 1.3. Цель работ

Формирование единого программного контура, обеспечивающего автоматизированное развёртывание всей платформы на произвольном вычислительном оборудовании без ручной настройки операционной системы и ручного конфигурирования каждого компонента.

Программный контур «упаковывает» всю платформу в единый самодостаточный переносимый программный блок, который автоматически подстраивается под целевое оборудование и не требует ручной настройки базовой операционной системы.

### 1.4. Ожидаемые результаты

- сокращение времени развёртывания платформы с нескольких дней до десятков минут
- исключение человеческого фактора при настройке программных компонентов
- обеспечение идентичности программной среды на любом целевом оборудовании
- возможность оперативного восстановления работоспособности при выходе оборудования из строя
- единый воспроизводимый процесс развёртывания, не зависящий от квалификации исполнителя на месте

## 2. Область применения

### 2.1. Целевое оборудование

Программный контур развёртывается на вычислительном оборудовании, входящем в состав программно-аппаратных комплексов, поставляемых для оснащения Центра занятости населения. Оборудование характеризуется:

- стандартная серверная архитектура на базе процессоров x86-64
- операционная система семейства Linux
- дисковое хранилище достаточного объёма для размещения платформы и данных

Конкретные характеристики оборудования (модель процессора, объём оперативной памяти, тип и объём дискового хранилища) определяются спецификацией ПАК и учитываются при формировании конфигурации контура.

### 2.2. Место эксплуатации

г. Рязань, ул. Электрозаводская, д. 52.

### 2.3. Разграничение ответственности

Программное обеспечение платформы «ПрофНавигатор» (медиаплатформа, CMS, модули аналитики, сервисы идентификации, подсистемы обратной связи и иные компоненты) передаётся Заказчиком. Исполнитель выполняет работы по формированию программного контура — изолированной переносимой программной среды, обеспечивающей автоматизированное развёртывание и функционирование переданной платформы на вычислительном оборудовании без ручной настройки операционной системы.

Исполнитель не несёт ответственности за функциональность самих компонентов платформы, переданных Заказчиком. Ответственность Исполнителя ограничивается корректностью развёртывания, изоляцией среды, управлением жизненным циклом и обеспечением переносимости.

## 3. Срок выполнения работ

**Срок оказания услуг:** не более **60 календарных дней** с даты заключения контракта.

Работы выполняются в один этап.

## 4. Требования к программному контуру

### 4.1. Изоляция программной среды

- вся платформа размещается в едином программном контейнере, включающем операционное окружение, зависимости, конфигурации и компоненты платформы
- программная среда полностью самодостаточна и не зависит от предустановленного программного обеспечения на хостовой операционной системе, за исключением базовых драйверов оборудования
- перенос программного контура на другое совместимое оборудование не требует повторной установки или ручной настройки компонентов платформы
- изоляция программной среды гарантирует отсутствие конфликтов версий библиотек и зависимостей между компонентами платформы и программным обеспечением хостовой системы
- программный контур не вносит изменений в хостовую операционную систему: не устанавливает пакеты, не модифицирует системные конфигурации, не регистрирует системные службы

### 4.2. Автоматизация развёртывания

- развёртывание программного контура на новом оборудовании выполняется минимальным набором команд без участия квалифицированного специалиста по настройке операционной системы
- при первом запуске программный контур автоматически выполняет инициализацию: подготовку хранилища данных, создание служебных учётных записей, настройку сетевых портов, запуск всех компонентов платформы
- автоматическая проверка доступности и работоспособности всех сервисов после развёртывания
- время развёртывания на новом оборудовании — не более **30 минут** при наличии подготовленного образа
- процесс развёртывания включает следующие этапы: загрузка образа, инициализация хранилища данных, применение конфигурации, запуск компонентов, проверка работоспособности — каждый этап фиксируется в журнале

### 4.3. Переносимость

- программный контур сохраняет полную работоспособность при переносе на другое оборудование с аналогичной архитектурой процессора и совместимой операционной системой
- при переносе сохраняются все данные, конфигурации, журнал событий и история сессий
- перенос не приводит к потере работоспособности и не требует повторного развёртывания компонентов
- поддерживается перенос в состоянии «выключен» (остановленный контур) и в состоянии «работающий» (с предварительной остановкой сервисов)
- процедура переноса сводится к копированию образа и данных на целевое оборудование и запуску — без выполнения дополнительных настроечных процедур

### 4.4. Состав компонентов в контуре

Программный контур включает все компоненты платформы «ПрофНавигатор», переданные Заказчиком. Конкретный перечень компонентов определяется на этапе проектирования и фиксируется в документации по развёртыванию.

Контур обеспечивает совместное функционирование всех переданных компонентов в единой изолированной среде, включая необходимые службы баз данных и сетевого взаимодействия.

### 4.5. Управление конфигурацией

- ключевые параметры развёртывания настраиваются через единый конфигурационный файл без пересборки или модификации программного контура
- настраиваемые параметры включают: сетевые порты и адреса, параметры подключения к базе данных, привязку к оборудованию (LED-разрешение, порты ввода), пути хранения контента и данных
- изменение конфигурации применяется при следующем запуске программного контура
- конфигурация по умолчанию обеспечивает работоспособность без дополнительных настроек
- конфигурационный файл имеет текстовый формат и может быть отредактирован стандартными средствами операционной системы

### 4.6. Управление жизненным циклом

- автоматический запуск всех компонентов платформы при старте программного контура
- автоматическая проверка работоспособности каждого компонента (health check) с настраиваемым интервалом
- корректное завершение всех сервисов при остановке контура с сохранением целостности данных
- автоматический перезапуск компонента при его аварийном завершении
- просмотр состояния всех компонентов через единую команду или сервисный интерфейс
- доступ к журналам событий каждого компонента через единый механизм
- компоненты запускаются в определённом порядке, обеспечивающем корректную инициализацию зависимостей (база данных — первой, затем сервисы, зависящие от неё)
- при остановке контура компоненты завершаются в обратном порядке

### 4.7. Хранение данных

- данные платформы (база данных, медиафайлы, конфигурации, журналы) хранятся в изолированном томе, отделённом от программного кода компонентов
- обновление или пересоздание программного контура не приводит к потере данных
- поддержка резервного копирования и восстановления данных через стандартные механизмы
- настраиваемый срок хранения данных с возможностью архивации
- структура хранения данных организована таким образом, что программный код и данные физически разделены: программный код может быть заменён без затрагивания тома данных

### 4.8. Сетевое взаимодействие

- программный контур предоставляет единый сетевой интерфейс для доступа к компонентам платформы
- маршрутизация внутренних запросов между компонентами осуществляется внутри контура без необходимости настройки хостовой сети
- доступ к веб-интерфейсам (CMS, панель оператора, личный кабинет) осуществляется через настраиваемые порты
- внутренние сетевые порты компонентов не доступны извне — взаимодействие между компонентами происходит по внутренней сети контура

### 4.9. Взаимодействие с оборудованием

- программный контур обеспечивает доступ компонентов платформы к устройствам ввода-вывода, подключённым к вычислительному оборудованию (сенсорные панели, считыватели карт, аудиоустройства)
- драйверы оборудования, необходимые для работы платформы, устанавливаются на хостовой операционной системе и предоставляются контуру через механизм проброса устройств
- контур корректно обрабатывает подключение и отключение периферийных устройств без необходимости перезапуска
- видеовыход для LED-экрана настраивается через конфигурационный файл с указанием разрешения и параметров отображения

### 4.10. Мониторинг и диагностика

- встроенный механизм сбора журналов событий всех компонентов с единой точкой доступа
- диагностика состояния контура: использование ресурсов (процессор, память, дисковое пространство), состояние каждого компонента, доступность сетевых портов
- экспорт диагностической информации для передачи техническому специалисту
- журнал событий содержит временные метки всех значимых событий: запуск, остановка, перезапуск компонентов, ошибки, изменения конфигурации

## 5. Требования к воспроизводимости

- процесс формирования программного контура описан в документации и воспроизводим: по документированной процедуре из исходного кода и ресурсов платформы формируется идентичный программный контур
- каждая сборка идентифицируется уникальной версией, зафиксированной в конфигурации контура
- возможность формирования контура на произвольном оборудовании, удовлетворяющем требованиям к среде сборки
- версионирование позволяет откатиться к предыдущей стабильной сборке
- описание процесса сборки включает перечень необходимых инструментов и зависимостей среды сборки

---

## 6. Требования к безопасности

- программный контур работает с минимально необходимыми привилегиями хостовой операционной системы
- внутренние сервисы контура изолированы от прямого доступа из внешней сети, за исключением явно настроенных портов
- учётные данные и конфиденциальные данные не хранятся в открытом виде в конфигурационных файлах контура
- журналы событий не содержат персональных данных и конфиденциальной информации в открытом виде
- при обновлении программного контура существующие данные и конфигурации не подвергаются риску модификации или удаления

---

## 7. Требования к надёжности

- программный контур обеспечивает непрерывную работу платформы в режиме эксплуатации не менее **8 часов** без перезагрузки
- при аварийном завершении отдельного компонента остальные компоненты продолжают функционировать
- автоматический перезапуск аварийно завершённого компонента без остановки всего контура
- при заполнении дискового пространства сверх допустимого порога контур фиксирует событие и продолжает работу с имеющимися ресурсами
- корректное поведение при кратковременных сбоях питания: после восстановления питания контур автоматически возобновляет работу
